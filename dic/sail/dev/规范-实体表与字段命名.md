# 规范 · 实体表名与字段名

> 状态：**实施中**（2026-11-14；实体 SooTable/SooColumn 已按本文改名；存量库需重建或迁移）  
> 用途：统一 sailflow 全部持久化实体的**表名 / 字段名**写法；指导新建表与存量整改。  
> 范围：`SooTable` / `SooColumn` 落库名；C# 属性名可保持可读 PascalCase，**不以**属性名代替列名。  
> 关联：[分析-流程运转表存储与分表策略](../../../doc/sail/分析-流程运转表存储与分表策略.md)

---

## 0. 结论先行

| 规则 | 口径 |
|------|------|
| **长度** | 表名、字段名**一般 ≤ 20 字符**（含前缀与下划线）；超长只压缩**非核心/非主义**词 |
| **表名核心词** | 表名中的**主义/核心语义词不得缩写**；只压缩修饰词。例：核心为实例 → `wf_proc_instance` |
| **字段主义词** | 字段语义的**主义单词全拼**；**仅一个单词时也不得缩写**（`name`/`code`/`type`/`state`/`version`…，禁止 `nm`/`cd`/`typ`/`stat`/`ver`） |
| **大小写** | 一律 **snake_case 小写**；禁止 PascalCase 列名/表名 |
| **表前缀** | 按**业务域**固定 1～2 字符 + `_`（如 `wf_`、`sf_`、`fm_`、`ai_`） |
| **字段前缀** | **必带**；由本表表名**关键单词**缩写拼成 1～2 字符 + `_` |
| **主键** | `{字段前缀}id`（如 `tk_id`）；不再使用裸 `id` |
| **外键** | `{字段前缀}{对方表非前缀全名}_id`；同表对同一对方表 ≥2 个 FK 时加业务含义 |
| **存量** | 实体已按本文改名；存量库需重建或迁移 |

## 1. 两条硬约束

### 1.1 长度 ≤ 20

- 统计含前缀、下划线全部字符。
- **例外（须在评审中显式批准）**：归档分表后缀 `*_hist_YYYY` 的年度后缀可超出 20；热表本体仍须 ≤20。

### 1.2 表名：核心词不缩写（主义词）

一张表只认定 **一个核心语义词**（“这张表是什么”），该词在表名中必须**全拼**；其余修饰词用 §3 压缩，以压进 20 字符。

| 表在说什么 | 核心词（全拼） | 修饰词（可缩） | 正确 | 错误 |
|------------|----------------|----------------|------|------|
| 流程**实例** | `instance` | process→`proc` | `wf_proc_instance` | `wf_proc_inst`、`wf_process_inst` |
| 活动**实例** | `instance` | activity→`act` | `wf_act_instance` | `wf_act_inst` |
| 转移**实例** | `instance` | transition→`tran` | `wf_tran_instance` | `wf_tran_inst`、`wf_transition_instance`（超长） |
| 流程**变量**（运行时） | `variable` | process→`proc` | `wf_proc_variable` | `wf_proc_var` |
| 变量**定义** | `variable` | — | `wf_variable` | — |
| 流程**定义** | `process` | — | `wf_process` | `wf_proc` |
| 任务 | `task` | — | `wf_task` | — |
| Hook **Outbox** | `outbox` | hook 可留 | `wf_hook_outbox` | `wf_hook_obox` |
| 模型**提供方** | `provider` | model→`mdl` | `ai_mdl_provider` | `ai_mdl_prov` |
| 活动 AI **配置** | `config` | activity→`act` | `ai_act_config` | `ai_act_cfg` |
| 知识库**文档** | `document` | — | `kb_document` | `kb_doc`（除非评审认定核心就是 doc 代号） |
| 流程实例**抄送** | `copy` | process→`proc` | `sf_proc_copy` | `sf_process_instance_copy`（超长） |

判定口诀：

1. 先问「去掉修饰后，表还是什么？」——留下的那个词即核心词，**禁止**走 §3 缩写。
2. 修饰词（所属对象、类型限定）才缩写。
3. 若核心词全拼后仍 >20：先再压修饰词；仍超则改域前缀策略或拆词，**仍不得**把核心词缩掉（需评审另案）。

> **外键字段**另遵 §1.4：对方表非前缀全名必须保留。  
> **普通字段**另遵 §1.5：主义词 / 单词语意全拼。

### 1.3 凡名必有前缀

| 对象 | 前缀来源 | 形态 |
|------|----------|------|
| **表名** | 业务域登记册（§2） | `{域前缀}{表主干}`，如 `wf_task`、`fm_form` |
| **字段名** | 本表关键单词缩写组合（§4） | `{字段前缀}{语义}`，如 `tk_state`、`tk_proc_instance_id` |

反例（禁止）：

- 表：`FbForm`、`activity_instance`（无域前缀 / 非 snake）
- 字段：`id`、`process_id`、`created_datetime`（无本表字段前缀）

### 1.5 字段：主义词全拼；单词不缩写

去掉本表字段前缀后，看剩下的语义段：

1. **只有一个单词** → 必须全拼，禁止走 §3 缩写。  
   例：`tk_name`、`p_code`、`p_version`、`rs_mode`、`ho_kind`、`v_value`（禁止 `tk_nm`、`p_cd`、`p_ver`、`v_val`）。
2. **多个单词** → 认定**一个主义词**（通常是最后的名词：`name`/`type`/`state`/`time`/`id`/`expression`/`content`…）**全拼**；仅压缩前面的修饰词。  
   例：`tk_task_type`、`ai_activity_state`、`p_start_expression`、`tk_crt_time`（`time` 全拼，`created`→`crt`）。
3. **仍超 20** → 只继续压修饰词；主义词不动。仍超则评审另案。

| 语义 | 正确 | 错误 |
|------|------|------|
| 名称 | `p_name` / `tk_activity_name` | `p_nm` / `tk_act_nm` |
| 编码 | `p_code` / `ai_activity_code` | `p_cd` / `ai_act_cd` |
| 版本 | `p_version` | `p_ver` |
| 类型 | `tk_task_type` | `tk_task_typ` / `tk_typ` |
| 状态 | `tk_task_state` / `pi_process_state` | `tk_task_stat` / `pi_proc_stat` |
| 描述 | `p_description` | `p_desc` |
| 内容 | `p_xml_content` | `p_xml_cnt` |
| 时间（审计） | `tk_crt_time` | `tk_crt_tm` |
| 用户 id/名 | `tk_crt_user_id` / `tk_crt_user_name` | `tk_crt_uid` / `tk_crt_unm` |
| 消息 | `lg_message` | `lg_msg` |

例外（仍允许短写）：

- 主键后缀 `id`、外键角色单字母（`f`/`t`/`m`/`s`/`o`/`i`，见 §1.4）——角色不是主义词。  
- BPMN 节点等**无实体表**引用：优先全拼 `activity_id`；仅当总长 >20 时才压修饰，主义词 `id`/`name` 仍全拼。

### 1.4 外键：保留对方表「非前缀全名」

指向**另一张实体表**主键（或业务键）的列，语义段必须使用对方**建议表名去掉域前缀**后的完整主干，不得改用字段前缀短码。

```text
# 本表对某对方表仅 1 个外键（默认真身）
{本表字段前缀}{对方表非前缀全名}_id

# 本表对同一对方表有 ≥2 个外键 → 必须按业务含义加角色
{本表字段前缀}{业务含义}_{对方表非前缀全名}_id
```

| 对方建议表名 | 非前缀全名（外键词干） | 单 FK 示例 | 禁止 |
|--------------|------------------------|------------|------|
| `wf_proc_instance` | `proc_instance` | `tk_proc_instance_id` | `tk_pi_id` |
| `wf_act_instance` | `act_instance` | `tk_act_instance_id` | `tk_ai_id` |
| `wf_process` | `process` | `tk_process_id` | `tk_proc_id`、`tk_p_id` |
| `wf_task` | `task` | `ho_task_id` | `ho_tk_id` |
| `wf_variable` | `variable` | （若有）`xx_variable_id` | `xx_v_id`、`xx_var_id` |
| `fm_form` | `form` | `fa_form_id` | `fa_ff_id` |
| `ai_mdl_provider` | `mdl_provider` | `ac_mdl_provider_id` | `ac_mp_id` |

#### 同一表、对同一对方表的多个外键

若一张表里有 **2 个及以上** 外键指向**同一张**对方表，则**每个**外键都必须带**业务含义**角色段，禁止再用「裸 stem」——否则列名冲突且分不清关系。

| 场景 | 对方表 | 业务含义 | 列名 |
|------|--------|----------|------|
| 转移：来源 / 去向活动实例 | `wf_act_instance` | from→`f` / to→`t` | `ti_f_act_instance_id`、`ti_t_act_instance_id`（均 =20；`frm`/`to` 会超长） |
| 活动：主实例（会签父） | `wf_act_instance` | main→`m` | `ai_m_act_instance_id` |
| 活动：退回源 / 退回原点 | `wf_act_instance` | back_src→`s` / back_org→`o` | `ai_s_act_instance_id`、`ai_o_act_instance_id` |
| 流程实例：唤起方活动实例 | `wf_act_instance` | invoked→`i` | `pi_i_act_instance_id` |
| 任务：被委托的原任务 | `wf_task` | entrust→`entr` | `tk_entr_task_id`（与本表主键 `tk_id` 区分；指向另一行 task） |

判定：

1. **仅 1 条**指向该对方表 → 可用裸名：`{pfx}{stem}_id`（业务上的「默认所属」）。
2. **≥2 条**指向该对方表 → **全部**写成 `{pfx}{业务含义}_{stem}_id`；不要留一条裸名、另一条带角色（除非评审认定裸名仍是唯一主从属、其余皆旁支——默认不采用，以免阅读歧义）。
3. 业务含义取自关系角色（来源/去向/父/子/委托/唤起…），用 §3 压缩；**不得**用 `fk1`/`fk2` 序号。

说明：

1. **域前缀去掉**：`wf_` / `sf_` / `fm_` / `ai_` / `kb_` 不进入外键词干；其余与表名一致（含表名里已压缩的修饰词，如 `proc`、`act`、`tran`、`mdl`）。
2. **角色/业务含义可缩**：`from`→`frm`、`to`、`main`→`mn`、`invoked`→`ik`、`back_src`→`bs` 等，用 §3；**不得**为省长度把 `act_instance` 收成 `ai`。
3. **非表外键**：指向 BPMN 节点 id、纯业务码等（无对应实体表）仍按普通字段缩写，如 `tk_act_id`（活动定义 id，不是 `wf_act_instance` 行）。
4. **超长处理**：`{pfx}{含义}_{stem}_id` 仍 >20 时，只继续压缩**业务含义**；stem 不动。仍超则评审另案，**禁止**把 stem 改回 `pi`/`ai`。

长度抽查：

| 列名 | 长 | 备注 |
|------|-----|------|
| `tk_proc_instance_id` | 18 | 单 FK，裸 stem ✓ |
| `tk_act_instance_id` | 17 | 单 FK，裸 stem ✓ |
| `ai_proc_instance_id` | 18 | 单 FK ✓ |
| `ti_f_act_instance_id` | 20 | from→`f` ✓ |
| `ti_t_act_instance_id` | 20 | to→`t` ✓ |
| `ai_m_act_instance_id` | 20 | main→`m` ✓ |
| `pi_i_act_instance_id` | 20 | invoked→`i` ✓ |
| `ai_s_act_instance_id` | 20 | back_src→`s` ✓ |
| `ai_o_act_instance_id` | 20 | back_org→`o` ✓ |

## 2. 业务域表前缀登记册

新表**必须**先选域前缀；不得自造第三种引擎前缀。

| 域前缀 | 业务域 | 落点（示意） | 说明 |
|--------|--------|--------------|------|
| `wf_` | 引擎核心运转 | `engine` 实体 | 流程定义、实例、活动、任务、转移、变量、规则、Job、Hook Outbox、引擎日志 |
| `sf_` | 产品/查询旁路 | `biz/query` 等 | 抄送、待办邮件标记扩展等**非引擎主路径**表 |
| `fm_` | 表单扩展 | `ext/form` | 原 `FbForm*` 统一迁此域 |
| `ai_` | AI 配置与调用 | `biz/AI` | 模型提供方、活动 AI 配置等 |
| `kb_` | 知识库 | `biz/AI` 文档侧 | 原 `biz_documents` 等 |
| `vw_` | 只读视图 | 视图定义 | 视图名：`vw_` + 被包装表域逻辑名，仍建议 ≤20 |

> **不用** `w_` 作为默认引擎前缀（保留给极端压缩场景的临时/内部别名）；正式表统一 `wf_`。  
> Host / 样品业务表（如 `samples/external`）不入本登记册，由宿主自定，但**建议**同样遵守长度与前缀原则。

## 4. 字段前缀推导规则

### 4.1 算法

1. 取表名去掉域前缀后的**主干词**（1～2 个关键语义词）。
2. 每个关键词取 **1 个首字母**（或 §3 已登记的 2 字母缩写中的代表字母），拼成 **1～2 字符**，再加 `_`。
3. 全库字段前缀应**尽量不冲突**；若冲突，次要表改为 2 字符（见下表）。

### 4.2 引擎表字段前缀（建议定稿）

| 现行表名 | 建议表名（≤20） | 核心词 | 字段前缀 | 示例字段（含外键） |
|----------|-----------------|--------|----------|---------------------|
| `wf_process` | `wf_process` | process | `p_` | `p_id`, `p_name`, `p_version` |
| `wf_process_instance` | `wf_proc_instance` | instance | `pi_` | `pi_id`, `pi_process_id`, `pi_state`, `pi_i_act_instance_id` |
| `wf_activity_instance` | `wf_act_instance` | instance | `ai_` | `ai_id`, `ai_proc_instance_id`, `ai_act_id`, `ai_m_act_instance_id` |
| `wf_task` | `wf_task` | task | `tk_` | `tk_id`, `tk_act_instance_id`, `tk_proc_instance_id` |
