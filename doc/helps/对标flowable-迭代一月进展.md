## 1. 对标对象要说清

| 参照面 | 代表问题 | Sail 怎么站 |
|--------|----------|-------------|
| **BPMN 内核**（Flowable 一类） | 图语义、事件节点、子流程、版本、嵌入性 | 同场竞技：BPMN + `sf:`；Mediator + `UseXxx` |
| **钉钉式 OA 产品面** | 按钮齐不齐、低代码表单、人员策略开箱 | 刻意正交：引擎命令宽、Host 码表可关；Leave×Resolve 不跟 Any/All 收窄 |

一句话：**不跟 Flowable 换内核，也不跟钉钉按钮集收窄动词面；学的是「宿主如何稳定消费引擎」。**

## 3. 诚实对照（相对 Flowable / 常见 OA）

### 3.1 Sail 明显强（相对常见钉钉式 OA）

BPMN 事件节点、子流程、跳转/撤回产品化路径、Assignee 管道（组/队长）、Gate-Hook-Outbox、插件分层、冷热归档运维向能力。改派/减签/委派/催办引擎+Host 已入码表（部分默认关）；**余债**在联调细矩阵与 Cancel/Suspend 暂缓。

### 3.2 常见 OA / 参照产品面更齐的地方

加批拆分、人员策略产品化、低代码/DIY 一体化、管理改派等开箱按钮；审批业务一等 SPI、结论回调失败可 Retry、Capability 版本与 conformance 套件——见讨论稿「可学」路径 A→D。

### 3.3 刻意不对齐

| 项 | 选择 |
|----|------|
| 承办按钮 | 不跟；用 Leave=`Race` |
| 退回五型枚举 | 改「目标 × 再发送」两维 |
| 未来节点动词 | 无 `*FutureAssignee`；走预选表 |
| 用 Any/All 取代 Leave | 不跟 |

### 3.4 相对 Flowable 的定位

| 维度 | Flowable 一类 | Sailflow |
|------|---------------|----------|
| 主叙事 | 标准 BPMN / Java 生态嵌入 | .NET + 中国式 OA 动词面 |
| 算人 | 候选人/委派等经典模型 | Resolve×Leave 正交 + Filter 后置 |
| 扩展 | Listener / Delegate / 外部 Job | Gate/Hook/Notifier + UseXxx |
| 产品壳 | 多在应用层自建 | 仓外 Host（sleveen-admin） |

不对标「逐 API 对齐 Flowable」；对标「可嵌入引擎 + 中国式办理是否站得住」。
