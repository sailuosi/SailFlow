# 办理动词解说（Sailflow OA）

> 状态：**产品语义解说**（2026-11-15）  
> 用途：用业务场景说清楚每个办理动词在干什么、会发生什么；给办理台文案、培训与按钮命名用。  
> 权威码表：宿主 `SailButtonsCatalog` / `buttonsCatalog.ts` · [特性说明-中国式OA审批要素.md](../sail/特性说明-中国式OA审批要素.md)  
> 引擎链路：[开发手册-OA命令执行链路.md](../sail/dev/开发手册-OA命令执行链路.md)

**读法约定**

| 标记 | 含义 |
|------|------|
| **码表已开** | 已进办理条，节点默认或可启用 |
| **码表默认关** | 已进码表，节点须显式打开 |
| **引擎有 / Host 未挂** | 有 `*Process`，办理条尚未产品化 |
| **产品候选** | 语义先固化，命令与按钮未落地 |

会签 / 或签 / 抢办是**办理模式（Leave）**，不是按钮，见文末附录；勿与加签、转办混称。

## 1. 通过 / 同意：我同意，继续往下走

### 业务场景

部门经理审完请假单，内容没问题，点「通过」——单子按流程图走到下一节点（或会签里还要等别人）。

### 会发生什么

1. 你的这条待办办结。
2. 是否离开当前节点，看办理模式：或签/抢办可能一人通过就走；会签要凑齐条件。
3. 离开后按连线条件演算下一跳，给后续人生成待办。
4. 若节点策略要求选下一办理人，办理台会让你先选人再提交。

### 一句话

**通过 =「我同意，按图继续往下走」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Approve` / `RunProcess` |
| 上下文 | 待办 `handle` |

## 2. 驳回：我不同意，按驳回路径处理

### 业务场景

财务一看报销明显不合规，不想「退回去改一改再报」，而是明确表示**不同意**——走驳回语义（具体落到哪、是否结束，看图与节点策略）。

### 会发生什么

1. 当前待办办结，走驳回路径（常回到历史节点一类位置）。
2. **不等于**整单直接作废；要整单作废请用「作废」。
3. 宿主可按节点策略把「驳回」改造成「退回到指定节点」（Handler 可能转调 `SendBack`）。

### 一句话

**驳回 =「我不同意，按驳回路径处理」（≠ 作废）。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Reject` / `RejectProcess` |
| 上下文 | 待办 `handle` |

---

## 3. 退回：打回，让他改完再来

### 业务场景

领导觉得方案材料不齐，不想直接否决，而是打回给发起人（或上一环节）补材料——改完再提交。

### 会发生什么

1. 你选退回目标（上一节点 / 发起人 / 历史节点，受策略约束）。
2. 当前办理位置回退，目标节点重新产生待办。
3. 对方改完后再送：可以「正常往下走」，也可以「返送给打回人」（见重发）。
4. 流程一般**不结束**，还能再提。

### 一句话

**退回 =「打回修改，流程还活着，改完再来」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `SendBack` / `SendBackProcess` |
| 上下文 | 待办 `handle` |
| 配置维 | 退回目标 × 再发送方式（见 [OA 审批要素 §4.1](../sail/特性说明-中国式OA审批要素.md)） |

## 4. 前加签：我审之前，先让他审

### 业务场景

经理审批采购单，金额涉及 IT 年度预算。自己虽有最终审批权，但最好先让 IT 负责人确认配置与预算，自己再拍板。

→ 在当前审批人**之前**临时插入一个审批环节。

### 会发生什么

1. 你点了前加签并选人后，**自己暂时不能操作这张单**。
2. 对方收到完整审批待办（同意 / 拒绝 / 退回，甚至再加签）。
3. 对方**通过**后，单子回到你继续审。
4. 对方**拒绝**后，按拒绝路径处理，你也不用再审。

### 一句话

**前加签 =「我先不审，让他先审完再说」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `SignForward` / `SignForwardProcess` |
| 子类型 | `SignForwardBefore` |

---

## 5. 后加签：我审完之后，再让他把个关

### 业务场景

财务审一笔大额付款，制度上自己是终审，但希望财务总监再过一眼——自己先批完，再让总监管。

→ 当前人**审完之后**，在后面临时追加审批环节。

### 会发生什么

1. 你通过后，单子**不会**立刻走到预设下一节点或结束。
2. 被加签人收到完整审批待办。
3. 对方同意，流程才继续；对方拒绝，单子退回来。

### 一句话

**后加签 =「我先批完了，再让他补审一下」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `SignForward` / `SignForwardProcess` |
| 子类型 | `SignForwardBehind` |

---

## 6. 并加签：拉他进来，跟我一起审

### 业务场景

产品总监审立项，涉及核心技术改造，需要研发总监一起确认——两人同时在这个节点审，都同意才过。

→ 在当前节点**并行追加**审批人。

### 会发生什么

1. 发起后**你自己仍可随时审**，不用等对方。
2. 双方同时有待办，谁先审都行。
3. 默认「全员同意才过」（会签）；产品可配或签。
4. 任一人拒绝，节点不通过。

### 一句话

**并加签 =「拉他进来，我们一起拍这个板」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `SignForward` / `SignForwardProcess` |
| 子类型 | `SignForwardParallel` |

---

## 7. 转办：这事交给他，我不办了

### 业务场景

你手头有张待办，出差在即，希望同事接手——节点还是这个节点，只是**换人办**，流程不往下跳。

### 会发生什么

1. 你的待办关闭；同活动上给对方开一条新待办。
2. **不发生节点流转**（还停在当前节点）。
3. 对方办完是按他自己的权限推进；**不会**自动还回给你（要还回 → 用委派）。

### 一句话

**转办 =「本节点交人，我不办了，也不指望他还给我」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Transfer` / `TransferProcess` |
| 上下文 | 待办 `handle` |

---

## 8. 委派：请他代办，办完还得还给我

### 业务场景

你是节点责任人，临时请秘书代看材料、代点通过——但**责任仍在你**，对方办完后待办应回到你手上，你再决定是否继续或亲自推进。

### 会发生什么

1. 你的待办关闭并标记委托；对方拿到代办待办。
2. 对方办结后，**自动回转**给你一条待办；**不**推进到下一节点。
3. 若办完不需要还回 → 用转办，不要用委派。
4. 一般不允许套娃委派。

### 一句话

**委派 =「请他代办，办完必须还给我」（≠ 转办）。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 `Delegate` / `DelegateProcess` |
| 现状 | 引擎已落地；Host 码表暂缓 |

---

## 9. 抄送：让他知道一下，不用他审

### 业务场景

审批通过前/后，希望法务或相关同事**知情**，但不需要他们点同意——发一条知会即可。

### 会发生什么

1. 写入抄送记录并通知对方。
2. **不产生**有推进权的审批待办。
3. **不锁**你的通过/拒绝按钮。
4. 走独立抄送通道（`ICopytoNotifier`），不是普通 Task 通知。

### 一句话

**抄送 =「让他知道，不用他拍板」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Copyto` / Host `WfCopyto/Create` |
| 上下文 | 待办 `handle` |

---

## 10. 沟通：我需要他给个信息，不用他拍板

### 业务场景

经理审请假，正好撞上项目上线周，需要问项目负责人「这几天缺人行不行」——对方**不审批请假**，只回复意见；批不批仍是经理说了算。

### 会发生什么

1. 发起后，你自己的通过/拒绝等按钮**暂时锁住**，避免没拿到信息就误操作。
2. 对方收到**待反馈**（不是审批待办）：只能提交意见/附件。
3. 多人沟通需全部反馈（或你主动收回剩余）后才解锁。
4. 可随时收回；可多轮追问。

### 一句话

**沟通 =「我问他点事，他回我就行，不用他拍板」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 产品候选（尚未入码表） |
| 勿混用 | ≠ `SignForward`；≠ `Copyto`（抄送不锁待办、不强制回复） |

## 11. 撤回：我刚批的，收回来

### 业务场景

你刚点通过，下一手还没开始办，发现材料填错了——想把已办收回，重新处理。

### 会发生什么

1. 在允许条件下（常见：下一手尚未办理），你的上一步办理被收回。
2. 流程回到你可再办的状态。
3. 若下一手已办，通常不允许撤回。

### 一句话

**撤回 =「已办收回，前提是下一手还没动」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Withdraw` / `WithdrawProcess` |
| 上下文 | 已办 `done` |

---

## 12. 重发 / 返送退回人：改完了，按规则再送出去

### 业务场景

单子被领导退回给你改。改完后有两种送法：按正常路径继续走，或**专门送回给打回你的那个人**再审一眼。

### 会发生什么

1. 有退回源（`BackSrc`）时，办理台常把重发文案显示成「返送退回人」。
2. 重发强制指向退回源活动，而不是随便选下一跳。
3. 「正常发送」通常仍走通过/`Run`；「返送退回人」走 `Resend`。
4. **不等于**再点一次普通通过。

### 一句话

**重发 =「被退回改完后，按返送规则再送出去」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Resend` / `ResendProcess` |
| 上下文 | 待办 / 已办（有 BackSrc 时办理台强化文案） |

---

## 13. 修订：退回来之后，改人再送

### 业务场景

被退回后，不仅要改表单，还要调整会签/加签子节点上的办理人集合，再按修订路径送出。

### 会发生什么

1. 完成当前（退回落点）任务。
2. 按修订模式在退回源活动上重建活动实例与待办（含会签/加签子节点克隆等）。
3. 默认关闭，节点按需开启；接入前核对业务是否真要这条路径。

### 一句话

**修订 =「退回后改办理结构/人员，再按修订路径送出」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Revise` / `ReviseProcess` |
| 上下文 | 待办 / 管理；**默认关** |

---

## 14. 跳转：别管图了，直接跳到那里

### 业务场景

运维发现实例卡在错误节点，或特事特办需要越过中间环节——有权限的人指定目标活动与办理人，直接跳过去。

### 会发生什么

1. 当前活动办结，跳到指定活动并生成待办。
2. **绕过**正常连线演算，属于强管控能力。
3. 慎对普通审批人默认开放。

### 一句话

**跳转 =「管理态自由跳到指定节点」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Jump` / `JumpProcess` |
| 上下文 | 管理 `admin` |

---

## 15. 关闭：正常把这张单子收掉

### 业务场景

管理员确认流程无需再办，走关闭路径把实例收口（常见落到结束类活动）。

### 会发生什么

1. 当前办理位置完结，按关闭运行时走向结束。
2. 产品文案上偏「正常收口」，与「终止 / 作废」需区分。

### 一句话

**关闭 =「管理向正常结束这张单」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Close` / `CloseProcess` |
| 上下文 | 管理 `admin` |

---

## 16. 终止：强行掐断还在跑的单子

### 业务场景

流程跑歪了或业务已取消执行，管理员要**强行结束运行中实例**，级联收口活动与待办。

### 会发生什么

1. 实例进入终止态；未办待办被收口并通知取消类生命周期。
2. 默认关；旧图不会自动启用。
3. ≠ 作废（作废偏「这单作废」业务语义）；≠ 关闭（关闭偏正常收口）。

### 一句话

**终止 =「强行结束运行中的实例」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Terminate` / `TerminateProcess` |
| 上下文 | 管理；**默认关** |

---

## 17. 作废：这张单作废了，别再当有效件

### 业务场景

合同作废、立项撤销——需要把流程实例标成作废，业务上不再当作有效审批件。

### 会发生什么

1. 实例进入作废态（Lifecycle）。
2. 默认关；与终止、关闭三分：终止偏掐断运行，关闭偏正常结束，作废偏业务废件。

### 一句话

**作废 =「实例作废，不再当有效件」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Discard` / `DiscardProcess` |
| 上下文 | 管理；**默认关** |

---

## 18. 反转：已经结束的单子，拉回来再签

### 业务场景

流程已经走到完成，因补签、纠错等需要从结束位置**反转回**历史节点继续办理（≠ 运行中的退回）。

### 会发生什么

1. 前提通常是实例已 **Completed**。
2. 从结束转移反转，重建可办活动/待办（`BackwardType.Reversed`）。
3. **不是**退回；默认关，接入前必须核对场景。

### 一句话

**反转 =「已完成实例返签/回转」（≠ 退回）。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | `Reverse` / `ReverseProcess` |
| 上下文 | 管理；**默认关** |

---

## 19. 减签：这个人不用审了，拿掉

### 业务场景

会签节点上原先拉了五个人，其中一人出差且业务上可不参与——从**尚未办完**的办理人里去掉他。

### 会发生什么

1. 匹配的未办待办关闭并取消；刷新节点办理人集合。
2. **禁止**减到 0 人。
3. 不推进下一节点。
4. 引擎 API 已有；办理条待产品挂接。

### 一句话

**减签 =「从当前多人节点拿掉还没办完的人」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 / `RemoveAssigneeProcess` |
| 现状 | 引擎有；Host 办理条待产品 |

## 20. 变更处理人：管理员把当前节点的人换成这批

### 业务场景

组织调整或算人算错，管理员需要把**当前节点办理人集合**整体改成新名单（差量增删）。

### 会发生什么

1. 不在新集合里的未办待办关闭取消；缺的人补开待办。
2. 停在当前节点，不按图推进。
3. 引擎 API 已有；码表/Handler 未挂。

### 一句话

**变更处理人 =「管理态改当前节点办理人全集」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 `ChangeAssignee` / `ChangeAssigneeProcess` |
| 现状 | 引擎有；Host 未挂 |

## 21. 催办：提醒他，还没办，别拖着

### 业务场景

发起人或管理员看到某环节待了三天，需要提醒当前办理人尽快处理——**只催，不改状态**。

### 会发生什么

1. 对当前节点打开的待办发催办通知（`Urged`）。
2. 可选限定催谁；空则催全部打开待办。
3. **不改** Task 状态，不推进流程。
4. 宿主需注册催办通知通道才有实际消息；≠「加急」优先级字段。

### 一句话

**催办 =「发提醒，状态不动」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 / `UrgeProcess` |
| 现状 | 引擎有；Host 未挂 |

---

## 22. 挂起 / 恢复：先暂停；过阵子再接着办

### 业务场景

关联合同还没签，审批先挂起；合同到位后再恢复继续。

### 会发生什么

1. 挂起：实例进入暂停态，办理暂停。
2. 恢复：实例恢复可办。
3. **勿与**自动节点 WaitToken 的 Resume 混称（那是事件等待刺激，不是人点挂起恢复）。
4. 引擎有；产品码表暂缓。

### 一句话

**挂起/恢复 =「整单先停，再接着跑」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 / `SuspendProcess` · `ResumeProcess` |
| 现状 | 引擎有；码表暂缓 |

## 23. 取消：这张单取消，不做了

### 业务场景

### 会发生什么

1. 实例进入取消态。
2. 引擎有；产品码表暂缓，未产品化按钮。

### 一句话

**取消 =「这张单取消不做了」（Lifecycle）。**

| Sail 锚点 | 值 |
|-----------|-----|
| 按钮 / 命令 | 候选 / `CancelProcess` |
| 现状 | 引擎有；码表暂缓 |

## 24. 发起：把单子交出去，开始跑

### 业务场景

填完表、选好人，点提交——流程实例启动，第一跳待办产生。

### 会发生什么

1. 按定义创建实例，写入启动上下文与首跳办理人。
2. 属**发起页**，不是任务办理条按钮。

### 一句话

**发起 =「创建实例，流程开始跑」。**

| Sail 锚点 | 值 |
|-----------|-----|
| 命令 | `StartProcess` / `StartProcessByMessage` |
| 上下文 | 发起页（不进 `ButtonsSetting`） |

## 25. 怎么选（速查）

```text
我要推进 / 否决 / 打回？
 ├─ 同意往下走           → 通过
 ├─ 明确不同意           → 驳回（≠ 作废）
 └─ 让人改完再来         → 退回；改完返送 → 重发

需要别人介入当前决策？
 ├─ 只要信息，不让他拍板 → 沟通（候选）/ 仅知情 → 抄送
 ├─ 让他先审我再审       → 前加签
 ├─ 我先批他再把关       → 后加签
 ├─ 一起审               → 并加签
 ├─ 交人且不还回         → 转办
 └─ 代办且办完还回       → 委派

已办反悔 / 管理纠偏？
 ├─ 下一手还没办         → 撤回
 ├─ 跳过图自由跳         → 跳转
 ├─ 改当前节点人         → 变更处理人
 ├─ 拿掉某人             → 减签
 ├─ 提醒未办             → 催办
 └─ 收口实例             → 关闭 / 终止 / 作废 / 取消（语义三分）
```

## 26. 易混对照

| 说法 | 别当成 | 正确区分 |
|------|--------|----------|
| 驳回 | 整单作废 | 驳回走驳回路径；作废用 `Discard` |
| 退回 | 反转 | 退回针对运行中；反转针对已完成 |
| 转办 | 委派 | 转办不还回；委派办完自动还回 |
| 加签 | 加批（生新节点） | 现统一 `SignForward`；加批语义待拆 |
| 并加签 | 会签节点 | 并加签是办理时临时加人；会签是节点 Leave 配置 |
| 沟通 | 前加签 / 抄送 | 沟通无审批权且锁你的按钮；抄送不锁、不强制回 |
| 催办 | 加急 | 催办只发通知；加急是优先级（两边都薄） |
| 关闭 | 终止 / 作废 | 正常收口 vs 强行结束 vs 业务废件 |
| 重发 | 再点通过 | 重发对齐退回源返送，不是普通 `Run` |
| 挂起恢复 | WaitToken Resume | 人点暂停恢复 ≠ 自动节点等待刺激 |

## 附录 A. 办理模式（不是按钮）

多人同节点时，**先定 Leave，再谈按钮**。编码在 Assignee 管道，不进办理条。

| 模式 | 编码 | 一句话 |
|------|------|--------|
| 抢办 / 或签 | `Race` | 任一人办完即可离开 |
| 会签 / 协办 | `Collaborate` | 凑齐条件才离开 |
| 组间抢办 | `GroupRace` | 组维度抢办 |
| 组间协办 | `GroupCollaborate` | 组维度协办 |
| 队长关卡 | `Captain` | 关卡办完才算组完成 |

Sail **默认不跟**「承办/认领」按钮；或签场景用 `Race` 表达谁办完谁独占。详见 [待办人管道](../sail/特性说明-待办人管道.md)。
