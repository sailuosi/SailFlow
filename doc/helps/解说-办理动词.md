# 办理动词解说（Sailflow OA）

> 状态：**产品语义解说**（2026-11-15）  
> 用途：用业务场景说清楚每个办理动词在干什么、会发生什么；给办理台文案、培训与按钮命名用。  
> 权威码表：宿主 `SailButtonsCatalog` / `buttonsCatalog.ts` · [特性说明-中国式OA审批要素.md](../sail/特性说明-中国式OA审批要素.md)  
> 引擎链路：[开发手册-OA命令执行链路.md](../sail/dev/开发手册-OA命令执行链路.md)

**读法约定**

| 标记 | 含义 |
|------|------|
| **码表已开** | 已进办理条，节点默认或可启用 |
| **码表默认关** | 已进码表，节点须显式打开 |
| **引擎有 / Host 未挂** | 有 `*Process`，办理条尚未产品化 |
| **产品候选** | 语义先固化，命令与按钮未落地 |

每个动词在「一句话」后有 **引擎关联**：码表 `ButtonId`、Host 调度入口、引擎 `*Process`、动作骨架族群 / Action、Gate、成功 Hook。类·方法深链见 [OA 命令执行链路](../sail/dev/开发手册-OA命令执行链路.md)。

会签 / 或签 / 抢办是**办理模式（Leave）**，不是按钮，见文末附录；勿与加签、转办混称。

## 1. 通过 / 同意：我同意，继续往下走

### 业务场景

部门经理审完请假单，内容没问题，点「通过」——单子按流程图走到下一节点（或会签里还要等别人）。

### 会发生什么

1. 你的这条待办办结。
2. 是否离开当前节点，看办理模式：或签/抢办可能一人通过就走；会签要凑齐条件。
3. 离开后按连线条件演算下一跳，给后续人生成待办。
4. 若节点策略要求选下一办理人，办理台会让你先选人再提交。

### 一句话

**通过 =「我同意，按图继续往下走」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Approve` → `RunProcess` |
| Host 入口 | `ButtonsOperation` → `ApproveOperationHandler` |
| 引擎 API | `IWorkflowService.RunProcess[Async]` |
| 动作骨架 | Transition 族 · `RunAction` |
| Gate | `FlowOperation.Run` |
| Runtime | `WfRuntimeManagerRun` → `NodeMediatorTask`（办结后 `ContinueForward`） |
| 成功 Hook | `OnProcessContinued`（实例 Completed 另 `OnProcessCompleted`） |
| 上下文 | 待办 `handle` |
| 详链 | [OA 手册 §5.2 / §6](../sail/dev/开发手册-OA命令执行链路.md) |

## 2. 驳回：我不同意，按配置自动落点（极简）

### 业务场景

财务一看报销明显不合规，不想「退回去改一改再报」，而是明确表示**不同意**——办理人**不选目标、不选人**，由节点策略定落点。

### 会发生什么

1. 当前待办办结；引擎按 `ControlParameterSheet.RejectMode` 自动落点（办理人取历史办结人）。
2. 四态落点（设计期配置，默认 **Previous**）：
   - `Previous`：上一办理节点
   - `Starter`：发起/首办节点
   - `Specified`：指定历史节点（须配 `RejectReturnActivityId`）
   - `Terminate`：终止流程（走 `TerminateProcess`；成功事件以 Terminate 为准，Reason/Message 带 `RejectMode=Terminate`）
3. **不等于**整单作废（作废用 `Discard`）；**不等于**退回（退回可选目标 × 再发送两维）。
4. 驳回**不**写 `BackSrc`、**不**启用 `Resend`；`Specified` 仍走 `RejectProcess`，禁止转调 `SendBack` 冒充。
5. ApprovalOrSplit「拒绝边」仍是网关分流，**不是**本枚举。

### 一句话

**驳回 =「不同意 + 不选手/选人，按配置自动落点」（≠ 作废，≠ 退回）。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Reject` → `RejectProcess` |
| Host 入口 | `ButtonsOperation` → `RejectOperationHandler`（NodePolicy → `SailRejectModeMapper`；**只**调 Reject，不转 SendBack） |
| 引擎 API | `IWorkflowService.RejectProcess[Async]` |
| 动作骨架 | Transition 族 · `RejectAction`（Terminate 模式委托 `TerminateAction`） |
| 控制袋 | `ControlParameterSheet.RejectMode` · `RejectReturnActivityId`（仅 Specified） |
| Host 策略 | `rejectHandlerType`：1=Terminate · 2=Specified · 3=Previous（默认）· 4=Starter |
| Gate | `FlowOperation.Reject` |
| Runtime | 回跳：`WfRuntimeManagerReject`；Terminate：Lifecycle 终止链 |
| 成功 Hook | 回跳 `OnProcessRejected`；Terminate 模式 `OnProcessTerminated` |
| ReasonCode | `RejectModeInvalid` · `RejectTargetMissing` · `RejectModeTerminate` |
| 上下文 | 待办 `handle` |
| 详链 | [OA 手册 §5.5](../sail/dev/开发手册-OA命令执行链路.md) |

## 3. 退回：打回，让他改完再来

### 业务场景

领导觉得方案材料不齐，不想直接否决，而是打回给发起人（或上一环节）补材料——改完再提交。

### 会发生什么

1. 你选退回目标（上一节点 / 发起人 / 历史节点，受策略约束）。
2. 当前办理位置回退，目标节点重新产生待办。
3. 对方改完后再送：可以「正常往下走」，也可以「返送给打回人」（见重发）。
4. 流程一般**不结束**，还能再提。

### 一句话

**退回 =「打回修改，流程还活着，改完再来」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `SendBack` → `SendBackProcess` |

| 动作骨架 | Transition 族 · `SendBackAction`（A3） |
| Gate | `FlowOperation.SendBack` |

## 4. 前加签：我审之前，先让他审

### 业务场景

经理审批采购单，金额涉及 IT 年度预算。自己虽有最终审批权，但最好先让 IT 负责人确认配置与预算，自己再拍板。

→ 在当前审批人**之前**临时插入一个审批环节。

### 会发生什么

1. 你点了前加签并选人后，**自己暂时不能操作这张单**。
2. 对方收到完整审批待办（同意 / 拒绝 / 退回，甚至再加签）。
3. 对方**通过**后，单子回到你继续审。
4. 对方**拒绝**后，按拒绝路径处理，你也不用再审。

### 一句话

**前加签 =「我先不审，让他先审完再说」。**

### 引擎关联

| 码表 / 命令 | `SignForward` → `SignForwardProcess` |

| 动作骨架 | Transition 族 · `SignForwardAction` |
| Gate | `FlowOperation.SignForward` |

## 5. 后加签：我审完之后，再让他把个关

### 业务场景

财务审一笔大额付款，制度上自己是终审，但希望财务总监再过一眼——自己先批完，再让总监管。

→ 当前人**审完之后**，在后面临时追加审批环节。

### 会发生什么

1. 你通过后，单子**不会**立刻走到预设下一节点或结束。
2. 被加签人收到完整审批待办。
3. 对方同意，流程才继续；对方拒绝，单子退回来。

### 一句话

**后加签 =「我先批完了，再让他补审一下」。**

## 6. 并加签：拉他进来，跟我一起审

### 业务场景

产品总监审立项，涉及核心技术改造，需要研发总监一起确认——两人同时在这个节点审，都同意才过。

→ 在当前节点**并行追加**审批人。

### 会发生什么

1. 发起后**你自己仍可随时审**，不用等对方。
2. 双方同时有待办，谁先审都行。
3. 默认「全员同意才过」（会签）；产品可配或签。
4. 任一人拒绝，节点不通过。

### 一句话

**并加签 =「拉他进来，我们一起拍这个板」。**

## 7. 转办：这事交给他，我不办了

### 业务场景

你手头有张待办，出差在即，希望同事接手——节点还是这个节点，只是**换人办**，流程不往下跳。

### 会发生什么

1. 你的待办关闭；同活动上给对方开一条新待办。
2. **不发生节点流转**（还停在当前节点）。
3. 对方办完是按他自己的权限推进；**不会**自动还回给你（要还回 → 用委派）。

### 一句话

**转办 =「本节点交人，我不办了，也不指望他还给我」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Transfer` → `TransferProcess` |
| Host 入口 | `ButtonsOperation` → `TransferOperationHandler` |
| 引擎 API | `IWorkflowService.TransferProcess[Async]` |
| 动作骨架 | Assignee 族 · `TransferAction`（A1；**不经** Runtime/Mediator） |
| Gate | `FlowOperation.Transfer` |
| 写库 | `TaskManager.Transfer`（原 Closed + 同 Activity 新待办；刷新 SignIds/Names） |
| 成功 Hook | `OnProcessTransferred`；路径内 `FireTaskLifecycle(Entrusted)` |
| 上下文 | 待办 `handle` |

## 8. 委派：请他代办，办完还得还给我

### 业务场景

你是节点责任人，临时请秘书代看材料、代点通过——但**责任仍在你**，对方办完后待办应回到你手上，你再决定是否继续或亲自推进。

### 会发生什么

1. 你的待办关闭并标记委托；对方拿到代办待办。
2. 对方办结后，**自动回转**给你一条待办；**不**推进到下一节点。
3. 若办完不需要还回 → 用转办，不要用委派。
4. 一般不允许套娃委派。

### 一句话

**委派 =「请他代办，办完必须还给我」（≠ 转办）。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | 候选 `Delegate` → `DelegateProcess` |
| Host 入口 | **未挂**（引擎 API 直调） |
| 引擎 API | `IWorkflowService.DelegateProcess[Async]` |
| 动作骨架 | Assignee 族 · `DelegateAction` |
| Gate | `FlowOperation.Delegate`（与 Transfer 同族时序） |
| 写库 | 发起：`TaskManager.Delegate`；办结回转：`TryCompleteAsDelegationReturn`（不完结 AI、不 ContinueForward） |
| 成功 Hook | 发起时 `OnProcessDelegated` |
| 现状 | 引擎已落地；Host 码表暂缓 |
| 详链 | [OA 手册 §5.12e](../sail/dev/开发手册-OA命令执行链路.md) |

## 9. 抄送：让他知道一下，不用他审

### 业务场景

审批通过前/后，希望法务或相关同事**知情**，但不需要他们点同意——发一条知会即可。

### 会发生什么

1. 写入抄送记录并通知对方。
2. **不产生**有推进权的审批待办。
3. **不锁**你的通过/拒绝按钮。
4. 走独立抄送通道（`ICopytoNotifier`），不是普通 Task 通知。

### 一句话

**抄送 =「让他知道，不用他拍板」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Copyto`（**非** `FlowOperation` / `*Process`） |
| Host 入口 | `WfCopyto/Create` → `SailCopytoService.CreateMany` |
| 生命周期 | 每行后 `FireCopytoLifecycle` → `OnCopytoCreated` |
| 通知旁路 | `AddCopytoNotifier` + `CopytoKinds`；Outbox Kind=`CopytoNotify`（≠ TaskNotifier） |
| 上下文 | 待办 `handle` |

## 10. 沟通：我需要他给个信息，不用他拍板

### 业务场景

经理审请假，正好撞上项目上线周，需要问项目负责人「这几天缺人行不行」——对方**不审批请假**，只回复意见；批不批仍是经理说了算。

### 会发生什么

1. 发起沟通后，引擎在同活动上为对方建 **参与者待办**（`AssigneeRole=1`），`ConsultSrcTaskId` 指向你的审批 Task。
2. 你自己的通过/拒绝等推进按钮**硬锁**（ReasonCode=`ConsultPending`），避免没拿到信息就误操作。
3. 对方打开待办时工具栏**仅阅办**：提交意见后关闭自己的参与者待办（`Acknowledge`）。
4. 全部参与者阅办完毕（或你点「收回沟通」取消剩余）后解锁；可再发一轮沟通。
5. 参与者不进 `SignIds`、不计入会签 Leave；节点离开时未阅参与者级联取消。

### 一句话

**沟通 =「我问他点事，他回我就行，不用他拍板」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | 发起 `Consult` → `ConsultProcess`；阅办 `Acknowledge` → `AcknowledgeProcess`；收回 `RecallConsult` → `RecallConsultProcess` |
| Host 入口 | 码表已挂；Workbench 下发 `AssigneeRole` / `ConsultPending` |
| 引擎 API | `ConsultProcess*` / `AcknowledgeProcess*` / `RecallConsultProcess*` |
| 动作骨架 | Assignee 族 · `ConsultAction` / `AcknowledgeAction` / `RecallConsultAction` |

## 25. 怎么选（速查）

```text
我要推进 / 否决 / 打回？
 ├─ 同意往下走           → 通过
 ├─ 明确不同意           → 驳回（≠ 作废）
 └─ 让人改完再来         → 退回；改完返送 → 重发

需要别人介入当前决策？
 ├─ 只要信息，不让他拍板 → 沟通（候选）/ 仅知情 → 抄送
 ├─ 让他先审我再审       → 前加签
 ├─ 我先批他再把关       → 后加签
 ├─ 一起审               → 并加签
 ├─ 交人且不还回         → 转办

 ├─ 下一手还没办         → 撤回
```

## 26. 易混对照

| 说法 | 别当成 | 正确区分 |
|------|--------|----------|
| 驳回 | 整单作废 | 驳回按 `RejectMode` 落点；作废用 `Discard` |
| 驳回 | 退回 | 驳回极简、配置落点、无 Resend；退回可选目标 × 再发送 |
| 退回 | 反转 | 退回针对运行中；反转针对已完成 |
| 转办 | 委派 | 转办不还回；委派办完自动还回 |
| 加签 | 加批（生新节点） | 现统一 `SignForward`；加批语义待拆 |
| 并加签 | 会签节点 | 并加签是办理时临时加人；会签是节点 Leave 配置 |
| 沟通 | 前加签 / 抄送 | 沟通无审批权且锁你的按钮；抄送不锁、不强制回 |
| 催办 | 加急 | 催办只发通知；加急是优先级（两边都薄） |
| 关闭 | 终止 / 作废 | 正常收口 vs 强行结束 vs 业务废件 |
| 重发 | 再点通过 | 重发对齐退回源返送，不是普通 `Run` |
| 挂起恢复 | WaitToken Resume | 人点暂停恢复 ≠ 自动节点等待刺激 |

## 附录 A. 办理模式（不是按钮）

多人同节点时，**先定 Leave，再谈按钮**。编码在 Assignee 管道，不进办理条。

| 模式 | 编码 | 一句话 |
|------|------|--------|
| 抢办 / 或签 | `Race` | 任一人办完即可离开 |
| 会签 / 协办 | `Collaborate` | 凑齐条件才离开 |
| 组间抢办 | `GroupRace` | 组维度抢办 |
| 组间协办 | `GroupCollaborate` | 组维度协办 |
| 队长关卡 | `Captain` | 关卡办完才算组完成 |

Sail **默认不跟**「承办/认领」按钮；或签场景用 `Race` 表达谁办完谁独占。详见 [待办人管道](../sail/特性说明-待办人管道.md)。
