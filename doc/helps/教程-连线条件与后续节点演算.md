## 前置说明

- **连线条件**决定「能不能走某条 `sequenceFlow`」；**后续节点演算**在条件过滤后的出边上做图遍历，遇网关按类型继续展开。
- **没有**「后续节点路由 Filter」注册口（不存在 `ITransitionFilter` / `AddNextActivityFilter`）。路由扩展靠 BPMN 表达式 + 运行时条件字典。
- 可注册的 **Filter** 属于 **待办人管道**（`UseAssign` → `AddFilter`），只改「谁来办」，不改「走哪条线」。
- `ConditionTypeEnum.Rule` 虽有枚举，连线解析当前固定为 `Expression`；规则引擎不用于连线条件求值。

## 一、如何定义连线条件

### 1.1 BPMN：`conditionExpression`

在 `sequenceFlow` 上写 `bpmn:conditionExpression`。`ProcessModelConvertor.ConvertTransition` 会建成 `ConditionDetail`：

| 字段 | 当前行为 |
|------|----------|
| `ConditionType` | 固定 `Expression` |
| `ConditionText` | 表达式原文（`InnerText`） |

示例：

```xml
<bpmn:sequenceFlow id="flow_to_finance" sourceRef="Gateway_1" targetRef="Task_Finance">
  <bpmn:conditionExpression>amount &gt; 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
<bpmn:sequenceFlow id="flow_to_dept" sourceRef="Gateway_1" targetRef="Task_Dept">
  <bpmn:conditionExpression>amount &lt;= 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
```

### 1.2 可选：网关连线行为（`sf:groupBehaviours`）

| 属性 | 作用 |
|------|------|
| `defaultBranch="true"` | **OrSplit** 无任何条件命中时走该默认线 |
| `priority` | **XOrSplit** 按优先级排序，取**第一条**条件为真的线 |
| `Approval`（审批分流） | **ApprovalOrSplit** 按通过/驳回选对应连线 |

### 1.3 条件何时算「有效」

`IsValidTransition` 规则：

| 情况 | 结果 |
|------|------|
| 连线无条件 / `ConditionText` 为空 | **始终可达** |
| 有条件，且条件字典非空 | 用表达式求值，真则可达 |
| 有条件，但条件字典为空或 null | **不可达**（易踩坑） |

求值：`ExpressionParser.ReplaceParameterToValue` 把字典键替换进表达式 → `System.Linq.Dynamic` 当布尔表达式编译执行。数值原样替换；非数字字符串自动加双引号。  
（定型中将改为 `IConditionEvaluator` 有序链，默认实现保持本行为；见特性说明 N13–N15。）

## 二、运行时如何传入条件变量

办理 / 查询下一步时，通过 `RunBuilder.IfCondition` 写入 `FlowCommandContext.Conditions`：

```csharp
await sail.CreateRunBuilder()
    .UseApp(appId, "采购申请")
    .UseProcess(processId)
    .OnTask(taskId)
    .IfCondition("amount", "15000")
    .IfCondition("dept", "finance")
    // ... NextStep / 执行
    ;
```

| 来源 | 用途 |
|------|------|
| `runner.Conditions` / `IfCondition` | 查询下一步、发送时的主条件袋 |
| `ActivityResource.ConditionKeyValuePair` | 运行时流转时使用的条件（常来自同一套 Conditions） |
| 活动实例已写入的流程变量 | Service/AI 等节点后会与条件袋 **合并** 再重算后续线 |
| 事件里 `IEventService.SetCondition` | 可改写当前活动资源上的条件键值 |

表达式里写 `amount > 10000`，字典键必须是 `amount`（替换是字符串替换，注意键名与表达式标识一致）。

## 三、某个节点有哪些后续节点——演算事实

### 3.1 分层入口

| 场景 | 入口 | 产出 |
|------|------|------|
| UI / 查询下一步 | `WorkflowService.GetNextStepInfo` → `NextStepParser` → `GetNextActivityListView` | `NodeView` 列表（可再挂办理人） |
| 运行时真正流转 | `NodeMediator.ContinueForwardCurrentNode` → `GetNextActivityTreeListRuntime` | `NextActivityComponent` 树，再递归创建后续实例 |
| 纯结构（共用内核） | `ProcessModelBPMNCore.GetNextActivityTreeListCore` | 上述两者的结构层结果 |

`IProcessModel.GetNextActivityTreeView*` 是**结构层**接口：不算实际用户列表。业务/界面优先 `GetNextStepInfo`。

### 3.2 核心步骤（`GetNextActivityTreeListCore`）

对当前 `activityId`：

1. **取所有出边**：`Process.TransitionList.Where(FromActivityId == 当前)`（`ProcessModelHelper.GetForwardTransitionList`）。
2. **条件过滤**：对每条边 `IsValidTransition`（见 §1.3）。
3. **按目标节点类型分发**：
   - **简单节点**（Task / Service / AI / 会签 / 子流程 / 起止）→ 直接作为后续候选。
   - **Gateway** → `NextActivityScheduleSplit` 或 `Join`，穿透网关继续找后面的节点。
   - **Intermediate** → 中间事件调度（类似网关展开）。
4. 组成 `NextActivityComponent` 树；有子节点则 **Tranverse 展平**为叶子列表（网关本身通常不出现在最终「下一步」列表里）。

特殊捷径：当前节点配置了 `SkipDetail.IsSkip == true` 时，`GetNextActivityListView` **直接跳到指定节点**，不再走连线演算。

### 3.3 网关展开语义

`CreateActivityScheduleGateway` 按 Split / Join 选型：

| 网关方向 | 后续演算行为 |
|----------|----------------|
| **AndSplit / AndSplitMI** | 所有出边都走，**不看**连线条件 |
| **OrSplit** | 条件为真的都走；全假则走 `defaultBranch`；无默认 → `NoneTransitionMatchedToSplit` |
| **XOrSplit** | 按 `priority` 排序，只取**第一条**条件为真的线 |
| **ApprovalOrSplit** | 按上游节点通过/驳回结果筛选 `Approval` 类型连线 |
| **Join** | 对合并点出边再做条件过滤后继续展开 |

### 3.4 运行时多一刀：前端选步过滤

真正发送（正常连线解析，非跳转/退回）时：

1. 先跑结构层 `GetNextActivityTreeListCore`（出边 + 条件 + 网关）。
2. AndSplit 多实例等场景可跳过二次过滤。
3. 否则用表达式再滤：默认要求目标活动在 `NextActivityPerformers` 中（前端选了要走的步）。

跳转 / 退回：`isNotParsedByTransition == true`，**不演算连线**，直接使用指定目标。

### 3.5 流程示意

```
当前 ActivityId
  → 取 From 出边
  → 连线条件过滤（无条件=通；有条件需变量字典）
  → To 为简单节点？→ 加入后续候选
  → To 为网关？→ 按 And/Or/XOr/Approval/Join 再取网关出边并递归
  → 展平为 NodeView / 运行时创建活动与待办
  （发送时）→ 再按 NextActivityPerformers 裁剪
```

## 四、与「可注册 Filter」的边界

| 需求 | 机制 | 能否自定义注册 |
|------|------|----------------|
| 按金额/字段决定走哪条线 | 连线 `conditionExpression` + 请求级 `IfCondition` / 流程变量 | ❌ 无 Client 级自动补袋（拟议：`UseNextStepRoute → IfCondition*` + Options Match，见下一节点过滤器 N6/N11/N12） |
| 演算后裁剪/标注多候选 | 现行仅前端自选 + 发送 `NextActivityPerformers` 裁剪 | ❌ 无 `INextStepFilter`（拟议：`UseNextStepRoute` → `AddFilter`，**未实施**） |
| 改下一节点办理人、去重、同人跳过等 | `UseAssign` → `AddFilter` / `AddEmptyAction` | ✅ 待办人后置链 |
| 推进前业务卡控（金额超限拒发等） | `IFlowGate`（`UseFlowGate`） | ✅ 见事件体系教程 |
| 强制跳过某节点 | 节点 `SkipDetail` 或运行时跳转命令 | 配置 / 命令，非连线 Filter |

**禁止混淆**：不要把「空人 / 同人 / 去重」做成连线条件；也不要把路由条件注册成 `IAssigneeResolver` Type。

## 五、常用 API 速查

| API | 说明 |
|-----|------|
| `RunBuilder.IfCondition(name, value)` / `IfCondition(dict)` | 写入办理条件袋 |
| `WorkflowService.GetNextStepInfo` / `GetNextActivityTree` | 业务层下一步（含角色/用户拼装入口） |
| `IProcessModel.GetNextActivityListView` | 结构层下一步（Skip + 连线 + 网关） |
| `IProcessModel.GetNextActivityTreeListRuntime` | 结构层 + 资源表达式二次过滤（引擎发送用） |
| `IProcessModel.IsValidTransition` | 单条连线条件判定 |
| `IProcessModel.GetForwardTransitionList(id)` | 未过滤出边 |
| `IProcessModel.GetForwardTransitionList(id, conditions)` | 条件过滤后出边 |
| `IProcessModel.GetNextActivityListWithoutCondition` | 忽略条件的后续活动（如部分退回逻辑） |

## 六、踩坑清单

1. **有条件但未传 `Conditions`**：该线会被判为不可达，整步可能变成「无匹配后续」。
2. **表达式键名与字典键不一致**：替换失败后表达式非法，解析 catch 后当 **false**（静默不抛）。
3. **AndSplit 出边上的条件**：And 分流调度**不看**条件；条件应写在 Or/XOr 等需要筛选的网关上。
4. **多出口不要用 `GetNextActivity`（单出边 API）**：多匹配会返回 null 或抛异常；多出口用 `GetForwardTransitionList` / 下一步树。
5. **结构层结果 ≠ 最终办理人**：算人在 Assignee 管道；结构 API 注释已声明不含实际用户列表。
6. **`ConditionType.Rule`**：连线侧未接线，不要按规则集配置连线条件。
