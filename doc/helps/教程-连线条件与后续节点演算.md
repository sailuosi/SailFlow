## 前置说明

- **连线条件**决定「能不能走某条 `sequenceFlow`」；**后续节点演算**在条件过滤后的出边上做图遍历，遇网关按类型继续展开。
- **Client 级扩展**一律经 **`UseNextStepRoute`**：Prepare（写条件袋）→ Evaluator（求值）→ Filter（裁/标注候选）。
- 可注册的 **Assignee `AddFilter`** 属于 **待办人管道**（`UseAssign`），只改办理人。
- `ConditionTypeEnum.Rule` 虽有枚举，连线解析当前固定为 `Expression`；规则引擎不用于连线条件求值。
- 条件求值**不是** IronPython Script；默认 ≡ `ExpressionParser`（LINQ Dynamic）。

## 一、如何定义连线条件

### 1.1 BPMN：`conditionExpression`

在 `sequenceFlow` 上写 `bpmn:conditionExpression`。`ProcessModelConvertor.ConvertTransition` 会建成 `ConditionDetail`：

| 字段 | 当前行为 |
|------|----------|
| `ConditionType` | 固定 `Expression` |
| `ConditionText` | 表达式原文（`InnerText`） |

示例：

```xml
<bpmn:sequenceFlow id="flow_to_finance" sourceRef="Gateway_1" targetRef="Task_Finance">
  <bpmn:conditionExpression>amount &gt; 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
<bpmn:sequenceFlow id="flow_to_dept" sourceRef="Gateway_1" targetRef="Task_Dept">
  <bpmn:conditionExpression>amount &lt;= 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
```

### 1.2 可选：网关连线行为（`sf:groupBehaviours`）

| 属性 | 作用 |
|------|------|
| `defaultBranch="true"` | **OrSplit** 无任何条件命中时走该默认线 |
| `priority` | **XOrSplit** 按优先级排序，取**第一条**条件为真的线 |
| `Approval`（审批分流） | **ApprovalOrSplit** 按通过/驳回选对应连线 |

### 1.3 条件何时算「有效」

`IsValidTransition` 规则：

| 情况 | 结果 |
|------|------|
| 连线无条件 / `ConditionText` 为空 | **始终可达** |
| 有条件，且条件字典非空 | 走 **`IConditionEvaluator` 链**（未挂管道时 ≡ `ExpressionParser`） |
| 有条件，但条件字典为空或 null | **不可达**（易踩坑） |

默认求值：`LinqDynamicConditionEvaluator` — `ReplaceParameterToValue` + `System.Linq.Dynamic`。数值原样替换；非数字字符串自动加双引号。  
自定义求值：`UseNextStepRoute(r => r.AddConditionEvaluator<T>(…))`，`TryEvaluate` 返回 `bool?`（`null` = 交下一 Order；`false` = 条件不成立）。  
可选 Python：`sailflow.action.Python.PythonConditionEvaluator`（表达式前缀 `python:` / `#python`）；**不**随 `UseIronPython` 注册，须显式 `AddConditionEvaluator`。

## 二、运行时如何传入条件变量

### 2.1 请求级（单次办理）

```csharp
await sail.CreateRunBuilder()
    .UseApp(appId, "采购申请")
    .UseProcess(processId)
    .OnTask(taskId)
    .IfCondition("amount", "15000")
    .IfCondition("dept", "finance")
    ;
```

### 2.2 Client 级（每次演算前自动写同一袋）

```csharp
builder.UseNextStepRoute(r =>
{
    r.IfCondition("needFinance", "1");
    r.IfCondition<SampleAmountPrepare>(o =>
    {
        o.ProcessCodes = new[] { "EXPENSE" };
        o.Match = NextStepMatch.Whitelist;
    });
    r.IfCondition(c => c
        .ForProcess("EXPENSE")
        .ForActivity("dept_approve")
        .IfCondition("routeFlag", "A"));
});
```

| 来源 | 用途 |
|------|------|
| `runner.Conditions` / 请求级 `IfCondition` | 查询下一步、发送时的主条件袋 |
| Client `UseNextStepRoute → IfCondition*` | 结构演算前 Prepare 写入**同一**袋（后写可覆盖） |
| 活动实例流程变量 | 与条件袋合并后再算 |
| `IEventService.SetCondition` | 可改写当前活动资源上的条件键值 |

表达式里写 `amount > 10000`，字典键必须是 `amount`。

## 三、某个节点有哪些后续节点——演算事实

### 3.1 分层入口

| 场景 | 入口 | 产出 |
|------|------|------|
| UI / 查询下一步 | `WorkflowService.GetNextStepInfo` → `NextStepParser` → `GetNextActivityListView` | `NodeView`（含 `Disabled` / `Required` / `ReasonCode`） |
| 运行时真正流转 | `NodeMediator` → `GetNextActivityTreeListRuntime` | 结构树 + Filter Prune + Performers 二次过滤 |
| 纯结构（共用内核） | `ProcessModelBPMNCore.GetNextActivityTreeListCore` | Prepare → 出边条件 → 网关展开 |

### 3.2 核心步骤（含管道）

对当前 `activityId`：

1. **Prepare**：Client `IfCondition*` 写条件袋（Options Match → IsMatch → Prepare）。
2. **取所有出边** → **条件过滤**（Evaluator 链）。
3. **按目标类型分发**（简单节点 / Gateway / Intermediate）。
4. **Filter**：标注/裁候选；AndSplit 必达支不可静默删（`AndSplitGuard`）。
5. 预览 Annotate `NodeView`；发送 Prune Disabled 后再按 `NextActivityPerformers` 裁。

### 3.3 网关展开语义

| 网关方向 | 后续演算行为 |
|----------|----------------|
| **AndSplit / AndSplitMI** | 所有出边都走，**不看**连线条件；Filter **禁止**静默删支 |
| **OrSplit** | 条件为真的都走；全假则走 `defaultBranch` |
| **XOrSplit** | 按 `priority` 排序，只取**第一条**条件为真的线 |
| **ApprovalOrSplit** | 按通过/驳回筛选 |
| **Join** | 对合并点出边再条件过滤后继续展开 |

### 3.4 流程示意

```
当前 ActivityId
  → Client Prepare 写 Conditions
  → 取 From 出边
  → Evaluator 求值连线条件
  → 网关展开
  → Filter（Disabled/Required/ReasonCode；AndSplitGuard）
  → 预览 NodeView / 发送 Prune + NextActivityPerformers
```

## 四、与「可注册扩展」的边界

| 需求 | 机制 | 能否自定义注册 |
|------|------|----------------|
| 按金额/字段决定走哪条线 | `conditionExpression` + 请求/Client `IfCondition` | ✅ `UseNextStepRoute` → `IfCondition*` |
| 替换条件求值引擎 | `IConditionEvaluator`（默认 LINQ） | ✅ `AddConditionEvaluator` / `UseConditionEvaluator` |
| 演算后裁剪/标注多候选 | `INextStepFilter` | ✅ `AddFilter`；预览看 `NodeView.Disabled` |
| 改下一节点办理人 | `UseAssign` → `AddFilter` | ✅ 待办人管道 |
| 推进前业务卡控 | `IFlowGate` | ✅ 事件体系教程 |
| 强制跳过某节点 | `SkipDetail` / 跳转命令 | 配置 / 命令 |

**禁止混淆**：Assignee Filter ≠ NextStep Filter；ScriptMethod ≠ 连线 Evaluator；Gate 不写 Conditions。

## 五、常用 API 速查

| API | 说明 |
|-----|------|
| `builder.UseNextStepRoute(r => …)` | 下一跳节点计算管道唯一门面 |
| `r.IfCondition` / `IfCondition<T>` / 链式糖 | Client 级写袋（Prepare） |
| `r.AddConditionEvaluator` / `UseConditionEvaluator` | 条件求值链 |
| `r.AddFilter` / `AddFilter<T>` | 候选 Filter |
| `RunBuilder.IfCondition` | 请求级写袋（保留） |
| `WorkflowService.GetNextStepInfo` | 业务层下一步 |
| `IProcessModel.IsValidTransition` | 单条连线条件判定 |

样例类（默认不自动挂）：`SampleAmountPrepare` · `SamplePermissionHideBranchFilter`（`sailflow.external.NextStep`，包 `samples/external`）。

## 六、踩坑清单

1. **有条件但未传 `Conditions`**：该线不可达（Prepare 未补键时同样）。
2. **表达式键名与字典键不一致**：默认 LINQ 路径失败 → false / 链上 `null`。
3. **AndSplit 出边上的条件**：And 分流调度不看条件；Filter 也删不掉必达支。
4. **多出口不要用单出边 API**。
5. **Whitelist 空流程维**：Options 不命中（字面量糖无 configure 时 Builder 会升为 `Match=All`）。
6. **`TryEvaluate` 不要用 `false` 表示「本器失败」** — 失败须 `null`。
