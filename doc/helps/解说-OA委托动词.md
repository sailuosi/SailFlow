| 标记 | 含义 |
|------|------|
| **现行引擎** | `IWorkflowService` 已有命令 / Manager 路径 |
| **码表已开** | 已进办理条（`SailButtonsCatalog`） |

口语里「委托」「代办」「交人」常混用。Sail **不**用一个万能按钮吞掉三者——先看下表，再进各节。

## 0. 一张表分清

| 能力 | 产品名 | 触发 | 原人 | 对方 | 办完之后 | 现状 |
|------|--------|------|------|------|----------|------|
| [转办](#1-转办本节点交人我不办了) | 转办 `Transfer` | 办理条 · **这一张**待办 | **关闭** | 同节点新待办 | **对方推进**；**不**还回 | 码表已开 |
| [委派](#2-委派请他代办办完必须还给我) | 委派 `Delegate` | 办理条 · **这一张**待办 | **关闭**（责任锚点仍在） | 新待办挂 `EntrustedTaskId` | **自动回转原人**；**不**推进节点 | **已接线**（码表默认关） |
| [委托代批](#3-委托代批事先配置建任务时并入代理人) | 委托代批（建议产品名） | **事先配置** · 建任务时自动 | **保留** | **追加**进参与者 | **任一可办**则推进（受 Leave） | **引擎+Host Filter 已挂**；「我的委托」页待 |
| 遗留 Entrust | （勿新产品化） | API `EntrustTask` | 可选关原待办 | 新建 | 与 Transfer 相近、口径旧 | 遗留；新代码走 Transfer / Delegate |

```text
我要换人办这件事？
 ├─ 这张单交出去，我不办了、也不指望还回  → 转办 Transfer
 ├─ 这张单请他先代看/代点，办完还得还我   → 委派 Delegate
 └─ 我这段时间出差，之后凡到我名下的单
    自动让他也能办（原人也留着）         → 委托代批（配置 · 候选）
```

## 1. 转办：本节点交人，我不办了

### 业务场景

手头有张待办，出差在即，希望同事**接手**——节点还是这个节点，只是**换人办**，流程不往下跳。办完也不用还回给你。

### 会发生什么

1. 你的待办关闭；同活动上给对方开一条新待办。
2. **不发生节点流转**（还停在当前节点）。
3. 活动 `SignIds` / `SignNames` **刷新**为当前打开办理人集合。
4. 对方办结后按他自己的权限推进；**不会**自动还回给你。

### 一句话

**转办 =「本节点交人，我不办了，也不指望他还给我」。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Transfer` → `TransferProcess` |
| Host 入口 | `ButtonsOperation` → `TransferOperationHandler` |
| 引擎 API | `IWorkflowService.TransferProcess[Async]` |
| 动作骨架 | Assignee 族 · `TransferAction` |
| 写库 | `TaskManager.Transfer`（原 Closed + 同 Activity 新待办；刷新 SignIds/Names） |
| 通知 | `FireTaskLifecycle(Entrusted)` + 目标 `Created` |
| 现状 | **码表已开** |
| 详链 | [解说-办理动词 §7](./解说-办理动词.md#7-转办这事交给他我不办了) · OA 手册 §5.12 |

## 2. 委派：请他代办，办完必须还给我

> Sail 码表编码用 **`Delegate`（委派）**。口语「委托」若指**单笔请人代办且要还回**，锚到本节，**不要**当成转办，也**不要**当成下面的「委托代批」。

### 业务场景

你是节点责任人，临时请秘书代看材料、代点同意——但**责任仍在你**。对方办完后，待办应**回到你手上**；你再决定是否亲自推进或继续办理。  
若办完**不需要**还回 → 用转办，不要用委派。

### 会发生什么

1. **发起**：你的待办关闭并走 `Entrusted` 生命周期；对方拿到新待办，`EntrustedTaskId` 指向你的原 TaskId。
2. **不刷新**活动 `SignIds`/`SignNames`（原人仍是责任锚点）。
3. **对方办结**（`Approve`/`Run`）：走 `TryCompleteAsDelegationReturn`——受托待办 Completed，原人待办重建为 Waiting；**不**完结活动实例、**不** `ContinueForward`（节点不往下走）。
4. **禁止套娃**：已是委派出来的待办（`EntrustedTaskId` 非空）不能再委派。
5. **禁止自委派**；目标若已有同活动打开待办则拒绝。
6. 有未完成沟通参与者时，与 Transfer 一样被 `ConsultPendingGuard` 拦截。

### 一句话

**委派 =「请他代办，办完必须还给我」（≠ 转办；≠ 委托代批）。**

### 引擎关联

| 项 | 值 |
|----|-----|
| 码表 / 命令 | `Delegate` → `DelegateProcess`（默认 enable=false） |
| Host 入口 | `ButtonsOperation` → `DelegateOperationHandler` |
| 引擎 API | `IWorkflowService.DelegateProcess[Async]` |
| 动作骨架 | Assignee 族 · `DelegateAction` |
| Gate | `FlowOperation.Delegate` |
| 写库 · 发起 | `TaskManager.Delegate` |
| 写库 · 办结回转 | `TaskManager.TryCompleteAsDelegationReturn`（Mediator 办结路径挂接） |
| 成功 Hook | 发起时 `OnProcessDelegated` |
| 字段 | `wf_task.tk_entr_task_id` → 实体 `EntrustedTaskId` |
| 现状 | **现行引擎**；Host 码表 / Handler **暂缓** |
| 详链 | [解说-办理动词 §8](./解说-办理动词.md#8-委派请他代办办完还得还给我) · OA 手册 §5.12e |

### 与转办对照（现行）

| 维度 | 转办 `Transfer` | 委派 `Delegate` |
|------|-----------------|-----------------|
| 原人待办 | Closed | Closed |
| 活动 Sign 集合 | **刷新**为新人 | **不刷新**（原人锚点） |
| 受托任务挂原 TaskId | 否（产品语义不靠此链） | **是**（`EntrustedTaskId`） |
| 对方办结 | 正常推进 / Leave | **回转原人**；不推进 |
| 套娃 | 按 Transfer 规则 | **禁止**再委派 |
| Host | 已接线 | 未挂 |

## 3. 委托代批：事先配置，建任务时并入代理人

> **产品候选**（2026-11-16 语义固化）。口语「出差委托」「代理审批」多指本节。  
> **不是** `DelegateProcess`，**不要**用现有委派按钮冒充；落地挂 **Assignee 时刻 A′ Filter**，不是新的 Resolve Type（见 [待办人管道 R10](../sail/特性说明-待办人管道.md)）。

### 业务场景

李四出差前在「我的委托」配一条：全部流程（或某流程）· 委托给张三 · 时间窗 · 启用。  
之后凡本该到李四名下的审批，**建任务那一刻**把张三一并写入参与者——**李四待办仍在，张三也有待办**；两人**任一**办完即可（须与 Leave 对齐，见下）。审批记录记实际办理人。

### 会发生什么（目标语义）

1. **命中 = 追加**，不是替换：原人保留，被委托人并入 `Performer[]` 后再落库。
2. **不接力**：A→B、B→C 时，C 不会因 B 的委托收到 A 的单；只对「本轮 Resolve 出的原始参与者」查委托。
3. **不扩会签名册**：只影响当步任务参与者快照。
4. **只对新单生效**：改/停用委托不影响已建待办。
5. **判据**：时间窗 · `enabled==1`（读侧白名单）· 禁止自委托 · 流程作用域（精确优先，判否回落「全部流程」）。
6. **取行**：同授权人+同作用域先取**最新一条**再裁决；判否不回退更旧行。

### 一句话

**委托代批 =「配一条委托，之后建到我名下的单自动让代理人也能办；原人保留，任一可办」。**

### 与委派 / 转办的硬边界

| 维度 | 委派 `Delegate` | 委托代批（候选） |
|------|-----------------|------------------|
| 触发 | 办理条 · 单笔 | 配置表 · 建任务自动 |
| 原人 | 关闭待办 | **保留**待办 |
| 对方 | 替换式代办（原关新开） | **追加**参与者 |
| 办完 | **还回**原人，不推进 | **推进**（谁办记谁） |
| 落点 | `DelegateAction` / TaskManager | Assignee **Filter** + Host 配置 CRUD |

### Leave 注意（落地前必拍板）

「任一可办」依赖办理模式：出厂 Leave 默认常为 `Collaborate`。若只追加人不改 Leave，会变成**两人都会签**。候选方案：

| 方案 | 含义 |
|------|------|
| A | 会走代批的节点设计为 `Race` |
| B | 并人时标记「代批席」，Leave 视原人/代理人为同一席（任一完成即过） |

未拍板前，**禁止**在 Host 空壳上线「委托代批」按钮。

### 建议落点（未实现 · 仅锚点）

| 层 | 建议 |
|----|------|
| 引擎 / 管道 | Host 注册 `IAssigneeResolveFilter`（如 `SurrogateAssigneeFilter`），挂在 Resolve 之后、建议再经 `DedupUsersFilter` |
| 计权 | `Weight` + `ProxySignId` + EffectiveWeight（同根去重）；详见 [专题-办理人权重与委托体系.md](../sail/dev/专题-办理人权重与委托体系.md) |
| Host 表 | 授权人 / 被委托人 / 流程作用域可空 / 时间窗 / `Enabled`；列表强制 `Grantor = 当前用户` |
| 前端 | 「我的委托」页（对齐抄送箱 / 我的待办骨架）；**不**进办理条冒充 `Delegate` |
| 禁止 | 新 Resolve Type；把代批语义塞进 `Transfer`/`DelegateProcess` |

## 4. 遗留 `EntrustTask`（勿新产品化）

| 项 | 说明 |
|----|------|
| API | `IWorkflowService.EntrustTask` / `CancelEntrustedTask` |
| 实现 | `TaskManager.Entrust` |
| 态度 | **遗留痕迹**；新产品与办理条一律走 **`Transfer` / `Delegate`** |
| 通知 Kind | 历史上与转办等共用 `TaskNotifyKind.Entrusted` 命名——Kind 名含 Entrusted **≠** 产品「委派」动词本身 |

## 5. 易混对照（委托一族）

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 委托（口语） | 一定是委派 | 先问：单笔还回？交人不再回？还是出差配置并入？ |
| 转办 | 委派 | 转办不还回；委派办完自动还回 |
| 委派 | 委托代批 | 委派关原人、办完还回不推进；代批保留原人、建单并入、谁办谁推进 |
| 委托代批 | 加签 | 加签是办理时临时加人；代批是配置驱动的建单并入 |
| 委托代批 | 抄送 | 抄送无推进权；代批有审批待办 |
| 委派回转 | 退回 / 反转 | 回转仍在同一节点把待办还给原人，不是打回改单 |
| `EntrustedTaskId` | 委托代批配置 Id | 仅委派链：受托任务指向原任务行 |
| `TaskNotifyKind.Entrusted` | 仅委派成功 | 转办路径也会 Fire 同 Kind（通知通道名，勿当产品动词） |

## 6. 选型速查

| 你想要的结果 | 用 |
|--------------|-----|
| 这张单交给他，我不办了 | **转办** |
| 这张单请他先办，办完还得还我再看 | **委派** |
| 出差/休假期间，以后到我名下的单他也能批，我也可以批 | **委托代批**（候选；未落地前勿空壳） |
| 只要他知情，不用他批 | **抄送** |
| 问他要个信息，锁住我的通过直到他回 | **沟通** |
