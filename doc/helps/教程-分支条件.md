# SailFlow 分支条件：定义、注册与生效

> 状态：对照 **已落地代码**（`UseNextStepRoute` · `NextStepPrepare` · `ApplyPrepare` + `FlowCommandContext`）整理。  
> 演算细节（网关展开、Evaluator 链、踩坑）见 [教程-连线条件与后续节点演算.md](./教程-连线条件与后续节点演算.md)。  
> 源码：`Plugin/NextStep/*` · `Hosting/SailNextStepRouteExtensions` · `ProcessModelBPMNCore.GetNextActivityTreeListCore`

---

## 一句话

**分支条件** = BPMN 连线上的表达式 + 运行时条件袋（`Conditions`）里的键值。  
业务侧只需：**注册 Prepare**（按需写袋）+ **请求可带 Conditions**；引擎在预览 / 发送演算前自动 `ApplyPrepare`，与 `context.Conditions` **同源**，无需 Controller 再调 Enrich。

---

## 1. 分支何时生效

### 1.1 生效点（结构演算前）

对「下一步」演算，无论 **预览**（GetNext）还是 **发送**（Start/Run），内核都会：

```
GetNextActivityTreeListCore
  → ApplyPrepare(context)     // Client 级 Prepare 写同一 Conditions 袋
  → 出边条件求值（Evaluator）
  → 网关展开 / Filter
```

| 路径 | 传入的 `context` | Prepare 是否跑 |
|------|------------------|----------------|
| `GetNextActivityListView`（预览） | `NextStepParser` 透传的 `FlowCommandContext` | ✅ Preview |
| `GetNextActivityTreeListRuntime`（发送） | `activityResource.AppRunner` | ✅ Send |
| `NodeMediator` 直接调 Core | `activityResource?.AppRunner` | ✅ |

条件袋与 `context.Conditions` **同一字典引用**时，Prepare 原地写即可落回请求上下文（后续 Persist 变量表可读到）。

### 1.2 连线层判定

| 连线情况 | 结果 |
|----------|------|
| 无 `conditionExpression` | 始终可达 |
| 有表达式，袋中有对应键 | `IConditionEvaluator` 求值 |
| 有表达式，袋空 / 缺键导致表达式失败 | 通常视为不可达（表达式 false） |
| 有表达式，但未注册任何 Evaluator | **抛异常**（须 `UseSailRuntimeDefaults` 或自挂 Evaluator） |

网关语义摘要：

| 网关 | 条件角色 |
|------|----------|
| **XOrSplit** | 按 `priority` 取**第一条**为真的线 |
| **OrSplit** | 为真的都走；全假走 `defaultBranch` |
| **AndSplit** | **不看**连线条件（全走） |

### 1.3 写袋语义：静态兜底 vs 动态不踩请求

| API | 时机 | 行为 |
|-----|------|------|
| `IfCondition(name, value)`（基类 / Builder 字面量） | Prepare 时 | **强制覆盖**该键 |
| `SetIfAbsent(ctx, name, value)` | `Contribute` 内 | 请求已有键 **不覆盖**；空值不写 |
| `Set(ctx, name, value)` | `Contribute` 内 | **强制写入**（可写 `""`） |
| 请求体 / `RunBuilder.IfCondition` | 调用前 | 先入袋；之后 Prepare 按上表覆盖或跳过 |

推荐业务写法：静态兜底用构造期 `IfCondition`；从表单/业务库读数用 `SetIfAbsent`，避免踩掉前端已传键。

## 2. 注册逻辑

### 2.1 唯一门面

```csharp
// Builder 期（DI / SailClientBuilder）
services.UseNextStepRoute(r => { /* ... */ });
// 或
builder.UseNextStepRoute(r => { /* ... */ });

// 已 Build 的 Client（宿主 PostBuild 常见）
client.UseNextStepRoute(r => { /* ... */ });
```

管道三类插件（按注册 Order 排序执行）：

| 类型 | Builder API | 作用 |
|------|-------------|------|
| **Prepare** | `r.IfCondition*` | 演算前写 `Conditions` |
| **Evaluator** | `r.AddConditionEvaluator` / `UseConditionEvaluator` | 求值 `conditionExpression` |
| **Filter** | `r.AddFilter` | 演算后标注/裁候选（不改连线真假本身） |

默认 LINQ 求值器通常由 `UseSailRuntimeDefaults()` / `UseBizRuntimeDefaults()` 挂入；有条件连线时至少要有一个 Evaluator。

### 2.2 Match 范围

`NextStepRouteOptions`：

| Match | 含义 |
|-------|------|
| `All` | 所有流程都跑该插件 |
| `Whitelist` | 仅 `ProcessCodes` / `ProcessIds` / `ProcessCodePatterns`（及可选 `ActivityCodes`）命中时跑 |

未配流程维且未显式 Match 的字面量糖，Builder 会升为 `Match=All`。

### 2.3 宿主最小面：只注册 Prepare

```csharp
// 宿主 PostBuild
client.UseSailBizConditionPrepares(); // 内部即 UseNextStepRoute + IfCondition<Leave...>

// 等价手写
client.UseNextStepRoute(r =>
{
    r.IfCondition(new LeaveConditionPrepare(), o =>
    {
        o.Match = NextStepMatch.All;
        o.Order = 40;
    });
});
```

**不要**在 Controller 再调一遍 Prepare；Start / Run / GetNext 只要带上 `FlowCommandContext`（含 `BizPK` / `ProcessId` / 可选 `Conditions`）即可。

## 3. API 形态代码

### 3.1 BPMN：连线表达式

```xml
<bpmn:exclusiveGateway id="Gateway_1" name="金额分流"/>
<bpmn:sequenceFlow id="to_hi" sourceRef="Gateway_1" targetRef="Task_Finance">
  <bpmn:conditionExpression>amount &gt; 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
<bpmn:sequenceFlow id="to_lo" sourceRef="Gateway_1" targetRef="Task_Dept">
  <bpmn:conditionExpression>amount &lt;= 10000</bpmn:conditionExpression>
</bpmn:sequenceFlow>
```

表达式里的标识符必须与条件袋键名一致（如 `amount`）。

### 3.2 请求级：直接传袋 / RunBuilder

```csharp
// HTTP：Body 即 FlowCommandContext
// { "processId": "...", "bizPK": "...", "conditions": { "amount": "15000" } }

// 代码发起
await sail.CreateRunBuilder()
    .UseProcess(processId)
    .UseApp(bizPk, "采购申请")
    .IfCondition("amount", "15000")
    .IfCondition("urgency", "high")
    // ... Start / Run
    ;
```

### 3.3 Client 级：字面量 / 泛型 / 委托 / 链式

```csharp
client.UseNextStepRoute(r =>
{
    // 字面量：Prepare 时强制写入
    r.IfCondition("needFinance", "1");

    // 泛型 Prepare + 白名单
    r.IfCondition<ExpenseAmountPrepare>(o =>
    {
        o.Match = NextStepMatch.Whitelist;
        o.ProcessCodes = new[] { "EXPENSE" };
        o.Order = 20;
    });

    // 委托 Contribute（简单场景；复杂逻辑请用独立 Prepare 类）
    r.IfCondition(ctx =>
    {
        if (ctx.Conditions != null && !ctx.Conditions.ContainsKey("flag"))
            ctx.Conditions["flag"] = "1";
    }, o => o.Match = NextStepMatch.All);

    // 链式：按流程/活动限定
    r.IfCondition(c => c
        .ForProcess("EXPENSE")
        .ForActivity("dept_approve")
        .IfCondition("routeFlag", "A"));
});
```

### 3.4 业务 Prepare（推荐形态）

```csharp
using sailflow.engine.NextStep;

/// <summary>请假单：BizPK → Conditions["days"]（不覆盖请求已有键）。</summary>
public sealed class LeaveConditionPrepare : NextStepPrepare
{
    public override bool IsMatch(NextStepRouteContext ctx)
    {
        if (ctx?.Conditions == null || ctx.Conditions.ContainsKey("days"))
            return false;
        return !string.IsNullOrWhiteSpace(ctx.ProcessCode)
               && ctx.ProcessCode.Contains("leave", StringComparison.OrdinalIgnoreCase);
    }

    protected override void Contribute(NextStepRouteContext ctx)
    {
        var bizPk = ctx.BizPK ?? ctx.Runner?.BizPK;
        if (string.IsNullOrWhiteSpace(bizPk) || ctx.Sail == null)
            return;

        // 读业务表...
        var days = "3"; // row.Days.ToString(...)
        SetIfAbsent(ctx, "days", days);
        // 需要强制覆盖时用：Set(ctx, "days", days);
    }
}

// 注册
client.UseNextStepRoute(r =>
    r.IfCondition<LeaveConditionPrepare>(o =>
    {
        o.Match = NextStepMatch.All;
        o.Order = 40;
    }));
```

构造期静态兜底可与动态并存：

```csharp
public sealed class DemoComplexCondPrepare : NextStepPrepare
{
    public DemoComplexCondPrepare()
    {
        // 可选：静态兜底（Prepare 时强制写）
        // IfCondition("skipAudit", "N");
    }

    public override bool IsMatch(NextStepRouteContext ctx)
        => string.Equals(ctx?.ProcessCode, "SEED_COMPLEX_COND", StringComparison.OrdinalIgnoreCase);

    protected override void Contribute(NextStepRouteContext ctx)
    {
        SetIfAbsent(ctx, "amount", "500");
        SetIfAbsent(ctx, "urgency", "low");
        SetIfAbsent(ctx, "needLegal", "Y");
    }
}
```

### 3.5 自定义 Evaluator（可选）

```csharp
client.UseNextStepRoute(r =>
{
    r.AddConditionEvaluator<LinqDynamicConditionEvaluator>(o =>
    {
        o.Match = NextStepMatch.All;
        o.Order = 100;
    });
    // 或 Python：AddConditionEvaluator<PythonConditionEvaluator>(o => o.Order = 10);
});
```

`TryEvaluate` 约定：本器无法处理返回 `null`（链继续）；明确假返回 `false`（链停止）。

### 3.6 Filter：隐藏某候选支（非改条件真假）

```csharp
client.UseNextStepRoute(r =>
    r.AddFilter<HideFinanceIfNoPermissionFilter>(o =>
    {
        o.ProcessCodes = new[] { "EXPENSE" };
        o.Match = NextStepMatch.Whitelist;
    }));
```

预览看 `NodeView.Disabled` / `ReasonCode`；发送路径会 Prune Disabled（AndSplit 必达支有守卫）。

## 4. 端到端心智图

```
BPMN conditionExpression(amount > 10000)
        ▲
        │ Evaluator 求值
        │
Conditions 袋 ◄── 请求 Conditions / RunBuilder.IfCondition
        ▲
        │ ApplyPrepare（与 context.Conditions 同源）
        │
UseNextStepRoute → IfCondition<YourPrepare>
                     Contribute → SetIfAbsent / Set / 基类 IfCondition
```

| 你要做的 | 不要做的 |
|----------|----------|
| 在 BPMN 写表达式 | 在 Controller 再 Enrich 一遍袋 |
| `UseNextStepRoute` 注册 Prepare | 把 Assignee Filter 当成分支条件 |
| 请求带 `BizPK` + 可选 `Conditions` | 有条件却不挂任何 Evaluator |
| 动态键用 `SetIfAbsent` | AndSplit 上指望连线条件分流 |
