# 审计：sailflow 相对常见 OA 引擎流程能力对照

> 状态：**只读审计结论**（2026-11-14）  
> 用途：记录相对常见钉钉式 / 中国式 OA 工作流引擎的流程能力对齐快照；**不直接当实施清单**。  
> 口径：  
> - **Sailflow** = 引擎仓 + 文档里约定的 Host（`sleveen-admin`）产品接线  
> - **常见 OA 引擎** = 市面常见仿钉钉审批 / 低代码 OA 工作流（对照样本含 .NET 实现）；声明有但运行时未接线的标为「部分」  
> 关联：[特性说明-引擎能力基线.md](../sail/特性说明-引擎能力基线.md) · [特性说明-中国式OA审批要素.md](../sail/特性说明-中国式OA审批要素.md) · [存疑参考功能点.md](../sail/存疑参考功能点.md) · [todo-产品缺口.md](../sail/todo-产品缺口.md)

按**流程能力**对照（不含前端壳、部署运维细节）。

图例：

| 标记 | 含义 |
|------|------|
| ✅ | 有（已落地可接） |
| 🟡 | 部分 / 弱 / 枚举有但未接线 / 引擎有未产品化 |
| ❌ | 无 |
| — | 无对等产品表达（用其他动词覆盖） |

表头缩写：**OA** = 常见 OA 引擎侧。

## 办理动词（审批动作）

| 特性 | Sailflow | OA | 说明 |
|------|:--------:|:--:|------|
| 发起 / 提交 | ✅ | ✅ | 两边都有 |
| 同意 / 通过 | ✅ | ✅ | Sail=`RunProcess`；OA 侧多为同意/审批通过按钮 |
| 驳回 / 不同意 | ✅ | ✅ | 语义略不同：Sail 的 Reject ≠ 整单作废 |
| 退回 / 打回修改 | ✅ | ✅ | OA 侧常见多型 Disagree；Sail 用「目标 × 再发送」两维 |
| 退回任意历史节点 | ✅ | 🟡 | OA 侧多靠 Disagree 类型 + 指定节点；独立「退任意节点」按钮常未完整接线 |
| 撤回 | ✅ | 🟡 | Sail 引擎稳定；OA 侧常有按钮声明，部分实现仓未接线 |
| 转办 | ✅ | ✅ | Sail 已接线（产品联调中）；OA 侧常见转办按钮 |
| 委托 / 委派 | 🟡 | 🟡 | Sail 暂缓产品化（有 Entrust 痕迹）；OA 侧有委托服务，偏替换审批人 |
| 变更处理人 | ❌ | ✅ | OA 侧常见管理改派；Sail 无产品命令 |
| 承办（或签先认领） | ❌* | ✅ | Sail **刻意不跟**；用 Leave=`Race` 表达抢办 |
| 加签（当前节点加人） | ✅ | 🟡 | Sail=`SignForward`；OA 侧常有声明，部分实现未接线 |
| 加批（生新审批段） | 🟡 | ✅ | OA 侧加批完整；Sail 与加签揉在一起，未拆 |
| 减签 | ❌ | 🟡 | OA 侧常有枚举声明、adaptor 未齐；Sail 无 |
| 未来节点加/减/换人 | ❌ | 🟡 | OA 侧常有声明；部分实现仓无 adaptor |
| 跳转（自由跳） | ✅ | 🟡 | Sail=`JumpProcess`；OA 侧引擎可跳，常无独立产品按钮 |
| 转发 | 🟡 | ✅ | OA 侧常见转发；Sail 主通道归抄送 |
| 终止 / 作废 | 🟡 | ✅ | Sail 引擎有、按钮默认关；OA 侧常见终止/作废 |
| 关闭 | ✅ | — | Sail 管理向；OA 侧多用终止/作废表达结束 |
| 挂起 / 恢复 | 🟡 | 🟡 | 两边都弱；Sail 有 API 未产品化；OA 侧多仅字段痕迹 |
| 重发 / 返送退回人 | ✅ | 🟡 | Sail 特色 `ResendProcess`；OA 侧靠「打回后重新提交」组合 |
| 修订 / 反转 | 🟡 | ❌ | Sail 有、默认关；OA 侧少见对等动词 |

\* 承办：Sail 文档明确「默认不抄常见 OA 引擎按钮」，不算缺口债。

## 对齐结论（一句话）

| 维度 | 态势 |
|------|------|
| **中国式办理动词** | 核心路径（同意/驳回/退回/转办/会签或签）大致对齐；常见 OA 引擎更偏钉钉产品按钮集，Sail 更偏引擎命令 + 正交 Leave |
| **Sail 明显强** | BPMN 事件节点、子流程、跳转/撤回产品化、Assignee 管道（组/队长）、Gate-Hook-Outbox、多库/分表、插件分层 |
| **常见 OA 引擎明显强** | 加批、承办、变更处理人、抄送节点、人员策略产品化、低代码/DIY/外部接入一体化、审批意见闭环 |
| **两边都弱 / 名义有实装薄** | 减签与未来节点加减人、挂起恢复、加急；OA 侧撤回/加签减签在部分实现仓多为枚举未接线 |
| **刻意不对齐** | 承办（Sail 不跟）；退回五型（Sail 改两维）；加批 vs 加签（Sail 尚未拆） |

若只盯「钉钉式 OA 开箱按钮」，常见 OA 引擎产品面更齐；若盯「可嵌入、可扩展的流程引擎能力」，Sailflow 在图语义、插槽与可靠性上更完整，OA 动词上仍有意留下减签/未来节点/委派/承办等空位。
