## 1. ID 语义辞典（现行口径）

> 目的：把「叫 Id / ProcessId / TaskId …」的字符串先按**生命周期层**分清，再谈对齐问题。  
> 类型现状：下列 ID 在引擎侧均为 **`string`**（行 PK 多为 `AutoKey=Guid`）；BPMN 元素 id 亦为 string，但来自图元而非库自增。  
> **用词约定（本文强制）：**  
> - **「业务」** 只指 **业务模块 / 业务单据**（§1.5 的 `App*`），不用于描述流程引擎内部身份。  
> - 流程定义上的稳定身份键称 **「流程设计定义键」**（即 `ProcessId`，与 `Version` 配对），**不要**说成「业务键 / 业务定义键」。  
> - 定义表行主键称 **「定义行主键」**（即 `wf_process.id` / `ProcessEntity.Id`）。

```text
业务模块单据 ──挂接──► 流程设计定义 ──发起──► 流程实例 ──推进──► 活动实例 ──生成──► 待办任务
App*                    Process*              ProcessInstance*    ActivityInstance*       Task*
                        Activity*（图）
                        Transition*（图）
```

### 1.1 四层总览

| 层 | 含义 | 典型字段 | 谁生成 | 典型用法 |
|----|------|----------|--------|----------|
| **A. 定义** | 流程/节点/连线在设计模型上的身份；可跨多次发起复用 | **流程设计定义键** `ProcessId`+`Version`、`ActivityId`、`TransitionId`；另有**定义行主键** `wf_process.id` | 设计器 / BPMN / 导入；行 PK 入库 AutoKey | 打开设计器、按版本取 XML、解析下一节点 |
| **B. 运转实例** | 某次发起后引擎落库的运行行 | `ProcessInstanceId`、`ActivityInstanceId`、转移实例 `Id`、任务 `Id` | 引擎运行时 AutoKey | 办理、强制结束、轨迹、子流程回挂 |
| **C. 人员 / 组织** | 谁办、属哪组/单位（非流程图元） | `UserId`、`AssignedUserId`、`GroupId`、`UnitId`、`CompanyId`、`StartUnitId` | 宿主身份 / Assignee 管道 | 待办归属、权限、发起单位 |
| **D. 业务挂接** | **业务模块**单据与流程的关联键（专指业务侧） | `AppName`、`AppInstanceId`、`AppInstanceCode` | **业务系统**，引擎只原样携带 | 打开业务表单、按单号查流程 |

**易混点（全文档最高频）：**

| 名字 | 常被误当成 | 实际 |
|------|------------|------|
| `ProcessId` | 流程实例 Id / 定义表行 PK / 「业务」单据键 | **流程设计定义键**（与 `Version` 配对）；实例上只是冗余指向定义 |
| `wf_process` 行主键 / `ProcessDefId` | 就是 ProcessId | **定义行主键**（属性名 `ProcessDefId`，列仍 `id`）；`GetById` / 部分删除 / 子流程 `subId` |
| `TaskId` / `wf_task.Id` | 办理人 Id | **待办任务行主键**；办理人是 `AssignedUserId` |
| `ActivityId` | 活动实例 Id | **节点设计定义 ID**（BPMN 元素 id）；活动实例是 `ActivityInstanceId` |
| `AppInstanceId` | 流程实例 Id | **业务模块单据 Id**（如请假单号）；流程实例是 `ProcessInstanceId` |

### 1.2 A · 流程 / 节点定义 ID

#### 流程定义（`wf_process` / `ProcessEntity`）

| 属性 | 列 | 含义 | 解析入口 |
|------|-----|------|----------|
| **`ProcessDefId`** | `id` | **定义行主键**（Guid 字符串；原属性名 `Id`，D4 已改） | `ProcessManager.GetById`；`DeleteProcess(id)`；子流程 XML `subId`→`SubProcessDefId` |
| **`ProcessId`** | `process_id` | **流程设计定义键**（设计侧稳定身份，常为 Guid） | 与 `Version` 一起：`GetByVersion`、`CreateByProcess`、发起入参 |
| **`Version`** | `version` | 定义版本（如 `"1"`） | 与 `ProcessId` 组成唯一「设计定义坐标」 |
| `ProcessCode` | `process_code` | 人类可读编码（非主键） | 列表展示 / 筛选 |
| `PackageId` | `package_id` | 协作包/泳道包关联（定义侧） | 包流程结构 |
| `ParticipantGUID` | `participant_guid` | 参与者定义引用（历史/包场景） | 少见；勿与办理人 `UserId` 混用 |

新建时常 **`Id ≠ ProcessId`**：`ProcessId` 可预置，`Id` 由插入 AutoKey 生成。`Insert`/`CreateProcess` 返回值是**行 PK**，局部变量却常叫 `processId`——命名陷阱。

#### 图元定义（BPMN / XPDL，不入库为独立 PK 表）

| 属性 | 来源 | 含义 |
|------|------|------|
| **`ActivityId`** | BPMN 元素 `@id` → `Activity.ActivityId` | **节点设计定义 ID**；写入实例表作 `activity_id` 冗余 |
| **`TransitionId`** | SequenceFlow `@id` | **连线设计定义 ID**；写入 `wf_transition_instance.transition_id` |
| `FromActivityId` / `ToActivityId` | 连线 sourceRef/targetRef | 定义层节点引用 |

#### 子流程定义绑定（Referenced）

| XML / 字段 | 应对哪一层 | 现行解析 |
|------------|------------|----------|
| `sf:SubInfo/@subId` → `SubProcessDefId` | **被引用流程的定义行主键**（`wf_process.id`） | `GetById(SubProcessDefId)` |
| `sf:SubInfo/@subProcessId` → `SubProcessId` | **被引用流程的流程设计定义键**（`process_id`） | 展示 / 嵌套路径等 |
| Nested 子流程 | 图内嵌套，无独立 `wf_process` 行 | `SubProcessId` 指向嵌套 process 元素 id |

### 1.3 B · 流程运转实例 ID

| 属性 | 表 / 实体 | 含义 | 常见 API / 袋字段 |
|------|-----------|------|-------------------|
| **`ProcessInstanceId`** | `wf_process_instance.id`（实体属性名多为 `Id`；外键与袋内叫 `ProcessInstanceId`） | **一次发起**的流程实例主键 | `FlowCommandContext.ProcessInstanceId`；强制结束、轨迹 |
| **`ActivityInstanceId`** | `wf_activity_instance.id` | **某次运行到某节点**的活动实例主键 | 袋内 `ActivityInstanceId`；会签主/子用 `MainActivityInstanceId` |
| **`TaskId`** | `wf_task.id`（视图 `TaskViewEntity.Id`；袋内 `TaskId`） | **某办理人在该活动上的待办行**主键 | `RunProcess` / 同意驳回等按 Task 定位 |
| 转移实例 `Id` | `wf_transition_instance.id` | 一次流转边的运行记录主键 | 轨迹；定义侧另有 `TransitionId` |
| `EntrustedTaskId` | `wf_task.entrusted_task_id` | 委托场景：指向原任务行 | 委托链 |
| `InvokedActivityInstanceId` / `InvokedActivityId` | 子流程实例上 | 父侧触发子流程的**活动实例 / 活动定义**回挂 | 子→父关联 |
| `MainActivityInstanceId` | 会签等 | 子活动实例指向主活动实例 | 会签归并 |

实例行上同时冗余挂着流程设计定义键（`ProcessId`、`Version`、`ActivityId`）与业务模块挂接（`AppName`、`AppInstanceId`），便于查询；**定位“这一次运转”仍以实例层 `*InstanceId` / `TaskId` 为准**。

### 1.4 C · 待办人 / 组织 ID（非图元、非实例主键）

| 属性 | 落点 | 含义 |
|------|------|------|
| **`UserId` / `UserName`** | `FlowCommandContext`；实例/任务上的 Created/Ended/Updated* | **当前操作者**（命令发起人） |
| **`AssignedUserId` / `AssignedUserName`** | `wf_task`；活动实例上有汇总 `AssignedUserIds` | **待办归属人**（真正“办这张任务的人”） |
| `GroupId` / `GroupName` / `GroupRole` | 任务 / 活动实例 | 办理组别与组内身份（会签等） |
| `UnitId` / `UnitCode` / `UnitName` | 任务 / 活动实例 | 办理单位维度 |
| `CompanyId` | 命令袋 | 公司；可回落为发起单位 |
| `StartUnitId` / Code / Name | 流程实例 | **发起单位**（不覆盖节点任务 Unit*） |

说明：没有单独叫「待办人 ID」的主键列；**待办行是 `TaskId`，人是 `AssignedUserId`**。二者都是 string，切勿互换。

### 1.5 D · 业务模块挂接 ID

> 本节是全文唯一合法使用「业务」指代对象身份的地方：指 **业务模块单据**，不是流程设计定义。

| 属性 | 含义 | 谁拥有 |
|------|------|--------|
| **`AppName`** | 业务模块名 / 单据类型名（如请假、报价） | 宿主约定 |
| **`AppInstanceId`** | **业务模块单据主键**（文档号、表单 OID 等） | 业务库；引擎只存拷贝 |
| **`AppInstanceCode`** | 业务模块单据编码（展示/检索用，可与 Id 不同） | 业务库 |

发起时由宿主写入 `FlowCommandContext`，再落到实例/任务/活动实例。引擎用 `(AppName, AppInstanceId, ProcessId)` 等组合查「这张业务单的待办」，**不负责生成业务模块单据主键**。

### 1.6 命令袋 `FlowCommandContext` 字段归属速查

| 字段 | 层 |
|------|-----|
| `AppName` / `AppInstanceId` / `AppInstanceCode` | D 业务模块挂接 |
| `ProcessId` / `ProcessCode` / `Version` | A 流程设计定义（`ProcessId`=流程设计定义键） |
| `ProcessInstanceId` / `ActivityInstanceId` / `TaskId` | B 运转 |
| `UserId` / `UserName` / `CompanyId` / `StartUnit*` | C 人员组织 |
| `Conditions` / `ApprovalStatus` 等 | 命令载荷（非 ID） |

依据：`FlowCommandContext.cs` 源码英文分区（Business / Process / User）——其中 Business **仅对应本层 App\***，勿把 Process 段的 `ProcessId` 理解成业务模块键。

### 1.7 宿主常见传参对照（避免混用）

| 场景 | 应传 | 勿传成 |
|------|------|--------|
| 打开设计器 / 查 XML（按定义） | **流程设计定义键** `ProcessId` + `Version` | 流程实例 Id；勿把**定义行主键** `Id` 当 `ProcessId`（除非 API 明确按 PK） |
| 管理端按行删定义 | **定义行主键** `Id` | 仅有 `ProcessId` 时应用 `DeleteProcess(ProcessId, Version)` 语义 |
| 办理同意/驳回 | `TaskId`（+ 操作者 `UserId`） | `AssignedUserId`、`ActivityId` |
| 强制结束某次发起 | `ProcessInstanceId` | `AppInstanceId`、`ProcessId` |
| 打开业务模块表单 | `AppInstanceId`（+ `AppName`） | `ProcessInstanceId` |
| 子流程绑定（现行） | `subId`=被引用**定义行主键**；`subProcessId`=其**流程设计定义键** | 两个 Guid 对调 |

## 2. 已确认对齐（基线事实）

### 2.1 类型层：定义 / 实例表 PK·FK 已为 string

同类迁移覆盖：实例、活动实例、任务、转移实例、变量、表单、抄送等——实体与 `useRepo<*, string>` 已为 string。语义分层见 §1；**类型对齐 ≠ 语义不混用**。

### 2.2 引用子流程 XML 契约（现行）

| XML 属性 | 引擎字段 | 运行时用法 |
|----------|----------|------------|
| `sf:SubInfo/@subId` | `SubProcessDefId` | **Referenced**：`Processes.GetById(subId)` → **定义行 PK**（§1.2） |
| `sf:SubInfo/@subProcessId` | `SubProcessId` | 流程设计定义键 `process_id`；嵌套路径等 |
| `subProcessName` 等 | 展示/辅助 | 不参与主键解析 |

依据：`SubProcessConvertor`、`DefaultProcessModelFactory.CreateSubByNode` / `CreateSubInternal`。

### 2.3 宿主侧已对齐面

- `runtime.ts`、`processEdit`、designer context：流程/任务/实例 ID 为 `string`
- 列表跳转、设计器打开：`String(row…)` / `ProcessId`，无 number 主路径
- 本地 DTO / Controller：任务与实例 ID 多为 `string`；报表里的 `int` 为计数而非实体 ID

### 2.4 明确非迁移目标

状态码、网关方向、事件类型等 `byte`/`short`/`int`；AI/KB 的 `long` Id；表达式字面量 `TryParse`——不计入流程 PK 迁移缺口。

### P0 · 子流程 `subId` 在元素配置保存路径可能写错

| 项 | 内容 |
|----|------|
| 现象 | 选择器写出正确的 `subId=Id`、`subProcessId=ProcessId`；但 **元素配置弹窗**未承接 `draft.subId`，模型无 `subId` 字段；保存时用 `ProcessId` 兜底 |

### 5.1 D1 · 已拍板口径（2026-11-10）

**选定倾向：A（`subId` / `SubProcessDefId` = 被引用流程的定义行主键），并明确升版产品规则。**

| 规则 | 说明 |
|------|------|
| 绑定目标 | 父图引用子流程时，钉住**某一版定义行**（`wf_process.id`），运行时 `GetById`，与现行引擎一致 |
| **禁止自动升版** | 父流程升版本、或子流程侧另存新版本时，**不得**自动把父图里的子流程关联改到新定义行 |
| 跟版方式 | 须在**业务上明确提示**（例如：关联的子流程已有新版本 / 当前钉住的版本将过时）；**用户确认后**再更新关联（重写 `subId`/`subProcessId` 等到新定义行） |
| 与 B 的关系 | 不做「一律改存 `ProcessId` + 运行时 `GetByVersion` 隐式跟最新版」；那会破坏「钉住当时定义」与历史可追溯 |
| 仍待实施（非决策） | 宿主元素配置弹窗须写全 `subId`（P0）；升版检测与确认 UX 另案设计 |

### 5.2 D5 · 已拍板口径（2026-11-10）

**须分开看定义面与运转面，不能笼统「只认 ProcessId+Version」或「只认行 PK」。**

| 面 | 口径 |
|----|------|
| **运转实例表**（`wf_process_instance` / 活动实例 / 任务等） | **定位与关联只认各自主键**（如 `ProcessInstanceId`、`ActivityInstanceId`、`TaskId`）。实例上的 `ProcessId`/`Version` 等是**冗余**，便于给人看、对账、追溯「当时按哪套设计定义跑」，**不是**二次定位键 |
| **历史可追溯** | 实例钉住发起时的定义坐标冗余是自然的：事后查轨迹不依赖「当前最新版定义」；与 D1「子流程不自动跟版」同一哲学 |
| **定义管理 / 设计器** | 打开设计、按版本取 XML、发起前选定义：仍用 **流程设计定义键 `ProcessId` + `Version`**；管理端按行删除等继续可用**定义行主键**，但 UI/文档须标签分清（对照 §1.7） |

原草案 A/B（「产品只认 ProcessId+Version」vs「管理端保留行 PK」）**拆开后同时成立于不同层**，不再互斥二选一。

### 5.3 D4 · 已拍板口径（2026-11-10）

**为清晰起见：实体主键在属性层就用完整语义名，不因为「这是自己的主键」就简化成 `Id`。**

| 规则 | 说明 |
|------|------|
| 原则 | 袋内、外键、实体主键**同名同义**（如任务主键就叫 `TaskId`，不要实体上 `Id`、袋里 `TaskId` 两套叫法） |
| 动机 | string Guid 时代所有键外形相似；简化名 `Id` 放大与 `ProcessId`（流程设计定义键）等的混淆 |
| 实例侧示例（目标名，实施时再定映射） | `ProcessInstanceEntity` → `ProcessInstanceId`；`ActivityInstanceEntity` → `ActivityInstanceId`；`TaskEntity` / `TaskViewEntity` → `TaskId`；`TransitionInstanceEntity` → `TransitionInstanceId` |
| 定义侧注意 | `ProcessEntity` 上 **`ProcessId` 已被流程设计定义键占用**；定义行主键须另取清晰名（候选如 `ProcessDefId` / 与 XML `subId`→`SubProcessDefId` 对齐的命名），**禁止**继续用含糊的 `Id` 充当「唯一叫 Id 的字段」 |
| 列名 | 库列可仍为 `id`（或同步改名，实施时另定）；本决策针对 **C# / API / 前端字段语义名** |
| 与原 A/B/C | 不是「只改注释」：以实体主键改名为纲，顺带清 `DeleteInstanceInt`、`GetById(模糊 processId)` 等歧义 API；P2 扫尾纳入同一实施专题 |
| 仍待实施 | 大范围 rename + 兼容期策略（未在本审计展开） |

### 5.4 D3 · 已拍板口径（2026-11-10）

**选定：全面改（原选项 A），不只修 `GetTaskOfMine*`。**

| 规则 | 说明 |
|------|------|
| 范围 | 引擎 Manager / `WorkflowQueryService` 等凡以 `orderByDesc(() => *.Id)`（或等价按主键倒序）表达「最新 / 当前一条 / 列表时间序」的路径，**一律**改为时间字段排序 |
| 字段优先 | 待办可办语义优先 `ActivatedDateTime`；否则 `CreatedDateTime` / `EndedDateTime` 等按场景选定；需要稳定次序时可再加语义主键（改名后的 `TaskId` 等）作第二键 |
| 禁止 | 继续把 Guid 字符串主键倒序当作时间序 |
| 仍待实施 | 回归验证；稳定次序第二键（语义主键）可随 D4 一并加 |
