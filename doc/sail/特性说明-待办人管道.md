## 0. 已决决议（2026-11-01，定型口径）

下列决议已与宿主侧对齐，**实施与扩展一律遵守**；其余开放项见宿主讨论稿 §8。

| # | 主题 | 决议 |
|---|------|------|
| **R1** | **Group\* vs Unit\*** | **分组与单位正交，禁止再用 GroupId 冒充单位。** ① **`GroupId`/`GroupName`/`GroupRole`**：仅办理分组与组内身份；**Leave（组内抢办/协办/队长）只读 Group\***，不得读 Unit\*。② **`UnitId`/`UnitCode`/`UnitName`**（均为 **string，可空**）：企业单位展示/筛选/对接；落在 **Performer → 任务 / 活动实例 / TaskView**。空 Unit\* **允许**，不因此改 Group 行为、不阻断流转（除非某 Resolve Type 自定必填）。③ **流程实例**另增可选 **`StartUnitId`/`StartUnitCode`/`StartUnitName`**（发起单位，供实例列表筛），**不覆盖**节点任务上的 Unit\*。④ 语义重叠时（如按单位组内抢办）可 **双写** `GroupId=UnitId` 且仍填齐 Unit\*；分组≠单位时各写各的。算人仍由 Resolve/宿主 adapter 填字段。 |
| **R2** | **单轨定型** | 引擎定型期**收掉双轨**，不背历史债。用户任务运行时只走 Assignee 管道；`Definition` 仅 Role、旧会签通过率旁路、`Try*=false` 回落既有路径均属待删除债务。Legacy 推断若保留，仅作「导入旧 XML → 写成 ConfigPair」的一次性适配，**不得**作为运行时静默回落。 |
| **R3** | **主数据与用户身份键** | 完整组织/人员主数据在**宿主**（如 sleveen-admin `SysUser`/Org）接入。sailflow 只保留 Lookup 钩子与可覆盖骨架（`RoleGroup` / `UnitMap` / `JobRelative` 等），**不**把宿主用户表 schema 塞进 pure。可抽「适配套路」进 assignee，不抽组织树模型。**身份键约定：** `Performer.UserId` / 任务 **`AssignedUserId`** / Runner 当前用户 统一存 **用户编码**（如登录账号 `SysUser.Account`），**不**默认存 GUID 主键或人事工号；选人、派发、待办过滤须同一套编码。展示名走 `UserName`/`AssignedUserName`。 |
| **R4** | **缺配置 / 空办理人** | 运行时**禁止暗默认**（不得静默当发起人/管理员、不得回落旧路径假装成功）。未配置 ConfigPair、Type 未注册、算人为空且未**显式**配置 `Fallback`/`onEmpty` → **拒绝推进**；`WfExecutedResult` 带可识别 `ReasonCode`（如 `AssigneeConfigMissing` / `AssigneeEmpty`），前端可感知并引导回设计器修正。设计期预埋见 **R6**（写入 BPMN 后运行时只认落盘配置）。 |
| **R5** | **三线分离** | **待办人管道 ≠ 通知 ≠ 抄送**。通知走 [回调与事件](./特性设计-回调与事件.md) 的 **Task Notifier**；抄送为**独立通道**（产品表/自有事件），即使引擎日后内置抄送也不复用 Assignee ConfigPair，不把抄送人塞进办理 `Performer[]`。 |
| **R6** | **设计期默认 ConfigPair** | 属**流程设计能力**，非运行时策略。① **发布前**每个用户任务的 Resolve + Leave **均不得为空**（Type 空禁止发布）。② 实现：**预埋默认值 + 允许覆盖**（节点已写 ≫ 流程模板 ≫ 租户/项目设计默认 ≫ 产品出厂）。③ **产品出厂主流默认**：Resolve = **`ApproverPick`（发送人自选，勿与发起人自选 StarterPick 混淆）**；Leave = **`Collaborate`（协办）**。Leave Params 建议预埋显式完成条件（如全员 `completeRate: 1`）。④ pure **运行时不**补默认 Type；由设计器新增 UserTask / 新建流程 / 模板种子写入 XML。不同项目要抢办等 → 覆盖设计默认，不改引擎分支。 |
| **R7** | **组间完成条件** | `GroupRace` / `GroupCollaborate` / `Captain` 在「组内已判定完成」之后，组间规则与协办同级灵活：除 **`groupJoin=And|Or`** 快捷外，支持按 **已完成组的数量 / 比例**（Params 建议 `groupCompleteCount` / `groupCompleteRate`）。语义：And ≈ 全部组；Or ≈ 至少 1 组；Count/Rate = 达标组数或占比。未配 Count/Rate 时默认 **And**。组内人数/比例仍用既有 `completeCount`/`completeRate`（勿与组间参数混名）。 |
| **R8** | **队长模式细则** | Leave Type=`Captain`。① **关卡身份必须办理**（默认 `gateRoles=["Leader"]`，可配含副组长等）。② **其他人也可办理**（组员同样建待办，可提交意见/同意，但** alone 不能使组完成**）。③ **关卡身份办理完成后，该组视为完成并可进入组间判定 / 节点发送**（「队长办完可发送」）。④ 不采用「仅 Leader 有待办」；不采用「组员办完即算组完成」。 |
| **R9** | **同码覆盖诊断强制** | 业务/宿主以相同 Type 字符串后注册覆盖内置（或先前实现）时，**必须**可观测：① **注册时**打日志（Type、被覆盖实现、新实现）；② 运行诊断/结果侧能标明 **本 Type 已被覆盖**（如字段或日志含 Overridden / 实现类型名）。禁止静默覆盖导致「配置仍是 Collaborate、行为却是租户版」且无从排查。 |

**实施进度（2026-11-01）：** R1 Unit\*/StartUnit\* 实体+落库+Schema+FE 载荷已开工；R7 组间 Count/Rate 已进 `GroupLeaveHelper`；R9 Registry/Pipeline 覆盖诊断已落地；R6 设计器预埋 ApproverPick+Collaborate 已挂；R2/R4 显式 Resolve Type 空结果硬失败已进 Mediator（无显式 Type 时仍可回落 Specific/Definition，全量删双轨待续）。R3 Org Lookup、发布校验 API 待宿主续作。

## 1. 目标与非目标

### 1.1 目标

- 用户任务「谁来办 / 办完能否离开」有统一、可注册、可覆盖的管道。  
- **两维正交**：定范围（Resolve）× 办理模式（Leave）。  
- **三根基**可落地：传入即派发、办理模式（含组/身份/人数比例）、算人可注册。  
- 业务扩展只加 **string Type** 或同码覆盖，不 fork 调度内核。

### 1.2 非目标

- 不实现完整组织中台 / HR 主数据（JobRelative、UnitMap 只提供挂钩与内置骨架；真接在宿主，见 **R3**）。  
- 不把 Unit\* 卷入 Leave 判定；不用 GroupId 承载企业单位展示（见 **R1**）。  
- 不把芋道 `CandidateStrategy` 枚举或 Flowable Identity 原样搬进 pure。  
- 不做抄送人、通知人配置进 Assignee（**R5**：通知走 Notifier；抄送独立通道）。  
- 金额分流等走**网关**，禁止塞进算人 Type。

## 2. 概念（勿混用）

| 术语 | 含义 |
|------|------|
| **办理人 / 待办人** | 任务已指派的执行者（`AssignedUserId` 等） |
| **Performer** | 运行时办理人条目：`UserId` / `UserName` / **`Group*`**（办理分组）/ **`Unit*`**（企业单位，可空） |
| **ConfigPair** | `{ Type: string, Params: dict }`；**禁止用 enum 作分发键** |
| **时刻 A · Resolve** | **创建待办前**算出 `Performer[]` |
| **时刻 B · Leave** | **流出前**判定能否离开本节点 |
| **参与者 sf:Performer** | 设计器旧挂载；可由 Legacy 适配推断 ConfigPair，**不是**完整策略模型 |
| **NextPerformerType** | Runner 上 Specific/Definition/… 运行时选人来源；与 Resolve Type **不同维** |

易混：

- **发起人自选 (StarterPick)** ≠ **发送人/审批人自选 (ApproverPick)**（产品出厂默认是后者，见 **R6**）。  
- **A 不决定几人办完能走；B 不负责下一跳找谁**（下一跳是下一节点的 A，或 Specific 预填）。

## 3. 三根基与两大时刻

### 3.1 三根基（F1–F3）

| # | 根基 | 引擎要求 |
|---|------|----------|
| **F1** | 发送时传入办理人 | `Specific`（及已写入的 Starter/Approver 载荷）**透传**；已传列表不得静默改写 |
| **F2** | 办理模式完整 | Leave：`Race` / `Collaborate` / `GroupRace` / `GroupCollaborate` / `Captain`；完成可用 **人数或比例**；关卡按 **GroupRole 码集**，禁用 Bool `IsLeader` |
| **F3** | 算人可注册 | `IAssigneeResolver` 按 Type 注册；内置 + 业务后写覆盖；输出必须带齐组/身份字段约定 |

```text
F1 传入（含 Group* / Unit*；Unit 可空）
F2 LeaveJudge 执行（只读 Group*）
F3 Resolver 注册表
        │
        ▼
挂到 Client 时刻 A / B；业务只扩 Type 与 Params
```

### 3.2 生命周期

```text
到达用户任务
创建 Task 之前 ──► 时刻 A  TryResolveForTaskCreate
                         → Performer[]（含组别/身份）
                         → 创建待办 / 写入指派
某人办理提交后
（完成检查）   ──► 时刻 B  TryCanLeave
                         → Passed | NotPassed | Waiting
                         → Allow 则离开 → 下一节点再走 A
```

### 3.3 节点上两套 ConfigPair

| 配置对 | BPMN（现行） | 驱动 |
|--------|--------------|------|
| **AssigneeResolve** | `sf:assigneeResolve` | 时刻 A |
| **LeaveJudge** | `sf:leaveJudge` | 时刻 B |

**定型口径（R2/R4/R6）：** 用户任务须具备可解析的 ConfigPair（设计期显式配置，或按 R6 新建时预埋的默认值）。**发布前 Type 不得为空**。运行时缺配置 / 空结果且无显式 Fallback → **拒绝**，不得静默推断成功。Legacy（Performers / MultiSign）仅允许用于**导入期转写** ConfigPair，不作运行时回落。

## 4. 架构与分层

### 4.1 包边界（铁律）

```text
宿主 / 客户程序集
  → useAssigneeResolver / useLeaveJudge / useAssigneeBusinessCallback
sailflow.biz
  → UseBizAssignees()（UseAssignees + 产品样例 Type）
core/ext（可选）
  → 依赖表单/规则/HTTP 的扩展 Type
core/pure/assignee     ★ 重量：ConfigPair、Registry、内置（非 seal）、Pipeline、BPMN 适配
core/pure/engine       ★ 极薄：IAssigneePipeline、InvokeRequest、LeaveJudgeResult、Performer 字段
                         Mediator/AIM 仅调用，不认识具体 Type 实现
```

| 层 | 放什么 | **禁止** |
|----|--------|----------|
| **engine** | `IAssigneePipeline`；`AssigneeInvokeRequest` / `LeaveInvokeRequest`；`LeaveJudgeResult`；`Performer`(+Group*)；Mediator **一行**调用 | Type 注册表、内置策略、Params 解释、会签通过率业务改写 |
| **assignee** | ConfigPair；Resolver/LeaveJudge；Type 常量；Registry（后写覆盖）；Pipeline；`UseAssignees`；Legacy 适配 | MQ/脚本/NRules 等重依赖；被业务反向改调度 |
| **biz / 宿主** | `UseBizAssignees`；`Business.*` Type；同码覆盖内置 | fork NodeMediator / AIM 写 if-else 算人 |
| **FE** | 双 ConfigPair 面板；选人带 GroupId/GroupRole | 在前端「判定能否离开」 |

依赖方向：`biz/宿主 → assignee → engine`。engine **只持插槽**，由 `UseAssignees` 注入实现。

### 4.2 单轨定型（取代双轨）

- **目标态（R2）**：算人与流出**只**经 `IAssigneePipeline`；会签通过率迁入 LeaveJudge；`Definition` 仅 Role、AIM 旧通过率旁路删除或改为硬失败。  
- **现状债**：代码仍可能存在 `Try*=false` → 回落既有路径；定型实施时按 R2/R4 **收掉**，禁止继续加固双轨。  
- **禁止**：为「快速满足某业务」在 Mediator 再开第三条算人路径；禁止用双轨「兼容旧 BPMN」作为长期产品策略。

### 4.3 注册与覆盖规则

1. Type 比较：`OrdinalIgnoreCase` 字符串。  
2. 同 Type **后注册覆盖先注册**（业务可覆写内置 `Collaborate` 等）。  
3. 内置 Resolver/LeaveJudge 类 **禁止 `sealed`**；可继承后同码再注册。  
4. 未挂载管道：调用方应能感知需 `UseAssignees()`（勿静默空实现假装成功）。  
5. 宿主主数据：覆盖/继承内置 Lookup，不 fork 调度（**R3**）。

## 5. API 形态

### 5.1 engine 薄契约

```csharp
// saiflow.engine.Assignee
public interface IAssigneePipeline
{
    /// <returns>false = 本节点未由管道处理 → 调用方走既有逻辑（双轨）</returns>
    bool TryResolveForTaskCreate(AssigneeInvokeRequest request, out PerformerList performers);

    bool TryCanLeave(LeaveInvokeRequest request, out LeaveJudgeResult result);
}
```

| 类型 | 职责 |
|------|------|
| `AssigneeInvokeRequest` | ProcessId/Version、实例、Activity、Runner、`NextActivityPerformers`；**不含 Type 分发** |
| `LeaveInvokeRequest` | 实例/活动、主/子活动快照、Runner；Pipeline 自行读 Leave ConfigPair |
| `LeaveJudgeResult` | `Decision` = `Passed` / `NotPassed` / `Waiting`（string 常量 `LeaveDecisions`） |

ConfigPair **优先只存在于 assignee**：engine 请求尽量不带 Type，由 Pipeline + `BpmnAssigneeConfigReader` 读定义。

### 5.2 assignee 处理器

```csharp
public interface IAssigneeResolver
{
    string Type { get; }
    PerformerList Resolve(AssigneeResolveContext ctx);
}

public interface IActivityLeaveJudge
{
    string Type { get; }
    LeaveJudgeResult CanLeave(LeaveJudgeContext ctx);
}

public class ConfigPair
{
    public string Type { get; set; }
    public IDictionary<string, object?> Params { get; set; }
}
```

### 5.3 挂载 API

```csharp
builder.Services.UseAssignees();          // 或 UseBizAssignees()
// Build 后 / 对 client：
client.useAssigneeResolver(new MyResolver());
client.useLeaveJudge(new MyLeaveJudge());
client.useAssigneeBusinessCallback(new MyCallback()); // Params.callback → 注册表
```

委托重载：`useAssigneeResolver(type, Func<…>)` / `useLeaveJudge(type, Func<…>)`。

### 5.4 Performer 载荷合同

```text
UserId      必填；用户编码（如登录账号，见 R3）；非 GUID 主键默认
UserName    建议（展示名）
── 办理分组（Leave 用；R1）──
GroupId     组别标识（扁平时可空或同组常量）；禁止单独拿来当「企业单位展示」
GroupName   组别展示名（可选）
GroupRole   组内身份码（默认 Member）
── 企业单位（展示/筛选；R1；均可空）──
UnitId      单位稳定键（string）
UnitCode    单位业务编码（string）
UnitName    单位展示名（string）
```

**流程实例（发起单位，可选）：** `StartUnitId` / `StartUnitCode` / `StartUnitName` — 与任务级 Unit\* 分离，不覆盖节点单位。

**GroupRole 内置码**（`GroupRoles`）：`Organizer` · `Leader` · `DeputyLeader` · `Member`。  
可扩展（如 `Secretary`）；Leave 用 `gateRoles` 引用，**禁止** Bool 是否组长。

Resolver 输出：有组语义须填齐 Group\*；有单位语境建议填齐 Unit\*（允许空）。**禁止**靠逗号拼接 `AssignedUserIds` 事后猜组；**禁止** Leave 读 Unit\*。

#### 5.6.1 与讨论稿草稿的关键差异

> **定型注意（R2/R4）：** 下表描述 **S0–S4 落地时** 的双轨实现。目标态为单轨 + 缺配置拒绝；后续改代码时删除回落，勿再按「双轨长期保留」扩展。

| 讨论稿草稿 | 真实实现（S4 时点） | 说明 |
|------------|----------|------|
| `ResolveForTaskCreate` / `CanLeave` 直接返回 | **`TryResolveForTaskCreate` / `TryCanLeave` → `bool`** | `false` = 未由管道处理 → Mediator/AIM **双轨回落**既有逻辑（**待按 R2 收掉**） |
| 未挂载则 `GetAssigneePipelineRequired()` 硬失败 | 调用点先读 **`Sail.AssigneePipeline`**，null 或 Try=false 则回落 | `GetAssigneePipelineRequired()` 仍保留，供必须强制管道的场景 |
| Registry 仅 `Get*` 抛错 | 另有 **`TryGetResolver` / `TryGetLeaveJudge`**；Pipeline 用 Try | 无 Type / 未注册 → 不炸主路径 |
| Resolve 空列表仍算「已处理」 | **`resolved.Count == 0` → return false** | Specific/StarterPick 无数据、RoleGroup 空集交回既有路径 |
| ConfigPair 仅 assignee | engine **Activity** 存 Type/Params 字符串；assignee **读**定义后分发 | Convertor 解析 BPMN；策略实现仍在 assignee |
| 业务回调未单列 | **`useAssigneeBusinessCallback`** + `AssigneeBusinessCallbackRegistry` | `BusinessCallback` + `Params.callback` |
| Type 常量仅草稿子集 | 另有 `UnitMap` / `JobRelative` / `BusinessCallback` / `Expression` / `Fallback` | `AssigneeTypeCodes.cs` |
| 草案独立 `GroupRoles.cs` | **合入 `AssigneeTypeCodes.cs`** | — |

#### 5.6.2 engine 契约与 DTO（现行代码）

```csharp
// saiflow.engine.Assignee.IAssigneePipeline
bool TryResolveForTaskCreate(AssigneeInvokeRequest request, out PerformerList performers);
bool TryCanLeave(LeaveInvokeRequest request, out LeaveJudgeResult result);

// SailClient
IAssigneePipeline AssigneePipeline { get; }
SailClient useAssigneePipeline(IAssigneePipeline pipeline);
IAssigneePipeline GetAssigneePipelineRequired(); // 未挂载抛错，提示 UseAssignees / UseBizAssignees
```

| 类型 | 字段（现行） |
|------|----------------|
| `AssigneeInvokeRequest` | `ProcessId` · `Version` · `ProcessInstanceId?` · `ActivityId` · `ActivityCode` · `Runner` · `NextActivityPerformers` |
| `LeaveInvokeRequest` | `ProcessInstanceId` · `ActivityInstanceId` · `ProcessId` · `Version` · `CurrentActivityInstance` · `MainActivityInstance` · `ChildActivityInstances` · `Runner` |
| `LeaveJudgeResult` | `Decision`（`LeaveDecisions.Passed` / `NotPassed` / `Waiting`）· `ReasonCode` · `Message` · `Allow` |

`Performer`（`engine.Common`）：现行已有 `UserId` · `UserName` · **`Group*`**；**目标态（R1）**另增 **`UnitId`/`UnitCode`/`UnitName`**。任务 / 活动实例 / `TaskViewEntity` 从 Performer 带入 Group\* 与 Unit\*；流程实例带可选 **StartUnit\***。代码未齐前以本节为合同。

## 6. 内置 Type 清单与场景映射

### 6.1 时刻 A · Resolve（定范围 1–9）

| 场景 | Type | 落层 | Params 要点 |
|------|------|------|-------------|
| F1 传入 | `Specific` | 内置 | Runner 已传列表 |
| 1 固定人 | `FixedUsers` | 内置 | `users[]` |
| 2 流程相对 | `ProcessRelative` | 内置 | `relative`: Starter / PrevSender / … |
| 3 岗位相对 | `JobRelative` | 内置骨架 → 接 HR | `jobCode`；可 override 查找 |
| 4/6 单位 | `UnitMap` | 内置骨架 → 接映射 | `unitField` + maps；填 **Unit\***；若需按单位组内抢办再双写 `GroupId=UnitId` |
| 5 群组/角色 | `RoleGroup` | 内置 | `roleIds[]`（经资源服务扩用户） |
| 7 缺省 | `Fallback` | 内置 | `onEmpty` + 可选下一 Type |
| 8 发起人自选 | `StarterPick` | 内置 + FE | `required`、`allowMultiGroup` |
| 发送人/审批人自选 | `ApproverPick` | 内置 + FE；**出厂设计默认（R6）** | 办理页写入下一跳载荷 |
| 9 业务动态 | `BusinessCallback` 或 `Business.*` | 回调注册表 / 业务类 | 如 `Business.ClassStudents` |
| 表达式 | `Expression` | 内置 | 从 Conditions 取值 |

第一维坐标系（扩展时先归类，再起 Type 名）：

```text
绝对钉死     → FixedUsers · RoleGroup
流程相对     → ProcessRelative
组织/人力    → JobRelative · UnitMap · Fallback
运行时补全   → StarterPick · ApproverPick · Specific
业务相对     → BusinessCallback / Business.*
```

### 6.2 时刻 B · Leave（办理模式）

| 模式 | Type | Params 要点 |
|------|------|-------------|
| 抢办 | `Race` | 完成≈1；可选认领语义 |
| 协办 | `Collaborate` | 扁平：`completeCount` / `completeRate` |
| 组内抢办 | `GroupRace` | 按 GroupId；组内 1 人；组间见 **R7** |
| 组内协办 | `GroupCollaborate` | 组内 `completeCount`/`completeRate`；组间见 **R7** |
| 队长 | `Captain` | **R8**：关卡必办、组员可办、关卡办完组完成；`gateRoles` 默认 `["Leader"]`；组间见 **R7** |

**组间（R7）：** `groupJoin=And|Or` 快捷，或 `groupCompleteCount` / `groupCompleteRate`（已完成组数/占比）。默认 And。与组内参数分名，避免混用。

### 6.3 组合场景（扩展时的正确拆法）

**多单位发起人自选 + 组内抢办 + 组间 AND**（现场高频「怪需求」）：

```text
Resolve: StarterPick（或 Specific 已带矩阵）
  → Performer[] 每行：
       UnitId/Code/Name = 各单位（展示/筛选）
       GroupId = UnitId（本场景分组=单位，双写）
       GroupRole = …
Leave:   GroupRace + groupJoin=AND   ← 只读 GroupId
```

**错误方向：** 只把单位塞进 GroupId、待办列表再靠 Group 猜单位；或在 AIM 写「按单位拆任务」特例。  
**正确方向：** F1 结构化列表带齐 Unit\* + Group\*；Leave 只按 Group；展示只读 Unit\*。

**班级学员签字（场景 9）：**

```text
Type = Business.ClassStudents（biz 样例）
Params.classIdField → 查学员
  → Performer[]：GroupId=班级；Unit*=学校/法人（可与班级不同）；均可按需留空字段
可继承 LookupStudents；勿改 engine
```

同码覆盖样例：biz `TenantCollaborateLeaveJudge` 覆盖 `Collaborate`。

## 7. 扩展指引（防走错）

### 7.1 允许

| 需求 | 做法 |
|------|------|
| 新定范围 | 新 `IAssigneeResolver`，唯一 Type 字符串，`useAssigneeResolver` |
| 改内置行为 | 继承非 seal 内置类，或同 Type 重新注册 |
| 接学籍/订单子表 | `Business.*` 或 `useAssigneeBusinessCallback` |
| 接 HR/单位主数据 | 扩展 `JobRelative` / `UnitMap`（override 查找），主数据在宿主 |
| 自定义完成公式 | 新 `IActivityLeaveJudge` 或覆盖 Leave Type |
| 表达式/规则算人 | `Expression` / 未来 ext 的 RuleSet Type，**仍是 Resolve Type** |

### 7.2 禁止

| 反模式 | 原因 |
|--------|------|
| 在 `NodeMediator` / AIM 增加「若流程码=XX 则…」算人 | 破坏薄调用与可测性 |
| 把定范围 + 抢办揉成**一个**下拉/一个 Type | 两维正交被破坏，组合场景无法表达 |
| Resolve/Leave Type 改成 **C# enum** 分发 | 业务无法无感加码；违反 string 铁律 |
| 内置类 `sealed` | 无法继承覆盖 |
| 用 Bool `IsLeader` 替代 GroupRole | 关卡身份无法扩展 |
| 空办理人静默当发起人/管理员 | 违反 **R4**；须显式 Fallback 或拒绝 |
| 缺 ConfigPair 时回落 Definition/旧会签 | 违反 **R2**；定型后应拒绝 |
| 用 GroupId 承载企业单位展示/筛待办 | 违反 **R1**；单位用 Unit\*；分组才用 Group\* |
| LeaveJudge 读取 Unit\* 做完成判定 | 违反 **R1**；Leave 只认 Group\* |
| 用实例 StartUnit\* 覆盖节点任务 Unit\* | 违反 **R1**；发起单位与节点单位分离 |
| 抄送/通知复用 Assignee ConfigPair | 违反 **R5**；语义污染 |
| 照搬芋道策略数字枚举进 pure | 与 Sail 载荷/身份模型不兼容 |

### 7.3 空结果与未命中（R4）

| 情况 | 行为 |
|------|------|
| 无 Resolve/Leave ConfigPair（且无设计期默认已写入） | **拒绝**；ReasonCode 如 `AssigneeConfigMissing`；前端可感知 |
| Type 未注册 | **拒绝**；勿回落旧路径 |
| Resolve 空集 / 单位未命中 | **拒绝**，除非建模者**显式**配置 `Fallback` / `onEmpty` |
| 新建用户任务 / 新流程 / 模板种子 | 按 **R6** 写入默认：`ApproverPick` + `Collaborate`（可被项目/模板覆盖） |
| **发布前** Type 为空 | **禁止发布**（R6）；与运行时拒绝双保险 |

部署/发布校验是 Host/设计器责任；**不能**替代运行时拒绝政策（R4）。

### 7.4 诊断（**R9：同码覆盖强制**）

调试应能看到：Resolve/Leave 的 Type+Params、命中人数、Group\*、Unit\*、Leave Decision+ReasonCode。  
**同码覆盖必须可观测**（注册日志 + 运行时标明 Overridden/实现类型）；不得静默覆盖。缺其它诊断时优先补日志/结果字段，而不是加旁路。

## 8. 设计原则（摘要）

1. Client 两大时刻契约优先于一切旁路脚本。  
2. 三根基落在契约上：F1→A 透传；F2→B；F3→A 注册表。  
3. 策略配置与 Runner Specific **分离又协作**（Specific 是 A 的一种来源）。  
4. 定范围 × 办理模式正交 → **两套** ConfigPair。  
5. 单一真源在流程定义（BPMN），不靠前端临时状态。  
6. 算人与流出必须可解释。  
7. 空办理人 / 缺配置：**拒绝**（R4）；设计期预埋 **ApproverPick + Collaborate**（R6），发布前非空。  
8. **Group\* ≠ Unit\***（R1）：Leave 只读 Group；展示/筛选用 Unit\*（可空）；实例可选 StartUnit\*。  
9. 扩展只挂注册表；Type 仅 string；后写覆盖；内置不 seal；主数据在宿主（R3）。  
10. 待办 / 通知 / 抄送三线分离（R5）。
