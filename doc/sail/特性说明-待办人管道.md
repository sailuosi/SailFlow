## 0. 已决决议（定型口径）

下列决议已与宿主侧对齐，**实施与扩展一律遵守**；其余开放项见宿主讨论稿 §8。R1–R9：2026-11-01；**R10**：2026-11-04。

| # | 主题 | 决议 |
|---|------|------|
| **R1** | **Group\* vs Unit\*** | **分组与单位正交，禁止再用 GroupId 冒充单位。** ① **`GroupId`/`GroupName`/`GroupRole`**：仅办理分组与组内身份；**Leave（组内抢办/协办/队长）只读 Group\***，不得读 Unit\*。② **`UnitId`/`UnitCode`/`UnitName`**（均为 **string，可空**）：企业单位展示/筛选/对接；落在 **Performer → 任务 / 活动实例 / TaskView**。空 Unit\* **允许**，不因此改 Group 行为、不阻断流转（除非某 Resolve Type 自定必填）。③ **流程实例**另增可选 **`StartUnitId`/`StartUnitCode`/`StartUnitName`**（发起单位，供实例列表筛），**不覆盖**节点任务上的 Unit\*。④ 语义重叠时（如按单位组内抢办）可 **双写** `GroupId=UnitId` 且仍填齐 Unit\*；分组≠单位时各写各的。算人仍由 Resolve/宿主 adapter 填字段。 |
| **R2** | **单轨定型** | 引擎定型期**收掉双轨**，不背历史债。用户任务运行时只走 Assignee 管道；`Definition` 仅 Role、旧会签通过率旁路、`Try*=false` 回落既有路径均属待删除债务。Legacy 推断若保留，仅作「导入旧 XML → 写成 ConfigPair」的一次性适配，**不得**作为运行时静默回落。 |
| **R3** | **主数据与用户身份键** | 完整组织/人员主数据在**宿主**（如 sleveen-admin `SysUser`/Org）接入。sailflow 只保留 Lookup 钩子与可覆盖骨架（`RoleGroup` / `UnitMap` / `JobRelative` 等），**不**把宿主用户表 schema 塞进 pure。可抽「适配套路」进 assignee，不抽组织树模型。**身份键约定：** `Performer.UserId` / 任务 **`AssignedUserId`** / Runner 当前用户 统一存 **用户编码**（如登录账号 `SysUser.Account`），**不**默认存 GUID 主键或人事工号；选人、派发、待办过滤须同一套编码。展示名走 `UserName`/`AssignedUserName`。 |
| **R4** | **缺配置 / 空办理人** | 运行时**禁止暗默认**（不得静默当发起人/管理员、不得回落旧路径假装成功）。未配置 ConfigPair、Type 未注册、算人为空且未**显式**换人/跳过策略 → **拒绝推进**；`WfExecutedResult` 带可识别 `ReasonCode`（如 `AssigneeConfigMissing` / `AssigneeEmpty`），前端可感知并引导回设计器修正。设计期预埋见 **R6**。**产品层：** 节点 `sf:NodePolicy.assignEmptyHandlerType` 默认 **`=2` 拒绝**（细义=本条 R4，**不是**默认 `RejectProcess` 整单结束）；仅显式 `=1/3/4` 才允许跳过/指定人/转管理员。管道内 `Fallback`（`primary`/`fallback`）是换人 Resolve，**≠** NodePolicy 空人策略；设计器旧 `onEmpty` 文案须与真实 Params 对齐或废弃。见 [todo-产品缺口.md](./todo-产品缺口.md) **§A**。 |
| **R5** | **三线分离** | **待办人管道 ≠ 通知 ≠ 抄送**。通知走 [回调与事件](./特性设计-回调与事件.md) 的 **Task Notifier**；抄送为**独立通道**（产品表/自有事件），即使引擎日后内置抄送也不复用 Assignee ConfigPair，不把抄送人塞进办理 `Performer[]`。 |
| **R6** | **设计期默认 ConfigPair** | 属**流程设计能力**，非运行时策略。① **发布前**每个用户任务的 Resolve + Leave **均不得为空**（Type 空禁止发布）。② 实现：**预埋默认值 + 允许覆盖**（节点已写 ≫ 流程模板 ≫ 租户/项目设计默认 ≫ 产品出厂）。③ **产品出厂主流默认**：Resolve = **`ApproverPick`（发送人自选，勿与发起人自选 StarterPick 混淆）**；Leave = **`Collaborate`（协办）**。Leave Params 建议预埋显式完成条件（如全员 `completeRate: 1`）。④ pure **运行时不**补默认 Type；由设计器新增 UserTask / 新建流程 / 模板种子写入 XML。不同项目要抢办等 → 覆盖设计默认，不改引擎分支。 |
| **R7** | **组间完成条件** | `GroupRace` / `GroupCollaborate` / `Captain` 在「组内已判定完成」之后，组间规则与协办同级灵活：除 **`groupJoin=And|Or`** 快捷外，支持按 **已完成组的数量 / 比例**（Params 建议 `groupCompleteCount` / `groupCompleteRate`）。语义：And ≈ 全部组；Or ≈ 至少 1 组；Count/Rate = 达标组数或占比。未配 Count/Rate 时默认 **And**。组内人数/比例仍用既有 `completeCount`/`completeRate`（勿与组间参数混名）。 |
| **R8** | **队长模式细则** | Leave Type=`Captain`。① **关卡身份必须办理**（默认 `gateRoles=["Leader"]`，可配含副组长等）。② **其他人也可办理**（组员同样建待办，可提交意见/同意，但** alone 不能使组完成**）。③ **关卡身份办理完成后，该组视为完成并可进入组间判定 / 节点发送**（「队长办完可发送」）。④ 不采用「仅 Leader 有待办」；不采用「组员办完即算组完成」。 |
| **R9** | **同码覆盖诊断强制** | 业务/宿主以相同 Type 字符串后注册覆盖内置（或先前实现）时，**必须**可观测：① **注册时**打日志（Type、被覆盖实现、新实现）；② 运行诊断/结果侧能标明 **本 Type 已被覆盖**（如字段或日志含 Overridden / 实现类型名）。禁止静默覆盖导致「配置仍是 Collaborate、行为却是租户版」且无从排查。 |
| **R10** | **后置策略三轨 + 自动审批锚点** | **定范围（Resolve）≠ 后置处置 ≠ 自动审批执行。** ① 空人 / 与发起人相同 / 重复已办 / 列表去重等 **禁止**再注册成 `IAssigneeResolver` Type；挂 **Filter 链**（有人）与 **EmptyAction**（空集选型）。② 「自动跳过/自动通过」**不**靠改成假办理人列表完成主语义；时刻 A 最多打 **锚点**，**发送主路径成功后**由普通 **Job** 苛刻复核并代办 `Run`；条件不满足或不触发，或触发失败 → **回落手动审批**（ReasonCode 可区分）。③ **F1** 改为：Specific 默认透传可追踪；是否改写 **交给各 Filter 自决**，管道须提供 `PerformerSource` 等上下文（见 §11.4）。④ 注册 API 收拢为 **`UseAssign` / `UseAssignees`** 子 Builder：`AddResolver<T>`（优先泛型）、`AddFilter`、`AddEmptyAction` 等，**注册顺序 = Filter 执行顺序**（与 ASP.NET Startup / Middleware 同心智）。⑤ Mediator 仍只调 `IAssigneePipeline`；Leave 不进 Filter 链。现行 Host `NodePolicyAssigneePipeline` + `__sail_policy_skip__` 为过渡实现，目标收敛到本条。细则见 **§11**。 |

**实施进度（2026-11-01）：** R1–R9 主干已落地。宿主（sleveen）：设计器保存前强制校验；身份键 `SysUser.Account`；UnitMap→Org/User；**RoleGroup→AuthVisitorBag/AuthDutyItem**（宿主无 SysRole 表）；JobRelative→maps 或访客袋 Code 占位；Claims 覆盖 Runner；办理条跳转；业务 API `[Authorize]`。真 HR 编制表仍可后接改 `LookupByJob`。

**R10 进度（2026-11-04）：** 口径已拍板；**引擎侧首包已落地**——`UseAssign` / `AddResolver<T>` / `AddFilter` / `AddEmptyAction`、`RejectEmptyAction`、`DedupUsersFilter`、锚点入 `wf_hook_outbox`（Kind=`AssigneeAutoApprove`）、`AutoApproveAnchorWorker` Drain。Host `NodePolicyAssigneePipeline` 仍为过渡，待收敛到 Filter/EmptyAction；同事务 kit 入队与同人 Filter 可后续补。  
**Host 互斥（须知）：** 引擎空集默认 `RejectEmptyAction` **抛** `WfAssigneeException(AssigneeEmpty)`，不再 `return false`。装饰器若仍假定「内层 false → 再套 NodePolicy 空人」，会吃不到 `assignEmptyHandlerType=1/3/4`。现行过渡：**装饰器 catch `AssigneeEmpty` 后再走 NodePolicy**；目标改为 `EmptyActionSelector` / Filter，去掉 catch。

## 1. 目标与非目标

### 1.1 目标

- 用户任务「谁来办 / 办完能否离开」有统一、可注册、可覆盖的管道。  
- **两维正交**：定范围（Resolve）× 办理模式（Leave）。  
- **三根基**可落地：传入即派发、办理模式（含组/身份/人数比例）、算人可注册。  
- 业务扩展只加 **string Type** 或同码覆盖，不 fork 调度内核。

### 1.2 非目标

- 不实现完整组织中台 / HR 主数据（JobRelative、UnitMap 只提供挂钩与内置骨架；真接在宿主，见 **R3**）。  
- 不把 Unit\* 卷入 Leave 判定；不用 GroupId 承载企业单位展示（见 **R1**）。  
- 不把芋道 `CandidateStrategy` 枚举或 Flowable Identity 原样搬进 pure。  
- 不做抄送人、通知人配置进 Assignee（**R5**：通知走 Notifier；抄送独立通道）。  
- 金额分流等走**网关**，禁止塞进算人 Type。

## 2. 概念（勿混用）

| 术语 | 含义 |
|------|------|
| **办理人 / 待办人** | 任务已指派的执行者（`AssignedUserId` 等） |
| **Performer** | 运行时办理人条目：`UserId` / `UserName` / **`Group*`**（办理分组）/ **`Unit*`**（企业单位，可空） |
| **ConfigPair** | `{ Type: string, Params: dict }`；**禁止用 enum 作分发键** |
| **时刻 A · Resolve** | **创建待办前**算出 `Performer[]` |
| **时刻 A′ · 后置** | Resolve 之后：Filter 链（有人）/ EmptyAction（空集）；可改人与/或打**自动审批锚点**（**R10** / §11） |
| **时刻 B · Leave** | **流出前**判定能否离开本节点 |
| **自动审批锚点** | 发送主路径成功后由 Job 苛刻复核并代办；≠ 改 Performer 假人（**R10**） |
| **参与者 sf:Performer** | 设计器旧挂载；可由 Legacy 适配推断 ConfigPair，**不是**完整策略模型 |
| **NextPerformerType** | Runner 上 Specific/Definition/… 运行时选人来源；与 Resolve Type **不同维** |
| **PerformerSource** | 当前列表来源标记（Specific / Resolver(Type) / Mixed…）；供 Filter 自决是否改写（**R10**） |

易混：

- **发起人自选 (StarterPick)** ≠ **发送人/审批人自选 (ApproverPick)**（产品出厂默认是后者，见 **R6**）。  
- **A 不决定几人办完能走；B 不负责下一跳找谁**（下一跳是下一节点的 A，或 Specific 预填）。  
- **Resolve Type** ≠ **空人/同人/去重策略**（后者是后置 Filter/EmptyAction，见 **R10**）。  
- **管道 `Fallback`（再算人）** ≠ **EmptyAction / NodePolicy 空人**（处置空集：拒绝/指定人/管理员/打锚点）。  
- **打锚点** ≠ **在时刻 A 内嵌套 RunProcess**（禁止；由发送后 Job 执行）。

## 3. 三根基与两大时刻

### 3.1 三根基（F1–F3）

| # | 根基 | 引擎要求 |
|---|------|----------|
| **F1** | 发送时传入办理人 | `Specific`（及已写入的 Starter/Approver 载荷）**默认透传且可追踪**（标注 `PerformerSource`）。**是否改写不由全局禁令写死**，交给后置 Filter 自决（须有足够上下文；改写须可诊断）。内置默认 Filter 建议不碰 Specific；产品 Filter 可显式改写（**R10**） |
| **F2** | 办理模式完整 | Leave：`Race` / `Collaborate` / `GroupRace` / `GroupCollaborate` / `Captain`；完成可用 **人数或比例**；关卡按 **GroupRole 码集**，禁用 Bool `IsLeader` |
| **F3** | 算人可注册 | `IAssigneeResolver` 按 Type 注册；内置 + 业务后写覆盖；输出必须带齐组/身份字段约定 |

```text
F1 传入（含 Group* / Unit*；Unit 可空；Source 可追踪）
F2 LeaveJudge 执行（只读 Group*）
F3 Resolver 注册表 +（目标）Filter / EmptyAction 注册（UseAssign）
        │
        ▼
挂到 Client 时刻 A / A′ / B；业务扩 Type、Filter、EmptyAction，不改 Mediator
```

### 3.2 生命周期

```text
到达用户任务
创建 Task 之前 ──► 时刻 A   TryResolveForTaskCreate
                         → ConfigPair → Resolver → Performer[] | 空
              ──► 时刻 A′  （目标态 R10）
                         → 空 → EmptyAction（拒绝 / 换人 / 打锚点…）
                         → 非空 → Filters[] 有序（改人 / 去重 / 打锚点…）
                         → 创建待办 / 写入指派（主路径继续）
发送命令成功后
（主事务已提交）──► Job 认领自动审批锚点（苛刻前置）
                         → 通过则代办 Run；否则不触发或失败回落手动
某人办理提交后
（完成检查）   ──► 时刻 B  TryCanLeave
                         → Passed | NotPassed | Waiting
                         → Allow 则离开 → 下一节点再走 A
```

### 3.3 节点上两套 ConfigPair

| 配置对 | BPMN（现行） | 驱动 |
|--------|--------------|------|
| **AssigneeResolve** | `sf:assigneeResolve` | 时刻 A |
| **LeaveJudge** | `sf:leaveJudge` | 时刻 B |

**定型口径（R2/R4/R6）：** 用户任务须具备可解析的 ConfigPair（设计期显式配置，或按 R6 新建时预埋的默认值）。**发布前 Type 不得为空**。运行时缺配置 / 空结果且无显式 Fallback → **拒绝**，不得静默推断成功。Legacy（Performers / MultiSign）仅允许用于**导入期转写** ConfigPair，不作运行时回落。

## 4. 架构与分层

### 4.1 包边界（铁律）

```text
宿主 / 客户程序集
  → useAssigneeResolver / useLeaveJudge / useAssigneeBusinessCallback
sailflow.biz
  → UseBizAssignees()（UseAssignees + 产品样例 Type）
core/ext（可选）
  → 依赖表单/规则/HTTP 的扩展 Type
core/pure/assignee     ★ 重量：ConfigPair、Registry、内置（非 seal）、Pipeline、BPMN 适配
core/pure/engine       ★ 极薄：IAssigneePipeline、InvokeRequest、LeaveJudgeResult、Performer 字段
                         Mediator/AIM 仅调用，不认识具体 Type 实现
```

| 层 | 放什么 | **禁止** |
|----|--------|----------|
| **engine** | `IAssigneePipeline`；`AssigneeInvokeRequest` / `LeaveInvokeRequest`；`LeaveJudgeResult`；`Performer`(+Group*)；Mediator **一行**调用 | Type 注册表、内置策略、Params 解释、会签通过率业务改写 |
| **assignee** | ConfigPair；Resolver/LeaveJudge；Type 常量；Registry（后写覆盖）；Pipeline；`UseAssignees`；Legacy 适配 | MQ/脚本/NRules 等重依赖；被业务反向改调度 |
| **biz / 宿主** | `UseBizAssignees`；`Business.*` Type；同码覆盖内置 | fork NodeMediator / AIM 写 if-else 算人 |
| **FE** | 双 ConfigPair 面板；选人带 GroupId/GroupRole | 在前端「判定能否离开」 |

依赖方向：`biz/宿主 → assignee → engine`。engine **只持插槽**，由 `UseAssignees` 注入实现。

### 4.2 单轨定型（取代双轨）

- **定型（R2）**：算人与流出**只**经 `IAssigneePipeline`；会签通过率迁入 LeaveJudge。  
- **现状（Resolve · 时刻 A）**：`NodeMediator.GenerateActivityAssignedUserInfo` 已挂管道时失败 → **`WfAssigneeException` + ReasonCode**（缺配置 / 空人）；**未挂管道** → `GetAssigneePipelineRequired()` 硬失败。**禁止**回落 Specific / Definition / Single。  
- **现状（Leave · 时刻 B）**：已挂管道时 `TryCanLeave` 失败 → **`LeaveConfigMissing`**；**仅未挂管道**时 AIM 仍保留旧会签通过率（兼容债，定型后应删或硬失败）。  
- **禁止**：为「快速满足某业务」在 Mediator 再开第三条算人路径；禁止用双轨「兼容旧 BPMN」作为长期产品策略。

### 4.3 注册与覆盖规则

1. Type 比较：`OrdinalIgnoreCase` 字符串。  
2. 同 Type **后注册覆盖先注册**（业务可覆写内置 `Collaborate` 等）。  
3. 内置 Resolver/LeaveJudge 类 **禁止 `sealed`**；可继承后同码再注册。  
4. 未挂载管道：调用方应能感知需 `UseAssignees()`（勿静默空实现假装成功）。  
5. 宿主主数据：覆盖/继承内置 Lookup，不 fork 调度（**R3**）。

## 5. API 形态

### 5.1 engine 薄契约

```csharp
// saiflow.engine.Assignee
public interface IAssigneePipeline
{
    /// <returns>
    /// false = 管道未处理（无 ConfigPair / Type 未注册等）。
    /// 已挂管道时 Mediator/AIM 按 R2/R4 拒绝，不再回落 Definition/旧会签。
    /// 空集且走 RejectEmptyAction 时可能直接抛 WfAssigneeException(AssigneeEmpty)。
    /// </returns>
    bool TryResolveForTaskCreate(AssigneeInvokeRequest request, out PerformerList performers);

    bool TryCanLeave(LeaveInvokeRequest request, out LeaveJudgeResult result);
}
```

| 类型 | 职责 |
|------|------|
| `AssigneeInvokeRequest` | ProcessId/Version、实例、Activity、Runner、`NextActivityPerformers`；**不含 Type 分发** |
| `LeaveInvokeRequest` | 实例/活动、主/子活动快照、Runner；Pipeline 自行读 Leave ConfigPair |
| `LeaveJudgeResult` | `Decision` = `Passed` / `NotPassed` / `Waiting`（string 常量 `LeaveDecisions`） |

ConfigPair **优先只存在于 assignee**：engine 请求尽量不带 Type，由 Pipeline + `BpmnAssigneeConfigReader` 读定义。

### 5.2 assignee 处理器

```csharp
public interface IAssigneeResolver
{
    string Type { get; }
    PerformerList Resolve(AssigneeResolveContext ctx);
}

public interface IActivityLeaveJudge
{
    string Type { get; }
    LeaveJudgeResult CanLeave(LeaveJudgeContext ctx);
}

public class ConfigPair
{
    public string Type { get; set; }
    public IDictionary<string, object?> Params { get; set; }
}
```

### 5.3 挂载 API



### 5.6 真实实现侧（对照讨论稿 §11.3，已落地）

#### 5.6.1 与讨论稿草稿的关键差异

> **定型（R2/R4，现行）：** Resolve **单轨**；已挂管道失败即拒绝。Leave 在**未挂管道**时仍有旧会签通过率债（见 §4.2）。勿再按「双轨长期保留」扩展。

| 讨论稿草稿 | 真实实现（现行） | 说明 |
|------------|----------|------|
| `ResolveForTaskCreate` / `CanLeave` 直接返回 | **`TryResolve*` / `TryCanLeave` → `bool`** | 已挂管道：`false` 或空人 Reject → Mediator/AIM **拒绝**（ReasonCode）；Resolve **未挂** → `GetAssigneePipelineRequired()` |
| 未挂载则硬失败 | Resolve：**必须**挂管道；Leave：未挂时仍可读旧通过率 | Leave 旧旁路为待删债 |
| Registry 仅 `Get*` 抛错 | 另有 **`TryGetResolver` / `TryGetLeaveJudge`**；Pipeline 用 Try | 无 Type / 未注册 → `Try*` 返回 false（再由调用点拒绝） |
| Resolve 空列表仍算「已处理」 | 空集 → **EmptyAction**（默认 `RejectEmptyAction` **抛** `AssigneeEmpty`）；Filter 后再空同理 | Host 装饰器须 catch 或改用 `EmptyActionSelector`（§11.6） |
| ConfigPair 仅 assignee | engine **Activity** 存 Type/Params 字符串；assignee **读**定义后分发 | Convertor 解析 BPMN；策略实现仍在 assignee |
| 业务回调未单列 | **`useAssigneeBusinessCallback`** + `AssigneeBusinessCallbackRegistry` | `BusinessCallback` + `Params.callback` |
| Type 常量仅草稿子集 | 另有 `UnitMap` / `JobRelative` / `BusinessCallback` / `Expression` / `Fallback` | `AssigneeTypeCodes.cs` |
| 草案独立 `GroupRoles.cs` | **合入 `AssigneeTypeCodes.cs`** | — |

## 6. 内置 Type 清单与场景映射

### 6.1 时刻 A · Resolve（定范围 1–9）

| 场景 | Type | 落层 | Params 要点 |
|------|------|------|-------------|
| F1 传入 | `Specific` | 内置 | Runner 已传列表 |
| 1 固定人 | `FixedUsers` | 内置 | `users[]` |
| 2 流程相对 | `ProcessRelative` | 内置 | `relative`: Starter / PrevSender / … |
| 3 岗位相对 | `JobRelative` | 内置骨架 → 接 HR | `jobCode`；可 override 查找 |
| 4/6 单位 | `UnitMap` | 内置骨架 → 接映射 | `unitField` + maps；填 **Unit\***；若需按单位组内抢办再双写 `GroupId=UnitId` |
| 5 群组/角色 | `RoleGroup` | 内置 | `roleIds[]`（经资源服务扩用户） |
| 7 缺省 | `Fallback` | 内置 | `onEmpty` + 可选下一 Type |
| 8 发起人自选 | `StarterPick` | 内置 + FE | `required`、`allowMultiGroup` |
| 发送人/审批人自选 | `ApproverPick` | 内置 + FE；**出厂设计默认（R6）** | 办理页写入下一跳载荷 |
| 9 业务动态 | `BusinessCallback` 或 `Business.*` | 回调注册表 / 业务类 | 如 `Business.ClassStudents` |
| 表达式 | `Expression` | 内置 | 从 Conditions 取值 |

第一维坐标系（扩展时先归类，再起 Type 名）：

```text
绝对钉死     → FixedUsers · RoleGroup
流程相对     → ProcessRelative
组织/人力    → JobRelative · UnitMap · Fallback
运行时补全   → StarterPick · ApproverPick · Specific
业务相对     → BusinessCallback / Business.*
```

### 6.2 时刻 B · Leave（办理模式）

| 模式 | Type | Params 要点 |
|------|------|-------------|
| 抢办 | `Race` | 完成≈1；可选认领语义 |
| 协办 | `Collaborate` | 扁平：`completeCount` / `completeRate` |
| 组内抢办 | `GroupRace` | 按 GroupId；组内 1 人；组间见 **R7** |
| 组内协办 | `GroupCollaborate` | 组内 `completeCount`/`completeRate`；组间见 **R7** |
| 队长 | `Captain` | **R8**：关卡必办、组员可办、关卡办完组完成；`gateRoles` 默认 `["Leader"]`；组间见 **R7** |

**组间（R7）：** `groupJoin=And|Or` 快捷，或 `groupCompleteCount` / `groupCompleteRate`（已完成组数/占比）。默认 And。与组内参数分名，避免混用。

### 6.3 组合场景（扩展时的正确拆法）

**多单位发起人自选 + 组内抢办 + 组间 AND**（现场高频「怪需求」）：

```text
Resolve: StarterPick（或 Specific 已带矩阵）
  → Performer[] 每行：
       UnitId/Code/Name = 各单位（展示/筛选）
       GroupId = UnitId（本场景分组=单位，双写）
       GroupRole = …
Leave:   GroupRace + groupJoin=AND   ← 只读 GroupId
```

**错误方向：** 只把单位塞进 GroupId、待办列表再靠 Group 猜单位；或在 AIM 写「按单位拆任务」特例。  
**正确方向：** F1 结构化列表带齐 Unit\* + Group\*；Leave 只按 Group；展示只读 Unit\*。

**班级学员签字（场景 9）：**

```text
Type = Business.ClassStudents（biz 样例）
Params.classIdField → 查学员
  → Performer[]：GroupId=班级；Unit*=学校/法人（可与班级不同）；均可按需留空字段
可继承 LookupStudents；勿改 engine
```

同码覆盖样例：biz `TenantCollaborateLeaveJudge` 覆盖 `Collaborate`。

## 7. 扩展指引（防走错）

### 7.1 允许

| 需求 | 做法 |
|------|------|
| 新定范围 | 新 `IAssigneeResolver`，唯一 Type 字符串；目标经 `UseAssign.AddResolver<T>` |
| 改内置行为 | 继承非 seal 内置类，或同 Type 重新注册 |
| 接学籍/订单子表 | `Business.*` 或 `useAssigneeBusinessCallback` |
| 接 HR/单位主数据 | 扩展 `JobRelative` / `UnitMap`（override 查找），主数据在宿主 |
| 自定义完成公式 | 新 `IActivityLeaveJudge` 或覆盖 Leave Type |
| 表达式/规则算人 | `Expression` / 未来 ext 的 RuleSet Type，**仍是 Resolve Type** |
| 空人/同人/去重/自动过意图 | **EmptyAction / Filter / 锚点 Job**（**R10** / §11）；配置可读 NodePolicy |
| 主策略空后再算人 | Resolve Type `Fallback`（≠ EmptyAction） |

### 7.2 禁止

| 反模式 | 原因 |
|--------|------|
| 在 `NodeMediator` / AIM 增加「若流程码=XX 则…」算人 | 破坏薄调用与可测性 |
| 把定范围 + 抢办揉成**一个**下拉/一个 Type | 两维正交被破坏，组合场景无法表达 |
| 把空人/同人/重复已办做成新 **Resolve Type** | 违反 **R10**；那是后置处置不是定范围 |
| 在 Resolver/Filter 内嵌套 `RunProcess` 做「自动过」 | 违反 **R10**；应用锚点 + Job |
| Resolve/Leave Type 改成 **C# enum** 分发 | 业务无法无感加码；违反 string 铁律 |
| 内置类 `sealed` | 无法继承覆盖 |
| 用 Bool `IsLeader` 替代 GroupRole | 关卡身份无法扩展 |
| 空办理人静默当发起人/管理员 | 违反 **R4**；须显式 Fallback / EmptyAction 或拒绝 |
| 缺 ConfigPair 时回落 Definition/旧会签 | 违反 **R2**；定型后应拒绝 |
| 用 GroupId 承载企业单位展示/筛待办 | 违反 **R1**；单位用 Unit\*；分组才用 Group\* |
| LeaveJudge 读取 Unit\* 做完成判定 | 违反 **R1**；Leave 只认 Group\* |
| 用实例 StartUnit\* 覆盖节点任务 Unit\* | 违反 **R1**；发起单位与节点单位分离 |
| 抄送/通知复用 Assignee ConfigPair | 违反 **R5**；语义污染 |
| 照搬芋道策略数字枚举进 pure | 与 Sail 载荷/身份模型不兼容 |

### 7.3 空结果与未命中（R4）

| 情况 | 行为 |
|------|------|
| 无 Resolve/Leave ConfigPair（且无设计期默认已写入） | **拒绝**；ReasonCode 如 `AssigneeConfigMissing`；前端可感知 |
| Type 未注册 | **拒绝**；勿回落旧路径 |
| Resolve 空集 / 单位未命中 | **拒绝**（默认）；例外仅当建模者**显式**配置管道 `Fallback`（再算人）或 EmptyAction / NodePolicy 空人 `=1/3/4`（指定人/管理员/打自动过锚点） |
| NodePolicy `assignEmptyHandlerType` 缺省 / `=2` | **拒绝推进**（与本表一致）；**禁止**产品默认 `=1` 自动通过 |
| 空人/同人「自动通过」 | 目标态：打锚点 → 发送后 Job 苛刻代办（**R10**）；过渡期可为策略人 + Job |
| 新建用户任务 / 新流程 / 模板种子 | 按 **R6** 写入默认：`ApproverPick` + `Collaborate`（可被项目/模板覆盖）；空人策略默认 `=2` |
| **发布前** Type 为空 | **禁止发布**（R6）；与运行时拒绝双保险 |

部署/发布校验是 Host/设计器责任；**不能**替代运行时拒绝政策（R4）。NodePolicy 现行接线见 [todo-产品缺口.md](./todo-产品缺口.md) **§A**；演进目标见本文 **§11**。

### 7.4 诊断（**R9：同码覆盖强制**）

调试应能看到：Resolve/Leave 的 Type+Params、命中人数、Group\*、Unit\*、Leave Decision+ReasonCode。  
**同码覆盖必须可观测**（注册日志 + 运行时标明 Overridden/实现类型）；不得静默覆盖。缺其它诊断时优先补日志/结果字段，而不是加旁路。

## 8. 设计原则（摘要）

1. Client 时刻 A / A′ / B 契约优先于一切旁路脚本；Mediator 只认 `IAssigneePipeline`。  
2. 三根基落在契约上：F1→A 默认可追踪透传（Filter 可自决改写）；F2→B；F3→A 注册表 +（目标）Filter/EmptyAction。  
3. 策略配置与 Runner Specific **分离又协作**（Specific 是 A 的一种来源；Source 供 Filter 读取）。  
4. 定范围 × 办理模式正交 → **两套** ConfigPair；后置策略 **不是** 第三套 Resolve Type（**R10**）。  
5. 单一真源在流程定义（BPMN），不靠前端临时状态。  
6. 算人与流出必须可解释；Filter 改写 / 锚点 Job 结果须可诊断（对齐 R9 精神）。  
7. 空办理人 / 缺配置：**拒绝**（R4）；设计期预埋 **ApproverPick + Collaborate**（R6），发布前非空；显式 EmptyAction / Fallback 除外。  
8. **Group\* ≠ Unit\***（R1）：Leave 只读 Group；展示/筛选用 Unit\*（可空）；实例可选 StartUnit\*。  
9. 扩展挂 `UseAssign`：Resolver（string Type）/ Filter 链 / EmptyAction；后写覆盖；内置不 seal；主数据在宿主（R3）。  
10. 待办 / 通知 / 抄送三线分离（R5）；自动审批 Job ≠ Notifier ≠ 抄送。  
11. **自动通过**：锚点 + 发送后普通 Job 苛刻执行；禁止在时刻 A 嵌套 `RunProcess`（**R10**）。

## 11. 后置策略：Filter · EmptyAction · 自动审批锚点（目标态 · R10）

> **状态：** 2026-11-04 **口径拍板**；**引擎契约与 Job 骨架已落地**（见 §9 / `Hosting/SailAssignExtensions`）。Host `NodePolicyAssigneePipeline` + `__sail_policy_skip__` 仍过渡，待迁到 Filter/EmptyAction。  
> **动机：** 空人、与发起人相同、重复已办、列表人员重复等会持续膨胀；若全部做成新 `IAssigneeResolver` Type 或写进 Mediator，将破坏「定范围 × 办理模式」正交与薄调用。

### 11.1 问题分层（勿混）

| 层 | 问题例子 | 正确挂载点 |
|----|----------|------------|
| **定范围** | 角色组、单位映射、发起人自选 | `IAssigneeResolver` + `sf:assigneeResolve` |
| **再算人** | 主策略空 → 换另一套算人 | Resolve Type `Fallback`（`primary`/`fallback`） |
| **空集处置** | 仍空 → 拒绝 / 指定人 / 管理员 / 意图自动过 | **EmptyAction**（选型，非长链） |
| **有人后处置** | 同发起人、已办过、去重、换上级 | **Filter 链**（有序） |
| **自动审批执行** | 跳过节点语义上的「自动同意」 | **锚点 + 普通 Job**（发送成功后） |
| **办理模式** | 抢办/协办/队长 | `IActivityLeaveJudge`（时刻 B） |

**禁止：** 把空人/同人/去重注册成 Resolve Type；在 Filter/EmptyAction 内嵌套 `RunProcess`；用 Leave 表达「建待办前该不该出现某人」。

### 11.2 目标管道形状

```text
UseAssign / UseAssignees
  ├─ Resolvers[]      时刻 A：按 ConfigPair.Type 分发（同 Type 后写覆盖，R9）
  ├─ Filters[]        时刻 A′：有序列表处置（改人 / 打锚点）；注册序=执行序
  ├─ EmptyActions     时刻 A′：空集时按节点策略选型（默认对齐 R4 拒绝）
  └─ AutoApprove Job  发送成功后：认领锚点 → 苛刻复核 → 代办 Run

对外：Mediator 仍只调用 IAssigneePipeline.TryResolveForTaskCreate / TryCanLeave
```

```text
TryResolveForTaskCreate（目标态）
  1. 读 Resolve ConfigPair → Resolver.Resolve
  2. 标注 PerformerSource（Specific / Resolver(type) / Mixed…）
  3. 若 Count==0 → 空人处置（见下）
  4. 若 Count>0  → foreach Filter（Order / 注册序）
  5. 若 Filter 后变空 → 再走空人处置
  6. 返回 Performers；锚点写入 Job 载荷（见 §11.3）

空人处置（EmptyActionSelector 给出 key，缺省 reject）：
  a. 已注册 IAssigneeEmptyAction(Key / 产品码 1|2|3|4 别名) → Handle
  b. 否则调「对应 Resolver」再算人（Params←PolicyBag.emptyResolveParams|params|整袋）
     · key 同名 Type（如 RoleGroup / 业务 Type）
     · 产品 3/users → FixedUsers；reject/skip/admin 不映射为 Resolver
     · 调不到 Type / 抛错 / 仍空 → 不采用
  c. 默认 RejectEmptyAction（R4）
```


### 11.3 自动审批锚点（当普通 Job）

**语义：** 「自动跳过 / 自动通过」在时刻 A **只记录意图锚点**，不把办理人改成假账号作为主语义（过渡期 `__sail_policy_skip__` 可并存至切换完成）。

**时机：** 当前发送命令（Start/Run/…）**主路径成功且事务已提交**之后，由 **普通后台 Job**（与现有 Host `SailNodePolicyJobWorker` 同族，或统一 Job 表）认领执行。  
**禁止：** 在 Resolver/Filter/EmptyAction 内同步二次 `RunProcess`（重入、事务、Gate 再入难控）。

**苛刻前置（默认全检；不满足则不触发或记失败后回落手动）：**

1. 原发送命令已 `Success`，实例/任务仍处于预期 Waiting（或策略约定态）。  
2. **无未完成的发送交互**：不依赖用户尚未选择的下一节点或下一办理人（Runner 已带齐必要 `NextActivityPerformers`，或节点非待填选人策略）。多出口未指定、选人未齐 → **禁止自动**。  
3. 锚点目标明确（`TaskId` / `ActivityInstanceId` + 策略码），禁止「扫任意 Waiting」。  
4. 节点策略仍有效；Leave 模式下该次代办有意义（会签未齐导致必然 Waiting → 视为条件不满足）。  
5. 幂等：同一锚点至多成功一次；失败限次后放弃自动，**待办留人手**。

**结果码（建议）：**

| 码 | 含义 |
|----|------|
| （不入队 / 不触发） | 前置不足，等同未开自动 |
| `AutoApproveSkipped` | 认领后复核未过，明确不代办 |
| `AutoApproveFailed` | 已尝试 Run 失败 → **回落手动**（保留真人待办） |
| 成功 | 代办 Run 成功；审计意见可标策略来源 |

锚点持久化：与发送 **同库事务** 写入 Job/Outbox 行（推荐）；仅内存挂 `WfExecutedResult` 不可作为默认（进程崩溃丢锚点）。

### 11.4 Filter 上下文与 F1

```text
AssigneeFilterContext（示意）
  Request            // AssigneeInvokeRequest
  Source             // PerformerSource：Specific | Resolver | Mixed | …
  Performers         // 可改写的当前列表
  Anchors            // 可追加的自动审批意图（只写意图，不执行）
  Policy / 只读配置  // 如 NodePolicy 视图、节点扩展
```

- **F1：** 管道保证 Specific 入线时可追踪；**不**设「全局禁止改写 Specific」。  
- **默认内置 Filter：** `DedupUsersFilter` 会对 Specific 去重，并置 `RewroteSpecific=true`（可诊断）；其它内置宜尽量不改 Specific 语义。  
- **产品 Filter（同人等）：** 自行读 `Source` 决定是否改写；若改写须诊断可见。  
- Filter **可以**只打锚点而不改 `Performers`（推荐的「自动过」路径）。  
- `PerformerSources.Mixed` 常量已预留；现行 Pipeline 主要标 `Specific` / `Resolver` / `EmptyAction`。

### 11.5 `UseAssign` API 形态（与 Startup 同心智）

对齐 [业务管道特性设计.md](./业务管道特性设计.md) / [最佳实践-宿主能力包UseXxx.md](./最佳实践-宿主能力包UseXxx.md)：一项能力一个 `UseXxx`；**子 Builder 上 `Add*`，注册顺序有意义**。

```csharp
// 示意：目标 API（优先泛型 AddResolver<T>）
builder.UseAssign(a =>
{
    a.AddResolver<RoleGroupAssigneeResolver>();
    a.AddResolver<FixedUsersAssigneeResolver>();
    // 同 Type 后注册覆盖；委托重载可保留
    a.AddResolver("Business.ClassStudents", ctx => /* … */);

    a.AddFilter<DedupUsersFilter>();                    // 注册序 = 执行序
    a.AddFilter<SameAsStarterFilter>(o => o.Order = 20);
    a.AddFilter(new AlreadyHandledFilter(), o => o.Order = 30);

    a.AddEmptyAction<RejectEmptyAction>();              // 默认 R4
    a.AddEmptyAction<AssignToAdminEmptyAction>();       // 由节点策略码选型，非与 Filter 抢长链

    a.UseAutoApproveJob();                              // 可选：启用锚点 Job 消费
});

// UseAssignees 可作为 UseAssign 的别名或薄封装，避免宿主双真相
```

| 注册物 | 顺序语义 | 说明 |
|--------|----------|------|
| **`AddResolver<T>`** | 同 Type **后写覆盖**（R9） | **API 优先泛型**；不同 Type 之间无流水线顺序 |
| **`AddFilter` / `AddFilter<T>`** | **注册顺序 = 执行顺序**；可用显式 `Order`，同 Order 按注册序 | 对齐 Middleware |
| **`AddEmptyAction` / `AddEmptyAction<T>`** | **选型表**（按 NodePolicy/策略码选一个实现） | 不要做成与 Filter 同构的长链；空集控制流不同 |
| **`UseAutoApproveJob`** | 总包开关 | 与 Filter 链分离；只消费锚点 |

`UseFlowAspects(b => b.AddGate…)` 是把 `configure` 打在 `ISailCollection` 上；**`UseAssign` 宜用专用子 Builder**，避免 Filter 与无关 Feature 挤在同一集合里抢顺序语义。

### 11.6 与现行 Host 接线的关系

| 现行（过渡） | 目标（R10） |
|--------------|-------------|
| `NodePolicyAssigneePipeline` 包一层 | Filter + EmptyAction 注册进 `UseAssign` |
| 装饰器 **catch `AssigneeEmpty`** 后再套 NodePolicy 空人 `1/3/4` | `EmptyActionSelector` + `UsePolicyBag`（无 catch） |
| `__sail_policy_skip__` + 扫 Waiting 代办 | 锚点 Job（可暂时双写策略人以便迁移） |
| NodePolicy 字段由 Host 硬读 | 同一字段改为驱动 Filter/EmptyAction 选型 |
| F1「不得静默改写」文案 | 改为 Source 可追踪 + Filter 自决（§11.4） |

**现行互斥：** 内层空集默认抛 `AssigneeEmpty`，装饰器若不 catch，Host `assignEmptyHandlerType=1/3/4` 到不了。缺 Config / Type 未注册仍 `return false`，该路径装饰器本就可接管。

迁移时：**行为对外可渐进**，契约以本 §11 为准；完成后删除大而全装饰 Pipeline 类与 catch 过渡。

### 11.7 扩展红线（本层）

| 允许 | 禁止 |
|------|------|
| 新 Filter / EmptyAction 类经 `UseAssign` 挂载 | 新空人/同人 **Resolve Type** |
| 锚点入普通 Job 表/队列 | Filter 内嵌套 `RunProcess` |
| Host 提供组织 Lookup 给「转上级」Filter | 组织 schema 进 pure |
| 诊断打印 Source、各 Filter 是否改写、锚点结果码 | 静默改 Specific 且无日志 |
| Leave 继续只负责完成条件 | 用 Leave 表达「同人跳过」 |
