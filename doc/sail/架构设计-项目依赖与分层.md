## 2. 分层总览

### 2.1 一句话

```text
宿主应用
  → biz（组合根 / 产品能力）
    → core/ext（可选实现 + 重型第三方库）
      → core/pure（引擎骨架 + 契约 + 数据原语）
        → mooSQL（外部数据访问库）
```

箭头表示 **ProjectReference 允许方向**（上层引用下层）。**禁止反向引用**。

### 2.2 分层图

```text
┌─────────────────────────────────────────────────────────────────┐
│  Host（ASP.NET / Console / 测试）                                 │
│  通常只引用 sailflow.biz；也可按需直引个别 ext 包                   │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  biz                                                            │
│  sailflow.biz          组合根：默认挂载一批 UseXxx 门面            │
│  sailflow.biz.AI       AI 执行器实现                              │
│  sailflow.biz.docs     文档/PDF 等产品能力                         │
│  sailflow.biz.query    查询侧业务                                  │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  core/ext（可选能力实现）                                          │
│  action / msg / bizRule / form / resource / localize / …         │
│  ★ IronPython / RabbitMQ / NRules / EF 等「重依赖」只允许出现在此层  │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  core/pure（框架内核）                                            │
│  sailflow.engine   流程引擎 + SailClient 管道骨架 + 插槽            │
│  sailflow.baseHub  跨切契约与 Locator（无重型 NuGet）                │
│  sailflow.basis    数据访问适配（经 mooSQL）                        │
│  sailflow.AI       AI 节点抽象 / Locator（无具体模型 SDK）           │
└───────────────────────────────┬─────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────┐
│  mooSQL（仓库外：moo-sqlm/mooSQL2024）                             │
│  mooSQL.Pure / mooSQL.Ext                                        │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 三层职责对照

| 层 | 目录 | 职责 | 允许的依赖特征 |
|----|------|------|----------------|
| **pure** | `src/core/pure/*` | 流程语义、管道骨架、跨切**接口**与 DTO、数据原语 | **禁止** MQ/脚本引擎/规则引擎/ORM/JSON 厂商包；JSON 仅保留 `IJsonSerializer` 契约 |
| **ext** | `src/core/ext/*` | 某一能力的**可替换实现**；对 `engine` 写 `UseXxx` | 可引入对应第三方；只依赖 pure（通常 `engine`，必要时 `basis`） |
| **biz** | `src/biz/*` | 产品组合、业务实现、默认启用门面（`UseBizMsg` 等） | 可组合多个 ext；**不得**被 pure/ext 反向引用 |

## 3. 源码与解决方案布局

### 3.1 目录树（权威）

```text
src/
├── Sailflow.sln
├── core/
│   ├── pure/
│   │   ├── basis/      → sailflow.basis     (PackageId: saiflow.data)
│   │   ├── baseHub/    → sailflow.baseHub   (PackageId: saiflow.hub)
│   │   ├── AI/         → sailflow.AI        (Assembly: saiflow.AI)
│   │   ├── engine/     → sailflow.engine    (PackageId: saiflow.engine)
│   │   └── assignee/   → sailflow.assignee  (S0：办理人重量逻辑；engine 仅薄管道调用)
│   └── ext/
│       ├── action/     → sailflow.action    (IronPython)
│       ├── msg/        → sailflow.msg       (RabbitMQ.Client)
│       ├── bizRule/    → sailflow.bizRule   (NRules)
│       ├── form/       → sailflow.form      (mooSQL / Newtonsoft.Json)
│       ├── resource/   → sailflow.resource
│       ├── localize/   → sailflow.localize
│       ├── external/   → sailflow.external
│       └── graph/      → sailflow.graph     (与 basis 同源数据层镜像，慎用)
└── biz/
    ├── host/           → sailflow.biz       (组合根)
    ├── AI/             → sailflow.biz.AI
    ├── docs/           → sailflow.biz.docs
    └── query/          → sailflow.biz.query
```

> **注意**：历史上曾有「`core/ext/baseHub` 扛 MailKit/RabbitMQ」的形态。**现行权威位置是 `core/pure/baseHub`**，只保留契约；重型实现已外迁。文档与索引若仍写 `ext/baseHub`，视为过时。

### 3.2 解决方案文件夹

| Solution Folder | 包含项目 |
|-----------------|----------|
| **core** | `basis`、`engine`、`AI`、`baseHub`、`assignee`（S0 已建） |
| **ext** | `action`、`msg`、`bizRule`、`form`、`resource`、`localize`、`external`、`graph` |
| **biz** | `biz`、`biz.AI`、`biz.docs`、`biz.query` |
| **mooSQL** | `mooSQL.Pure`、`mooSQL.Ext`（指向外部仓库路径） |

目标框架惯例：`net6.0;net8.0;net10.0`。文件夹名多为 `sailflow.*`，NuGet `PackageId` / 程序集常为 **`saiflow.*`**（历史拼写，新增包保持一致即可）。

## 4. 依赖铁律

### 4.1 允许的引用方向

```text
host ──► biz ──► ext ──► engine ──► baseHub / AI / basis ──► mooSQL
                 │                    ▲
                 └────────────────────┘  （ext 亦可直接引用 basis，如 form/resource）
```

### 4.2 禁止清单（硬约束）

| 规则 | 说明 |
|------|------|
| **engine ↛ ext / biz** | 引擎不得 ProjectReference 任何可选包或业务包 |
| **baseHub ↛ engine** | Hub 只依赖 `basis`；日志等通过注入 `Func<SQLBuilder>` 等避免拉引擎 |
| **basis ↛ engine / ext / biz** | 数据层保持最底层 |
| **pure ↛ biz** | 内核不知道产品组合 |
| **pure 禁止重型第三方** | RabbitMQ、IronPython、NRules、MailKit、厂商 EF 驱动等**不得**进入 `engine` / `baseHub` / `AI` / `basis` 的 PackageReference |
| **禁止「为了方便」把实现塞回 pure** | 哪怕只有一个默认实现，也放 ext，由 `UseXxx` 挂载 |

### 4.3 现行 ProjectReference 图（摘要）

```text
mooSQL.Ext
  ↑ basis, graph

basis
  ↑ baseHub, engine, form, resource, biz.AI, biz.query

baseHub
  ↑ engine

AI (pure)
  ↑ engine, biz.AI

engine
  ↑ action, msg, bizRule, form, resource, localize, external,
    biz, biz.AI, biz.docs, biz.query

action / msg / bizRule / resource / localize
  ↑ biz（组合根默认引用；form / external / graph 默认不进 biz）
```

`sailflow.biz` 当前默认组合：

- 必引：`engine`、`action`、`msg`、`bizRule`、`resource`、`localize`、`biz.AI`、`biz.docs`、`biz.query`
- **不默认引**：`form`、`external`、`graph`（宿主按需加 ProjectReference + `UseForm()` 等）

### 4.4 判定口诀

新增一个类型或 NuGet 包时：

1. **只被引擎调度、无第三方** → 放 **pure/engine**（或契约放 **baseHub**）。
2. **接口给多方用、实现可换** → 接口 **baseHub（或 pure/AI）**，实现 **ext 或 biz**。
3. **绑定某一第三方 SDK** → 必须 **ext**（或 biz 若纯业务定制）。
4. **「默认产品里打开」** → **biz** 写薄门面 `UseBizXxx`，内部转调 ext 的 `UseXxx`。

## 5. 各层项目说明

### 5.1 pure

#### `sailflow.basis`（saiflow.data）

- 经 mooSQL 提供 `SailDBFactory` / SQL 访问适配。
- **不**包含流程语义。

#### `sailflow.baseHub`（saiflow.hub）

跨切**契约与共享类型**，无重型 PackageReference：

| 域 | 内容 |
|----|------|
| Form | `IFormService`、`FormServiceLocator`、表单/字段 DTO |
| Resource | `IResourceService`、`ResourceServiceLocator`、角色/用户 DTO |
| Localize | `ILocalizeMessages`、`LocalizeMessagesLocator`、passthrough |
| Essential | Message/Signal 实体与 Mediator、`IMessageQueueService` |
| Logging | `ILogService` / `LogService`（SQL 工厂注入，不引用 engine） |

**设计意图**：engine 可以对接口编程；实现由 ext 在 Build 时注册到 Locator / `SailClient` 插槽。

#### `sailflow.AI`

- AI 节点抽象与 `AiNodeExecutorLocator`。
- **无**具体 LLM/HTTP SDK；具体执行器在 `sailflow.biz.AI`。

#### `sailflow.assignee`（saiflow.assignee，**S0–S4 已齐**；定型决议见管道文档 §0 R1–R9）

- 办理人重量逻辑：查找待办人 / 流出判定、ConfigPair、按 **string Type** 注册（后写覆盖）、内置实现（**禁止 sealed**）。
- **engine 仅保留 `IAssigneePipeline` 薄调用**，不内嵌策略分发。
- **定型目标（R2/R4）：** 运行时单轨；缺 ConfigPair / 空办理人无显式 Fallback → **拒绝**（禁止长期双轨回落）。S4 代码仍可能 `Try*=false` 回落，收口时删除。
- **R1（修订）：** `Group*`=办理分组（Leave 用）；`UnitId/Code/Name`=企业单位（可空，展示/筛选）；实例可选 `StartUnit*`；二者正交，禁止用 GroupId 冒充单位。**R3：** 组织主数据在宿主；本包只留 Lookup 骨架。**R5：** 与 Notifier / 抄送分离。
- Resolve Type：Specific / FixedUsers / RoleGroup / ProcessRelative / StarterPick / ApproverPick / **UnitMap / JobRelative / BusinessCallback / Expression / Fallback**。
- Leave Type：Race / Collaborate / GroupRace / GroupCollaborate / Captain。
- BPMN：`sf:assigneeResolve` / `sf:leaveJudge`；`useAssigneeBusinessCallback`；biz 样例 `Business.ClassStudents`、`TenantCollaborateLeaveJudge`。
- 依赖：`ProjectReference → engine`；由 biz `UseBizAssignees` / `UseAssignees` 注入管道。
- 专题：[特性说明-待办人管道.md](./特性说明-待办人管道.md)；宿主 `doc/sailflow-assignee-candidate-design.md` §7.5 / §11。

#### `sailflow.engine`（saiflow.engine）

- 工作流核心：定义解析、实例推进、Task、Message/Signal 委托等。
- **管道骨架**：`SailClient`、`SailClientBuilder`、`ISailCollection`、`SailFeatureDescriptor`、`SailBuilderKeys`。
- **插槽**（由外部挂载，engine 只定义挂载点）：

| 插槽 | 契约位置 | 典型挂载 |
|------|----------|----------|
| `MessageQueue` | `IMessageQueueService` @ baseHub | `UseRabbitMq` / `UseBizMsg` / `UseMessageQueue` |
| `JsonSerializer` | `IJsonSerializer` @ engine Client | `UseBizJson` / `UseJsonSerializer`（默认 Newtonsoft 在 biz） |
| Rule engines | `RuleEngineRegistry` @ engine | `UseBizRuleEngines` / `UseBizRules` |
| Action / Script / Service | Method registries @ engine | 内建 + `UseIronPython` / `UseBizAction` |
| `AssigneePipeline` | `IAssigneePipeline` @ engine | `UseAssignees` / `UseBizAssignees`（实现在 `sailflow.assignee`） |
| `Messages` | `ILocalizeMessages` @ baseHub | `UseLocalize` / `UseBizLocalize` |
| DB / Cache / Config | engine | `UseDatabase` / `UseCache` / `UseConfig` |

引擎侧 **无** PackageReference（JSON 等厂商实现外置）；ProjectReference **仅** `AI`、`baseHub`、`basis`。

未挂载时：`GetMessageQueueRequired()` 等**快速失败**并提示调用哪个 `UseXxx`；`JsonSerializer` 未挂载则为 null，调用方直接用属性（需宿主先 `UseBizJson()`）——这是刻意行为，避免隐式默认拖入重依赖。

### 5.2 ext

每个 ext 包遵循同一形状：

```text
core/ext/<name>/
  sailflow.<name>.csproj     → ProjectReference → engine（± basis）
  src/Hosting/*SailExtensions.cs   → UseXxx(ISailCollection / SailClientBuilder / SailClient)
  src/... 实现
```

| 项目 | 重依赖 | 挂载 API | 实现内容 |
|------|--------|----------|----------|
| `sailflow.action` | IronPython | `UseIronPython` | Python Action/Script Handler |
| `sailflow.msg` | RabbitMQ.Client | `UseRabbitMq` | `IMessageQueueService`；待办推送骨架亦归属本包（见回调文档） |
| `sailflow.bizRule` | NRules | `UseBizRuleEngines` | 规则引擎实现 |
| `sailflow.form` | Newtonsoft.Json（经 basis/engine → mooSQL） | `UseForm` | `IFormService` 实现 + Locator |
| `sailflow.resource` | （轻） | `UseResource` | `IResourceService` 实现 |
| `sailflow.localize` | MemoryCache 等 | `UseLocalize` | JSON 本地化 → `Messages` + Locator |
| `sailflow.external` | Configuration 等 | （示例集成） | 外部系统样例 |
| `sailflow.graph` | mooSQL | — | 与 basis 类似的数据层镜像；**biz 不默认引用** |

### 5.3 biz

| 项目 | 角色 |
|------|------|
| `sailflow.biz` | **组合根**：引用默认 ext 栈；提供 `UseBizJson` / `UseBizMsg` / `UseBizAction` / `UseBizRules` / `UseBizLocalize` / `UseSchema` / `CreateBuilder(IConfiguration)` 等门面 |
| `sailflow.biz.AI` | `AiRuntime.UseDefaultExecutor`、`UseBizAI` |
| `sailflow.biz.docs` | PDF 等（如 iTextSharp）；文档侧能力 |
| `sailflow.biz.query` | 查询业务 |

门面约定：

```csharp
// biz：产品默认名，转调 ext / 本包默认实现
services.UseBizJson();                  // → NewtonsoftJsonSerializer
services.UseBizMsg(opt => { ... });     // → UseRabbitMq
services.UseBizAction();                // → UseIronPython
services.UseBizRules();                 // → UseBizRuleEngines
```

宿主仍可跳过 biz 门面，直接引用 `sailflow.msg` 并调用 `UseRabbitMq`，或 `UseMessageQueue(custom)` 换自研实现。

## 6. 运行时组合模型（与依赖的关系）

### 6.1 编译期 vs 运行期

| | 编译期（csproj） | 运行期（Build） |
|--|------------------|-----------------|
| 含义 | 程序集是否出现在依赖图中 | 能力是否挂到 `SailClient` |
| 手段 | `ProjectReference` / `PackageReference` | `UseXxx` → `SailFeatureDescriptor` → 插槽/Locator |
| 失败形态 | 无法编译 | `GetXxxRequired` / Locator 未注册异常 |

**仅引用而不 `UseXxx`**：实现程序集可能进输出目录，但插槽仍为空——与「显式启用」原则一致。

### 6.2 宿主典型写法

```csharp
var builder = SailClient.CreateBuilder(configuration); // 或 biz 扩展
builder.Services
    .UseDatabase(db)
    .UseBizJson()
    .UseBizLocalize()
    .UseBizMsg(o => { /* RabbitMqOptions */ })
    .UseBizAction()
    .UseBizRules()
    .UseBizAI()
    .UseResource()
    // .UseForm()   // 需额外引用 sailflow.form
    .UseSchema(o => o.Seed = true);

var sail = builder.Build();
var wf = new WorkflowService(sail);
```

要点：

- **Build 一次，实例下传**；禁止静态全局取库（见管道文档）。
- 多租户若未来多 `SailClient`，注册表必须挂在实例上，禁止进程级静态列表新增长期状态。

### 6.3 契约在 pure、实现在 ext 的闭环

以消息队列为例（依赖改造的标杆）：

```text
baseHub:  IMessageQueueService
engine:   SailClient.MessageQueue 插槽
          MessageDelegateService / SignalDelegateService → GetMessageQueueRequired()
msg:      RabbitMQService + UseRabbitMq（PackageReference RabbitMQ.Client）
biz:      UseBizJson → NewtonsoftJsonSerializer；UseBizMsg → UseRabbitMq
```

**错误示范（已废除）**：在 `baseHub` 直接引用 RabbitMQ/MailKit，导致所有引用 hub 的程序集被迫带上 MQ/邮件栈。

## 7. 能力落位决策树

```text
需要新能力？
├─ 是否改变流程推进语义 / 核心调度？
│  └─ 是 → 逻辑进 engine；若可插拔则同时在 baseHub 定义接口
├─ 是否需要第三方 SDK / 协议客户端？
│  └─ 是 → 新建或扩 core/ext/<name>，写 UseXxx；禁止进 pure
├─ 是否仅本产品默认行为？
│  └─ 是 → biz 实现或 biz 门面转调 ext
└─ 接口是否被 engine 与多个实现共享？
   └─ 是 → 接口放 baseHub（或 pure/AI）；实现放 ext/biz
```

### 7.1 改造案例（现行结论）

| 能力 | 旧问题 | 现行落位 |
|------|--------|----------|
| RabbitMQ | 曾贴近 hub / 引擎周边 | **契约** `IMessageQueueService` @ baseHub；**实现** `sailflow.msg` |
| MailKit | 曾进入 hub 依赖面 | **已移出**；邮件走 BCL `SmtpClient` 或未来若引 MailKit 必须进 **ext**（如 msg 或独立 mail 包） |
| IronPython | 若进 engine 则污染内核 | **`sailflow.action`** |
| NRules | 同上 | **`sailflow.bizRule`** |
| Form/Resource/Localize 实现 | 曾可能与引擎硬绑 | 实现在 **ext**；契约/Locator 在 **baseHub** |

### 7.2 与回调/事件设计的对齐

| 能力 | 建议包 |
|------|--------|
| Gate / Hook 契约与引擎内分发 | **engine**（必要时接口可沉 baseHub） |
| 待办推送骨架、默认邮件 Notifier、`UseDefaultTaskMail` | **`sailflow.msg`** |
| 企微/钉钉等通道 | **ext 新包或 biz**，实现同一 Notifier 契约 |

详见 [`特性设计-回调与事件.md`](./特性设计-回调与事件.md)。

## 8. 命名与 API 分层

### 8.1 三层命名

| 层级 | 命名 | 例子 | 所在程序集 |
|------|------|------|------------|
| 引擎插槽 API | `UseMessageQueue` / `useMessageQueue` | 挂任意 `IMessageQueueService` | engine |
| 实现包 API | `UseRabbitMq` / `UseIronPython` | 绑定具体技术 | 对应 ext |
| 产品门面 | `UseBizMsg` / `UseBizAction` | 默认技术选型 | biz |

上层可以覆盖下层：先 `UseBizMsg()`，再 `UseMessageQueue(custom)` 替换。

### 8.2 包 ID 与文件夹

| 概念 | 约定 |
|------|------|
| 仓库文件夹 / 项目文件名 | `sailflow.*` |
| NuGet PackageId / 常见 AssemblyName | `saiflow.*` |
| 命名空间 | 与程序集一致（如 `saiflow.msg`、`saiflow.hub.*`） |

新增项目时两边同时声明，避免只改文件夹名。

## 9. 新增 / 迁移检查清单

### 9.1 新增 ext 能力包

1. 在 `src/core/ext/<name>/` 建项目，`ProjectReference` → `engine`（需要数据原语再加 `basis`）。
2. 第三方库只加在本 csproj。
3. 实现接口（优先已有 baseHub 契约；否则先在 pure 加接口再实现）。
4. 提供 `UseXxx`（`ISailCollection` + `SailClientBuilder`，必要时 `SailClient` 扩展）。
5. 加入 `Sailflow.sln` 的 **ext** 文件夹。
6. 若为产品默认能力：在 `sailflow.biz` 增加 ProjectReference + `UseBizXxx` 门面。
7. 更新本文「项目表」与管道文档中的程序集归属表。

### 9.2 从 pure 外迁实现（重构模板）

1. 在 pure 保留**接口**（或移到 baseHub）。
2. engine 改为调用插槽 / Locator，未注册时明确报错。
3. 在 ext 实现并 `UseXxx`。
4. 删除 pure 上对应 PackageReference。
5. 全解决方案编译，检查是否有程序集仍间接带上旧 NuGet。

### 9.3 PR / 评审关注点

- [ ] 新 PackageReference 是否落在正确层？
- [ ] engine / baseHub 的引用图是否仍「干净」？
- [ ] 是否只有 `UseXxx`、没有静态隐式初始化重依赖？
- [ ] biz 门面是否过厚（应薄转调，不复制实现）？

## 12. 总结

sailflow 依赖架构的核心不是「目录好看」，而是：

1. **pure 保持可被任意宿主引用而不被迫带上 MQ/脚本/规则/ORM 厂商栈**；
2. **ext 用重依赖换能力，用 UseXxx 换可拔插**；
3. **biz 只做组合与产品默认，不做内核**；
4. **契约下沉、实现上浮**——`baseHub` 接口 + `SailClient` 插槽是连接两界的唯一正规通道。

后续任何「图省事把 NuGet 加进 engine/baseHub」的改动，都应视为架构回退，需按第 9 节外迁。
