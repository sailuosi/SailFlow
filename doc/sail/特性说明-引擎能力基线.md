# Sailflow 引擎能力基线

> 状态：**现行引擎能力说明**（2026-11-01）  
> 仓库：`sailflow`（程序集命名空间多为 `saiflow.*`）  
> 用途：后续演进的**能力基准**——改语义、加命令、拆包、换插槽前先对照本文；产品壳说明见宿主仓 `sleveen-admin/doc/sailflow-features.md`  
> 深度设计（非本文件）：[架构设计-项目依赖与分层.md](./架构设计-项目依赖与分层.md) · [业务管道特性设计.md](./业务管道特性设计.md) · [特性设计-回调与事件.md](./特性设计-回调与事件.md)

本文回答：**引擎今天承诺什么、落在哪一层、通过什么契约暴露、演进时哪些边界不可破。** 不写 Host HTTP 路由与前端菜单。

---

## 1. 一句话与职责切分

| 层 | 职责 | 典型落点 |
|----|------|----------|
| **pure** | 流程语义、命令、查询契约、管道骨架、Assignee 插槽 | `sailflow.engine` / `baseHub` / `basis` / `AI` / `assignee` |
| **ext** | 可替换实现 + 重依赖（表单、规则引擎、Python、MQ、资源…） | `sailflow.form` / `bizRule` / `action` / `msg` / `resource` / … |
| **biz** | 产品默认组合、`UseBiz*`、查询门面、AI/文档实现 | `sailflow.biz` / `biz.query` / `biz.AI` / `biz.docs` |
| **Host** | HTTP、产品表、鉴权、工作台聚合 | 仓外（如 `sleveen-admin/backend/saiflow`） |

```text
Host  →  WorkflowService / Managers / QueryService  →  SailClient（插槽）
                                                      ↑ UseXxx 注册
```

**禁止：** 用 NFlow Pure / Flowable 替换本引擎；在 pure 引入芋道 `/bpm` 合同或重型第三方；为迁就某一前端壳改写调度内核。

## 2. 成熟度图例

| 标记 | 含义 |
|------|------|
| **稳定** | 对外契约，破坏性变更需显式版本/迁移说明 |
| **可用** | 已落地可接；细节仍可能打磨 |
| **可扩展** | 内置 + 注册覆盖（同 Type 码后写覆盖） |
| **债/弱** | 有代码路径，语义或覆盖面不足，演进时优先还债 |
| **非引擎** | 属 Host/产品表，引擎不内置 |

## 3. 运行命令（`WorkflowService`）

入口：`WorkflowService`（须注入 `SailClient`）。常用形态：`XxxProcess(WfAppRunner)` / `XxxProcessAsync`；亦支持链式 `Start()`/`Run()` + 已设 Runner，以及传入 `SQLBuilder kit` 的事务内调用。

| 命令 | 成熟度 | 语义摘要 |
|------|--------|----------|
| `StartProcess` / `StartProcessByMessage` | 稳定 | 按定义启动实例；消息启动走 Message 路径 |
| `RunProcess` / `RunProcessApp` / `RunProcessAuto` | 稳定 | 推进用户任务 / 应用运行 / 自动节点续跑 |
| `WithdrawProcess` | 稳定 | 撤回 |
| `SendBackProcess` | 稳定 | 退回到可选历史节点 |
| `ResendProcess` | 稳定 | 重新发送（Sail 特色路径） |
| `ReviseProcess` | 可用 | 修订 |
| `ReverseProcess` | 可用 | 反转/回转类路径（与退回区分，接入前核对场景） |
| `RejectProcess` | 稳定 | 驳回（**≠** 部分产品「驳回即删整单」） |
| `CloseProcess` | 稳定 | 关闭实例 |
| `JumpProcess` | 稳定 | 跳转（`JumpOptionEnum`） |
| `SignForwardProcess` | 稳定 | 加签；对齐会签/SignForward 复杂类型 |
| `TransferProcess` | 可用 | 转办：个人办结 + **本节点交人**，不发生节点流转（≠ 委派） |
| `TerminateProcess` | 可用 | 终止运行实例（bool；Host 包装为办理按钮，默认关） |
| `DiscardProcess` | 可用 | 作废实例（bool；Host 包装，默认关） |
| `CancelProcess` / `SuspendProcess` / `ResumeProcess` | 债/弱 | 引擎有；产品码表暂缓 |

结果形态：`WfExecutedResult`（含成功/失败、校验拒绝、`ReasonCode` 等）。Gate 业务拒绝走校验拒绝通道，勿与系统异常混用（见回调文档）。

**Assignee ReasonCode（R4 / NodePolicy）：** `AssigneeConfigMissing` · `AssigneeEmpty` · `ProcessAdminNotConfigured` · `AssignEmptyUsersMissing` · Leave 相关码。产品空人默认拒绝见 [todo-产品缺口.md](./todo-产品缺口.md) §A；超时 / 策略跳过由 **Host** 作业消费，非引擎内置 drain。

**演进基线：** 新增办理动词优先在现有命令语义上扩展参数/选项；确需新命令时保持「Runner 入、ExecutedResult 出」并补齐 Gate/Hook 触发点。

## 6. 节点与执行器（Mediator）

引擎以 `NodeMediator*` 执行图元素。基线覆盖：

| 类别 | 代表 | 成熟度 |
|------|------|--------|
| 开始/结束/中间 | `NodeMediatorStart` / `End` / `Intermediate` | 稳定 |
| 用户任务 | `NodeMediatorTask` | 稳定 |
| 会签 / 加签 | `MultiSignTogether` / `MultiSignForward` / `SignForward` / `MultiSignCreator` | 可用（真并行会签仍有债，演进走本语义） |
| 网关 | And/Or/XOr Split·Join、ApprovalOrSplit、EOrJoin、MI 变体 | 可用 |
| 自动 | `Service` / `Script` / `Rule` / `AIService` | 可用（依赖对应 UseXxx） |
| 子流程 | `SubProcess` / `SubProcessNested` | 可用 |
| 后退 | `NodeMediatorBackward` | 稳定（退回等） |
| Message / Signal / Timer / Conditional | 各组 `NodeMediator*Msg*|Signal*|Timer*|Conditional*` | 可用（常依赖 MQ/调度插槽） |

**演进基线：** 新节点类型 = 新 Mediator + Factory 注册 + BPMN 解析；禁止在 Host 用脚本「假装」节点语义。

## 7. 待办人管道（`sailflow.assignee`）

> **专项基准（架构/分层/API/场景/扩展红线）：** [特性说明-待办人管道.md](./特性说明-待办人管道.md)

包：`src/core/pure/assignee`。启用：`UseAssignees` / `UseBizAssignees`。

### 7.1 两大时刻

| 时刻 | 契约 | 时机 |
|------|------|------|
| **Resolve** | 查找待办人 → `Performer[]` | 创建待办前 |
| **Leave** | 流出判定 → 能否离开本节点 | 完成/推进前 |

配置对：**`{ Type: string, Params }`**（Type **禁止**改成枚举；同码注册后写覆盖；内置实现禁止 seal）。

Performer 可带 **`Group*`**（办理分组 / 组内身份）与 **`UnitId`/`UnitCode`/`UnitName`**（企业单位，可空；与 Group 正交）。流程实例可选 **`StartUnit*`**（发起单位）。Leave **只读 Group\***。

### 7.2 内置 Resolve Type

| Type | 说明 |
|------|------|
| `Specific` | 调用方传入办理人 |
| `FixedUsers` | 固定用户列表 |
| `RoleGroup` | 角色展开 |
| `ProcessRelative` | 流程相对人 |
| `StarterPick` / `ApproverPick` | 发起人自选 / **发送人自选**（出厂设计默认 ApproverPick，R6） |
| `UnitMap` | 单位映射 |
| `JobRelative` | 岗位相对 |
| `BusinessCallback` | 业务回调注册表 |
| `Expression` | 从条件/字段表达式取值 |
| `Fallback` | 回退策略 |

### 7.3 内置 Leave Type

`Race` · `Collaborate` · `GroupRace` · `GroupCollaborate` · `Captain`

BPMN：`sf:assigneeResolve` / `sf:leaveJudge`。

**已决（详见待办人管道 §0 R1–R9）：** …；队长细则（R8）；**同码覆盖诊断强制（R9）**。

**演进基线：** 个性化算人/完成条件只加 Resolver/LeaveJudge 或业务同码覆盖；不改写 AIM 主调度去堆 if-else。Legacy 仅作导入转写，不作运行时静默成功。

## 8. Gate / Hook / Notifier / Outbox

设计全文见 [特性设计-回调与事件.md](./特性设计-回调与事件.md)；Phase 1–3b 已落地。

| 能力 | 注册 | 成熟度 |
|------|------|--------|
| Workflow Gate（推进前校验，可 Reject） | `UseFlowGate` | 稳定 |
| Workflow Hook（推进后业务） | `UseFlowHook` | 稳定 |
| Task Notifier（待办旁路通知） | `UseTaskNotifier` | 可用 |
| Sync / AsyncOutbox、FailFast / RecordAndRetry | 选项 + Outbox 表 | 稳定 |
| 流程/节点过滤白名单 | 注册 configure | 稳定 |
| Sync Hook 硬超时 | `CapabilityOptions.SyncHookTimeoutMs` | 可用 |
| Outbox Drain 循环 | `UseHookOutboxDrain` / `UseBizHookOutboxDrain` | 可用 |
| 死信复活 | `HookOutboxManager.ResetDead*` | 可用 |
| 指标 | `IWorkflowCapabilityMetrics` | 可用 |
| 旧 `Subscribe(EventFireType)` | 单次 Runner 挂钩 | 保留兼容，新逻辑优先 Gate/Hook |

**非引擎：** 抄送箱、分类树、报表 UI、审批打印模板 —— Host 产品表/页面。

**宿主挂载写法：** 一项能力一个 `builder.UseXxx`，开关/建表/Drain 内聚；勿在组合根 `Build()` 后散落注册。见 [最佳实践-宿主能力包UseXxx.md](./最佳实践-宿主能力包UseXxx.md)。

## 9. 能力包与 `UseXxx`（插槽基线）

| UseXxx（代表） | 层 | 作用 |
|----------------|----|------|
| `UseDatabase` / `UseConfig` / `UseCache` | pure | 库、配置、缓存 |
| `UseJsonSerializer` / `UseBizJson` | pure/biz | JSON 契约实现 |
| `UseAssignees` / `UseBizAssignees` | pure/biz | 待办人管道 |
| `UseFlowGate` / `UseFlowHook` · `UseTaskNotifier` | pure | 回调三轨 |
| `UseHookOutboxDrain` | pure/biz | 出站补调 |
| `UseRuleEngine` / `UseBizRules` | pure/ext/biz | 规则节点 |
| `UseActionMethod` / `UseScriptMethod` / `UseServiceMethod` / `UseIronPython` / `UseBizAction` | pure/ext/biz | Action/Script/Service |
| `UseMessageQueue` / `UseRabbitMq` / `UseBizMsg` | pure/ext/biz | 消息 |
| `UseDefaultTaskMail` / `UseBizTaskMail` | ext/biz | 待办邮件默认实现 |
| `UseForm` / `UseResource` / `UseLocalize` | ext | 表单、资源、本地化 |
| `UseBizAI` | biz | AI 执行 |
| `UseSchema` | biz | 库表初始化/种子 |

原则：**引擎只提供骨架与契约；业务包只写扩展；Build 一次、SailClient 实例下传；禁止静态取库。**

## 10. 表单 / 规则 / AI / 资源（引擎视角）

| 域 | 契约位置 | 说明 |
|----|----------|------|
| 表单元数据与字段活动权限 | `ext/form` + Locator | Host CRUD；运行时按活动取 FieldACL |
| 规则集 | engine 实体 API + `bizRule` | Rule 节点经 RuleEngine 插槽 |
| AI 活动 | `sailflow.AI` 契约 + `biz.AI` | `NodeMediatorAIService` |
| 知识库 | AI/资源相关 API | 向量检索等由 biz/Host 暴露 |
| 资源/本地化 | `UseResource` / `UseLocalize` | 可选 |

动态表单 **conf JSON 设计器**属前端；引擎只认 Form 服务与节点绑定，不绑定某一 UI 框架。

## 11. 数据与持久化约定

- 访问经 **mooSQL**（`basis` / `UseRunSQL`）；事务内命令传 `SQLBuilder kit`。
- 核心运行表（定义、实例、活动、任务、变迁、变量等）属引擎 schema；**产品表**（抄送、分类、业务请假单）不得塞进 pure。
- Host `Probe/init-db` 可建扩展表，但不得要求改调度内核。

## 12. 与宿主产品面的边界

| 在引擎 | 在 Host / 前端 |
|--------|----------------|
| `Start/Run/Reject/…` 语义 | 按钮文案、确认框、菜单 |
| `GetTaskView` / Next·Previous 树 | `GetApprovalWorkbench` 聚合 DTO |
| Assignee ConfigPair | 选人控件、GroupRole 表单项 |
| Hook Outbox 实体与 Drain | 死信台页面、批量重试 UX |
| Form 服务与 FieldACL | form-create 设计器 |
| 无内置抄送箱（独立通道） | `sf_process_instance_copy`；**禁止**与 Assignee ConfigPair / 办理 Performer 混用 |
| 待办通知 | `ITaskNotifier`（回调与事件轨）；**禁止**塞进算人 Type |

破坏引擎基线的改动（换执行内核、把 `/bpm` 当引擎契约、删 AI/Rule/Hook 插槽）一律拒绝。

## 13. 已知债与演进优先级（基准上的「可改清单」）

| 项 | 说明 |
|----|------|
| 真并行会签 | 在现有 Multisign/SignForward 上演进，不照搬外部 MI 方案整体替换 |
| `Reverse` vs `SendBack` 文档化 | 接入方场景矩阵补齐，避免误用 |
| **Unit\* / StartUnit\* 落库（R1 修订）** | Performer/任务/活动/视图扩 UnitId·Code·Name（可空）；实例可选 StartUnit\*；Leave 仍只读 Group\* |
| **Assignee 双轨收口（R2）** | 删除 `Try*=false`→Definition/旧会签回落；运行时只走管道；缺配置按 R4 拒绝 |
| Assignee 缺配置 ReasonCode + FE 感知（R4） | 与单轨收口一并落地 |
| **设计默认 ConfigPair + 发布校验（R6）** | 新增 UserTask 预埋 ApproverPick+Collaborate；发布前 Type 非空；项目/模板可覆盖 |
| **组间 Count/Rate（R7）** | Leave 组间在 And/Or 外支持 groupCompleteCount/Rate（现行多仅 And/Or） |
| **队长细则（R8）** | 关卡与组员均建待办；Leave 以 gateRoles 办完为组完成 |
| **同码覆盖诊断（R9）** | 注册日志 + 运行标明 Overridden；禁止静默覆盖 |
| 宿主 Org/User 覆盖 Lookup（R3） | sleveen-admin 接组织人员；sailflow 只留钩子；**AssignedUserId=用户编码（如登录账号）** |
| EventFireType 部分未 Invoke | 新扩展走 Gate/Hook，旧 Subscribe 逐步收敛 |
| 转办/委派产品语义 | 仅当有清晰命令/状态机时再升一等公民；禁止空壳 API |
| Locator 去静态 | 管道文档中的后续议题；与本基线兼容 |
| 非办理等待统一 Resume | Timer/Msg/外部回调入口分裂；见 [草案-挂起与统一Resume.md](./草案-挂起与统一Resume.md)（未立项） |
| 命令入口执行管道 | 各动词 Gate 样板重复、引擎横切易散落；见 [草案-命令执行管道.md](./草案-命令执行管道.md)（未立项） |

## 14. 验收烟雾（引擎级）

不依赖具体 UI，宿主或测试可复现：

1. `SailClient` Build + `UseDatabase` + 必要 `UseXxx` → `new WorkflowService(client)`。  
2. 保存合法 BPMN → `StartProcess` → 待办可查（Query 或 TaskView）。  
3. `RunProcess` 到下一用户节点；`Reject` / `SendBack` / `Withdraw` 至少各一条路径。  
4. 注册 Gate 拒绝时 `WfExecutedResult` 可区分业务拒绝。  
5. Hook AsyncOutbox 写入并可 Drain/死信复活。  
6. Assignee：ConfigPair Resolve + Leave（含 GroupRole）一条；业务同码覆盖一条。  
7. Assignee（定型后）：缺 ConfigPair / 空办理人无 Fallback → 拒绝且 ReasonCode 可区分；不得回落 Definition。  
8. Unit\*：任务可带 UnitId/Code/Name（可空）；实例可选 StartUnit\*；Leave 不依赖 Unit。
