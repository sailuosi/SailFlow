# 专题 · 对象生命周期与复用边界

> 状态：**讨论草案 / 未定型**（2026-11-06）  
> 用途：立「**典型用例三分法**（A 应用单例富功能 / B 请求上下文·链式 / C 静态纯函数）」+ 寿命档位 +「变化进 B、A 主路径不持上下文」+ **引擎工厂必须降至 A（最高应用级单例，ClientBuilder 可覆写）**——并给关键类型拟定位，供评审拍板。**禁止**在未定型前大范围改静态 Factory / 散落 `new Manager`。  
> 关联：[架构设计-项目依赖与分层.md](../架构设计-项目依赖与分层.md) · [业务管道特性设计.md](../业务管道特性设计.md) · [开发手册-OA命令执行链路.md](./开发手册-OA命令执行链路.md) · [特性设计-回调与事件.md](../特性设计-回调与事件.md) · [草案-引擎异步化.md](../草案-引擎异步化.md)  
> 触发背景：办理链路上大量 `new ActivityInstanceManager(client)` 等；`client` 为应用单例、Manager 仅持 Client → 语义上无请求态，但**寿命档位从未立法**；同时命令参数散落字段/隐式 Runner，与「Context 承载变化」目标不一致。

---

## 1. 一句话

引擎里一类对象，先归入三种**典型用户级用例**之一，再落到寿命档位：

| 用例 | 一句话 | 并发 |
|------|--------|------|
| **应用单例 · 富功能类** | `SailClient`、方言、过滤器/拦截器/副作用、**引擎工厂**、Manager——同寿于一个 Client；**Builder 可覆写工厂** | 须可共享（或明确单线程宿主） |
| **请求级 · 上下文 / 链式构造** | 承载本请求变化；或链式袋持构造期参数；用毕即弃或 `Clear`；由 **A 工厂** Create 编排袋 | **一般不能并发** |
| **纯函数范式 · 静态工具** | 无策略纯变换（如 EnumHelper）；**不承载可替换工厂** | 天然可并发 |

外加：变化进 B；A 主路径不持 B（偏函数式）；**工厂封顶为应用级单例**（不得终态 static）。本稿只定思想与拟定位；**定型 → 再改代码**。

---

## 2. 为什么要立法（问题）

### 2.1 现状症状

```text
SailClient          ← Host AddSingleton（应用单例，契约相对清楚）
WorkflowService     ← Host AddScoped，但内部 _wfAppRunner 可变（壳与命令态叠在一起）
*Manager(client)    ← 仅持 Client，却处处 new；Mediator 内又懒缓存同寿于一次 Execute
WfRuntimeManager*   ← 按次 new，持 Runner / 结果（命令次级，合理）
NodeMediator*       ← 按次 new，持 Kit / LinkContext / Runner 上下文（命令次级，合理）
SQLBuilder kit      ← 命令入口 beginTransaction，参数下传（调用/事务级，合理）
```

同一类型（如 `ActivityInstanceManager`）出现两种叙事：

- Factory / Service：**瞬时** `new`；
- `NodeMediator`：**与本次 Mediator 同寿**的懒字段。

两边都不「错」，但**没有统一立法** → 新人无法判断「能不能在 Manager 上加实例缓存 / 当前用户」。

### 2.2 含糊寿命的典型后果

| 后续想加的能力 | 若误当应用单例 | 若误当瞬时且又加了字段 |
|----------------|----------------|------------------------|
| 请求 Correlation / User | 串请求、数据串户 | 字段写了却每次 new 丢掉，或半缓存半不缓存 |
| 定义/上一跳缓存 | 未做线程安全则竞态 | 缓存永远冷启动，行为不一致 |
| 指标 / 诊断计数器 | 全局累加 OK；若夹带请求维度则脏 | 无法挂稳定计数器 |
| 非线程安全懒资源（类旧 `ManagerBase.Repository`） | 多线程炸 | 「偶发」复用路径才炸，更难查 |

根因不是性能，是**依赖方向与状态归属失去裁决标准**。

### 2.3 用三分法重述：典型错档

| 错档 | 例子 | 后果 |
|------|------|------|
| 该 **A** 却当瞬时乱 `new` | `*Manager` 未立法 | 无法安全加缓存/指标；与 Mediator 懒缓存双叙事 |
| 该 **A** 却吸了 **B** | Service/`Manager` 扣 Runner、kit | 串请求；单例不可并发 |
| 该 **B** 却升单例 | 把未 Clear 的 Runner/Builder 挂全局 | 脏上下文 |
| 该 **B** 却当可并发 | 同 Scope 并行两个 `Run` 共一个 `_wfAppRunner` | 踩踏 |
| 该 **C** 却塞静态可变 | Factory 静态字典当「当前办理」缓存 | 隐性请求态，极难查 |

立法目标：每新增/改类型，先答「A / B / C？」，再答寿命与并发。

## 3. 设计思想

### 3.1 原则

1. **先归用例、再定档位**：新类型先回答属于 §3.2 三分法哪一类，再映射 L-App / L-Cmd / 静态工具。  
2. **一类一档**：文档（定型后可到类注释）写明寿命；评审必问「同寿于谁」。  
3. **依赖只指向更长寿或同寿**：短寿可持长寿；**禁止**长寿持短寿可变态。  
4. **状态跟寿命走**：请求变化 → 请求级 Context/链式袋；共享能力 → 应用单例富功能类；无状态变换 → 静态工具。  
5. **Context 承载变化，富功能类不吸上下文（偏函数式）**：见 §3.3。  
6. **立法先于优化**：先选用例与档位，再谈 Client 门面或 DI。  
7. **与分层正交**：包边界 ≠ 寿命 ≠ Context/Worker 分工。

### 3.2 典型用户级用例（三分法）

这是面向「写代码的人」的**第一分类**；§3.4 档位是实现映射。

#### A. 应用单例 · 富功能类（Rich App Singleton）

| 项 | 约定 |
|----|------|
| **是什么** | 进程（或一个 `SailClient`）内**共享**的能力载体：配置已装好、插件已挂上，被无数请求反复调用。 |
| **典型** | `SailClient`；各功能**方言**（Dialect / DB / JSON / 消息…）；**已注册**的 Assignee Filter、Flow Gate/Hook、Task Notifier、Outbox/副作用管道；`*Manager` 门面；**引擎工厂**（Runtime / Mediator / ProcessModel / Manager 创建，见 §3.7） |
| **持有** | 长寿依赖、注册表、可选线程安全只读缓存/指标 |
| **禁止** | 本次请求的 Runner、kit、User、LinkContext、未清理的链式中间态 |
| **调用形态** | `client.Xxx.Do(ctxOrArgs…)` —— 入参带齐请求信息 |
| **寿命映射** | **L-App**（主） |
| **并发** | 默认按可被多请求同时调用设计；若某实现不能，必须在类型上标明并禁止 Host 多线程入口 |

#### B. 请求级 · 上下文类 / 链式构造类（Request-scoped bag）

| 项 | 约定 |
|----|------|
| **是什么** | 只服务**一次请求或一次构造会话**的可变袋：装变化、装建造中参数。 |
| **两类形态** | ① **上下文类**：`WfAppRunner`、`ActivityForwardContext`、Gate/Hook Context、事务 `kit`… ② **链式 / 构造器**：`CreateRunner().UseApp().UseProcess()…`、各类 Builder——**构造期间**把参数收进自身 |
| **生命结束** | 见下方 **B.1 结束策略** |
| **并发** | **一般不能并发**（同一实例勿多线程读写；勿跨请求共享未 Clear 的实例） |
| **禁止** | 升为应用单例；在未 Clear 时被第二个请求复用；把富功能类的注册表塞进来当「第二个 Client」 |
| **寿命映射** | **L-Cmd**（办理）；链式建造过程也可视为短命 L-Cmd；Host 请求壳见 L-Scope |
| **与编排袋** | `WfRuntimeManager*` / `NodeMediator*` 现行是「加厚的请求级袋」——归本类，勿当成 A 类富功能 |

##### B.1 结束策略：用毕即弃 vs Clear

| 策略 | 适用 | 约定 |
|------|------|------|
| **用毕即弃** | 一次 HTTP/一次 `RunProcess` 内的 Runtime、Mediator、GateContext、kit | 不回收；下次重新 `new` / Build |
| **Clear / 重置** | 希望复用同一 Builder/Runner 袋做下一笔（少分配或链式 DX） | `Clear()` 后对外状态 ≡ 新建空袋；**Clear 前禁止**被另一逻辑请求使用 |
| **禁止** | 「半 Clear」只清部分字段 | 必留清单写进类型契约；未列字段视为泄漏 |

```text
链式示例（请求级，用毕即弃或 Clear）：
  service.CreateRunner(uid, name).UseApp(…).UseProcess(…).Run()
         └─ 建造中参数落在 B 袋上 → 结束应释放或 Clear
         └─ 理想：袋是 B；Service 是壳，不长期扣住袋
```

`Clear` **不**使 B 变成可并发；只允许「串行：Clear → 再建造 → 再执行」。

#### C. 纯函数范式 · 静态工具类（Pure / static）

| 项 | 约定 |
|----|------|
| **是什么** | **无实例可变状态**；相同入参 → 相同（或明确副作用边界外的）结果。 |
| **典型** | `EnumHelper`、纯计算/映射、无策略分支的字符串/集合工具；**不含**引擎命令选型工厂（见 §3.7） |
| **持有** | 无（或仅常量） |
| **禁止** | 静态可变字段当请求缓存；ThreadStatic 偷运 Context；**把可覆写的工厂做成不可替换的 static** |
| **调用形态** | `Util.Map(…)` |
| **寿命映射** | 无实例寿命 |
| **并发** | 天然可并发 |

> **修订**：`WfRuntimeManagerFactory` / `NodeMediatorFactory` / `ProcessModelFactory` 等**不再默认归 C**。现行虽是静态类，**定型目标是降至 A（应用级单例）**，以便 `SailClientBuilder` 覆写实例。见 §3.7。

#### 三分法对照（一眼）

```text
┌─ A 应用单例富功能 ── Client / Dialect / Filter·Gate·Hook / Manager / **引擎工厂** ─┐
│  共享 · 可并发（默） · 方法吃参数 · 不吸请求字段 · Builder 可覆写工厂实例              │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─ B 请求级上下文/链式 ── Runner · ForwardContext · kit · Builder袋 · Runtime/Mediator ─┐
│  装变化 · 用毕即弃或 Clear · 一般不能并发 · **由 A 工厂按次 Create**                    │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─ C 纯函数静态工具 ── EnumHelper · 纯映射（无策略、不可覆写） ──────────────────────────┐
│  无实例态 · 可并发 · 禁止静态请求缓存 · **不承载可替换工厂**                             │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**归类口诀**：能挂注册表 / 可被 Builder 替换 / 被全局调用 → **A**；只活一次请求/一次建造、字段在变 → **B**；没字段、纯变换、不可替换 → **C**。

### 3.3 本引擎职责：Context 与功能类（偏函数式）

#### 3.3.1 分工（与三分法对齐）

| 角色 | 对应用例 | 职责 | 持有 / 不持有 |
|------|----------|------|----------------|
| **富功能 Worker / 工厂** | **A** | 读库写库、过滤拦截、副作用；**选型并 Create B**；**创建并保管 Manager** | 持 L-App 依赖；**主路径不持** Context 字段 |
| **Context / 链式袋** | **B** | 承载本请求/本建造期变化 | 持 Runner、kit、中间结果；不持全局注册表 |
| **静态工具** | **C** | 无策略纯变换 | 无实例态；**不做可覆写工厂** |

操作化（A 类被调用时偏函数式）：

```text
result = AppSingletonWorker.Do(context, …)   // A 吃 B（或显式参数）
// 而非：worker._runner = runner; worker.Do();
```

B 类链式：

```text
bag = bag.UseX(…).UseY(…);  // 建造期参数进袋
// 结束后：丢弃，或 bag.Clear() 后复用同一实例（仍禁止并发）
```

#### 3.3.2 为何要立法（与三分法同一原因）

办理链变化点极多。若变化散落在 A 类字段、C 类静态可变、或 B 类未 Clear 就跨请求复用 → **用例错档**，寿命与并发假设全部作废。  
先「变化进 B、能力在 A、变换在 C」，A 才能稳定单例且可并发。

#### 3.3.3 与寿命档位的咬合

```text
A 富功能     → L-App
B 上下文/链式 → L-Cmd（或建造期短命袋）；Clear 复用仍是「逻辑上的新请求」
C 静态工具   → 无实例寿命；产出物另归 A/B
```

| 若违反 | 后果 |
|--------|------|
| A 持有 B 的字段 | 串请求；单例吸短寿态 |
| B 未 Clear 跨请求 | 脏数据；「偶发」难查 |
| B 多线程共用 | 数据竞争（**一般不能并发**） |
| C 用静态/ThreadStatic 偷运 B | 隐性请求态，比 A 吸字段更难发现 |

#### 3.3.4 现行对照（诚实差距）

| 区域 | 宜归 | 较符合 | 较偏离 |
|------|------|--------|--------|
| `SailClient` / Dialect / 已注册 Gate·Hook·Filter·Notifier | **A** | ✅ 应用单例 | — |
| `*Manager` 吃 kit/runner 参数 | **A** | ✅ 调用偏函数式 | ❌ 未立法、处处 `new` |
| `WfAppRunner` / `ActivityForwardContext` / Gate Context | **B** | ✅ | — |
| 链式 `CreateRunner().Use…` | **B** | ✅ 建造期参数 | ❌ `_wfAppRunner` 扣在 Service 上不 Clear |
| `WfRuntimeManager*` / `NodeMediator*` | **B 编排袋** | 按次创建 | 易被误当成 A；内懒 `new` Manager |
| `WfRuntimeManagerFactory` 等 | **宜 A** | 现行静态可调 | ❌ 静态不可按 Client 覆写；内散落 `new Manager`；`ProcessModelFactory` 还有静态缓存 |

定型时：**A 禁止持 B 字段**；**引擎工厂必须 A**（§3.7）；**B 编排袋**点名属 B；**Manager 只由 A 工厂/门面创建**。

### 3.4 寿命档位（词汇表）

| 档位代号 | 含义 | 同寿于 | 主要对应用例 |
|----------|------|--------|----------------|
| **L-App** | 应用单例 | 一个 `SailClient` / 进程根 | **A** 富功能 |
| **L-Scope** | 宿主请求壳 | ASP.NET Scope | Host 壳；内部若扣 B 须 Clear/勿并发 |
| **L-Cmd** | 办理命令次级 | 一次 Start/Run/… | **B** 上下文 / 编排袋 / kit |
| **L-Call** | 调用/语句级 | 单次 Sibling/语句 | 短命 B 碎片或 C 的瞬时句柄 |
| **L-Ephem** | 未立法瞬时（不推荐默认） | 任意次 `new` | 仅当显式拒绝 A 时 |

**推荐**：无请求态、只依赖 Client 的门面 → 归 **A / L-App**，勿停在未立法的 L-Ephem。

### 3.5 依赖方向（硬边界）

```text
L-App  ─────────────────────────────────────────────► 最长寿
  ▲ 可依赖
L-Scope（可选壳）
  ▲ 可依赖
L-Cmd（Context / 编排袋 / 事务 kit）
  ▲ 可依赖
L-Call
```

禁止箭头向上「吸」短寿状态进 L-App。  
禁止 **A** 把 **B** 收成字段。

```text
┌─ A / L-App：SailClient + Dialect + 注册表 + Managers + **Factories** ─┐
│  无 Runner/kit 字段；Do(kit, runner, …)；Create*(B 参数) → 产出 B        │
│  SailClientBuilder 可 useXxxFactory(自定义实例) 覆写                      │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ 注入 / 读取
┌─ 壳 / L-Scope：WorkflowService ───────────────────────────────────────┐
│  可持 A；理想不扣 B                                                     │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ 一次动词：经 A 工厂组装 B
┌─ B / L-Cmd：Runner · kit · Runtime · Mediator · Context ─────────────┐
│  调用 A Manager；用毕即弃或 Clear；一般不能并发                          │
└───────────────────────────────────────────────────────────────────────┘
         C 仅纯工具（EnumHelper…）；不承载可替换工厂
```

### 3.6 新增 / 改类型检查清单（评审用）

定型后可作为 PR / 设计评审必答（草案阶段先作讨论清单）：

1. **用例**：A / B / C？（不能「都有一点」——编排袋点名属 B；**引擎工厂不得标 C**）  
2. **寿命**：L-App / L-Scope / L-Cmd / L-Call / 静态无实例？  
3. **并发**：默认可共享（A/C）还是一般不能并发（B）？  
4. **若 A**：方法是否吃齐 B/参数？有无请求字段？缓存是否线程安全？**若是工厂：是否挂在 Client、Builder 能否覆写？**  
5. **若 B**：用毕即弃还是 Clear？Clear 字段清单？谁拥有袋子（勿扣在 A 上）？  
6. **若 C**：是否误把可覆写工厂做成 static？有无静态可变 / ThreadStatic？  
7. **依赖方向**：是否出现 A→持有 B、C→偷运 B、业务代码私自 `new Manager`？  

### 3.7 工厂职责与档位（必须降至应用级单例）

#### 3.7.1 一句话

**引擎侧「工厂」必须下降并封顶为应用级单例（A / L-App，同寿于一个 `SailClient`）**——不得以进程级不可替换的 `static` 类作为终态；以便在 **`SailClientBuilder` / `useXxxFactory` 中覆写工厂实例**（测替、租户定制、特殊选型策略）。

「下降」相对现状：现行 `WfRuntimeManagerFactory` 等是**类型级静态**（比 A 更「飘」、且无法按 Client 注入）。  
「最高为应用级」：禁止再升到「全进程唯一、与 Client 脱钩、Builder 换不掉」的全局静态上帝。

#### 3.7.2 职责切分

| 工厂角色（均属 **A**） | 职责 | 产出 |
|------------------------|------|------|
| **Manager 工厂 / Client 门面** | **唯一**创建并保管 `ActivityInstanceManager`、`TaskManager`、`ProcessInstanceManager`… | **A** Manager 实例（每 Client 一套，懒创建） |
| **Runtime 工厂** | 按动词选型、预检（经 Manager 读库）、灌装 **B** 袋 | **B** `WfRuntimeManager*` |
| **Mediator 工厂** | 按节点类型选型，灌装 ForwardContext/kit | **B** `NodeMediator*` |
| **ProcessModel 工厂** | 加载/缓存流程定义模型（缓存属 A 合法能力，须线程安全） | 模型供 **B** 使用期持有 |

```text
SailClientBuilder
  .UseRuntimeFactory(customOrDefault)      // 覆写 A
  .UseMediatorFactory(…)
  .UseProcessModelFactory(…)
  .UseManagers(…) / 默认门面
  .Build()
       │
       ▼
SailClient（A）
  ├─ RuntimeFactory（A）──Create*(runner, kit, …)──► Runtime（B）
  ├─ MediatorFactory（A）─Create*(forward, kit, …)─► Mediator（B）
  ├─ ProcessModelFactory（A）─CreateBy*(…)─────────► Model（使用期随 B）
  └─ Managers（A）◄── 仅工厂/门面可 new；Service/Mediator/Runtime 只读取
```

#### 3.7.3 红线

| 做 | 不做 |
|----|------|
| 工厂实例挂在 `SailClient`；默认实现 Build 时装上 | 业务代码 / Mediator / Service **私自** `new XxxManager(client)` |
| `SailClientBuilder.UseXxxFactory(IXxxFactory)` 可替换 | 工厂做成 **不可覆写的 static 类** 作为终态 API |
| Manager **只**由 Manager 门面/工厂创建 | Runtime 工厂内部继续散落 `new Manager`（过渡期可暂存，定型后删除） |
| Create* 方法吃 **B 参数**（runner、kit、forwardContext），工厂自身不扣 B 字段 | 工厂字段吸 Runner/kit；或静态字典偷运「当前办理」 |
| 多 `SailClient` → 多套工厂实例 | 全进程一个 static Factory 服务所有 Client |

#### 3.7.4 与 Builder 覆写的关系（动机）

与现有 `useMessageQueue` / `UseFlowGate` / `useAssigneePipeline` 同构：

- **默认**：Build 装配内置工厂实现。  
- **覆写**：测试可注入 Fake RuntimeFactory；产品可换「带审计的 MediatorFactory」或「带租户过滤的 ProcessModelFactory」。  
- **若工厂停留在 static**：覆写只能靠改源码或危险的静态替换，**违反「组合根在 Builder」**（见 [业务管道特性设计.md](../业务管道特性设计.md)）。

概念形状（立项后定 API 名，本稿不拍最终签名）：

```csharp
// 概念：非现行 API
builder.Services.UseRuntimeFactory(sp => new MyRuntimeFactory());
// 或
builder.UseRuntimeFactory(new MyRuntimeFactory());
var sail = builder.Build();
// 运行期：
sail.RuntimeFactory.CreateRuntimeInstanceAppRunning(runner, kit, ref result);
```

#### 3.7.5 现行差距（诚实）

| 现状 | 问题 | 定型目标 |
|------|------|----------|
| `WfRuntimeManagerFactory` 全静态 + 内 `new Manager` | 不可按 Client 覆写；Manager 无主 | **A** 实例；Create 只用 Client.Managers |
| `NodeMediatorFactory` 全静态 | 同上 | **A** 实例挂 Client |
| `ProcessModelFactory` 静态 + `ConcurrentDictionary` 缓存 | 缓存是 A 能力，却挂在 C 形态上 | **A** 实例；缓存进该实例或 Client |
| Mediator 懒 `new Manager` | 第二套「创建权」 | 改为读 A Managers |

**过渡**：允许保留 static 转发到 `SailClient` 上默认工厂（兼容旧调用），但文档与新代码以实例为准；禁止新增 static 工厂 API。

## 4. 利弊（选型时对照）

### 4.1 坚持三分法 + A 不吸 B

| 利 | 弊 |
|----|----|
| 变化归属清晰；A 可安全共享、可测 | 参数列表变长；需习惯显式传 ctx |
| 与寿命立法同向 | 现行 Mediator/Runtime 作 B 编排袋需点名，防误当成 A |
| Gate/Hook 已有 B Context 习惯 | 链式 DX（壳扣 B）需收敛或标例外 |
| B 并发边界清楚（一般不能） | 过薄拆编排可能损可读性——编排袋允许但须属 B |

### 4.2 将无状态 Manager 定为 L-App（推荐方向）

| 利 | 弊 |
|----|----|
| 寿命与「只依赖 Client」语义一致；符合 Worker 角色 | 改动面：调用点从 `new` 改为 Client 门面或注入 |
| 后续横切（只读缓存、指标）有合法挂点，且强制线程安全评审 | 误加请求字段（变成吸 Context）会造成全局事故 |
| 与 Host `SailClient` Singleton 自然对齐 | 测试需可替换 Client / 门面 |

### 4.3 将 Manager 明定为 L-Ephem（处处 new）

| 利 | 弊 |
|----|----|
| 零装配、现状改动小 | 与「Worker = L-App」及 Mediator 懒缓存矛盾 |
| 「绝无实例缓存」简单粗暴 | 横切无处安放；易在临时对象上偷偷加字段 |

### 4.4 WorkflowService：Scoped 壳 + 命令态 Runner

| 利 | 弊 |
|----|----|
| 链式 `CreateRunner…Start()` 方便 | **壳吸住 B 类袋**，偏离 §3.2；不可升 A/L-App |
| 与 ASP.NET 请求边界大致同寿 | 同 Scope 并发/重入踩 `_wfAppRunner`（B **一般不能并发**） |

### 4.5 Runtime / Mediator：B 类编排袋（现状）vs 更薄 Context（远期）

| 路径 | 利 | 弊 |
|------|----|----|
| **保留为 B 编排袋** | 与现码对齐 | 易被误当成 A 富功能 |
| **拆成显式 Context + 薄编排** | 更贴 §3.2/3.3 | 改动面大；D4 专项 |

### 4.6 引擎工厂：静态 C（现状）vs 应用级 A + Builder 覆写（定型方向）

| 路径 | 利 | 弊 |
|------|----|----|
| **维持全 static** | 零装配、调用短 | **无法**按 Client / Builder 换实现；Manager 创建权涣散；与管道组合根哲学冲突 |
| **降至 A，挂 Client，Builder 可覆写**（推荐） | 测替/租户/审计可插；Manager 创建有主；多 Client 隔离 | 需迁 API：`sail.RuntimeFactory.Create*`；过渡期 static 转发 |

**结论倾向（待拍板）**：

- **A**：Client / Dialect / 注册 Filter·Gate·Hook·Notifier / **Manager** / **引擎工厂（Runtime·Mediator·ProcessModel·Manager 创建）** → L-App；方法吃 B；不持 B 字段；**Builder 可覆写工厂**。  
- **B**：Runner、Forward/Gate Context、kit、链式建造袋、Runtime/Mediator **实例** → L-Cmd；由 **A 工厂** Create；用毕即弃或 Clear。  
- **C**：仅无策略纯工具（如 EnumHelper）；**不承载可替换工厂**。  
- **`WorkflowService`**：L-Scope 壳；理想不长期扣 B。

## 5. 架构落位（与分层、管道的关系）

| 主题 | 关系 |
|------|------|
| 三分法 × 分层 | pure 内可同时有 A/B/C；包边界不决定用例档 |
| A / B / C | 能力与**工厂**在 A；变化在 B；无策略纯变换在 C |
| `SailClient` / Builder | **A** 组合根；**工厂实例挂 Client**；`UseXxxFactory` 覆写 |
| Gate / Hook / Notifier / Filter | **A** 注册；每次传入 **B** Context |
| 链式 Builder（Runner） | **B**；结束丢弃或 Clear；勿当 A |
| 引擎 `*Factory` | **A**（封顶应用单例）；**禁止**终态 static；产出 B |
| Manager 创建 | **仅** A 门面/Manager 工厂；Runtime/Mediator 工厂只读取 |
| 事务 kit | **B**；只参数下传 |
| DI | Client=A；工厂随 Client；Service=壳 |

## 6. 相关类型：现行用法 vs 拟定位

> **拟定位**为讨论稿，定型前不得当实施依据。  
> 列 **用例（A/B/C）** + 寿命档位；红线见 §3.2。

### 6.1 A · 应用单例富功能（L-App）

| 类型 | 现行 | 拟定位 | 说明 / 红线 |
|------|------|--------|-------------|
| `SailClient` | Host Singleton | **A / L-App** | 富功能根；禁止持本次 Runner/kit |
| Dialect / DBFactory / JSON 等已挂能力 | 挂在 Client | **A / L-App** | 方言与基础设施 |
| `IAssigneePipeline` 及 Resolver/Filter | 挂在 Client | **A / L-App** | 已注册过滤器；解析吃入参 |
| Gate / Hook / TaskNotifier 注册与 Dispatcher | 挂在 Client | **A / L-App** | 拦截器/副作用注册；执行吃 **B** Context |
| `InstanceExecutionLock` 机制 | 应用级 | **A / L-App** | 机制共享；key 来自 B |
| `ActivityInstanceManager` 等 `*Manager` | 处处 `new` | **A / L-App** | 仅由 **Manager 工厂/门面**创建；禁止 Runner 字段 |
| `PreviousStepChecker` / `NextStepParser` 等 | `new(client)` | **A / L-App** | 同上或并入门面 |
| **`IWfRuntimeManagerFactory` / 实现** | 现行静态类 | **A / L-App** | 挂 Client；Create* → **B** Runtime；Builder 可覆写 |
| **`INodeMediatorFactory` / 实现** | 现行静态类 | **A / L-App** | 同上 → **B** Mediator |
| **`IProcessModelFactory` / 实现** | 静态 + 静态缓存 | **A / L-App** | 缓存进实例；Builder 可覆写 |
| **Manager 工厂 / Client.Managers** | 无 | **A / L-App** | **唯一** `new Manager` 入口 |

装配：默认 Build 装内置工厂；`UseXxxFactory` 覆写。禁止散落 `new XxxManager(Sail)`。

### 6.2 C · 纯函数静态工具（不含引擎工厂）

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `EnumHelper` 等纯映射 | 静态 | **C** | 无策略、不可覆写 |
| （过渡）旧 static Factory 转发 | 静态壳 | **弃用** | 仅转发到 Client 上 A 工厂；禁止新 API |

### 6.3 壳（L-Scope）与偏离

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `IWorkflowService` / `WorkflowService` | Scoped + `_wfAppRunner` | 壳 + 误持 **B** | 理想：链式参数进 B，壳不扣袋；见 §3.3.4 |
| `WorkflowQueryService` 等 | Scoped + Client | 壳 | 无 Runner 字段则干净 |

### 6.4 B · 请求级上下文 / 链式 / 编排袋（L-Cmd）

| 类型 | 现行 | 拟定位 | 说明 / 红线 |
|------|------|--------|-------------|
| `WfAppRunner` | 入参 / 链式 | **B / L-Cmd** | 上下文；亦可作链式建造终点；不进 Client |
| `WfExecutedResult` | 按次 | **B / L-Cmd** | 输出袋 |
| `ActivityForwardContext` / `BackwardContext` / `SendBackOperation` / `ActivityResource` | 按次 | **B / L-Cmd** | 上下文 |
| Gate/Hook `*Context` | 按次 Build | **B / L-Cmd** | 符合 §3.2 |
| 入口 `SQLBuilder kit` | 按次 | **B / L-Cmd** | 事务根；只下传 |
| 链式 `CreateRunner().UseApp()…` | 建造期写字段 | **B** | 用毕即弃或 **Clear**；**一般不能并发** |
| `WfRuntimeManager*` | 按次；持 Runner/AI | **B 编排袋** | 由 **A** RuntimeFactory Create；禁止升 A |
| `NodeMediator*` / `NodeSendBack*` | 按次；持 Kit/Link | **B 编排袋** | 由 **A** MediatorFactory Create；Manager → **A** 引用 |

### 6.5 调用级碎片（L-Call · 短命 B 或 C 句柄）

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `SailSqlAccess.Sibling(kit)` 结果 | 临时 | **L-Call** | 同事务、短用；勿塞进 **A** |
| mooSQL `useRepo` / `useClip` 句柄 | 临时 | **L-Call** | 同上 |

### 6.6 Host 侧（对照）

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `SailOperationDispatcher` / Handlers | 无状态则偏 **A** | A 或壳 | 不持 Runner 字段 |
| `Wf2XmlController` | 请求级 | Host **B** 边界 | — |

## 7. 与 OA 命令链的对照（读法）

```text
ButtonsOperation（Host 请求）
  → WorkflowService（壳；理想不扣 B）
      → 组装 B：kit + Lock + Runner
      → A RuntimeFactory.Create*(runner, kit, …)
            └─ 经 A Managers 读库 → 产出 B Runtime 编排袋
      → A Gate + 本次 B GateContext
      → B Runtime.Execute
          → A MediatorFactory.Create*(forward, kit) → B Mediator
              → A Managers.Write(kit, …)
      → A Hook + 本次 B HookContext
```

```text
// A Manager ✅
sail.Managers.Activities.Complete(kit, id, runner);
// ❌ new ActivityInstanceManager(sail); 或 aim.CurrentRunner = runner;

// A 工厂覆写（概念）
builder.UseRuntimeFactory(new MyRuntimeFactory());
```

链路细节见 [开发手册-OA命令执行链路.md](./开发手册-OA命令执行链路.md)；用例与寿命标签以本专题定型为准回写。
