# 专题 · 对象生命周期与复用边界

> 状态：**D1 思想定型**（2026-11-06；§H.1 / §8 / §11；D2 起契约显现）  
> 用途：立「**A/B/C + 壳 H**」+ 寿命档位 +「变化进 B、A 不持 B」+ **引擎工厂改档为每 Client 的 A（相对进程 static 下降封顶，Builder 可覆写）**——拟定位供评审。**禁止**未定型前大改静态 Factory / 散落 `new Manager`。  
> 关联：[架构设计-项目依赖与分层.md](../架构设计-项目依赖与分层.md) · [业务管道特性设计.md](../业务管道特性设计.md) · [开发手册-OA命令执行链路.md](./开发手册-OA命令执行链路.md) · [特性设计-回调与事件.md](../特性设计-回调与事件.md) · [草案-引擎异步化.md](../草案-引擎异步化.md)  
> 触发背景：办理链路上大量 `new ActivityInstanceManager(client)` 等；`client` 为应用单例、Manager 仅持 Client → 语义上无请求态，但**寿命档位从未立法**；同时命令参数散落字段/隐式 Runner，与「Context 承载变化」目标不一致。

---

## 1. 一句话

引擎里一类对象，先归入用例，再落到寿命档位。

| 用例 | 一句话 | 并发 |
|------|--------|------|
| **A · 应用级富功能** | 同寿于**一个 `SailClient`**（非「进程上帝」）：方言、过滤器/拦截器/副作用、**引擎工厂**、Manager；**Builder 可覆写工厂** | 默认可被多请求共享 |
| **B · 请求级上下文 / 链式** | 本请求变化或建造期参数；用毕即弃或 `Clear`；编排袋由 **A 工厂** Create | **一般不能并发** |
| **C · 纯函数静态工具** | 无策略纯变换（如 `EnumHelper`）；**不承载可替换工厂** | 天然可并发 |
| **壳 / 组合根**（辅档） | Host `WorkflowService` 等壳；`SailClientBuilder` 建造期——**不是请求 B**，也不得做成进程 static | 壳随 Host；Builder 用毕即弃 |

外加：变化进 B；A 主路径不持 B（偏函数式）；**工厂改档为 A，并相对进程级 static「下降封顶」为每 Client 一套**（不得终态不可覆写 static）。本稿只定思想与拟定位；**定型 → 再改代码**。

> **「应用级」口径**：权威锚点是 **一个 `SailClient` 实例**（Host 常见再把它 `AddSingleton`）。多 Client（多库/多租户）= 多套 A，**不是**全进程共用一个工厂。

## 2. 为什么要立法（问题）

### 2.1 现状症状

```text
SailClient          ← Host AddSingleton（应用单例，契约相对清楚）
WorkflowService     ← Host AddScoped，但内部 _wfAppRunner 可变（壳与命令态叠在一起）
*Manager(client)    ← 仅持 Client，却处处 new；Mediator 内又懒缓存同寿于一次 Execute
WfRuntimeManager*   ← 按次 new，持 Runner / 结果（命令次级，合理）
NodeMediator*       ← 按次 new，持 Kit / LinkContext / Runner 上下文（命令次级，合理）
SQLBuilder kit      ← 命令入口 beginTransaction，参数下传（调用/事务级，合理）
```

同一类型（如 `ActivityInstanceManager`）出现两种叙事：

- Factory / Service：**瞬时** `new`；
- `NodeMediator`：**与本次 Mediator 同寿**的懒字段。

两边都不「错」，但**没有统一立法** → 新人无法判断「能不能在 Manager 上加实例缓存 / 当前用户」。

### 2.2 含糊寿命的典型后果

| 后续想加的能力 | 若误当应用单例 | 若误当瞬时且又加了字段 |
|----------------|----------------|------------------------|
| 请求 Correlation / User | 串请求、数据串户 | 字段写了却每次 new 丢掉，或半缓存半不缓存 |
| 定义/上一跳缓存 | 未做线程安全则竞态 | 缓存永远冷启动，行为不一致 |
| 指标 / 诊断计数器 | 全局累加 OK；若夹带请求维度则脏 | 无法挂稳定计数器 |
| 非线程安全懒资源（类旧 `ManagerBase.Repository`） | 多线程炸 | 「偶发」复用路径才炸，更难查 |

根因不是性能，是**依赖方向与状态归属失去裁决标准**。

### 2.3 用三分法重述：典型错档

| 错档 | 例子 | 后果 |
|------|------|------|
| 该 **A** 却当瞬时乱 `new` | `*Manager` 未立法 | 无法安全加缓存/指标；与 Mediator 懒缓存双叙事 |
| 该 **A** 却吸了 **B** | Service/`Manager` 扣 Runner、kit | 串请求；单例不可并发 |
| 该 **A** 却做成进程级不可覆写 static | 引擎 Factory 全 static，Builder 换不掉 | 无法测替/按 Client 隔离；违组合根 |
| 该 **A**（可缓存）却用 C 形态挂全局字典 | `ProcessModelFactory` 静态缓存跨 Client | 隐性共享、难测 |
| 该 **B** 却升单例 | 未 Clear 的 Runner 挂全局 | 脏上下文 |
| 该 **B** 却当可并发 | 同 Scope 并行两动词共 `_wfAppRunner` | 踩踏 |
| 该 **C** 却塞静态可变/偷运请求 | ThreadStatic「当前 Runner」 | 隐性请求态 |
| 壳扣死 B 不 Clear | `WorkflowService._wfAppRunner` | 重入/并发踩踏 |

立法目标：先答「A / B / C / 壳？」，再答寿命与并发。

## 3. 设计思想

### 3.1 原则

1. **先归用例、再定档位**：先答 §3.2 的 A/B/C/壳，再映射 L-*。
2. **一类一档**：写明寿命；评审必问「同寿于谁」（默认：**哪个 `SailClient`**）。
3. **依赖只指向更长寿或同寿**：短寿可持长寿；**禁止**长寿持短寿可变态。
4. **状态跟寿命走**：请求变化 → B；共享能力 → A（每 Client）；无策略变换 → C。
5. **Context 承载变化，富功能类不吸上下文（偏函数式）**：见 §3.3。
6. **立法先于优化**：先选用例与档位，再谈 Client 门面。
7. **与分层正交**：包边界 ≠ 寿命 ≠ A/B/C。

### 3.2 典型用户级用例（主三分 + 壳辅档）

面向写代码的人的**第一分类**；§3.4 是寿命映射。

#### A. 应用级 · 富功能类（Rich App Singleton，锚点 = 一个 SailClient）

| 项 | 约定 |
|----|------|
| **是什么** | **同一个 `SailClient`** 内共享的能力：配置与插件已挂好，被该 Client 上无数请求反复调用。 |
| **典型** | `SailClient`；方言（Dialect / DB / JSON / 消息…）；已注册 Filter / Gate / Hook / Notifier；`*Manager`；**引擎工厂**（§3.7）；`InstanceExecutionLock`（**A·协调机制**，见下） |
| **持有** | 长寿依赖、注册表、可选**线程安全**只读缓存/指标；协调器用并发字典等 |
| **禁止** | 本次 Runner、kit、User、LinkContext、未清理链式中间态；**跨 Client 共享同一工厂/Manager 实例** |
| **调用形态** | `client.Xxx.Do(ctxOrArgs…)` / `client.RuntimeFactory.Create*(…)` |
| **寿命映射** | **L-App** |
| **并发** | 默认可多请求同时调用；不能则类型上标明 |
| **口语** | 「应用单例」= **Client 级**，不是「进程里只能有一个」；Host 常再 `AddSingleton(SailClient)` |

**A·协调机制**（如 `InstanceExecutionLock`）：可变共享表按 key 互斥，仍归 A，但**不是**无状态数据门面；勿与 Manager 混谈「无字段即可乱加缓存」。

#### B. 请求级 · 上下文类 / 链式构造类（Request-scoped bag）

| 项 | 约定 |
|----|------|
| **是什么** | 只服务**一次请求或一次构造会话**的可变袋：装变化、装建造中参数。 |
| **两类形态** | ① **上下文类 / 袋**：`WfAppRunner`、命令 Context、`ActivityForwardContext`、Gate/Hook Context、事务 `kit`… ② **链式建造器**：**`RunBuilder`**（`sail.CreateRunBuilder()…UseApp()…Build()`）——**构造期间**把参数收进自身；**禁止**焊在 Client/Service 字段上（§H.1） |
| **生命结束** | 见下方 **B.1 结束策略** |
| **并发** | **一般不能并发**（同一实例勿多线程读写；勿跨请求共享未 Clear 的实例） |
| **禁止** | 升为应用单例；在未 Clear 时被第二个请求复用；把富功能类的注册表塞进来当「第二个 Client」 |
| **寿命映射** | **L-Cmd**（办理）；链式建造过程也可视为短命 L-Cmd；Host 请求壳见 L-Scope |
| **与编排袋** | `WfRuntimeManager*` / `NodeMediator*` 是加厚的请求级袋——归 **B**，勿当成 A |

##### B.0 编排袋字段白名单（防变成伪 A）

B 编排袋（Runtime / Mediator）**只允许**持本命令导航状态，例如：

- 允许：`AppRunner`、`Kit`、`ProcessModel`（使用期引用）、`RunningActivityInstance`、`TaskView`、`ActivityResource`、`LinkContext`、`BackwardContext`、`SendBackOperation`、执行结果。
- 允许：对 **A** 的**只读引用**（`Sail` / Managers / Factories）——用于调用，不在袋内 `new` Manager。
- **禁止**：自建注册表；把 Gate/Hook/Filter 列表拷进字段；实例级「当前用户」缓存当全局；私自 `new XxxManager`。

业务规则仍落在 **A** 或 **C**，不要堆进编排袋。

##### B.1 结束策略：用毕即弃 vs Clear

| 策略 | 适用 | 约定 |
|------|------|------|
| **用毕即弃** | 一次 HTTP/一次 `RunProcess` 内的 Runtime、Mediator、GateContext、kit | 不回收；下次重新 `new` / Build |
| **Clear / 重置** | 希望复用同一 Builder/Runner 袋做下一笔（少分配或链式 DX） | `Clear()` 后对外状态 ≡ 新建空袋；**Clear 前禁止**被另一逻辑请求使用 |
| **禁止** | 「半 Clear」只清部分字段 | 必留清单写进类型契约；未列字段视为泄漏 |

```text
链式示例（定型，用毕即弃）：
  ctx = sail.CreateRunBuilder(uid, name).UseApp(…).UseProcess(…).Build()
  executor.Run(ctx)   // 或 sail.RuntimeFactory.Create*(ctx).Execute(kit)
         └─ RunBuilder / Context 皆 B；Client/Service 不扣袋（§H.1）
```

`Clear` **不**使 B 变成可并发；只允许「串行：Clear → 再建造 → 再执行」。

#### C. 纯函数范式 · 静态工具类（Pure / static）

| 项 | 约定 |
|----|------|
| **是什么** | **无实例可变状态**；相同入参 → 相同（或明确副作用边界外的）结果。 |
| **典型** | `EnumHelper`、纯计算/映射、无策略分支的字符串/集合工具；**不含**引擎命令选型工厂（见 §3.7） |
| **持有** | 无（或仅常量） |
| **禁止** | 静态可变字段当请求缓存；ThreadStatic 偷运 Context；**把可覆写的工厂做成不可替换的 static** |
| **调用形态** | `Util.Map(…)` |
| **寿命映射** | 无实例寿命 |
| **并发** | 天然可并发 |

> **修订**：引擎 `*Factory` **不再归 C**。现行静态 → 定型为 **A（每 Client 一套）**，相对进程 static「下降封顶」；`SailClientBuilder` 可覆写。见 §3.7。

#### H. 壳 / 组合根（辅档，勿硬塞进 A/B/C）

| 项 | 约定 |
|----|------|
| **Host 壳** | 如 `WorkflowService`（L-Scope）：可持 **A**（`Sail`）；**不扣 B**；链式不经 Service 字段（见 §H.1） |
| **组合根 Builder** | `SailClientBuilder`：仅 **Build 前**可变；Build 后冻结进 Client；**不是**请求级 B，也禁止升进程 static 上帝 |
| **Handlers** | 无状态则偏 A 或薄壳；不持 Runner 字段 |

##### H.1 定型：Client → 每次 `new RunBuilder` → Context → 执行器

**定型结论（D1）**：保留链式 DX 与办理入参袋；**所有权离开 `WorkflowService`**。由 **`SailClient` 方法**每次 **`new RunBuilder`**（B 建造会话），`Use*` 写建造器；`Build()` 产出 **Context**（B）；再交给执行器（RuntimeFactory / 薄壳转发）。**禁止**把 Runner/建造态做成 Client 或 Service 的实例字段/属性。

**现行问题**（对照）：

```text
wf.CreateRunner(uid, name).UseApp(…).UseProcess(…).Start();
         └─ 写 Service._wfAppRunner（B 扣在 H 上）── Start 读自己
```

`WorkflowService.Chain.cs`：`_wfAppRunner` + `Use*` 返回 `this`。链式无罪；错在挂 Scoped 壳且无 Clear/禁重入立法。

**定型形态**：

```text
SailClient（A）
  └─ CreateRunBuilder(…) / RunBuilder(…)   ← 方法，每次 new；非属性、不缓存
        └─ RunBuilder（B，建造期）
              .UseApp / .UseProcess / .NextStep …
              .Build() → Context（B；可含或即 WfAppRunner 视图）
                    └─ RuntimeFactory.Create*(ctx).Execute(kit)
                       或薄 H：workflow.Run(ctx) 只转发、不持袋
```

| 角色 | 档 | 约定 |
|------|-----|------|
| `SailClient` 开建造器入口 | A 上的方法 | **每次 new**；Client **无** `_runner` / `UseAppRunner` 属性 |
| **`RunBuilder`** | B 建造期 | 链式 `Use*`；名强调建造，勿与「正在跑」混淆 |
| **Context / `WfAppRunner`（袋）** | B | `Build()` 产物 = 命令入参 Context（§8.7）；类型名一期可用 `WfAppRunner` 或 `FlowCommandContext` |
| Runtime / 执行路径 | B 编排 + A Worker | **吃** Context；主路径不持 Context 字段 |
| `WorkflowService` | H | 可薄转发；**D3 起去掉 `_wfAppRunner` 与无参 Start 读字段** |

命名备选入口：`CreateRunBuilder` / `NewRun` / `Run()`——避免 `UseAppRunner` 听起来像给 Client 配属性。  
袋名可暂留 `WfAppRunner`；**建造器与袋分名**（`RunBuilder` ≠ 袋）。

**已否决**：

| 方案 | 为何否 |
|------|--------|
| **H0** 永久扣在 Service + 靠 Clear | 壳吸 B；纪律易漏 |
| **H2** 砍尽链式 | DX 损失过大；定型选择留链式、搬所有权 |
| Client/Service **属性**挂 Runner | 把 A/H 变成第二个 `_wfAppRunner` |

过渡：D3 前旧 `CreateRunner…Start()` 可标弃用并转发到 RunBuilder 路径；新代码只走 Client → RunBuilder → Context → 执行器。

#### 对照（一眼）

```text
┌─ A（每 SailClient）── Dialect / Filter·Gate·Hook / Manager / 引擎工厂 / Lock机制 ─┐
│  可并发（默）· 吃参数 · 不吸 B · Builder 可覆写工厂                                      │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─ B（每命令/建造会话）── RunBuilder · Context/WfAppRunner · kit · Runtime/Mediator ──┐
│  用毕即弃或 Clear · 一般不能并发 · 由 A 工厂 Create · 字段白名单见 B.0                    │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─ C ── EnumHelper 等纯映射（不可覆写工厂） ───────────────────────────────────────────┐
└──────────────────────────────────────────────────────────────────────────────────┘
┌─ H 壳/组合根 ── WorkflowService（薄转发）· SailClientBuilder（辅档） ────────────────┐
│  不扣 Runner；链式见 §H.1                                                            │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**口诀**：挂注册表 / Builder 可换 / 每 Client 共享 → **A**；一次请求或一次建造在变（含 **RunBuilder**）→ **B**；无字段纯变换 → **C**；Host 薄壳或 Build 期 → **H**。

### 3.3 本引擎职责：Context 与功能类（偏函数式）

#### 3.3.1 分工（与三分法对齐）

| 角色 | 对应用例 | 职责 | 持有 / 不持有 |
|------|----------|------|----------------|
| **富功能 Worker / 工厂** | **A** | 读库写库、过滤拦截、副作用；**选型并 Create B**；**创建并保管 Manager** | 持 L-App 依赖；**主路径不持** Context 字段 |
| **Context / 链式袋** | **B** | 承载本请求/本建造期变化 | 持 Runner、kit、中间结果；不持全局注册表 |
| **静态工具** | **C** | 无策略纯变换 | 无实例态；**不做可覆写工厂** |

操作化（A 类被调用时偏函数式）：

```text
result = AppSingletonWorker.Do(context, …)   // A 吃 B（或显式参数）
// 而非：worker._runner = runner; worker.Do();
```

B 类链式（定型）：

```text
ctx = sail.CreateRunBuilder(…).UseX(…).UseY(…).Build();  // RunBuilder → Context
executor.Run(ctx);
// RunBuilder/Context 用毕即弃；若 Clear 复用仍禁止并发；永不写回 Client 字段
```

#### 3.3.2 为何要立法（与三分法同一原因）

办理链变化点极多。若变化散落在 A 类字段、C 类静态可变、或 B 类未 Clear 就跨请求复用 → **用例错档**，寿命与并发假设全部作废。  
先「变化进 B、能力在 A、变换在 C」，A 才能稳定（每 Client）且可并发。

#### 3.3.3 与寿命档位的咬合

```text
A 富功能     → L-App（锚点 = 一个 SailClient）
B 上下文/链式 → L-Cmd（或建造期短命袋）；Clear 复用仍是「逻辑上的新请求」
C 静态工具   → 无实例寿命
H 壳         → L-Scope；组合根 Builder 仅 Build 期
```

| 若违反 | 后果 |
|--------|------|
| A 持有 B 的字段 | 串请求；单例吸短寿态 |
| B 未 Clear 跨请求 | 脏数据；「偶发」难查 |
| B 多线程共用 | 数据竞争（**一般不能并发**） |
| C 用静态/ThreadStatic 偷运 B | 隐性请求态，比 A 吸字段更难发现 |

#### 3.3.4 现行对照（诚实差距）

| 区域 | 宜归 | 较符合 | 较偏离 |
|------|------|--------|--------|
| `SailClient` / Dialect / 已注册 Gate·Hook·Filter·Notifier | **A** | ✅ 应用单例 | — |
| `*Manager` 吃 kit/runner 参数 | **A** | ✅ 调用偏函数式 | ❌ 未立法、处处 `new` |
| `WfAppRunner` / `ActivityForwardContext` / Gate Context | **B** | ✅ | — |
| 链式 / `RunBuilder` | **B** | ✅ Client 每次 new → Build→Context（§H.1） | ❌ `_wfAppRunner` 扣在 Service；Client 属性挂袋 |
| `WfRuntimeManager*` / `NodeMediator*` | **B 编排袋** | 按次创建 | 易被误当成 A；内懒 `new` Manager |
| `WfRuntimeManagerFactory` 等 | **宜 A** | 现行静态可调 | ❌ 静态不可按 Client 覆写；内散落 `new Manager`；`ProcessModelFactory` 还有静态缓存 |

定型时：**A 禁止持 B 字段**；**引擎工厂必须 A**（§3.7）；**B 编排袋**点名属 B；**Manager 只由 A 工厂/门面创建**。

### 3.4 寿命档位（词汇表）

| 档位代号 | 含义 | 同寿于 | 主要对应用例 |
|----------|------|--------|----------------|
| **L-App** | 应用级（Client 级）单例 | **一个 `SailClient`** | **A** |
| **L-Scope** | 宿主壳 | ASP.NET Scope | **H**（`WorkflowService` 等） |
| **L-Cmd** | 办理命令次级 | 一次 Start/Run/… | **B** |
| **L-Call** | 调用/语句级 | 单次 Sibling/语句 | 短命 B 碎片 |
| **L-Ephem** | 未立法瞬时 | 任意次 `new` | 一般不推荐；**不适用于** Manager / 引擎工厂 |

**推荐**：无请求态、只依赖 Client → **A / L-App**。Manager 与引擎工厂**禁止**用 L-Ephem 搪塞。

### 3.5 依赖方向（硬边界）

```text
L-App  ─────────────────────────────────────────────► 最长寿
  ▲ 可依赖
L-Scope（可选壳）
  ▲ 可依赖
L-Cmd（Context / 编排袋 / 事务 kit）
  ▲ 可依赖
L-Call
```

禁止箭头向上「吸」短寿状态进 L-App。  
禁止 **A** 把 **B** 收成字段。

```text
┌─ A / L-App：SailClient + Dialect + 注册表 + Managers + **Factories** ─┐
│  无 Runner/kit 字段；Do(kit, runner, …)；Create*(B 参数) → 产出 B        │
│  SailClientBuilder 可 useXxxFactory(自定义实例) 覆写                      │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ 注入 / 读取
┌─ 壳 / L-Scope：WorkflowService ───────────────────────────────────────┐
│  可持 A；不扣 B；可选 Run(ctx) 薄转发（§H.1）                              │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ 一次动词：RunBuilder.Build → Context → A 工厂
┌─ B / L-Cmd：RunBuilder · Context/WfAppRunner · kit · Runtime · Mediator ─┐
│  调用 A Manager；用毕即弃或 Clear；一般不能并发                          │
└───────────────────────────────────────────────────────────────────────┘
         C 仅纯工具（EnumHelper…）；不承载可替换工厂
```

### 3.6 新增 / 改类型检查清单（评审用）

定型后可作为 PR / 设计评审必答（草案阶段先作讨论清单）：

1. **用例**：A / B / C / H？（编排袋点名 B；**引擎工厂不得标 C**）  
2. **同寿于哪个 `SailClient`？**（A 必答）  
3. **寿命**：L-App / L-Scope / L-Cmd / L-Call？  
4. **并发**：A/C 默认可共享；B/H 扣袋则一般不能？  
5. **若 A**：吃齐 B/参数？无请求字段？缓存线程安全？工厂是否 Client 挂载且 Builder 可覆写？  
6. **若 B**：用毕即弃还是 Clear？是否遵守 B.0 字段白名单？  
7. **若 C**：有无静态可变 / 误做可覆写工厂？  
8. **若 H**：壳是否扣 B？组合根是否 Build 后仍可变？  
9. **依赖**：A→持有 B？私自 `new Manager`？

### 3.7 工厂职责与档位（必须降至应用级单例）

#### 3.7.1 一句话

**引擎工厂定型为 A（L-App，同寿于一个 `SailClient`）**，并相对「进程级不可覆写 static」**下降封顶**——终态不得是 Builder 换不掉的全局上帝；以便在 `SailClientBuilder` / `UseXxxFactory` **覆写工厂实例**（测替、租户、审计选型）。

| 说法 | 相对什么 |
|------|----------|
| **改档为 A** | 旧文档曾把 Factory 当 C；目标用例是 A |
| **下降封顶为应用级** | 现行/误用的**进程级 static** → 每 Client 一套可注入实例（不能再「升」回进程上帝） |

#### 3.7.2 职责切分

| 工厂角色（均属 **A**） | 职责 | 产出 |
|------------------------|------|------|
| **Manager 工厂 / Client 门面** | **唯一**创建并保管 `ActivityInstanceManager`、`TaskManager`、`ProcessInstanceManager`… | **A** Manager 实例（每 Client 一套，懒创建） |
| **Runtime 工厂** | 按动词选型、预检（经 Manager 读库）、灌装 **B** 袋 | **B** `WfRuntimeManager`* |
| **Mediator 工厂** | 按节点类型选型，灌装 ForwardContext/kit | **B** `NodeMediator`* |
| **ProcessModel 工厂** | 加载/缓存流程定义模型（缓存属 A 合法能力，须线程安全） | 模型供 **B** 使用期持有 |

```text
SailClientBuilder
  .UseRuntimeFactory(customOrDefault)      // 覆写 A
  .UseMediatorFactory(…)
  .UseProcessModelFactory(…)
  .UseManagers(…) / 默认门面
  .Build()
       │
       ▼
SailClient（A）
  ├─ RuntimeFactory（A）──Create*(runner, kit, …)──► Runtime（B）
  ├─ MediatorFactory（A）─Create*(forward, kit, …)─► Mediator（B）
  ├─ ProcessModelFactory（A）─CreateBy*(…)─────────► Model（使用期随 B）
  └─ Managers（A）◄── 仅工厂/门面可 new；Service/Mediator/Runtime 只读取
```

#### 3.7.3 红线

| 做 | 不做 |
|----|------|
| 工厂实例挂在 `SailClient`；默认实现 Build 时装上 | 业务代码 / Mediator / Service **私自** `new XxxManager(client)` |
| `SailClientBuilder.UseXxxFactory(IXxxFactory)` 可替换 | 工厂做成 **不可覆写的 static 类** 作为终态 API |
| Manager **只**由 Manager 门面/工厂创建（**D3 起强制**） | 业务/Mediator/Service 私自 `new`；D3 后 Runtime 工厂内也不再 `new Manager` |
| Create* 吃 **B 参数**，工厂**不扣** B 字段 | 工厂字段吸 Runner/kit；静态字典偷运「当前办理」 |
| 多 `SailClient` → 多套工厂+Managers | 全进程一个 static Factory 伺候所有 Client |

**过渡（写入节奏，避免和「唯一创建」打架）**：

| 阶段 | Manager 创建 |
|------|-------------|
| D3 前 | 允许 Runtime 工厂内暂 `new Manager`（债）；新代码尽量走门面 |
| D3 | 门面成为**唯一**入口；删散落 `new`；调用点**直接**改走 `client.XxxFactory` 后删除旧 static 表面（**不做** Obsolete 二次清理） |

#### 3.7.4 与 Builder 覆写的关系（动机）

与现有 `useMessageQueue` / `UseFlowGate` / `useAssigneePipeline` **同构**——**推荐只走 Client/Builder 门面，不另起一套纯 MS.DI 工厂注册**（是否偶发 `ConfigureServices` 转发见 §8，本文不双轨示范）。

- **默认**：`Build()` 装内置工厂实现到 `SailClient`。  
- **覆写**：`UseXxxFactory(实例或工厂委托)` 换 Fake/租户/审计实现。  
- **若停留 static**：无法按 Client 覆写，违反组合根（见 [业务管道特性设计.md](../业务管道特性设计.md)）。

概念形状（**非现行 API**，立项再定名）：

```csharp
// 推荐示意：挂在 Builder / Client 门面（单一路径）
builder.UseRuntimeFactory(new MyRuntimeFactory());
var sail = builder.Build();
sail.RuntimeFactory.CreateRuntimeInstanceAppRunning(runner, kit, ref result);
```

#### 3.7.5 现行差距（诚实）

| 现状 | 问题 | 定型目标 |
|------|------|----------|
| `WfRuntimeManagerFactory` 全静态 + 内 `new Manager` | 不可按 Client 覆写；Manager 无主 | **A**；Create 只用 Client.Managers |
| `NodeMediatorFactory` 全静态 | 同上 | **A** 挂 Client |
| `ProcessModelFactory` 静态 + 静态缓存 | A 能力挂在错误形态上 | **A**；缓存进该实例；**在途 B 沿用创建时引用**（§8.8） |
| Mediator 懒 `new Manager` | 第二套创建权 | 读 A Managers |

**迁移策略**：调用点改造到位后**直接删**旧 static 表面（如 `ProcessModelFactory`）；**不做** `[Obsolete]` 过渡壳二次清理。`WfRuntimeManagerFactory` / `NodeMediatorFactory` 仅作 `Default*` 内部实现，不对业务调用面开放。禁止新增 static 工厂表面 API。

## 4. 利弊（选型时对照）

### 4.1 坚持三分法 + A 不吸 B

| 利 | 弊 |
|----|----|
| 变化归属清晰；A 可安全共享、可测 | 参数列表变长；需习惯显式传 ctx |
| 与寿命立法同向 | 现行 Mediator/Runtime 作 B 编排袋需点名，防误当成 A |
| Gate/Hook 已有 B Context 习惯 | 链式 DX（壳扣 B）需收敛或标例外 |
| B 并发边界清楚（一般不能） | 过薄拆编排可能损可读性——编排袋允许但须属 B |

### 4.2 将无状态 Manager 定为 L-App（推荐方向）

| 利 | 弊 |
|----|----|
| 寿命与「只依赖 Client」语义一致；符合 Worker 角色 | 改动面：调用点从 `new` 改为 Client 门面或注入 |
| 后续横切（只读缓存、指标）有合法挂点，且强制线程安全评审 | 误加请求字段（变成吸 Context）会造成全局事故 |
| 与 Host `SailClient` Singleton 自然对齐 | 测试需可替换 Client / 门面 |

### 4.3 将 Manager 明定为 L-Ephem（处处 new）

| 利 | 弊 |
|----|----|
| 零装配、现状改动小 | 与「Worker = L-App」及 Mediator 懒缓存矛盾 |
| 「绝无实例缓存」简单粗暴 | 横切无处安放；易在临时对象上偷偷加字段 |

### 4.4 WorkflowService：Scoped 壳 + 命令态 Runner（现行）→ 定型后薄转发

| 现行 | 定型后（§H.1） |
|------|----------------|
| 链式写 `_wfAppRunner`，无参 `Start` 读自己 | **去掉**字段；可选 `Run(ctx)` 薄转发 |
| 同 Scope 重入踩袋 | 袋在 **RunBuilder/Context**，每次 new |
| 利：链式短 | 利保留：链式改挂 **Client → RunBuilder** |

### 4.5 Runtime / Mediator：B 类编排袋（现状）vs 更薄 Context（远期）

| 路径 | 利 | 弊 |
|------|----|----|
| **保留为 B 编排袋** | 与现码对齐 | 易被误当成 A 富功能 |
| **拆成显式 Context + 薄编排** | 更贴 §3.2/3.3 | 改动面大；D4 专项 |

### 4.6 引擎工厂：静态 C（现状）vs 应用级 A + Builder 覆写（定型方向）

| 路径 | 利 | 弊 |
|------|----|----|
| **维持全 static** | 零装配、调用短 | **无法**按 Client / Builder 换实现；Manager 创建权涣散；与管道组合根哲学冲突 |
| **降至 A，挂 Client，Builder 可覆写**（推荐） | 测替/租户/审计可插；Manager 创建有主；多 Client 隔离 | 需迁 API：`sail.RuntimeFactory.Create`*；调用点改完即删旧 static |

**结论倾向（部分已定型）**：

- **A**：每 `SailClient` 一套——Dialect / Filter·Gate·Hook·Notifier / Manager / **引擎工厂** / Lock 机制；吃 B 参数；不持 B 字段；**Builder 可覆写工厂**；提供 **CreateRunBuilder** 方法（不缓存）。  
- **B**：**`RunBuilder`**、Context/`WfAppRunner`、kit、Runtime/Mediator **实例**；由 A 工厂或 Client 方法 Create；字段白名单见 B.0。  
- **C**：仅无策略纯工具；不承载可替换工厂。  
- **H**：`WorkflowService` 等壳——**不扣 B**（§H.1 **已定型**）；`SailClientBuilder` 仅 Build 期。

## 6. 相关类型：现行用法 vs 拟定位

> **拟定位**为讨论稿，定型前不得当实施依据。  
> 列 **用例（A/B/C）** + 寿命档位；红线见 §3.2。

### 6.1 A · 应用级富功能（L-App，每 SailClient）

| 类型 | 现行 | 拟定位 | 说明 / 红线 |
|------|------|--------|-------------|
| `SailClient` | Host 常 Singleton | **A / L-App** | 富功能根；禁止持本次 Runner/kit |
| Dialect / DBFactory / JSON 等 | 挂在 Client | **A / L-App** | 方言与基础设施 |
| Assignee Pipeline / Filter | 挂在 Client | **A / L-App** | 解析吃入参 |
| Gate / Hook / Notifier / Dispatcher | 挂在 Client | **A / L-App** | 执行吃 **B** Context |
| `InstanceExecutionLock` | 应用级字典 | **A·协调** | 按 key 互斥；非无状态门面 |
| `*Manager` | 处处 `new` | **A / L-App** | D3 起仅门面创建；禁止 Runner 字段 |
| `PreviousStepChecker` 等 | `new(client)` | **A / L-App** | 或并入门面 |
| Runtime / Mediator / ProcessModel **工厂**（拟接口） | 现行静态类 | **A / L-App** | 挂 Client；Create → B；Builder 可覆写 |
| Manager 工厂（`Client` 上**一个槽**） | 无 | **A / L-App** | D3 起**唯一** `new Manager`；**不**在 Client 上挂齐 Activities/Tasks… 属性（§3.7.6） |
| `ActivityResourceFactory` / `NodeSendBackFactory` / Locator 等 | 多为静态 | **A：并入四槽或附属** | 禁止新不可覆写 static（§8.9） |

装配：Build 装默认；`UseXxxFactory` 覆写。禁止散落 `new XxxManager(Sail)`（D3 强制）。

### 6.2 C · 纯函数静态工具（不含引擎工厂）

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `EnumHelper` 等纯映射 | 静态 | **C** | 无策略、不可覆写 |
| （过渡）旧 static Factory 转发 | 静态壳 | **弃用** | 仅转发到 Client 上 A 工厂；禁止新 API |

### 6.3 H · 壳 / 组合根

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|
| `IWorkflowService` / `WorkflowService` | Scoped + `_wfAppRunner` | **H** 薄转发 | **D3 去** `_wfAppRunner`；见 §H.1 |
| `WorkflowQueryService` 等 | Scoped + Client | **H** | 无 Runner 则干净 |
| `SailClientBuilder` | Build 期可变 | **H·组合根** | Build 后冻结；非请求 B |

### 6.4 B · 请求级上下文 / 链式 / 编排袋（L-Cmd）

| 类型 | 现行 | 拟定位 | 说明 / 红线 |
|------|------|--------|-------------|
| **`RunBuilder`** | （拟） | **B / L-Cmd** | Client **方法每次 new**；链式 `Use*`；**非** Client/Service 字段 |
| `WfAppRunner` | 入参 / 链式混用 | **B / L-Cmd** | **袋**（可作 `Build()` 产物或 Context 内视图）；不进 Client |
| 命令 `Context`（可演进为 `FlowCommandContext`） | 散落 | **B / L-Cmd** | `RunBuilder.Build()` 产出；交执行器 |
| `WfExecutedResult` | 按次 | **B / L-Cmd** | 输出袋 |
| `ActivityForwardContext` / `BackwardContext` / `SendBackOperation` / `ActivityResource` | 按次 | **B / L-Cmd** | 上下文 |
| Gate/Hook `*Context` | 按次 Build | **B / L-Cmd** | 符合 §3.2 |
| 入口 `SQLBuilder kit` | 按次 | **B / L-Cmd** | 事务根；只下传 |
| 旧链式 `wf.CreateRunner().UseApp()…` | 写 Service 字段 | **弃用 → 转发** | 迁 **Client → RunBuilder**（§H.1） |
| `WfRuntimeManager*` | 按次；持 Runner/AI | **B 编排袋** | 由 **A** RuntimeFactory Create；禁止升 A |
| `NodeMediator*` / `NodeSendBack*` | 按次；持 Kit/Link | **B 编排袋** | 由 **A** MediatorFactory Create；Manager → **A** 引用 |

### 6.5 调用级碎片（L-Call · 短命 B 或 C 句柄）

| 类型 | 现行 | 拟定位 | 说明 |
|------|------|--------|------|

## 7. 与 OA 命令链的对照（读法）

```text
ButtonsOperation（Host 请求）
  → sail.CreateRunBuilder(…).Use*(…).Build() → Context（B）
  → WorkflowService.Run(ctx) 或直接执行器（H 薄转发；不持袋）
      → kit + Lock + Context
      → A RuntimeFactory.Create*(ctx, kit, …)
            └─ 经 A Managers 读库 → 产出 B Runtime 编排袋
      → A Gate + 本次 B GateContext
      → B Runtime.Execute
          → A MediatorFactory.Create*(forward, kit) → B Mediator
              → A Managers.Write(kit, …)
      → A Hook + 本次 B HookContext
```

```text
// A Manager ✅
sail.Managers.Activities.Complete(kit, id, runner);
// ❌ new ActivityInstanceManager(sail); 或 aim.CurrentRunner = runner;

// A 工厂覆写（概念）
builder.UseRuntimeFactory(new MyRuntimeFactory());
```

链路细节见 [开发手册-OA命令执行链路.md](./开发手册-OA命令执行链路.md)；用例与寿命标签以本专题定型为准回写。

### 3.7.6 Manager 怎么挂到 Client：只挂工厂，不挂一长串属性（已定型）

**定型：经 `ManagerFactory` 拿，不在 `SailClient` 上无限膨胀属性。槽名固定为 `ManagerFactory`（与 Runtime/Mediator/ProcessModel 工厂同构）。**

| 做法 | 评价 |
|------|------|
| `client.Activities` / `client.Tasks` / `client.ProcessInstances`… 各挂一个 | ❌ Client 表面积随表/实体膨胀；每加一种 Manager 改 Client |
| `client.Managers.Activities` 大聚合属性袋 | ⚠️ 稍好，仍把「有哪些 Manager」焊在 Client 类型上 |
| **`client.ManagerFactory` → 工厂内懒持有各 Manager** | ✅ **定型**：Client 只多一个工厂槽；扩 Manager 改工厂实现/接口，不胀 Client |

```text
SailClient（A，槽位宜少）
  ├─ RuntimeFactory（A）──Create*──► Runtime（B）
  ├─ MediatorFactory（A）─Create*──► Mediator（B）
  ├─ ProcessModelFactory（A）
  └─ ManagerFactory（A）── Activities / Tasks / …（懒创建、每 Client 一套）
         ▲
         └── 唯一 new Manager 入口；Runtime/Service/Mediator 只向工厂要
```

调用形态（概念）：

```csharp
// ✅
sail.ManagerFactory.Activities.Complete(kit, id, runner);

// ❌ 不推荐
sail.ActivityInstanceManager.Complete(…);  // Client 属性清单无限加长
```

与「工厂改档 A、Builder 可覆写」一致：`UseManagerFactory(custom)` 可整体替换 Manager 供给策略（测替、装饰、按租户裁剪），而无需给 Client 加字段。

**Client 上建议只保留**：可覆写的**四工厂槽**（Runtime / Mediator / ProcessModel / Manager，§8.2）+ **开 `RunBuilder` 的方法**（§H.1）+ 方言/管道插槽；**业务表级 Manager 一律藏在 ManagerFactory 后**；**禁止** Client 属性挂 Runner/建造态。

## 8. 开放问题 → 定型结论

| # | 议题 | 结论 | 说明 |
|---|------|------|------|
| 1 | Manager 挂法 / 命名 | **已定型** | **`ManagerFactory` 一槽**（§3.7.6）；不挂齐 Activities/Tasks…；不采用 `Managers()` 作主名（可作别名指向同一实例，非必须） |
| 2 | 工厂槽拆分 | **已定型 · 四槽** | **Runtime / Mediator / ProcessModel / Manager** 四个可覆写槽；Create→B 与 Hold→A Manager 职责分开，不把 Manager 并进 Runtime |
| 3 | `UseXxxFactory` 挂载路径 | **已定型** | **只走 `SailClientBuilder` / Client 门面**；本文不示范 `ISailCollection` / 纯 MS.DI 双轨；Host 若要 DI 可在组合根里 `UseXxxFactory(sp.Get…)` 一次注入 |
| 4 | static 迁移策略 | **已定型 · 修订** | 调用点**直接**改走 Client 工厂后**立刻删除**旧 static 表面；**不做** Obsolete 转发二次清理；禁止新增 static 工厂表面 API |
| 5 | 链式 / `_wfAppRunner` | **已定型** | §H.1：Client → 每次 `new RunBuilder` → Context → 执行器 |
| 6 | 编排袋拆薄 | **已定型 · 分期** | **一期只立法 B.0**（Runtime/Mediator 点名 B）；**D4** 再考虑变薄 / 显式 Context |
| 7 | 统一命令 Context | **已定型**（§H.1） | **`RunBuilder.Build()` 产物 = 命令入参 Context**，唯一交给执行器；与散落字段/`_wfAppRunner` 脱钩。类型名一期可用 **`WfAppRunner` 充当或内嵌**，亦可命名 `FlowCommandContext`——**是袋名选择，不是「要不要 Context」** |
| 8 | ProcessModel 缓存 vs 在途 B | **已定型 · 快照** | 在途 B **继续使用创建时拿到的模型引用**；缓存失效 / 换版 **只影响之后的 Create**；禁止中途把袋内模型指针改成「最新」 |
| 9 | 附属 Factory / Locator | **已定型** | **一并改档为 A**：优先 **并入四槽**（如 ActivityResource→Runtime 侧，NodeSendBack→Mediator 侧）；确需独立再加槽；**禁止**新不可覆写 static |
| 10 | 每 Client 一套 A | **已定型** | 与 §1「应用级」口径一致；多 Client = 多套工厂+Managers |

§8 议题均已定型；袋**类型名**（`WfAppRunner` vs `FlowCommandContext`）属 D2 命名细节，不另开开放项。
