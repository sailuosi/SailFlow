## 0. 结论先行

| 项 | 口径 |
|----|------|
| **Weight** | 办理人票权；默认 **1**（= 一个人）；类型建议 `decimal`（库 / 实体），Leave 汇总统一类型 |
| **ProxySignId** | 委托代批所代理的根办理人 `SignId`（同活动）；**可空** = 自己是根席 |
| **EndType** | 任务**结束类型**（string 码）；细分「自己办结 / 抢办被关 / 代批同链被关 / 转办委派出…」；**不替代** `TaskState` |
| **EndText** | 办结简约描述；**Host 本地化**生成/覆写；引擎可写缺省或只落 `EndType`；**≠** `Msg` |
| **EffectiveWeight** | 计权只认**委托链根**的 Weight；同根多人同意**只计一次**根权 |
| **主落库** | **`wf_task`**（+ Resolve 时 `Performer` 透传）；会签原人子 AI 仍双写 Weight/Proxy；**代批并人 = 同 AI 下多 Task**（不为代理人新建子 AI） |
| **Leave** | 先改 `Collaborate`；Seats 以 **Task 投影**为主（代批扁平后必需）；Captain 另案 |
| **LeaveSeatSnapshot** | `LeaveInvokeRequest.Seats`；只读窄投影；AIM 预加载 |
| **办结同链** | 关 Task + EndType/EndText；**禁止**运行中改 Weight=0 当主机制 |
| **委托代批** | Filter 追加 Performer → **同活动实例追加 Task** + `ProxySignId`；**不是** `DelegateProcess` |
| **委派 / 转办** | 正交；本包**一并**写 `EndType`（及 Host 侧 EndText） |
| **权重 UX** | 加签 / 预选等选人 UI **增加权重列**，默认 1，可调 |
| **委托作用域** | Host 表流程范围键用 **`ProcessId`（Id）**，精确优先、空=全部 |
| **红线** | 禁止新 Resolve Type；Leave 不读 Unit\*；禁止空壳办理条「委托代批」；历史 Closed **不回填** EndType（空即可） |

```text
增强点：
  加权会签（大股东 0.6 …）
  + 委托代批并入不撑大分母（李四+张三 有效权仍 1）
  → 同一套 EffectiveWeight 账本
```

## 1. 问题陈述

1. **Leave 按「人头」**：`MiPassRateHelper` 对子活动 `Agreed` **计数**；委托代批若只追加 Performer，在默认 `Collaborate` 下会变成「两人都会签」，与「任一可办」冲突。
2. **两层模型**：待办在 `wf_task`；会签计票在**子** `wf_act_instance`。权重若只写一层，Leave 读另一层会对不上账（见 §2）。
3. **委托语义三分已产品化**（转办 / 委派 / 委托代批），但代批缺**计权模型**与字段锚点；不能拿 `DelegateProcess`（办完还回）冒充。
4. ~~运行中改 Weight=0 当主机制~~ → **已拍板否决**（见 §4.3）：正确性只认「关 Task / 终态 + EffectiveWeight 同根去重」。

## 2. 数据面：Task 与子 ActivityInstance

### 2.1 职责

| 表 | 职责 |
|----|------|
| `wf_act_instance` | 节点（或会签席位）激活；主/子、`ApprovalStatus`、Leave 阈值 |
| `wf_task` | 人工待办；`SignId`、待办态、委托/沟通字段 |

`wf_task.tk_act_instance_id` → 所属活动实例。

### 2.2 两种结构（权重必须两边对齐）

**A. 普通用户任务（非 SignTogether）**

```text
ActivityInstance（1）
  ├─ Task 张三
  └─ Task 李四          ← 多 Task 挂同一 AI
```

**B. 会签 SignTogether**

```text
主 ActivityInstance（容器，常 Suspended）
  ├─ 子 AI 张三 → Task 张三
  └─ 子 AI 李四 → Task 李四
```

现行时刻 B 预加载的是 **`ChildActivityInstances`**，不是 Task 列表。演进目标：**统一灌入 `LeaveSeatSnapshot` 列表**（见 §4.0），Leave 不再直接依赖「人头数子 AI」或整颗 Task。

| 结构 | Weight / ProxySignId 落点 | Leave 读哪里（目标） |
|------|---------------------------|----------------------|
| A 扁平 | **必须**在 `wf_task` | 同 AI 下 Task → `LeaveSeatSnapshot[]` |
| B 会签 | 原人：子 AI + Task **双写**；**代理人：只加 Task，挂原人子 AI（扁平多 Task）** | **优先 Task 投影**为 `Seats`（一人一子 AI 且无代批时可仍从子 AI 投影，实现统一走 Task 更省分叉） |

**拍板（§11.5）：** 委托代批 **不为**代理人新建会签子 AI；在**被代理人所在活动实例**上追加 Task。

**禁止**：只改 `Performer` 内存字段、不落库；Leave 继续只按子 AI 人头、无视同 AI 多 Task；把完整 `TaskEntity` 列表塞进 Leave 上下文。

## 3. 字段契约

### 3.1 `Performer`（Resolve / Filter 载荷）

| 属性 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `Weight` | `decimal` | `1` | 票权；`≤0` 表示废席（不计分母/分子，视实现） |
| `ProxySignId` | `string` | `null` | 所代理根办理人的 `SignId`；空 = 自己是根 |

命名不用泛化 `ParentCode`（易与组织码/流程码混淆）；**不**用 TaskId（并人时父 Task 可能尚未稳定，且一人多 Task 歧义）。

### 3.2 `wf_task` 列建议

前缀 `tk_`；长度遵守命名规范。

| C# | 列名建议 | 类型 | 说明 |
|----|----------|------|------|
| `Weight` | `tk_weight` | decimal(18,4) 或等价 | 默认 1 |
| `ProxySignId` | `tk_proxy_sign_id` | varchar(64) | 可空；**非表 FK**（指向同活动 SignId） |
| `EndType` | `tk_end_type` | varchar(64) | 可空；仅任务**终态**后有值；见 §3.5 |
| `EndText` | `tk_end_text` | varchar(255) | 可空；办结简约文案；见 §3.5.5 |

与既有字段划界：

| 字段 | 用途 | 本专题 |
|------|------|--------|
| `TaskState` | 生命周期态（Waiting/Completed/Closed/…） | **保留**；`EndType` 解释「为何落到该态」 |
| `Msg`（`tk_msg`） | **审批/办理意见**（人填） | **禁止**塞系统办结文案；意见与结束描述分离 |
| `EntrustedTaskId` | **委派**回转链 | **不**改；与 `ProxySignId` 正交 |
| `ConsultSrcTaskId` | 沟通源 | 不参与计权 |
| `GroupId` | Leave 分组（R1） | 权重在组内/组间之上另算；Leave 仍不读 Unit\* |
| `EndedUserId` / `CompletedAt` | 谁结束 / 何时 | 与 `EndType`/`EndText` 正交；代批抢办关旁人时 Ended 可记触发人 |

### 3.3 子 `ActivityInstance` 同步列（会签）

| C# | 列名建议 | 说明 |
|----|----------|------|
| `Weight` | `ai_weight` | 与对应 Task 一致 |
| `ProxySignId` | `ai_proxy_sign_id` | 同上 |

`CompleteOrder` **保持**「串行序 / 主阈值」语义，**禁止**与 Weight 混用。

### 3.4 建任务透传

`TaskManager.Insert(ai, performer, …)`：从 `Performer` 写入 Task；会签 `CreateMultipleInstance` 循环建子 AI 时同步写入子 AI。Filter 追加代理人时必须带齐 Weight/`ProxySignId`。新建任务 `EndType` 为空。

### 3.5 `EndType`（任务结束类型）

> 动机：现行 `TaskState.Closed` 注释为「多人可办，他人办完后关闭」，但实现里 **转办 / 委派发起 / 减签 / 抢办旁关 / 代批同链旁关** 等都会落到 Closed（或 Canceled），列表与审计无法区分。  
> 定型：**string 码**（与 Resolve/Leave Type 同哲学），**不**再扩 `TaskStateEnum` 枚举位；**不**同步到活动实例。

#### 3.5.1 与 `TaskState` 的分工

| 层 | 问什么 | 字段 |
|----|--------|------|
| 状态机 | 待办是否还打开、是否算「办完」 | `TaskState`（Completed / Closed / Canceled / Withdrawed / …） |
| 结束原因 | **为什么**结束 | `EndType`（string） |

规则：

1. 打开态（Waiting / Reading）→ `EndType` 必须为空。  
2. 写入终态的**同一事务**内赋值 `EndType`；禁止事后只改其一。  
3. 历史/旧数据：`EndType`/`EndText` **允许为空**（不做回填）；展示侧空则不强调原因即可（§11.8）。

#### 3.5.2 建议码表（可增，禁止空壳上线）

| 码 | 典型 `TaskState` | 含义 |
|----|------------------|------|
| `SelfComplete` | Completed | **本人**正常发送/同意办结（推进或回转前的实办） |
| `RaceTaken` | Closed | 或签/抢办：同活动他人先办完，本待办被关 |
| `ProxyTaken` | Closed | 委托代批：同 `ProxySignId` 根链上他人办结，本待办被关 |
| `DelegatedOut` | Closed | 委派发起：原人待办交出（挂 `EntrustedTaskId` 的是对方） |
| `TransferredOut` | Closed | 转办：本人交出，不还回 |
| `Removed` | Closed | 减签 / 改派踢出 |
| `ConsultRecalled` | Closed / Canceled | 沟通收回未阅参与者 |
| `ActivityCancelled` | Canceled | 节点取消、撤回等批量作废未办 |
| `Withdrawn` | Withdrawed | 与状态对齐；可冗余写码便于统一筛 |
| `SendBacked` | SendBacked | 同上 |

产品文案由 Host 映射；引擎只认稳定码。Host 可扩展前缀（如 `Biz.*`），pure 内置码勿随意改名。

#### 3.5.3 写入锚点（本包一并补齐 · §11.9）

| 路径 | `EndType` |
|------|-----------|
| 本人 `Approve`/`Run` 办结且非委派回转 | `SelfComplete` |
| 委派受托人办结触发回转（受托行 Completed） | 受托 `SelfComplete`；原人重建 Waiting（清 `EndType`/`EndText`） |
| Race / Collaborate 旁人关打开待办 | `RaceTaken`（无 Proxy 链）或 `ProxyTaken`（同根优先） |
| `TaskManager.Transfer` 关原人 | `TransferredOut` |
| `TaskManager.Delegate` 关原人 | `DelegatedOut` |
| RemoveAssignee / ChangeAssignee 关旧 | `Removed` |
| 同链代批办结关旁人（§7） | `ProxyTaken` |
| Consult 收回等 | `ConsultRecalled`（若本包触及则写；否则可 P1） |

判定优先级（旁关时）：同 `ProxySignId` 根链 → `ProxyTaken`，否则 `RaceTaken`。  
**本包范围：** 转办 / 委派 / 减签改派 / 抢办旁关 / 代批旁关 / 本人办结 **一并**落 `EndType`（不只代批路径）。

#### 3.5.4 查询与产品

- 待办箱：只扫打开态，不依赖 `EndType` / `EndText`。  
- 已办/轨迹：优先 `EndText`；空则 Host 按 `EndType` 本地化回落（可不落库）。  
- Leave **不读**二者。  
- 历史行二者为空即可，不回填（§11.8）。

#### 3.5.5 `EndText`（办结简约描述）

> **现行没有**专用列。`Msg` 是审批意见，不可复用。

| 项 | 口径 |
|----|------|
| 字段 | `EndText` / `tk_end_text`（varchar 255） |
| 谁写 | **Host 本地化**（§11.7）：按 `EndType` + 触发人生成；引擎**必写** `EndType`，pure **不**写死中文 |
| 谁读 | 已办/轨迹；不进 Leave |

| | `EndType` | `EndText` |
|--|-----------|-----------|
| 形态 | 引擎机器码 | Host 可读短句 |
| 本地化 | 不变 | **Host** 资源串 |

Host 示例：`SelfComplete`→自行办结；`ProxyTaken`→「{0}代办结」；`RaceTaken`→「{0}抢办结」。

## 4. Leave 席位快照与有效权重

### 4.0 拍板：`LeaveSeatSnapshot`（简化类）纳入实施计划

> 动机：Leave 历史只吃子 AI（会签计票）；权重/代批落在 Task，扁平节点会断档。加完整 `TaskEntity` 过重且诱使 Judge 写库。  
> 定型：增加**只读简化席位类**，由 AIM（或等价预加载）注入 `LeaveInvokeRequest`；性能上 N 为个位数～十几，相对已有子 AI 列表可忽略（窄投影，短生命周期）。

#### 4.0.1 建议形状（示意）

```csharp
// 建议落点：sailflow.engine.Assignee（与 LeaveInvokeRequest 同层）
public sealed class LeaveSeatSnapshot
{
    public string SignId { get; init; }
    public string SignName { get; init; }
    public decimal Weight { get; init; }           // 默认 1
    public string ProxySignId { get; init; }       // 可空 = 根
    public bool Agreed { get; init; }
    public bool Refused { get; init; }
    public bool ClosedOrCancelled { get; init; } // 不计入打开席；旁关后为 true
    public string TaskId { get; init; }            // 可选，诊断/旁关定位
    public string ActivityInstanceId { get; init; }// 可选，会签子 AI Id
    public string GroupId { get; init; }           // Leave 组内模式需要时带
    // 不含 Msg / 时钟 / RowPara 等与计权无关字段
}
```

#### 4.0.2 `LeaveInvokeRequest` 扩展

| 字段 | 说明 |
|------|------|
| `IList<LeaveSeatSnapshot> Seats` | **计权主输入**（P0 起 Leave/EffectiveWeight 优先读此） |
| `ChildActivityInstances` | **过渡保留**：投影源 / 旧 Judge 兼容；新代码禁止再按人头直接 Count |

`LeaveJudgeContext` 仍只挂 `Request` + `Config`；Judge 经 `Request.Seats` 读席位。

#### 4.0.3 谁负责填充

| 结构 | 填充 |
|------|------|
| 会签 / 扁平（统一倾向） | 预加载相关 AI 下**常规办理人 Task** → 投影 `Seats`（Agreed≈Task Completed+同意；Closed/Canceled→`ClosedOrCancelled`）；代批同 AI 多 Task 自然入座 |
| 无代批的纯会签过渡 | 仍允许子 AI → Seats，但目标实现**优先 Task 投影**以免双分叉 |
| 共通 | **Judge 内禁止再查库**；沟通 `AssigneeRole=Participant` **默认不进** `Seats` |

#### 4.0.4 边界

- 快照**只读**；关旁人 / 写 `EndType`/`EndText` 仍在 TaskManager 办结路径。  
- 不把 `LeaveSeatSnapshot` 做成常驻缓存；随本次 Leave 请求释放。  
- EffectiveWeight API 入参改为 `IEnumerable<LeaveSeatSnapshot>`（或适配器），与 §4.1 一致。

### 4.1 定义

对同一活动的 **`LeaveSeatSnapshot` 集合**中每一行席位 \(p\)：

```text
root(p) =
  若 ProxySignId 为空 → p
  否则沿 ProxySignId 在 Seats 内找到根（防环；孤儿 → 自身为根并诊断日志）

EffectiveWeight(p) =
  若 p.ClosedOrCancelled → 0
  若 p.Weight ≤ 0 → 0
  否则 → Weight(root(p))   // 链上任何人只贡献根的权
```

**同根去重（硬规则）：** 统计「已同意有效权」时，按 `root.SignId` **分组**，每组最多计入 **一次** `Weight(root)`。  
否则李四、张三都点同意会把权加两次。

### 4.2 扩展方法（建议落点）

包：`sailflow.assignee`（与 `MiPassRateHelper` 同层），例如：

| API | 职责 |
|-----|------|
| `GetWeightRoot(seats, p)` | 找根；环/孤儿策略 |
| `EffectiveWeight(p)` | 单行 |
| `SumDenominator(seats)` | 按根去重后的权之和（分母） |
| `SumAgreedEffective(seats)` | 已同意、按根去重（分子） |
| `SumRefusedEffective(seats)` | 拒绝侧：**同根去重**（与同意侧对称，§11.3） |

**所有 Leave 实现禁止私自「跟 ProxySignId 找根」**——只调上述 API；**禁止**在 Judge 内遍历裸 `TaskEntity` / 自行 Count 子 AI。

### 4.3 拍板：运行中改 `Weight=0` **不当**主机制

| 做法 | 定位 |
|------|------|
| 同链一人办结 → **关闭**其余打开 Task + 写 `EndType`/`EndText`（及会签子 AI 旁路） | **唯一主路径**（对齐 Race 关旁人） |
| Leave 按终态排除已关席 + 同根去重计权 | **计权正确性**所在 |
| 将同链未办行再改 `Weight=0` | **非必须**；最多作审计快照；实现可整段省略 |
| 只改 Weight、待办仍 Waiting | **禁止** |
| 以 Weight=0 作为 Leave 通过/旁关的**唯一**依据 | **禁止** |

理由（固化）：

1. **状态分裂**：Weight 已 0 但 Task 仍 Waiting → 待办箱与计权打架。  
2. **并发**：两人同时同意时，去重计权靠 root，不靠谁先把对方改成 0。  
3. **回放/对账**：终态 + EndType 可解释；可变 Weight 难复盘「办结瞬间分母」。  
4. **建单快照**：Weight 表示建任务时的票权；办结后改权会污染「原始席位权」语义。

`Weight ≤ 0` 仍可用于**建单时**显式废席（产品主动作废某一票），与「办结旁关再改 0」不是同一场景。

## 5. Leave 接入策略（分级）

| Leave | 是否用 EffectiveWeight | 说明 |
|-------|------------------------|------|
| `Collaborate` | **是（P0）** | 读 `Request.Seats`；`completeCount` / `completeRate` 用 EffectiveWeight；禁止再混用人头数 |
| `GroupCollaborate` | **是（P1）** | 组内先按 EffectiveWeight（`Seats.GroupId`）；组间 R7 仍按「组是否完成」 |
| `Race` / `GroupRace` | **弱** | 仍「先同意即过」；实现上忽略 Weight≤0 / 已关席；办结关同链 |
| `Captain` | **P2 另案** | 关卡权 vs 组员权，不可简单 sum |

未挂管道 / 旧债路径不在本专题默认可依赖范围内。

### 5.1 委托代批在 Collaborate 下的自然结果

| 席位 | Weight | ProxySignId | 有效贡献 |
|------|--------|-------------|----------|
| 李四 | 1 | ∅ | 根权 1 |
| 张三 | 1 | 李四 | 同根，分母仍 1 |

`completeRate=1`：任一人同意 → 该根计入 1 → 通过。  
**不必**为此把节点改成 `Race`，也**不必**单独发明「代批席 Leave Type」。

## 6. 委托体系如何挂在本模型上

### 6.1 三分（不合并命令）

| 能力 | 触发 | 原人 | 计权 / 字段 |
|------|------|------|-------------|
| 转办 `Transfer` | 办理条 · 单笔 | 关 | 新人 Weight 默认 1；刷新 Sign；**无** `ProxySignId` 代批语义 |
| 委派 `Delegate` | 办理条候选 · 单笔 | 关 + `EntrustedTaskId` | **还回**；**不**用 `ProxySignId`；办结不推进 |
| 委托代批 | 配置 · 建任务 Filter | **保留** | 代理人 `ProxySignId=原人 SignId`，Weight 默认 1（或显式继承展示） |

产品解说见 [解说-OA委托动词.md](../../helps/解说-OA委托动词.md)。

### 6.2 委托代批 Filter（时刻 A′）

建议 Host：`SurrogateAssigneeFilter`（名可议），注册序在业务 Filter 之后、建议再经 `DedupUsersFilter`。

行为钉死：

1. 仅对**本轮 Resolve 原始** Performer 查生效委托（**不接力**）。  
2. 命中则 **Add** 代理人，填 `ProxySignId = 原人.UserId`，`Weight = 1`（默认）。  
3. 判据：时间窗 · `enabled==1` · 禁自委托 · 流程作用域键 **`ProcessId`**（精确优先，空=全部）· 同作用域取最新一条再裁决。  
4. **只影响新单**；改配置不回写已建 Task。  
5. **落库形态（§11.5）：** 建任务时代理人与原人落在**同一 `ActivityInstanceId`** 下各一条 Task（扁平多 Task）。会签节点：**不**为代理人再 `Insert` 子 AI；代理人 Task 挂在**原人子 AI**（或该节点唯一 AI）上。

**禁止**：新 `IAssigneeResolver` Type（违反 R10）；把代批塞进 `DelegateProcess`；为代批扩出会签子实例数。

### 6.3 Host「我的委托」

- 表属宿主（如 sleveen-admin），非 pure。  
- 流程范围字段：**`ProcessId`**（string Id；空=全部流程）；匹配当前实例/定义的 ProcessId。  
- 列表强制 `GrantorId = 当前用户`；仓储缺归属 → 空页。  
- 页面骨架对齐抄送箱 / 我的待办；**不**进办理条码表冒充委派。  
- **EndText** 文案：Host 资源本地化（§11.7）。

### 6.4 持续委托链

- Filter：**默认不展开** B→C。  
- 若业务强行多级 `ProxySignId`：Leave 仍只认 **root** 权重，展示链与计权分离。

## 7. 办结同链算法（示意）

当办理人 \(u\) 同意且准备 Leave 判定前/后（实现挂点：Task 完成路径，与 Race 关旁人同类）：

```text
root = GetWeightRoot(u)
for each open seat s in same activity scope where GetWeightRoot(s) == root and s != u:
    CloseTask(s, EndType = ProxyTaken)  // EndText 由 Host 本地化写入
    // TaskState=Closed；同 AI 上其余打开 Task；不改 Weight
```

并发：两人同时同意 → 去重计权保证只加一次根权；关闭旁人须幂等。  
**正确性不依赖**把旁人 `Weight` 改成 0。

## 9. 红线与易混

| 禁止 / 易混 | 正确 |
|-------------|------|
| 新 Resolve Type「Surrogate」 | Filter（时刻 A′） |
| `ProxySignId` 复用 `EntrustedTaskId` | 委派归 Entrusted；代批归 `ProxySignId` |
| 办结旁关靠改 `Weight=0` | **禁止当主机制**；关 Task + EndType/EndText（§4.3） |
| Leave 读 Unit\* | 只读 Group\* + Weight/`ProxySignId` |
| Percentage 仍用人头当分子分母 | 只用 EffectiveWeight |
| Weight 与 CompleteOrder 混列 | Order=次序/阈值；Weight=票权 |
| 用 `EndType` 替代 `TaskState` | 态机仍用 State；Type 只解释原因 |
| 系统办结文案写入 `Msg` | `Msg`=审批意见；描述用 Host `EndText` |
| 为代批新建会签子 AI | 同 AI 扁平多 Task（§11.5） |
| 旁关一律 `RaceTaken` | 同代理链优先 `ProxyTaken` |
| Leave 上下文塞整颗 `TaskEntity` | 用 `LeaveSeatSnapshot` 窄投影 |
| Judge 内自查 Task/AI | AIM 预加载注入 `Seats` |
| 空壳办理条「委托代批」 | 先有 Filter + 表 + Leave 账 |
| 口语「委托」= 委派 | 先问单笔还回 vs 配置并入 |
