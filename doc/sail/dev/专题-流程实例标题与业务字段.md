# 专题 · 流程实例标题与业务字段

> 状态：**P0+P1 已落地（待库迁移/标题模板）**（2026-11-14）  
> 用途：厘清「流程名称 ≠ 流程标题」、统一 `biz*` 业务字段语义，并约定流程实例创建 Hook 与启动入参注入。  
> 范围：`wf_proc_instance` 实体列、节点定义属性透传、启动入口 / `RunBuilder`、创建 Hook。  
> 关联：[规范-实体表与字段命名.md](../../../dic/sail/dev/规范-实体表与字段命名.md) · [教程-事件体系Gate-Hook-Notifier-Outbox.md](../../helps/教程-事件体系Gate-Hook-Notifier-Outbox.md) · [专题-对象生命周期与复用边界.md](./专题-对象生命周期与复用边界.md)

## 0. 结论先行

| 项                         | 口径                                                                                |
| ------------------------- | --------------------------------------------------------------------------------- |
| **ProcessName**           | **流程名称** = 流程定义名的副本（`wf_process.ProcessName` → `pi_name`）。**不是**流程标题。             |
| **Title**                 | **流程实例标题** = 新列 `pi_title`；由业务参数 / 创建 Hook /（后续）标题模板写入。                           |
| **biz**                   | 业务侧统一前缀；旧 `AppInstanceId` / `AppInstanceCode` / `AppName` 语义收口到 `biz`*。           |
| **节点 bizState / bizCode** | 节点定义属性（int / string），解析进 `Activity`，持续透传到 Gate/Hook/Notifier 上下文。                 |
| **创建 Hook**               | 专用于「流程实例对象已拼装、落库前」；业务可改 `Title` / `biz*` 等字段；**条件生效与 Gate/Hook 同套**（`Match` / `ProcessCodes` / `ProcessIds` / `Order` + `BizChannels` / `BizTypes`）。 |
| **BizDataDto**            | 承载 `BizPK` / `BizType` / `BizCode` / `BizChannel` / `BizName`；链式与常规入口均可注入；不注入保持空。 |

---

## 1. 问题陈述

1. **名称与标题混用**：现行 `ProcessInstanceEntity.ProcessName` 在创建时直接拷贝定义名（`CreateNewProcessInstanceObject`），列表/详情又把它当「标题」展示；产品「更多设置 · 标题设置」（`extra_json.titleSetting`）仅前端落库，**运行时未消费**。
2. **业务键语义漂移**：`AppName` / `AppInstanceId` / `AppInstanceCode` 同时承载「应用名、FormCode、单据主键、表单 Id」等，命名不像业务域字段，跨宿主难对齐。
3. **节点业务态缺失**：办理/回写常需「节点业务状态码 / 节点业务编码」，今日只能塞自定义 JSON 或业务表；无一等公民透传到 Hook。
4. **创建不可扩展**：实例对象由引擎内部拼装后直接 `Insert`，业务无法在不改引擎的前提下补标题、补 `bizType` 等。

## 2. 任务 1 · 基础实体

### 2.1 语义三分

| 概念 | 字段（C# / 列） | 含义 | 谁写 |
|------|-----------------|------|------|
| **流程名称** | `ProcessName` / `pi_name` | 定义名快照；改定义名**不回溯**已建实例 | 引擎：`processEntity.ProcessName` |
| **流程标题** | `Title` / `pi_title` | 实例对外展示标题（待办、列表、门户） | 启动入参 / 创建 Hook /（后续）标题模板 |
| **业务标识组** | `Biz`* / `pi_biz_*` | 关联业务单据与通道 | 启动 `BizDataDto` / 创建 Hook |

**禁止**：再把 `ProcessName` 当作标题；展示与推送优先读 `Title`，空时再回落 `ProcessName`（兼容过渡）。

### 2.2 `wf_proc_instance` 列变更

字段前缀仍为 `pi_`（见命名规范）。

| C# 属性 | 列名 | 类型建议 | 说明 |
|---------|------|----------|------|
| `Title` | `pi_title` | varchar(255) | **新增** · 流程实例标题 |
| `BizType` | `pi_biz_type` | varchar(64) | **新增** · 业务类型 |
| `BizPK` | `pi_biz_pk` | varchar(128) | **由** `AppInstanceId` / `pi_app_instance_id` **更名** |
| `BizCode` | `pi_biz_code` | varchar(64) | **由** `AppInstanceCode` / `pi_app_instance_code` **更名** |
| `BizName` | `pi_biz_name` | varchar(128) | **新增** · 业务名称（展示用） |
| `BizChannel` | `pi_biz_channel` | varchar(128) | **由** `AppName` / `pi_app_name` **语义收口并更名** · 业务通道（路由/FormCode/接入方） |
| `ProcessName` | `pi_name` | varchar(255) | **保留** · 仅表示流程名称 |

#### 2.2.1 旧 → 新映射

| 旧属性 | 旧列 | 新属性 | 新列 | 备注 |
|--------|------|--------|------|------|
| `AppInstanceId` | `pi_app_instance_id` | `BizPK` | `pi_biz_pk` | 业务主键（单据 Id 等） |
| `AppInstanceCode` | `pi_app_instance_code` | `BizCode` | `pi_biz_code` | 业务编码；历史亦曾写 formId，过渡期兼容读 |
| `AppName` | `pi_app_name` | `BizChannel` | `pi_biz_channel` | 业务通道；FormBiz 的 `FormCode` 落此字段 |
| — | — | `BizName` | `pi_biz_name` | 业务名称；可与通道不同 |
| — | — | `BizType` | `pi_biz_type` | 业务类型字符串 |
| — | — | `Title` | `pi_title` | 实例标题 |

#### 2.2.2 实体草稿（示意）

```csharp
[SooColumn(Name = "pi_name", Length = 255)]
public string ProcessName { get; set; }          // 流程名称（定义名副本）

[SooColumn(Name = "pi_title", Length = 255)]
public string Title { get; set; }                // 流程实例标题

[SooColumn(Name = "pi_biz_type", Length = 64)]
public string BizType { get; set; }

[SooColumn(Name = "pi_biz_pk", Length = 128)]
public string BizPK { get; set; }

[SooColumn(Name = "pi_biz_code", Length = 100)]
public string BizCode { get; set; }

[SooColumn(Name = "pi_biz_name", Length = 128)]
public string BizName { get; set; }

[SooColumn(Name = "pi_biz_channel", Length = 128)]
public string BizChannel { get; set; }
```

#### 2.2.3 关联运转表（同步收口）

下列实体/视图中的 `AppName` / `AppInstanceId` / `AppInstanceCode` **同一套更名**，避免 Join 语义分裂：

- `ActivityInstanceEntity`、`TaskEntity`、`TaskViewEntity`
- `TransitionInstanceEntity`、`ProcessVariableEntity`（若仅有 `AppInstanceId` → `BizPK`）
- `FlowCommandContext`、`FlowHookContext`、`TaskNotifyContext`
- `RunBuilder.UseApp(...)` → `UseBiz(...)`（见 §3）

查询 API、索引、归档冷表列名随热表迁移一并改；过渡期可提供只读别名属性（`[Obsolete] AppInstanceId => BizPK`），**新代码禁止再写旧名**。

### 2.3 节点定义 · `bizState` / `bizCode`

#### 2.3.1 定义侧

在流程节点（BPMN 人工任务等）上增加一等属性：

| 属性 | 类型 | 建议 BPMN 形态 | 说明 |
|------|------|----------------|------|
| `BizState` | `int` | `sf:bizState`（元素属性或 extension） | 节点业务状态码（业务字典，引擎不解释） |
| `BizCode` | `string` | `sf:bizCode` | 节点业务编码（与实例级 `BizCode` 不同命名空间：节点成员 vs 实例业务编码） |

落点：

1. **设计器**：节点配置面板可编。
2. **XML ↔** `Activity`：`ConvertorBuilder` / 保存路径读写上述属性。
3. **内存模型**：`Activity`（及必要时 `ActivityView`）增加同名成员。

```csharp
// Activity（节点定义成员）
public int BizState { get; set; }
public string BizCode { get; set; }
```

> 命名注意：实例级 `ProcessInstanceEntity.BizCode` = 业务单据编码；节点级 `Activity.BizCode` = 节点业务编码。上下文中分别称 **实例 BizCode** / **节点 BizCode**，Hook 上下文用 `ActivityBizCode` / `NodeBizCode` 消歧（见下）。

#### 2.3.2 运行透传

节点属性在活动创建、任务创建、Gate/Hook/Notifier 组装时**原样带入**，不落库到 `wf_act_instance` 亦可（定义可逆解析）；若需审计可另增列，**本专题不强制落库**。

`FlowHookContext` / `TaskNotifyContext` 增补：

| 属性 | 来源 |
|------|------|
| `ActivityBizState`（int） | 当前节点 `Activity.BizState` |
| `ActivityBizCode`（string） | 当前节点 `Activity.BizCode` |

同步透传到：`FlowCapabilityPipeline.BuildHookContext`、`BuildHookContextFromTask`、以及现有从 `runner` / `task` 填袋的路径。业务 Hook 按节点业务态分支，无需再解析 BPMN。

## 3. 任务 2 · 流程实例创建 Hook 与 BizData 注入

### 3.1 `BizDataDto`（启动业务袋）

五项业务参数（可空；不注入则全空字符串 / null，引擎不强制）：

```csharp
namespace sailflow.engine.Common
{
    /// <summary>B · 启动/创建时注入的业务数据袋；不注入保持空。</summary>
    public sealed class BizDataDto
    {
        /// <summary>业务主键（原 AppInstanceId）。</summary>
        public string BizPK { get; set; }

        /// <summary>业务类型。</summary>
        public string BizType { get; set; }

        /// <summary>业务编码（原 AppInstanceCode）。</summary>
        public string BizCode { get; set; }

        /// <summary>业务通道（原 AppName / FormCode 路由键）。</summary>
        public string BizChannel { get; set; }

        /// <summary>业务名称。</summary>
        public string BizName { get; set; }
    }
}
```

挂到 `FlowCommandContext`：

```csharp
public BizDataDto BizData { get; set; }

// 便捷：读写时与扁平字段同步（实现期二选一，避免双源）
// 推荐仅保留 BizData；扁平 BizPK 等为转发属性。
```

**写入实例规则**（`CreateNewProcessInstanceObject`）：

| 实例字段 | 来源 |
|----------|------|
| `BizPK` | `runner.BizData?.BizPK` |
| `BizType` | `runner.BizData?.BizType` |
| `BizCode` | `runner.BizData?.BizCode` |
| `BizChannel` | `runner.BizData?.BizChannel` |
| `BizName` | `runner.BizData?.BizName` |
| `Title` | 默认空；由创建 Hook 或后续标题模板填充 |
| `ProcessName` | 仍只来自 `processEntity.ProcessName` |

### 3.2 注入入口

#### 3.2.1 链式（`RunBuilder`）

```csharp
sail.CreateRunBuilder()
    .UseProcess(processId, version)
    .UseBizData(new BizDataDto
    {
        BizPK = leaveId,
        BizType = "leave",
        BizCode = leaveNo,
        BizChannel = "leave",
        BizName = "张三的请假"
    })
    // 或：.UseBiz(pk, type, code, channel, name)
    .UseUser(...)
    .Start();
```

旧 `UseApp(appInstanceId, appName, appCode)` **直接删除并替换**为 `UseBiz`（不做 `[Obsolete]` 转发）：

| 旧参数 | 新字段 |
|--------|--------|
| `appInstanceId` | `BizPK` |
| `appName` | `BizChannel` |
| `appCode` | `BizCode` |

调用方一并改名；引擎内不保留 `UseApp` 别名方法。

#### 3.2.2 常规入口

- `POST` Start / FormBiz：`FlowCommandContext.BizData` 或等价 JSON 段 `bizData`。
- FormBiz Host：`OnSubmit` 后填充 `ctx.BizData`（`BizChannel = FormCode`，`BizPK =` 业务主键等），再 `ToRunner()`。

不传 `BizData` / 字段全空 → 实例对应列为空；**引擎不报错**（与今日可空 App* 一致）。业务 Gate 若要求必填，自行 `Reject`。

### 3.3 流程实例创建 Hook

与现有 `IFlowHook`（流转事件后）分离：本 Hook 只在**实例实体拼装完成、Insert 之前**调用，专门改实例行。

#### 3.3.1 契约（pure）

```csharp
namespace sailflow.engine.Hooks
{
    /// <summary>
    /// 流程实例创建钩子：对象已由引擎拼装，尚未 Insert。
    /// 业务可改 Title / Biz* 等；禁止改 ProcessInstanceId（若已预发号）以外的主键策略字段时须文档约定。
    /// </summary>
    public interface IProcessInstanceCreateHook
    {
        string Name { get; }

        /// <summary>同步；同创建事务。异常 → 启动失败回滚。</summary>
        void OnCreating(ProcessInstanceCreateContext ctx);
    }

    public sealed class ProcessInstanceCreateContext
    {
        public FlowCommandContext Runner { get; set; }
        public ProcessEntity Process { get; set; }

        /// <summary>待插入的实例；Hook 可就地修改。</summary>
        public ProcessInstanceEntity Instance { get; set; }

        /// <summary>同事务 kit（勿另开连接）。</summary>
        [JsonIgnore]
        public SQLBuilder Kit { get; set; }
    }
}
```

#### 3.3.2 调用点

`ProcessInstanceManager.CreateNewProcessInstanceObject` 返回前，或 `Insert` 之前统一：

```
拼装 ProcessInstanceEntity（定义名 → ProcessName；BizData → Biz*）
  → 按 Order 筛选 IProcessInstanceCreateHook（条件匹配，见 §3.3.3）
  → 依次 OnCreating
  → Insert
```

子流程创建走同一路径，保证标题/业务字段策略一致。

#### 3.3.3 注册与条件生效

寿命 **A · 应用级**（同 `SailClient`），与 Gate/Hook 注册表并列；**过滤模型对齐现有 `HookRegistrationOptions` / `FlowCapabilityMatch`**，创建场景在共用字段上扩展 `Biz*` 维。

| 选项 | 与 Gate/Hook | 创建 Hook 口径 |
|------|--------------|-------------|
| `Match` | 同（默认 `Whitelist`；`All` 跳过名单） | 同：控制 `ProcessCodes`/`ProcessIds` 白名单语义 |
| `ProcessCodes` | 同 | 按定义 `ProcessCode` 过滤 |
| `ProcessIds` | 同 | 按定义 `ProcessId` 过滤 |
| `Order` | 同 | 同：升序执行 |
| `ActivityCodes` | Gate/Hook 有 | **不适用**（创建时尚无活动节点）；忽略 |
| `Events` / `TaskKinds` | Hook/Notifier 有 | **不适用**（非事件/待办旁路）；忽略 |
| `Mode` | Hook 默认 AsyncOutbox | **固定 Sync**（须同事务改实例后再 Insert）；忽略传入值 |
| `BizChannels` | —（创建扩展） | 按实例已写入的 `BizChannel` 过滤；空名单=不限 |
| `BizTypes` | —（创建扩展） | 按实例已写入的 `BizType` 过滤；空名单=不限 |

匹配伪代码（与 `FlowCapabilityMatch.MatchesProcess` 同风格）：

```
MatchesProcess(Match, ProcessCodes, ProcessIds, process.ProcessCode, process.ProcessId)
  && MatchesBizChannel(BizChannels, instance.BizChannel)   // 空数组/null → true
  && MatchesBizType(BizTypes, instance.BizType)             // 空数组/null → true
```

注册选项可复用 / 继承 `HookRegistrationOptions`，或独立 `ProcessInstanceCreateHookOptions :` 同字段 + `BizChannels`/`BizTypes`（实现期择一，对外 API 形状一致即可）：

```csharp
builder.UseFlowAspects(b =>
{
    b.AddProcessInstanceCreateHook(new LeaveTitleCreateHook(), o =>
    {
        o.Order = 10;
        o.Match = HookMatch.Whitelist;
        o.ProcessCodes = new[] { "LEAVE" };       // 与 IFlowHook 相同
        o.BizChannels = new[] { "leave" };        // 创建扩展维
        // o.BizTypes = new[] { "leave" };
    });
});

// 或
client.addProcessInstanceCreateHook(new LeaveTitleCreateHook(), o =>
{
    o.ProcessIds = new[] { processId };
    o.Order = 20;
});
```

未命中条件的 Hook **不调用** `OnCreating`（与 Gate/Hook 未命中则跳过一致）；勿在 Handler 内再手写一套 ProcessCode 分支，除非业务细规则超出注册过滤。

委托快捷（对齐 `AddHook(name, Action)`）：

```csharp
// 通用创建 Hook
b.AddProcessInstanceCreateHook("leave-fill", ctx =>
{
    ctx.Instance.BizType ??= "leave";
}, o => o.BizChannels = new[] { "leave" });

// 仅写标题：Func 返回非空且 Instance.Title 为空时写入
b.AddProcessInstanceTitleRule(
    "leave-title",
    ctx => ctx.Instance.BizName
        ?? $"{ctx.Instance.ProcessName}-{ctx.Instance.BizPK}",
    o =>
    {
        o.ProcessCodes = new[] { "LEAVE" };
        o.BizChannels = new[] { "leave" };
    });
```

#### 3.3.4 典型用法

```csharp
public sealed class LeaveTitleCreateHook : IProcessInstanceCreateHook
{
    public string Name => "leave-title";

    public void OnCreating(ProcessInstanceCreateContext ctx)
    {
        var ins = ctx.Instance;
        // 流程/通道已由注册条件过滤，此处只写标题策略
        if (string.IsNullOrWhiteSpace(ins.Title))
        {
            ins.Title = !string.IsNullOrWhiteSpace(ins.BizName)
                ? ins.BizName
                : $"{ins.ProcessName}-{ins.BizPK}";
        }

        if (string.IsNullOrWhiteSpace(ins.BizType))
            ins.BizType = "leave";
    }
}
```

**边界**：

| 允许 | 禁止 |
|------|------|
| 改 `Title`、`Biz*`、展示相关可空列 | 改 `ProcessId` / `Version` 指错定义 |
| 只读查业务表补全字段（用 `ctx.Kit`） | 另开 `Sail.UseRunSQL()` 导致锁死 |
| 按 `BizChannel`/`BizType` 分支 | 在此 Hook 里推进流程 / 建任务 |

现有流转后 `IFlowHook` **不替代**本 Hook：回写业务表仍用事件 Hook；**生成/改写实例标题与 biz 落库字段**用创建 Hook。

## 4. 展示与推送（过渡约定）

| 场景 | 优先 | 回落 |
|------|------|------|
| 详情页大标题、实例列表「标题」列 | `Title` | `ProcessName` |
| 待办列表业务列 | `BizName` 或 `BizChannel` | 历史 `AppName` |
| 门户待办 Name | `Title` 或 `{Title}-{ActivityName}` | `{BizChannel}-{ActivityName}` |
| 流程定义名展示 | `ProcessName` | — |

产品 `titleSetting`（`sf_process_meta.extra_json`）消费属**后续任务**：建议由默认创建 Hook 或 Host 包读取模板 + 表单字段生成 `Title`；本专题只保证 **有列可写、有 Hook 可挂**。

## 5. 迁移与兼容

1. **库**：热表 `wf_proc_instance`（及 task / act_instance 等）`RENAME COLUMN` 或加新列双写；归档冷表按年分表同步。
2. **代码**：引擎 + 宿主（pxxt8 `api8/sailflow`）同一变更集切换属性名；JSON 序列化可用过渡别名。
3. **API**：对外 DTO 新字段用 `bizPK` 等；旧 `appInstanceId` 保留只读映射一个版本。
4. **存量数据**：`Title` 可空；列表回落 `ProcessName`。可选批处理：`UPDATE ... SET pi_title = pi_name WHERE pi_title IS NULL`。
