# 专题 · 主键与设计键发号契约

> 状态：**P0+P1 已落地**（2026-11-14）；P2 Guid7 / P3 非 Guid 列待续  

> 用途：把引擎侧「Id **取值**」提升为可替换契约；默认实现与注册在 runtime；业务宿主可覆盖（Guid7 / Yitter / 流水码器等）。  
> 范围：行主键发号、流程设计定义键 `ProcessId` 发号、与 mooSQL `AutoKey` 桥接、BPMN `process@id` 形态（独立 codec）。  
> 关联：[审计-流程ID自增转string对齐-2026-11-10.md](../../audit/审计-流程ID自增转string对齐-2026-11-10.md) · [专题-对象生命周期与复用边界.md](./专题-对象生命周期与复用边界.md)  
> **已删**：静态 `ProcessIdHelper`；调用方一律 `Sail.Ids` / `Sail.BpmnIds`（宿主工具入参注入）。

---

## 0. 结论先行

| 项 | 口径 |
|----|------|
| **问题** | 列类型 / `AutoKey` 名已可配，但取值写死 Guid；`ProcessId` 与行 PK 两套入口 |
| **契约** | engine：`ISailIdSource`（**每种 Id 一个方法**，不用枚举分发）+ `ISailBpmnIdCodec` |
| **默认** | **实现与注册在 runtime**：`GuidStringIdSource` + `DefaultSailBpmnIdCodec`；`UseGuidString` / `UseSailIdDefaults` / `UseSailRuntimeDefaults` |
| **覆盖** | 宿主 `UseSailIds(o => o.UseSource(...).UseBpmnCodec(...))` 覆盖；禁止只改 moo、引擎 `ProcessId` 仍走另一套 |
| **P0 列类型** | **仍锁 Guid 列**（`Tag=sail.id` → uniqueidentifier）；换非 Guid 发号属 P3，须同步 InitDb |
| **AutoKey 名** | **跟改**：实体与注册表正名为 **`SailId`**（勿再语义绑死 `"Guid"`）；过渡期 **双注册** `"SailId"` + `"Guid"` 同指向 `ISailIdSource.NextEntityRowId` |

---

## 1. 问题陈述

1. **行主键**：实体普遍 `AutoKey = "Guid"`，插入走 mooSQL `ResolveAutoKey`；`SailClient.EnsureGuidStringAutoKey` 已把 `"Guid"` 注册为 `Guid.NewGuid().ToString()`——**半抽象**，但发号策略仍钉死在 Client 内部。
2. **流程设计定义键 `ProcessId`**：历史上散落 `Guid.NewGuid()` / 静态 Helper，**不走** AutoKey，换算法要改多处（现已统一 `Ids.NextProcessDesignId`）。
3. **BPMN**：库侧须 Guid 兼容列时，XML `process@id` 还要满足 NCName（`Process_{guid:N}`）。发号与 XML 形态绑在同一静态类里，难替换。
4. 业务侧常见诉求：Yitter、Guid7、按租户/表的流水码——需要 **engine 契约 + ext 默认 + 宿主覆盖**，而不是继续散落 `new Guid`。

---

## 2. 三件事分开（禁止揉进一个接口）

| 能力 | 职责 | 载体 |
|------|------|------|
| **A. 发号** | 生成下一个 string Id | `ISailIdSource` |
| **B. 列类型** | 库列 Guid vs nvarchar | InitDb `Tag=sail.id` + `IsGuidCompatible` 策略 |
| **C. BPMN 形态** | `ProcessId` ↔ `process@id` / Plane | `ISailBpmnIdCodec` |

口诀：**发号可换；列类型跟着兼容性声明走；XML 编解码独立。**

寿命：发号源与 codec 属 **A · 应用级**（同寿于一个 `SailClient`），见 [专题-对象生命周期与复用边界.md](./专题-对象生命周期与复用边界.md)。

## 3. 引擎契约（pure）

### 3.1 `ISailIdSource` — 每种 Id 一个方法

**不用** `enum SailIdKind` + `Next(kind)`。显式方法便于实现类按键分流（例如行键 Guid7、设计键流水），也避免新增 Kind 时漏改 switch。

```csharp
namespace sailflow.engine.Ids
{
    /// <summary>
    /// 引擎统一 string Id 发号源。实现放 runtime/ext 或宿主；pure 不引用 Yitter 等。
    /// </summary>
    public interface ISailIdSource
    {
        /// <summary>
        /// 实体行主键（对应 SooColumn AutoKey 插入路径）。
        /// 须与实体属性类型兼容（现行均为 string）。
        /// </summary>
        string NextEntityRowId();

        /// <summary>
        /// 流程设计定义键 ProcessId（与 Version 配对；不是 wf_process 行 PK）。
        /// </summary>
        string NextProcessDesignId();

        /// <summary>
        /// 当前策略生成的值是否可写入 sail.id → uniqueidentifier 列。
        /// true：Guid / Guid7 等；false：Yitter / 流水码（须改列类型，见 §7）。
        /// </summary>
        bool IsGuidCompatible { get; }

        /// <summary>
        /// 挂到 mooSQL RegisterKeyGenerator 的 AutoKey 正名。
        /// 约定默认 <c>SailId</c>（见 §4）；勿再把算法名 Guid 当作注册名。
        /// </summary>
        string AutoKeyName { get; }
    }
}
```

扩展新键时：**在接口上加方法**（或拆子接口），不要回头引入枚举分发。预留示例（落地时按需）：

| 方法（预留） | 语义 |
|--------------|------|
| `NextActivityElementId()` | 图元活动 id（若统一发号） |
| `NextTransitionElementId()` | 图元连线 id |

首期只实现 `NextEntityRowId` / `NextProcessDesignId` 即可；预留方法可暂不出现在接口上，避免空实现噪音。

### 3.2 `ISailBpmnIdCodec`

```csharp
public interface ISailBpmnIdCodec
{
    string ToBpmnElementId(string processId);
    string FromBpmnElementId(string bpmnOrProcessId, out bool generatedNew);
    string RewriteProcessElementId(string xmlContent, string oldId, string newBpmnId);
    string TruncateCode(string code, int maxLen = 64);
}
```

与发号无关的纯变换；默认实现可继续承载现行 `Process_*` / Guid 互转逻辑。

### 3.3 挂载点

| 成员 | 说明 |
|------|------|
| `SailClient.Ids` | `ISailIdSource` |
| `SailClient.BpmnIds` | `ISailBpmnIdCodec` |
| `UseSailIds(Action<SailIdBuilder>)` | Builder / `ISailCollection` 风格，与 Gate/Hook 一致 |

未配置时：Build 期由 runtime 默认填入，**禁止**运行期 NRE。

## 4. 与 mooSQL AutoKey 的关系

moo 已有：`AutoKey`、`IKeyGenerator`、`MooClient.RegisterKeyGenerator`、`ResolveAutoKey`。  
moo 对未注册的 `"Guid"` 仍有**内置回退**（`Guid.NewGuid` 对象）——正因如此，Sail 更应**个性化注册名**，避免业务以为换了 Source、实体却仍命中 moo 内置 Guid。

### 4.1 Tag vs AutoKey（两套名字，勿混）

| 元数据 | 现行 / 目标 | 管什么 |
|--------|-------------|--------|
| **`Tag = "sail.id"`** | 保持 | **列类型族**（InitDb → Guid / 将来 str） |
| **`AutoKey = "SailId"`** | **目标正名**（原 `"Guid"`） | **发号器注册表 key** → `ISailIdSource.NextEntityRowId` |

不要用 `sailKey`（过泛）；不要用 `sailID` 大小写混用。常量建议：

```csharp
public static class SailIdNames
{
    /// <summary>SooColumn.AutoKey 正名；RegisterKeyGenerator 主 key。</summary>
    public const string AutoKey = "SailId";

    /// <summary>过渡期兼容旧实体 / 旧文档。</summary>
    public const string AutoKeyLegacyGuid = "Guid";

    /// <summary>SooColumn.Tag：列类型族（与 AutoKey 正交）。</summary>
    public const string ColumnTag = "sail.id";
}
```

### 4.2 桥接与双注册

1. **新实体 / 改动触达的实体**：`AutoKey = "SailId"`（或 `SailIdNames.AutoKey`）。
2. `UseSailIds` Apply 时向 moo **双注册**（同委托，覆盖 moo 内置 Guid 回退）：

   ```csharp
   Func<object> gen = () => source.NextEntityRowId();
   moo.RegisterKeyGenerator(source.AutoKeyName, gen);          // 默认 "SailId"
   moo.RegisterKeyGenerator(SailIdNames.AutoKeyLegacyGuid, gen); // "Guid" → 同一 Source
   ```

3. 行 PK 插入仍只走 AutoKey；换算法 = 换 `ISailIdSource` + 重注册（两名一起指新 Source）。
4. `ProcessId` 手工赋值：`client.Ids.NextProcessDesignId()`，与行键共用同一 Source 实例。

**禁止：** 宿主只改 moo、引擎 `ProcessId` 仍 `Guid.NewGuid`；禁止实体继续写 `"Guid"` 却未双注册（会落到 moo 内置、与 Sail Source 分叉）。

### 4.3 存量实体迁移

| 步 | 动作 |
|----|------|
| P0 | 双注册；实体可暂留 `AutoKey="Guid"` |
| P1 | 引擎 / biz / 宿主实体批量改为 `AutoKey="SailId"`（约 20+ 处 sailflow + 宿主若干） |
| P1 末 | 文档与单测只认 `SailId`；`"Guid"` 注册可保留一版作兼容，标 Obsolete 注释 |

## 5. 默认实现与覆盖（runtime）

**分层：** engine 只保留契约（`ISailIdSource` / `ISailBpmnIdCodec` / `SailIdNames`）与通用装配（`UseSailIds` + moo 双注册）；**内置 Guid 实现与 `UseGuidString` 注册在 `sailflow.runtime`**。

| 类型 | 落点 | 行为 |
|------|------|------|
| `GuidStringIdSource` | **runtime.Ids** | 两方法均 `Guid.NewGuid().ToString("D")`；`IsGuidCompatible=true`；`AutoKeyName="SailId"` |
| `DefaultSailBpmnIdCodec` | **runtime.Ids** | 现行 NCName / Rewrite / Truncate |
| `UseGuidString` / `UseSailIdDefaults` | **runtime.Hosting** | 挂 Source+Codec；由 Build `ApplyPending` 落到 Client + moo |
| `Guid7IdSource` | ext 可选（待 P2） | 两方法 Guid7→D；仍 `AutoKeyName="SailId"` |
| 宿主自定义 | 业务仓 | `UseSailIds(o => o.UseSource(...).UseBpmnCodec(...))` |

说明：换 Yitter/Guid7 时 **AutoKey 名不变**（仍是 `SailId`），变的是注册到该名上的委托实现。

装配示例：

```csharp
// 推荐：runtime 总包（含 Id 默认）
builder.UseSailRuntimeDefaults();

// 或仅 Id 默认
builder.UseSailIdDefaults(); // ≡ UseSailIds(o => o.UseGuidString())

// 宿主覆盖（后注册覆盖）
builder.UseSailIds(o => o
    .UseSource(new YitterSailIdSource(workerId: 1))
    .UseBpmnCodec(new DefaultSailBpmnIdCodec(/* 或自定义 codec */)));
```

engine `SailIdBuilder` 能力：`UseSource` / `UseBpmnCodec` / `SetGuidCompatibleColumns`（**无** `UseGuidString`）。  
行键与设计键分流：`UseSource(entityRow, processDesign)` → `CompositeSailIdSource`（仍在 engine）。

## 7. 列类型与非 Guid 策略（P3）

| `IsGuidCompatible` | InitDb | BPMN |
|--------------------|--------|------|
| `true`（P0/P1） | `sail.id` → Guid / uniqueidentifier | `Process_{N}` 互转 |
| `false` | **不得**再映成 Guid；改 nvarchar 或 Tag `sail.id.str` | 数字开头加前缀；`FromBpmn` 可逆剥前缀 |

流水码更适合 `ProcessCode` / 业务单据号，**慎用**作 `ProcessId`（设计键会进大量 FK/查询）。若坚持，须全库 string 列 + 文档声明。

## 8. 分期落地

| 期 | 内容 | 验收 |
|----|------|------|
| **P0** | ✅ 契约 + `GuidStringIdSource` + codec + moo **双注册** `SailId`/`Guid` + 单测 | 行为与现一致；假 Source 同时打到两名 |
| **P1** | ✅ 清硬编码发号；实体 `AutoKey`→`SailId`；`UseSailRuntimeDefaults` 挂默认；删 `EnsureGuidStringAutoKey` | 全路径走 `Ids`/`BpmnIds`；特性正名 `SailId` |
| **P2** | `Guid7IdSource`、宿主样例 | 换实现不改实体 AutoKey 名 |
| **P3** | 非 Guid：Tag/InitDb、Yitter 样例、迁移说明 | `IsGuidCompatible=false` 时建表不为 uniqueidentifier |

## 9. 已拍板 / 待拍板

### 9.1 已拍板（本文）

| 题 | 结论 |
|----|------|
| 接口形态 | **每种 Id 一个方法**，不用 `SailIdKind` 枚举 |
| P0 列类型 | 锁 Guid 兼容列 |
| AutoKey 注册名 | **正名 `SailId`**；过渡双注册 `"Guid"`；**不**用 `sailKey` |
| Tag | 保持 `sail.id`（列类型族，与 AutoKey 正交） |
| 发号 vs BPMN | 两个接口 |
| 默认落点 | **实现+注册在 runtime**；engine 仅契约与 `UseSailIds` 通用装配；Yitter 等不进 pure |
| 换算法 | 只换 `ISailIdSource` 注册内容，**不**改实体上的 `AutoKey="SailId"` |

### 9.2 实施时再确认

| 题 | 选项 |
|----|------|
| `"Guid"` 双注册保留多久 | 再留一版兼容 vs 去掉 |
| Guid7 进 runtime 还是独立 ext 包 | 依赖体积决定 |

## 10. 非目标

- 不在 pure 引用 Yitter / IdGen 等 NuGet。
- 不把 `AppInstanceId`（业务单据键）纳入 `ISailIdSource`——属宿主业务域。
- 不改变「定义行主键 vs ProcessId」语义分层（见 ID 审计文档）。
- 不借发号契约改表名前缀规范（见 [dic/sail/dev/规范-实体表与字段命名.md](../../../dic/sail/dev/规范-实体表与字段命名.md)）。
