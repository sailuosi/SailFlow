# 专题 · 办理工具栏与按钮呈现

> 状态：**实施中**（2026-11-28；引擎 `TryLoadScopeCandidates` + 宿主 Workbench/办理条/设计器已接线）  
> 用途：把办理页工具栏的**呈现分层**与按钮配置属性对齐；明确 Scope 对**选人组件**的约束，以及引擎 / 宿主在「按钮参数」与「范围加载」上的接洽边界。

## 0. 结论先行

| 项 | 口径 |
|----|------|
| **一句话** | 工具栏按 `priority` 分层外露 / 收纳；同层内按 `sort` 排序；`icon`/`theme` 只影响观感；选人 UI 按按钮 `scopeType`（+`params`）选型；并允许夹杂**自定义（非流程）按钮** |
| **放置** | 办理条挂**页头右侧**；二级交互统一**强掌控 Dialog**（遮罩、禁点遮罩/Esc 关闭）；**不再**占底栏 / 锚点 popover |
| **sort** | **同一 priority 内**的左右顺序；数值越小越靠前 |
| **priority** | **前端分组键**（引擎不解释）：`1` 外露深底浅字；`2` 外露浅底；`3` 外露**弱视文字按钮**；`11` 收进「更多」 |
| **icon / theme** | 仅 UX；空 icon=无图标；theme 定**色相**（与 priority 深/浅正交） |
| **自定义按钮** | 保存/打印/下载/返回等**非流程能力**：设计器快捷添加；**类型固定为 Custom**；**code（id）用约定闭集**；引擎**不执行**，由宿主页壳监听 |
| **按钮参数传递** | Workbench / 办理条加载时已 Merge 好的 `sf:button` 属性随工具栏下发；**点按钮触发弹层/提交时直接用内存中的该按钮配置**，**不必**再调接口拉 Button 参数 |
| **范围加载** | 引擎提供「按 scopeType+params 调已注册 Scope 加载器」的**快捷方法**；宿主选人 API **可选用**该方法，也可自研——自研须自行保证与 Fixed 路径行为一致 |
| **选人器选型** | 宿主职责：空/`AnyMan`→任意人选择器；单位/部门等→对应选择器；引擎只给**原始按钮配置 +（可选）范围加载结果** |

## 1. 目标布局（对照办理页页头示意）

```text
编号：xxx          [发送] [保存] [退回] … [更多 ▾] │ （可选壳层兜底）刷新…
────────────────────────────────────────────────────────
标题 / 状态 / 元信息 …
```

| 区 | 内容 | 来源 |
|----|------|------|
| **工具栏（统一条）** | 流程动词（通过/退回/转办…）**+** 非流程自定义（保存/打印/下载/返回…） | 均来自 `sf:ButtonsSetting` → Merge → `SailOperationBar`；按同一套 `priority`/`sort` 混排 |
| **自定义按钮** | 类型固定 `Custom`；code 用约定表（§2.8）；点击由宿主处理 | 设计器「快捷添加」一键写入 |
| **壳层兜底** | 仅当节点未配置对应 Custom 时，详情页可保留默认刷新/返回等 | 避免裸页无出口；**有配置则以工具栏为准**，勿重复两套 |

底栏 sticky footer **取消**；表单区不被办理条遮挡。窄屏允许办理按钮换行，不挡标题区。

打印：工具栏继续走既有 `sf-no-print`（或按 Custom.Print 是否参与打印自定）；打印预览默认隐藏办理/自定义动作。

## 2. 任务 1 · 按钮呈现属性（初步设想）

配置载体不变：节点 `sf:ButtonsSetting` > `sf:button@*`（见对象解析器 §5.3）。本专题把 **呈现向**字段写清楚，供设计器默认值、Merge、办理条渲染统一解释。

### 2.1 属性一览（呈现相关）

| 属性 | 类型 | 缺省建议 | 谁解释 | 含义 |
|------|------|----------|--------|------|
| `type` | string | 空 = 流程按钮 | 前端 + 宿主 | 仅自定义写死 **`Custom`**（§2.8）；空/缺省走流程动词码表 |
| `sort` | number | 码表序 / 设计器落盘序 | **仅前端** | **同一 `priority` 内**的顺序；越小越靠左 |
| `priority` | number | 建议码表给常用动词默认 | **仅前端** | 分层：外露突出 / 外露普通 / 外露文字弱化 / 「更多」 |
| `icon` | string | 空 | **仅前端** | 图标键；**空 = 无图标** |
| `theme` | string | 空或码表语义色 | **仅前端** | 按钮主题；映射宿主 UI 库 type（见 §2.5；勿与 `button@type` 混淆） |

与取人正交、但常同写在一个 `sf:button` 上的字段（本专题不改语义，引用对象解析器）：

| 属性 | 用途 |
|------|------|
| `selectModel` / `scopeType` / `params` | 本动词取人 Mode × Scope |
| `minSelect` / `maxSelect` | 本动词选人数 |
| `id` / `enable` / `displayName` | 键、启用、文案 |

### 2.2 `sort` 与 `priority` 的关系

```text
渲染顺序
  1. 按 priority 分桶（升序：1 → 2 → … → 11）
  2. 桶内按 sort 升序
  3. sort 缺失时回落码表默认序 / id 稳定序
```

**示例（同一节点）：**

| id | priority | sort | 呈现 |
|----|----------|------|------|
| Approve（发送/通过） | `1` | `10` | 外露、**突出**（实心 / 主色） |
| （示意）保存草稿 | `1` | `20` | 外露、突出（若产品启用该按钮） |
| SendBack（退回） | `2` | `10` | 外露、**不突出**（描边 / plain） |
| （页级）打印 | — | — | 页壳 link，**不**走 `sf:button` |
| Copyto（抄送） | `11` | `10` | 「更多」内 |
| Transfer / SignForward / … | `11` | … | 「更多」内 |

说明：示意里的「保存草稿 / 第 N 次打印」若本仓无对应动词代表，**不必**造假按钮；页级「打印」保持详情页壳动作即可。

### 2.3 `priority` 档位约定（产品闭集建议）

| 值 | 档位 | 工具栏行为 | 视觉（默认设计实现构想） |
|----|------|------------|------|
| **`1`** | 高 | **外层**直接显示 | **深色底 + 浅色字**（实心填充）；`theme` 决定色相（如 success 绿底白字、primary 蓝底白字）；抓眼球 |
| **`2`** | 中 | **外层**直接显示 | **浅色底风格**（浅底 / 白底 + 描边或同色浅字）；同 `theme` 色相但不抢主按钮；次要但不藏 |
| **`3`** | 弱 | **外层**直接显示 | **弱视感文字按钮**（无底无框 / link）；比 `2` 更弱，不抢视线；常用于刷新、返回等壳层感动作 |
| **`11`** | 低 | **折叠进「更多」** | 下拉项；点开后再走同一套 Dialog / 确认链 |
| 其它 | 未登记 | 建议视为「低」进更多，或设计器校验拦非法值 | — |

**默认绘制约定（与宿主 UI 库映射）：**

| priority | 绘制 | Element Plus 等常见映射 | 说明 |
|----------|------|-------------------------|------|
| `1` | 深底浅字 | `type={theme}`，**非** `plain`（实心） | 对照示意「发送 / 保存」 |
| `2` | 浅底风格 | 同 `type={theme}` + **`plain`**，或浅灰底 + 主题色描边/文字 | 对照示意「退回 / 打印」 |
| `3` | 文字弱化 | **`link`**（或纯文字 + 次要色）；一般不再加实心/描边底 | 弱视感；不抢主操作 |
| `11` | 菜单项 | 下拉文字；可选小色点，不强制深底 | 「更多」内 |

`theme` 空时：色相回落码表语义 fallback（Approve→success、SendBack→danger 等）。**priority 管视觉权重（实心 / 浅底 / 文字 / 更多），theme 管色相**——二者正交，勿用 theme 单独冒充「是否突出」。

> **与旧实现差异：** 早期办理条可能「凡启用皆外露」。本专题定稿后，办理条应以 `priority` 分层；**未配 priority** 时建议回落：Approve/Acknowledge/Save→`1`，SendBack/Print→`2`，Back/Refresh→`3`，其余→`11`，避免顶栏挤爆。

「更多」内点击：仍打开该按钮既有 **强掌控 Dialog** / 确认链；**不**另造一套命令协议。通过 / 驳回 / 阅办等意见类亦用 Dialog（非页头锚点 popover）。

### 2.4 `icon`

| 规则 | 说明 |
|------|------|
| 有值 | 宿主按约定映射到图标组件（如 `transfer` → 转办图标） |
| **空 / 未配** | **不渲染图标**，仅文案（或「更多」菜单纯文字） |
| 引擎 | **不**依赖、不校验图标资源 |

### 2.5 `theme`（用户口语「them」）

| 规则 | 说明 |
|------|------|
| 取值 | 建议对齐宿主按钮 type 闭集：`primary` / `success` / `warning` / `danger` / `info` / 空 |
| 空 | 用码表或办理条对应该动词的**语义 fallback**（如 Reject/SendBack → `danger`，Approve → `success`） |
| 与 priority | **正交**：theme=色相；priority=`1`→实心、`2`→plain、`3`→link 文字弱化、`11`→菜单项（§2.3） |

宿主已有映射参考：`resolveButtonElType(settings, id, fallback)`（`buttonsCatalog.ts`）。

### 2.6 沟通锁定等非按钮条

待沟通未反馈完时，顶栏用**紧凑** `el-tag` / 短文案，勿用宽 `el-alert` 撑破页头。行为锁定规则仍听运行时 `consultPending`，与本专题属性无关。

### 2.8 自定义按钮（非流程能力）

工具栏在真实业务里常夹杂**与引擎流转无关**的动作：保存草稿/表单、打印、下载附件包、返回列表等。这些**不应**假装成 `FlowOperation`，但应与流程按钮**同一配置面、同一排序/优先级模型**，避免页壳硬编码与设计器脱节。

#### 2.8.1 类型

| 项 | 口径 |
|----|------|
| **属性名** | `type`（XML / 设置对象）；缺省或未写 = **流程按钮**（走码表 `Approve`/`Transfer`…） |
| **自定义取值** | 固定 **`Custom`**（大小写敏感建议统一 Pascal：`Custom`） |
| **引擎** | `type=Custom` **不**进入 Lane / `FlowOperation`；Workbench 原样下发快照即可 |
| **取人字段** | Custom **忽略** `selectModel`/`scopeType`/`params`/`minSelect`/`maxSelect`（设计器可灰显） |

#### 2.8.2 约定 code（`id`）

快捷添加写入的 **`id` 用闭集 code**，宿主按 code 挂行为；**禁止**与流程动词 id 撞名。

| code（`id`） | 默认文案 | 建议 priority | 宿主典型行为 |
|--------------|----------|---------------|--------------|
| `Save` | 保存 | `1` | 保存表单/业务草稿（非发送） |
| `Print` | 打印 | `2` | 调页壳打印 / 打印预览 |
| `Download` | 下载 | `11` 或 `2` | 下载附件包 / 导出 |
| `Back` | 返回 | `3` | `router.back` / 回列表（弱视文字） |
| `Refresh` | 刷新 | `3` | 重新拉 Workbench（弱视文字） |
| `Export` | 导出 | `11` | 导出 Excel/PDF 等（可选） |

> 扩展：宿主私有能力用 **`Custom.` 前缀** 自定义 code（如 `Custom.Archive`），仍写 `type="Custom"`；设计器「快捷添加」只保证上表**一等快捷项**，前缀项走「添加自定义」高级入口。

#### 2.8.3 设计器：快捷添加

| 能力 | 说明 |
|------|------|
| **快捷条/菜单** | 「添加保存 / 打印 / 下载 / 返回 / 刷新…」一键插入一条 `sf:button` |
| **落盘** | `type="Custom"` + 上表对应 `id` + 默认 `displayName`/`priority`/`sort`（可再改） |
| **去重** | 同节点同一 `id` 仅一条；已存在则聚焦/提示，不重复插入 |
| **与流程按钮混排** | 同一 `ButtonsSetting` 列表；预览即按 priority+sort 显示 |
| **不可改 type** | 快捷项创建后 `type` 锁定为 `Custom`；不允许改成流程动词 id |

#### 2.8.4 运行时接洽

```text
用户点击工具栏按钮
  → 若 type≠Custom（或无 type）：走既有办理动词（Approve/Transfer…）
  → 若 type=Custom：
        emit('custom', { id, displayName, theme, icon, …快照 })
        宿主详情页 / 业务壳 switch(id)：
          Save → 调业务保存 API
          Print → onPrint()
          Back → router.back()
          …
        引擎无命令、无 Lane
```

| 规则 | 口径 |
|------|------|
| **行为归属** | **宿主**；引擎不注册 Custom 处理器 |
| **未识别 code** | 前端可 no-op + 开发态警告；勿当流程动词误提交 |
| **与壳层默认按钮** | 节点已配置 `Print`/`Back`/`Refresh` 时，页壳**隐藏**同义硬编码按钮，避免双份 |
| **权限** | Custom 是否显示可由宿主按业务权限再过滤；`enable=false` 仍表示设计器关闭 |

## 3. 任务 2 · 范围参数驱动选人组件

### 3.1 问题

按钮上的 `scopeType` / `params`（及节点 `assigneeResolve`）已经约束「能圈哪些人」，但**选人 UI** 若一律「全站任意人搜索」，则：

- 配置成部门/单位范围时，用户仍看到无关人员；
- Fixed 路径引擎展开与 Pick 路径选人器体验不一致。

**原则（与对象解析器一致）：** 引擎/判定层**不做**「所选 ⊆ Scope」强拦截；**由选人器**按 Scope 限制可选名单。本专题补的是：**选人器如何按配置选型，以及宿主如何拿到范围数据。**

### 3.2 选型矩阵（宿主侧）

| `scopeType`（空或码） | 选人组件效果（产品期望） |
|----------------------|--------------------------|
| **空** 或 **`AnyMan`** | **任意人选择器**（全站/组织树搜索，不预绑部门） |
| **`DeptMembers`** / 部门全员 | **部门人员选择器**（按部门树或固定部门过滤） |
| **单位 / UnitMap** 等 | **单位选择器或单位下人员选择器**（按 params 字段） |
| **`RoleGroup`** | 角色成员选择器 / 先选角色再展人（宿主定） |
| **`FixedUsers` / `Specific`** | 名单内多选；可弱化为只读勾选 |
| **`deptBoss` 等领导链** | 宿主专用选择器或预计算名单 + 列表勾选 |
| **其它已注册 Scope** | 优先「范围加载结果 → 列表/树勾选」；无合适控件时回落「任意人 + 提示」 |

`selectModel=Fixed`：常**免手选**（办理条已有 Fixed 免选路径）；若仍展示人选，以范围加载结果为唯一候选。  
`selectModel=Pick`：必须手选（或按 min/max）；候选由 Scope 决定。  
`Approve` 下一跳：听**目标节点** `assigneeResolve`，不听「通过」按钮上的 scope（对象解析器 §4）。

### 3.3 数据从哪来：按钮参数 vs 范围加载

```text
┌─ 工具栏 / Workbench 加载 ─────────────────────────────┐
│  Merge(Catalog, sf:ButtonsSetting)                     │
│  → 每个启用按钮的完整属性快照（含 selectModel/scopeType/ │
│    params/min·max/sort/priority/icon/theme…）           │
│  → 前端办理条持有；点按钮时直接读该快照                  │
└────────────────────────────────────────────────────────┘
         │ 触发选人（Pick 等）
         ▼
┌─ 宿主选人接洽 ─────────────────────────────────────────┐
│  入参 A：按钮原始配置（来自工具栏快照，不二次拉 Button） │
│  入参 B（可选）：调用引擎「范围加载快捷方法」的结果        │
│  → 按 scopeType 选组件 + 灌入候选 / 过滤树               │
└────────────────────────────────────────────────────────┘
```

| 数据 | 时机 | 说明 |
|------|------|------|
| **Button 参数** | 工具栏加载时已有 | 点「转办/加签/抄送…」打开选人时**直接传递**该按钮 Merge 后对象；**禁止**再为读配置打一枪专用接口 |
| **范围加载结果** | 打开选人时按需 | 调引擎/宿主 API，内部走**已注册** `IAssigneeResolver`（Scope）；用于灌候选或约束树 |

### 3.4 引擎统一接口（契约意图）

引擎侧不负责画 UI，只提供两类信息的稳定出口：

#### A. 原始按钮配置

Workbench / 办理上下文中已包含 Merge 后的按钮列表（与 XML `sf:button` 字段对齐）。前端与宿主 API 共用同一形状，例如：

```text
ButtonSettingSnapshot {
  id, enable, displayName,
  selectModel, scopeType, params,   // params 为 JSON 字符串或已解析字典
  minSelect, maxSelect,
  sort, priority, icon, theme,
  … // 码表补齐的 engine 等可不下发到前端
}
```

#### B. 范围加载快捷方法

```text
// 概念签名（实现名以代码为准）
LoadScopeCandidates(
  scopeType: string,          // 空 → 按 AnyMan 语义处理
  params: object | string,    // 与 sf:button@params / assigneeResolve@params 同形
  context: RuntimeContext     // 实例/活动/当前用户/Conditions 等解析所需
) → PerformerList | CandidateBundle
```

| 规则 | 口径 |
|------|------|
| **实现** | 转发到**当前 Sail 已注册**的 Scope 加载器（与 Fixed `Scope.Resolve` 同源注册表） |
| **空 / AnyMan** | 返回「无固定名单 / 空约束」标记，宿主据此挂任意人选择器，**不要**误当成「无人可选」 |
| **未注册 scopeType** | 明确失败码；宿主勿静默当 AnyMan（避免与设计不符） |
| **谁调用** | **宿主定义**对外 HTTP/应用服务；内部**推荐**调该快捷方法 |
| **可否不用** | 允许宿主自研圈人；但有与 Fixed/预览路径**行为不一致**的风险，须自测对齐 |

抄送（R5）：可选人预览可共用范围加载；提交仍走 Copyto Targets，**不**写入办理 `Performer[]`（见范围注册清单 §4）。

### 3.5 宿主接洽清单

| 项 | 宿主做 | 引擎做 |
|----|--------|--------|
| 选择器组件库 | 任意人 / 部门 / 单位 / 角色… 多套控件 | 不提供 UI |
| 选型路由 | `scopeType` → 选哪套控件 | 只给码与 params |
| 候选灌入 | 调「范围加载」API 或自研 | 提供快捷方法 + 注册表 |
| 按钮触发 | 用工具栏已下发的 Button 快照开弹层 | Workbench 带齐 Merge 结果 |
| 校验 min/max | 提交前前端 + 服务端按按钮配置 | 管道侧既有 Pick 人数规则可复用 |

## 4. 办理条渲染算法（前端）

```text
visible = Merge 后 enable=true 且当前语境允许的按钮
buckets = group by priority
outerProminent = priority==1 按 sort
outerNormal    = priority==2 按 sort
outerWeak      = priority==3 按 sort   // 文字弱化 link
more           = priority>=11（及未识别低档）按 sort

页头：
  [outerProminent 实心] [outerNormal plain] [outerWeak link] [更多(more)]
  （流程按钮与 type=Custom 混排；Custom 点击走宿主 custom 事件）
  「更多」按钮的 flex order = 更多内各项 sort 的**最小值**（插在外露按钮序列中的对应位置）

二级表单：统一 el-dialog（append-to-body；close-on-click-modal=false；close-on-press-escape=false）
确认链：ElMessageBox（Withdraw / Close / Terminate 等）保持不变
```

`Approve` 的下一跳选人：读**目标节点** assigneeResolve 的 scope，选型规则同 §3.2，配置来源不是 Approve 按钮自身。  
`type=Custom`：不参与选人 / Lane；只参与分层渲染与宿主回调。
