## 0. 结论先行（决策表）

| 编号 | 决策 | 口径 |
|------|------|------|
| **D1** | Sync + 主事务 kit 时，**软超时仍生效且超时必抛** | 有 `kit` 也计时；`Handle` **返回后**超时 → **抛** `FlowSyncHookTimeoutException`，FailFast。超时阈值取自**钩子实例**（见 D8），非仅全局 Options。不保证打断阻塞 SQL；永久阻塞靠 D2。 |
| **D2** | **进度日志（排障主手段）** | 每个 Sync 钩子：**BEGIN / END / SLOW / FAIL** 经 **D10 `SailClient.Log`**；BEGIN/END 级别为 **Debug**（开发把 `MinimumLevel=Debug`）。卡死时「有 BEGIN、无 END」定位钩子名。 |
| **D3** | 同事务优先复用 kit（**建议，非运行时强制**） | 有 `ctx.Kit` 时，**推荐**用 `ctx.Kit` / `kit.useSQL()` 及带 kit 的 Service/Manager 重载读写引擎库；另开 `UseRunSQL` 易与主事务自锁。本期**不做**运行时拦截。 |
| **D4** | ~~开发期 UseRunSQL 硬护栏~~ | **已删除**（不做 AsyncLocal 禁连）。 |
| **D5** | 禁止空吞 | Sync 钩子不得 `catch { }` 无日志；至少经 `Sail.Log` 打 Warning/Error；开发环境建议直接上抛。调度层包装为带钩子名的 `FlowSyncHookException`（与超时异常并列，便于 API 映射）。 |
| **D6** | 慢钩子可观测 | `SyncHookWarnMs` 放 **`FlowCapabilityOptions`**；低于硬超时打 SLOW（Warning）。与 D2 共用耗时。 |
| **D7** | Sync / AsyncOutbox 选型 | 必须读写**未提交**流程数据 → Sync+kit；可延后副作用 → AsyncOutbox；仅观测 → BestEffort/文件，不得 Sync 堵主路径。 |
| **D8** | **按钩子超时（基类默认 30s）** | `FlowHookBase.TimeoutMs` 默认 **30000**；子类可改。调度读实例超时；`≤0` 表示不限制（仍打 BEGIN/END）。全局 `CapabilityOptions.SyncHookTimeoutMs` 仅作委托钩子/未继承基类时的回退，宿主勿再靠放大全局掩盖锁等待。 |
| **D9** | 教程纠偏 | 《事件体系》注明：现行 `kit != null` 旁路超时；落地后以 **D1/D2/D8** 为准（有 kit 也软超时 + 进度日志 + 钩子级 TimeoutMs）。 |
| **D10** | **全局运行时日志契约** | `SailClient.Log` + `LogOptions`；级别 Debug / **Message** / Warning / Error（可选 Trace）。Builder：`useLogLevel(...)`、`useLogger(ISailLogger)`。默认 **ConsoleSailLogger**；测试可 `NullSailLogger`。Gate/Hook/Notifier/回调统一 `client.Log.*`；与 `IEngineLogSink` 分工见 §3.9。 |

**一句话**：没法安全打断同步 `Handle` 时，**进度日志是排障主手段**；输出走 `SailClient.Log`；超时按钩子基类默认 30s 且返回后必抛；kit 复用是建议而非强制拦截。

## 1. 问题陈述

### 1.1 故障形态（已确认）

1. `CommitOnSuccessAsync` → `beginTransaction` **成功**。
2. 流转插入实例 / 活动 / 待办后触发 `OnProcessStarted` Sync 钩子。
3. 钩子内调用 `GetProcessVariable*` / `SaveProcessVariable` 等**无 kit** API → 内部 `Sail.UseRunSQL()`。
4. 新连接等待主事务锁（SQLite Error 5/6 或 SQL Server 锁等待）；主事务等待钩子返回 → **自锁**。
5. 调试表现为停在宿主钩子某一行「无响应」；强制终止后库可能残留写锁，后续发起在 `beginTransaction` 即失败，待办查询亦挂。

### 1.2 为何极难排查

| 因素 | 说明 |
|------|------|
| **超时旁路** | `FlowCapabilityDispatcher.RunSyncHooks`：`kit != null` 时直接 `Handle`，**不走** `Thread.Join(timeoutMs)`。宿主设置的 `SyncHookTimeoutMs` 对发起路径**无效**。 |
| **不能安全杀线程** | 有 kit 时连接/事务不可跨线程；C# 亦无对任意同步 `Action` 的抢占式中断（`Thread.Abort` 已不可用）。`Stopwatch` 只计时，不会到点抛事件。 |
| **无进度日志** | 不知道「正在跑哪个钩子、是否已结束」。 |
| **空 catch** | 部分宿主钩子吞掉异常，超时/锁错误不可见。 |
| **教程口径偏差** | 文档写「Sync 受超时约束」，与 `kit != null` 旁路行为不一致。 |

### 1.3 相关代码锚点

```csharp
// FlowCapabilityDispatcher.RunSyncHooks（现行）
if (timeoutMs <= 0 || kit != null)
{
    hook.Handler.Handle(ctx);   // 有 kit → 无超时、无 BEGIN/END
}
else
{
    // Thread + Join(timeoutMs) → FlowSyncHookTimeoutException
}
```

宿主放大超时（治标不治本，且有 kit 时仍无效）：

```csharp
// sleveen-admin SailflowHostSetup
client.CapabilityOptions.SyncHookTimeoutMs = 20_000;
```

## 2. 目标与非目标

### 2.1 目标

1. 建立 **SailClient 顶级运行时日志**（`Log` + `LogOptions`），Gate/Hook/Notifier/回调统一输出（D10）。
2. Sync+kit 路径下，**能看见正在唤起谁、是否结束、耗时多少**（D2，经 `Log` 输出）。
3. `Handle` 能返回时，超时/慢钩子**可失败、可归因**（D1/D6）。
4. kit 复用作为**最佳实践**写入文档与审计清单，**不**做运行时强制拦截。
5. 决策已定，按 **P0 → P1** 分期改引擎代码（本稿仍可先文档后实施）。

### 2.2 非目标（本期不做）

1. 在有 kit 时用工作线程强杀阻塞 SQL / `Thread.Abort`。
2. `AsyncLocal` 禁止 `UseRunSQL`（原 D4，已删除）。
3. 批量废弃 Manager 无参重载。
4. 用 SQLite 连接串技巧替代钩子可观测（可作宿主运维手段，非本专题必做）。
5. 取消 Sync 模式或强制全部 Outbox。
6. 改 `IFlowHook.Handle` 签名加 `CancellationToken`。
7. 用 `ISailLogger` **替代** `IEngineLogSink` 落库（二者并存，见 §3.9.1）。

## 3. 决策细则

### 3.1 D1 · 有 kit 时的软超时（超时必抛）

**行为**：

1. 每个匹配的 Sync 钩子：与 D2 同一轮 `Stopwatch` → `Handle` → 读耗时。
2. 解析该钩子 `timeoutMs`（见 D8）：若 `timeoutMs > 0` 且 `ElapsedMs > timeoutMs` →  
   `IncrementSyncHookTimeout()` + **必抛** `FlowSyncHookTimeoutException`（Message 含钩子名、EventType、KitPresent、ElapsedMs、TimeoutMs）。
3. **不**另开线程；超时判定在 `Handle` **返回之后**。
   - `Handle` 永久阻塞 → 软超时不触发，靠 **D2 缺 END** 归因。  
   - 阻塞受 ADO/`busy_timeout` 限制 → 返回后按耗时 FailFast。

#### 3.1.1 永久阻塞的补充（可选二期）

| 方案 | 利弊 |
|------|------|
| A. DB `CommandTimeout` / `busy_timeout` 与钩子超时对齐 | 实现简单；缩短闷锅上限 |
| B. Sync 内禁止同步长 HTTP 等 | 规范；HTTP → Outbox |
| C. `Handle` 增加 `CancellationToken` | 破坏面大，**本期不做** |

**本期采纳**：D2 进度日志（主）+ D1 软超时必抛（返回后）+ 可选 A/B。不做 C。

### 3.2 D2 · 进度日志（排障主手段）

**前提**：C# 无法安全打断任意同步逻辑；`Stopwatch` 也不会到点抛事件。因此 **BEGIN/END 是卡死时的主线索**。

每个 Sync 钩子固定四类输出（经 `Sail.Log`，category=`sync-hook`）：

| 时机 | 级别（已定） | 内容 |
|------|--------------|------|
| **调用前** | **Debug** | `BEGIN name=… event=… kit=… pi=… task=…` |
| **调用后成功** | **Debug** | `END name=… event=… elapsedMs=…` |
| **elapsed &gt; WarnMs** | Warning | `SLOW name=… event=… elapsedMs=… warnMs=…` |
| **抛错** | Error | `FAIL name=… event=… elapsedMs=… ex=…` |

**卡死读法**：日志里最后一条是某钩子的 `BEGIN` 且没有对应 `END` → 即卡在该钩子（或其调用的同步依赖）内。

**实施注意**：

1. 开发环境：`builder.useLogLevel(SailLogLevel.Debug)`，且 Sink 尽量同步刷出，避免卡死后 BEGIN 还在缓冲区。  
2. 生产默认 `MinimumLevel=Message`（或更高）时 BEGIN/END 自然关闭，保留 Warning/Error。  
3. 同一轮 `RunSyncHooks` 可带短 `traceId`，与请求关联。  
4. 钩子内部大步骤可另打子进度，但调度层 BEGIN/END 已足够定位「哪个钩子」。  
5. **禁止**调度层再用 `System.Diagnostics.Trace` / `Console` 打进度（统一 D10）。

超时异常 Message 建议模板：

```text
Sync workflow hook '{name}' on {eventType} exceeded {timeoutMs} ms (elapsed={elapsed}ms, kit={kitPresent}).
Check sync-hook BEGIN without END in logs; prefer FlowHookContext.Kit for engine DB access.
```

### 3.3 D3 · kit 复用（建议，非强制）

| 推荐 | 风险说明（不强制拦截） |
|------|------------------------|
| `ctx.Kit` / `ctx.Kit.useSQL()` | — |
| 带 kit 的 API：`GetProcessVariable(kit,…)`、`SaveProcessVariable(kit,…)`、`GetProcessFile(kit,…)`、`GetProcessInitiator(kit,…)` 等 | — |
| 跨库主数据（用户/组织）且确认不同库 | 一般不碰引擎写锁 |
| 同库另开 `UseRunSQL` / 无 kit Service 读未提交 PI/变量/待办 | **易自锁**；靠 D2 暴露卡点，靠代码评审与 P1 审计收敛 |

Assignee：`AssigneeInvokeRequest.Kit` 与上同为**建议**。本期不设运行时禁连。

### 3.4 D4 ·（已删除）

原「AsyncLocal + Sync 期间禁止 `UseRunSQL`」不做。排障依赖 D2；正确性依赖评审与 kit 重载补齐。

### 3.5 D5 · 异常策略

| 层级 | 要求 |
|------|------|
| 调度 `RunSyncHooks` | 钩子异常**不上吞**；包装为 **`FlowSyncHookException(hookName, eventType, inner)`**（与超时异常并列，便于 API 映射错误码）；与 D2 的 FAIL 日志一致 |
| 宿主 Sync 钩子 | 禁止空 `catch`；「不阻断」须打 Warn，并评估是否应改 AsyncOutbox |
| 与 D1 | 超时与业务异常均 FailFast 回滚（保持教程 FailFast 语义） |

### 3.6 D6 · 慢钩子

- `FlowCapabilityOptions.SyncHookWarnMs`（默认 500，或 `min(500, 有效TimeoutMs/2)`）。
- `ElapsedMs > WarnMs` 且未达该钩子硬超时 → D2 的 **SLOW**（Warning）+（可选）metrics。
- 级别配置在 `LogOptions`；Warn 阈值在 `CapabilityOptions`（已定）。

### 3.7 D7 · 模式选型清单（宿主自检）

| 能力示例 | 模式 |
|----------|------|
| 打戳 DueAt / ActiveAt、同事务写变量、创建前改 Title | **Sync + 建议用 kit** |
| 待办推送、HTTP 回调、业务库镜像、Debug 控制台 | **AsyncOutbox** |
| 文件事件日志 | BestEffort / 旁路，勿 Sync |

**已踩坑对照**：`sail.process.extra.started` 写流程变量 → 应 Sync 且用 kit（已修）；无 kit 变量 API 曾导致自锁，靠进度日志本可直接看到 BEGIN 无 END。

### 3.8 D8 · 按钩子超时（基类默认 30s）

新增抽象基类（示意）：

```csharp
public abstract class FlowHookBase : IFlowHook
{
    public abstract string Name { get; }

    /// <summary>
    /// Sync 软超时（毫秒）。默认 30000；子类可 override 或在构造里赋值。
    /// ≤0 表示不限制（仍输出 BEGIN/END；超时必抛逻辑跳过）。
    /// </summary>
    public virtual int TimeoutMs { get; set; } = 30_000;

    public abstract void Handle(FlowHookContext ctx);
}
```

**调度解析顺序**（每个 Sync 钩子）：

1. 若 `HookRegistrationOptions.TimeoutMs` 有值 → 用注册覆盖。  
2. 否则若 Handler 为 `FlowHookBase` → 用实例 `TimeoutMs`（默认 30000）。  
3. 否则回退 `CapabilityOptions.SyncHookTimeoutMs`（默认已与基类对齐为 **30000**）。  
4. `≤0` → 不计硬超时，仍打进度日志。

| 场景 | 口径 |
|------|------|
| 常规宿主钩子 | 继承 `FlowHookBase`，默认 **30s**；个别慢钩子子类调大或改 Outbox |
| 确需更长 | 优先拆钩子 / AsyncOutbox；再改该钩子 `TimeoutMs` |
| 宿主全局 20s | P0 落地后**去掉**靠放大 `SyncHookTimeoutMs` 掩盖问题的写法 |

CreateHook / Gate 本期可不强制 TimeoutMs；若需一致，CreateHook 基类可同样默认 30s（P1）。

### 3.9 D10 · 全局运行时日志契约（SailClient 顶级）

#### 3.9.1 与现有能力的关系

| 成员 | 职责 | 典型用途 |
|------|------|----------|
| **`SailClient.Log`（新建）** | **运行时诊断 / 进度**：按级别过滤后写控制台、Host `ILogger`、或自定义 Sink | Sync BEGIN/END、Gate 拒绝说明、Notifier 调度轨迹 |
| **`SailClient.LogSink`（已有 `IEngineLogSink`）** | **结构化引擎日志实体**落库/作业日志（`LogEntity` / `JobLogEntity`） | 异常归档、作业诊断表 |
| **`CapabilityMetrics`** | 计数器 | timeout 次数、enqueue 等 |

**禁止**把钩子进度打成 `LogEntity` 灌表（量大、与排障实时性不符）。默认实现：`ISailLogger` → 可同时转发 Host Logger；需要落库时由宿主另接，不作为默认。

#### 3.9.2 级别（经典四分 + 可选 Trace）

| 级别 | 名称 | 用途 |
|------|------|------|
| `Trace` | 追踪（可选） | 极细粒度；默认关闭 |
| `Debug` | 调试 | 开发细节；生产常关闭 |
| `Message` | **消息** | 正常进度（BEGIN/END、Gate 通过摘要等） |
| `Warning` | **警告** | 可恢复异常、慢钩子 SLOW、降级 |
| `Error` | **错误** | 失败、超时 FAIL、未预期异常 |

过滤规则：仅当 `level >= LogOptions.MinimumLevel` 时输出（数值序 Trace &lt; Debug &lt; Message &lt; Warning &lt; Error）。

#### 3.9.3 配置（全局顶级）

建议新增与 `CapabilityOptions` 平级：

```csharp
// SailClient 顶级
public SailLogOptions LogOptions { get; set; } = new();
public ISailLogger Log { get; /* 默认 ConsoleSailLogger，可读 LogOptions */ }

public sealed class SailLogOptions
{
    /// <summary>最低输出级别；默认 Message（开发用 useLogLevel(Debug) 看 BEGIN/END）。</summary>
    public SailLogLevel MinimumLevel { get; set; } = SailLogLevel.Message;

    /// <summary>是否在每条日志附带 UTC 时间戳（默认 true）。</summary>
    public bool IncludeTimestamp { get; set; } = true;

    /// <summary>category 白名单；空=全部。可用于只开 sync-hook。</summary>
    public string[] CategoryIncludes { get; set; }
}
```

宿主配置亦可映射：`Sail:Log:MinimumLevel`（字符串 `Debug`/`Message`/`Warning`/`Error`）。

**Builder（已定命名，挂在 `SailClientBuilder`）**：

```csharp
/// <summary>设置最低日志级别（写入 Sail.LogOptions.MinimumLevel）。</summary>
public SailClientBuilder useLogLevel(SailLogLevel level);

/// <summary>注册运行时日志实现（替换默认 ConsoleSailLogger）。</summary>
public SailClientBuilder useLogger(ISailLogger logger);
```

**ext/msg 启用控制台实现**（推荐宿主显式挂）：

```csharp
using sailflow.msg.Hosting;

builder
    .UseConsoleSailLog(
        log => log.MinimumLevel = SailLogLevel.Debug,  // 看 sync-hook BEGIN/END
        console => console.UseColors = true)
    // 或构建后：client.useConsoleSailLog(...)
    .Build();
```

#### 3.9.4 契约成员（示意）

```csharp
public enum SailLogLevel
{
    Trace = 0,
    Debug = 1,
    Message = 2,   // 消息（方法名 Message，非 Information）
    Warning = 3,   // 警告
    Error = 4,     // 错误
}

public interface ISailLogger
{
    bool IsEnabled(SailLogLevel level);

    void Trace(string category, string message);
    void Debug(string category, string message);
    void Message(string category, string message);
    void Warning(string category, string message);
    void Error(string category, string message, Exception ex = null);

    void Message(string category, string format, params object[] args);
    // …
}

public sealed class NullSailLogger : ISailLogger { /* no-op */ }
public sealed class ConsoleSailLogger : ISailLogger { /* 读 Sail.LogOptions，同步 WriteLine */ }
```

**默认**：未调用 `useLogger` 时使用 **`ConsoleSailLogger`**（继承 `SailLoggerBase`；开箱可见；测试显式 `useLogger(Null…)`）。  
业务自定义：继承 **`SailLoggerBase`**，实现 `Emit`（可覆盖 `FormatLine`）；ext/msg 的 `ConsoleSailLog` 同系着色实现。Host 适配器内将 `Message` → `LogLevel.Information`。

**category 约定**（调度与能力侧统一前缀，便于过滤）：

| category | 使用方 |
|----------|--------|
| `sync-hook` | `RunSyncHooks` BEGIN/END/SLOW/FAIL |
| `async-hook` | Outbox enqueue / dispatch |
| `gate` | `IFlowGate.Validate` 拒绝/通过摘要 |
| `notifier` | Task/Copyto Notifier 调度 |
| `create-hook` | `IProcessInstanceCreateHook` |
| `assignee` | Assignee 管道 / Filter（可选） |
| `outbox` | Drain/认领；dispatch 硬失败 THROW |
| `transition` / `assignee-action` / `lifecycle` | 动作族结果非 Success / 异常 |
| `guard` | 沟通等待等硬锁中断 |
| `engine` | Manager 业务硬失败（状态不符等） |

#### 3.9.4a 失败路径统一入口（`SailFailLog`）

引擎中断 / 返回失败 / 即将抛错，统一经 `SailFailLog`（写 `Sail.Log`，与 `IEngineLogSink` 落库并行）：

| 方法 | 场景 | 日志前缀 |
|------|------|----------|
| `Interrupt` | 业务校验未过、硬锁拦截、不抛即中止 | `INTERRUPT` |
| `ResultNotSuccess` | 动作 `WfExecutedResult` 非 Success | `RESULT` |
| `Exception` | catch 后转 Failed / Manager `FailThrow` | `EXCEPTION` |
| `Throw` | 记日志后原样上抛（Outbox 等） | `THROW` |

接入面：`TransitionActionBase` / `AssigneeActionBase` / `LifecycleActionBase`、`ConsultPendingGuard`、`ProcessInstanceManager` / `TaskManager` / `ActivityInstanceManager` 等 Manager 硬失败、Outbox dispatch `InvalidOperationException`。Gate REJECT / Sync FAIL 仍走既有专用日志，不重复包一层。

#### 3.9.5 接入面（均须具备输出能力）

| 位置 | 最低要求 |
|------|----------|
| **`FlowCapabilityDispatcher.RunSyncHooks`** | D2 全套经 `Sail.Log` |
| **`RunGates` / Gate 拒绝** | Warning 或 Message：gate 名 + 拒绝码/摘要 |
| **`EnqueueAsyncHooks` / Outbox dispatch** | Message：enqueue；Error：dispatch 失败 |
| **Notifier 分发** | Message/Warning：handler 名 + kind |
| **`IProcessInstanceCreateHook` 调度** | 可选 BEGIN/END（与 Sync 同模式，category=`create-hook`） |
| **动作 / Guard / Manager 失败** | 经 `SailFailLog`（见 §3.9.4a） |
| **宿主钩子实现内部** | 需要排障时用 `sail.Log`（构造注入 `SailClient`）；禁止空吞且无 Error 日志 |

调度层拿 `SailClient` 已有；纯宿主钩子若无 Client 引用，经构造函数注入 `SailClient` 或 `ISailLogger`。

#### 3.9.6 与 D2 级别映射（已定）

| 事件 | 级别 |
|------|------|
| BEGIN / END | **Debug** |
| SLOW | `Warning` |
| FAIL / 超时 | `Error` |
| Gate 业务拒绝 | `Warning`（非系统故障） |
| Gate/调度未预期异常 | `Error` |

## 5. 验收标准

1. `useLogLevel` / `useLogger` 生效；`MinimumLevel=Message` 时 BEGIN（Debug）不出现，SLOW/FAIL 仍出现。  
2. 继承 `FlowHookBase` 的钩子默认 30s；子类改小后睡眠超时必抛，异常含钩子名；有 kit 同样生效。  
3. 人为构造钩子内长时间阻塞：日志停在该钩子 **BEGIN**，无 **END**，即可归因（需 `useLogLevel(Debug)`）。  
4. Gate 拒绝或 Sync 失败至少各有一条经 `Log` 的 Warning/Error。  
5. 正常发起路径无回归；**不要求** `UseRunSQL` 被运行时拒绝。  
6. 教程与本专题对「钩子级 TimeoutMs + 有 kit 也计时 + Log 契约」口径一致。
