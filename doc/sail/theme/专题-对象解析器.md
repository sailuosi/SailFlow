## 0. 结论先行

| 项 | 口径 |
|----|------|
| **一句话** | 对象解析器：入语境 → 出 `PerformerList`；内含 **Mode × Scope**；拿到项集后由 Lane/Mediator 继续 |
| **Mode** | 闭集三态：`Fixed` \| `Pick` \| `Preselect`；**不**扩展注册表 |
| **配置名** | Mode 在配置中统一写 **`selectModel`**（BPMN 属性 / 动词代表等）；文档口语仍可称 Mode |
| **历史 BPMN** | **不考虑**存量/历史 BPMN 配置兼容；**不做**按旧 Type 推断 Mode；旧图须重配或另做迁移工具（本契约不背） |
| **Pick 语义** | **一律「发送人选」**（审批/发送当次带人）；**不是**发起人选 |
| **原「发起自选」** | **不再**用 Mode=Pick / 旧 StarterPick；改为 **Mode=Preselect** + `allowPreselectFrom` 含 **`Start`**（发起时写入预选仓） |
| **Scope** | Resolve Type 一律视为人员集合；BPMN `type` = Scope 注册键 |
| **BPMN** | `sf:assigneeResolve type="…" selectModel="…"`（**属性旁挂**；**禁止**塞进 Params 冒充） |
| **同形契约** | Fixed 与 Preselect 的 Load **形状相同**；实现交注册解析器；管道不写 Preselect 特判业务 |
| **落库** | Fixed **不存**；Pick **可选存**（引擎不定死）；**默认实现不落库**；Preselect **必存** |
| **预选/自选表** | **分表**：Preselect 仓 ≠ Picked 仓；数据量大，**须考虑分表**（勿混一张宽表） |
| **已拍 API** | Pick 持久化用 **`LoadPicked` / `StorePicked`**（与 Fixed 的 Scope 加载拆名） |
| **Preselect** | 无 Store → **硬失败**；空结果默认 **Reject**；回落入参须显式开关 |
| **预选写入授权** | **目标节点** `allowPreselectFrom`；Store 校验写入方；**空/未配 → 仅 `Start`**；**不**在本 Params 再卡「当前人∈该节点办理人」（§2.4） |
| **可选人数** | **目标节点** `minSelect` / `maxSelect`；Pick/Preselect 写入校验；**缺省 `minSelect=1`**，`maxSelect` 空=不限（§2.4） |
| **Scope 越权** | **引擎/判定层不拦截**；由**选人器**按 Scope 限制可选名单 |
| **新节点缺省** | **`selectModel=Pick` + 任意选人**（Scope 空 / `AnyMan`；对齐 R6 发送人自选） |
| **节点 vs 动词** | **节点 `assigneeResolve` 只管发送/下一跳**；其它动词**只听动词自身**配置；动词未配 → 默认任意自选（Pick+AnyMan）；**退回除外**（§4） |
| **取人形态** | **共享内核** + 薄适配；**不上**完整 `AssigneeLoader<T>` 类树；**发送、退回独有**；转办/加签/改派等常规动词共用内核（§4） |
| **按钮/动词代表** | **扩展** `SailButton*`；XML=`sf:ButtonsSetting` 下 **每按钮一个** `sf:button` 子元素（属性挂 `selectModel`/`scopeType`…）；**勿**平行再造；sort/priority/icon/theme **仅前端**（§5.3；工具栏分层见 [办理工具栏专题](./专题-办理工具栏与按钮呈现.md)） |
| **部门范围** | = **部门所有人**（宿主外置 Scope）；**≠** `deptBoss`（领导）；不升引擎内置一等码（§2.2） |
| **Leave / R10** | **不动**；在项集取出之后 |
| **R5** | 抄送可共用 Scope 展开；**禁止**写入办理 `Performer[]` |

## 1. 一句话与边界

**新增/改造取人能力 ≈ 配 Mode + Scope，经对象解析器拿项集，再交给既有管道后续。**

| 做 | 不做 |
|----|------|
| Mode 外挂（配置名 **`selectModel`**）；Type=Scope | **不**发明 ScopedPick 组合 Type；**不**做历史 BPMN 兼容推断 |
| Fixed/Preselect 同形 Load；注册实现 | **不**在 Mediator 为 Preselect 开第三派发轨 |
| Pick 断言入参必备；可选 StorePicked | **不**让 Fixed 读入参或写办理人持久化 |
| 跨动词调用同一取人内核（先发送，再 Transfer 等） | **不**把 Transfer 业务写进 Scope |
| 扩展 `SailButton*` 挂 selectModel/Scope/UX 元数据 | **不**平行再造第三套动词配置类型 |
| 范围：内置可覆盖 / 外置宿主必注册（R3/R9） | **不**把宿主 HR schema 塞进 pure |
| Scope 展开供**选人器**圈定候选 | **不**在管道/判定层做「所选 ⊆ Scope」拦截 |
| 抄送：共用圈人 API | **不**把抄送人塞进待办 SignIds（R5） |
| | **不**用对象解析器替代 Leave / EmptyAction / Filter |

与 [流转动作骨架](./专题-流转动作骨架.md) **正交**：骨架管 Gate→Core→Hook；本专题管 Core 内或建待办前的**取人**。

## 2. Mode × Scope

### 2.1 Mode（闭集）

| Mode | 口语 | 传参 | 入参 | 存储 |
|------|------|------|------|------|
| **Fixed** | 固定 | 不传、**不看入参** | 忽略 | **不存**；Load = Scope.Resolve |
| **Pick** | **发送人自选** | **必备** | 发送/审批当次 `NextActivityPerformers` | **可选**；不存→入参；存→`LoadPicked` |
| **Preselect** | 超前选 / 预选 | 通常不传 | 仅显式回落时可读 | **必存**；Load/Store 走 pre |

**Pick 不含「发起人选」。** 产品上若要「发起时先定好后续办理人」：

```text
目标节点 selectModel=Preselect
  + allowPreselectFrom 含 "Start"
  + 发起面板/API 在 Start 成功后 Store
≡ 产品「发起自选」的写法（配置面用 selectModel，不用历史 StarterPick Type）
```

禁止再引入 `pickWhen=Start|Approve`；禁止用旧 Type 名冒充 Mode。

### 2.2 Scope

| 种类 | 典型 | 规则 |
|------|------|------|
| **内置** | ProcessRelative、Expression、FixedUsers…；**`AnyMan`（空约束/任意人，供 Pick 缺省）** | pure 骨架；可同码覆盖（R9） |
| **外置** | RoleGroup Lookup、UnitMap、JobRelative、**部门全员**、deptBoss… | **宿主注册**；引擎不塞 HR 表 |

`AnyMan`：不展开固定名单；配合 Mode=`Pick` 时选人器**不限范围**。实现上可为「空 type」的同义码，设计器显示「任意选人」。

**部门相关（已定语义，宿主实现）：**

| 码/说法 | 含义 | 说明 |
|---------|------|------|
| **部门范围**（产品口语） | **该部门的所有人** | 宿主外置 Scope 码 **`DeptMembers`**（已注册）；**不是**部门领导 |
| **`deptBoss`** | 部门领导 / 领导链 | **另一 Scope**；不得拿来顶替「部门范围」 |
| 引擎内置「部门」一等码 | **不做** | 守 R3；部门全员/领导均由宿主注册 |

Scope / 模式码对照（**概念对照，非运行时自动迁移**；历史 BPMN **不**兼容推断）：

| 概念/旧说法 | 新配置 |
|-------------|--------|
| RoleGroup / FixedUsers / UnitMap / JobRelative / ProcessRelative / Expression / Business* / deptBoss | `type`=该 Scope；另配 **`selectModel`** |
| 发送人自选（旧 ApproverPick） | `selectModel=Pick` + Scope（常 AnyMan/空） |
| 发起自选（旧 StarterPick） | `selectModel=Preselect` + `allowPreselectFrom` 含 `"Start"` |
| 超前选（旧 Preselect Type） | `selectModel=Preselect`（Store 保留，不占 type 槽） |

### 2.3 BPMN

配置属性名：**`selectModel`**（对应概念 Mode）。**不考虑**历史 BPMN 兼容：缺属性 / 旧 Type 混模式码 → **发布校验失败或显式要求重配**，引擎**不**做存量推断。

```xml
<!-- 出厂/新建 UserTask 缺省：发送人任意选 -->
<sf:assigneeResolve type="" selectModel="Pick" params="" />
<!-- 或显式任意人 Scope 码（若注册 AnyMan 空展开） -->
<sf:assigneeResolve type="AnyMan" selectModel="Pick" params="" />

<!-- Preselect 示例 -->
<sf:assigneeResolve type="RoleGroup" selectModel="Preselect"
  params='{"roleIds":["R_MGR"],"allowPreselectFrom":["Start","Activity_Apply"],"minSelect":1,"maxSelect":3}' />
```

- Convertor / `Activity` 增读 **`selectModel`** → 实体 `AssigneeResolveMode`（或等价）  
- **新建缺省**：`selectModel=Pick`，Scope **空或 `AnyMan`** = 选人器任意人（不预绑角色）  
- `allowPreselectFrom` / `minSelect` / `maxSelect` 落在 **Params**（或日后升独立属性；首版 Params 即可）  
- **禁止** `params.selectModel` / `params.mode` 冒充正式契约  
- **不做**「缺 selectModel 时按旧 ApproverPick/StarterPick/… Type 推断」

### 2.4 预选写入授权 · 可选人数

> 配置挂在**被预选/被选人的目标节点**上（Mode=`Preselect` 或 Mode=`Pick` 且需要人数约束时），不挂在「谁去选」的中间节点上。

#### 2.4.1 哪些节点可以预选本节点（`allowPreselectFrom`）

| 项 | 口径 |
|----|------|
| **含义** | 允许对**本节点**执行预选 **Store** 的来源活动定义 Id 列表 |
| **典型值** | `"Start"`（流程发起，特殊码）· 某 UserTask 的 `activityId`（如申请岗、部门审核岗） |
| **校验时机** | **Store 写入**（预选面板 Persist / API Replace）；Load 建待办时**不**再验写入方 |
| **缺省（已定）** | 未配或空列表 → **仅允许 `Start`**（覆盖旧「发起自选」）；显式列出才开放中间节点改预选；**不是**「空=拒绝一切写入」 |
| **多来源** | 列表内任一来源可写；后写覆盖策略仍由 Store 实现（整节点 Replace 等） |
| **与 Scope** | 正交：来源节点决定**哪个活动有权写**；Scope 决定**能圈哪些人** |
| **与办理人身份**（已定） | **不**在本 Params 要求「当前登录人 ∈ 该来源节点办理人」；任务办理权限 / 角色等**另走**，勿塞进 `allowPreselectFrom` |

```text
预选面板 / WfPreselect API
  → 当前办理（或发起）活动 Id = writerActivityId
  → 读目标节点 allowPreselectFrom
  → writer ∉ 列表 → 拒绝写入（ReasonCode 可识别，如 PreselectWriterNotAllowed）
  → writer ∈ 列表 → pre.Store / Replace
```

设计器：目标节点 Mode=`Preselect` 时展示「允许预选来源」多选（开始事件 + 流程内 UserTask）。

#### 2.4.2 可以选多少人（`minSelect` / `maxSelect`）

| 项 | 口径 |
|----|------|
| **含义** | 本节点办理对象项集人数下/上限 |
| **适用** | **Pick**（当次入参）· **Preselect**（Store 写入与 Load 前校验）· 可选用于 persist 的 Picked |
| **与 Leave** | **正交**：人数约束是「派谁」；Leave 是「几人办完能走」。会签三人派发 ≠ 三人全过 |
| **与旧 Params** | 可替代/细化既有 `required` / `allowMulti`：`required≈minSelect≥1`；`allowMulti≈maxSelect>1` |
| **缺省（已定）** | Pick/Preselect：`minSelect=1`；`maxSelect` 未配或 `null` = **不限制上限**（单人场景配 `maxSelect=1`）；Fixed **不适用**人数上下限 |
| **校验时机** | Pick：断言入参人数；Preselect/Picked：**Store 时**强制；Load 时空集仍走 EmptyAction/R4，人数越界应在写入期拦掉 |

```text
校验（示意）
  count = PerformerList.Count
  if count < minSelect → 拒绝（SelectCountBelowMin）
  if maxSelect != null && count > maxSelect → 拒绝（SelectCountAboveMax）
```

#### 2.4.3 Params 键名（首版建议）

| 键 | 类型 | 说明 |
|----|------|------|
| `allowPreselectFrom` | `string[]` | 可含 `"Start"` 与 activityId |
| `minSelect` | `int` | ≥0；默认 1 |
| `maxSelect` | `int?` | 空=不限；须 ≥ minSelect |

亦可后续升 BPMN 属性；首版进 `params` JSON，与 Scope 参数并列，Mode 处理器读取。

## 3. 运行时形状

```text
对象解析器.Load(ctx)
  Mode=Fixed     → Scope.Resolve(type, params)     → 项集（无视入参）
  Mode=Preselect → pre.Load；空则按开关 Reject 或读入参
  Mode=Pick      → 入参必备；persist 开则 LoadPicked（与入参优先级由实现定，须文档化）
  → PerformerList
  → EmptyAction / Filter（R10）→ 建待办 / 动词继续

Store（仅写入路径）
  Preselect → 校验 allowPreselectFrom + min/maxSelect → pre.Store
  Pick+persist → 校验 min/maxSelect → StorePicked
  Fixed → 禁止
```

Pick Load / Preselect Load 前：可再验 `minSelect`/`maxSelect`（写入已拦则 Load 多为通过；防旁路写库）。

```text
契约形状（Fixed / Preselect Load 同构）
  入：ActivityId / 实例语境 / Scope ConfigPair / Runner / Kit…
  出：PerformerList | 空
```

**已拍（讨论稿 §8）：**

| # | 决议 |
|---|------|
| Preselect 无 Store | **硬失败** |
| 预选空→入参 | **允许，默认关（Reject）**；显式 `preselectFallback=Input`；空且未回落 → ReasonCode=`PreselectEmpty` |
| Pick 持久化 API | **`LoadPicked` / `StorePicked`**（`IPickedAssigneeStore`）；引擎默认 `Noop`；宿主已挂 `sf_picked_assignee`；须 Params `persistPick=true` |
| Pick 优先级 | **入参非空优先**；入参空且 persist → `LoadPicked` |

分层：

| 层 | 放什么 |
|----|--------|
| pure | Mode 常量；分派；Load/Store **契约**；Fixed 禁 Store |
| ext | 默认 pre 实现、可选 Picked 表/实现；可继承 |
| 宿主 | 覆盖实现；外置 Scope；预选表（宜演进 `IPreselectAssigneeStore`） |

Picked/Preselect 表访问最终应走 [专题-IStorage.md](./专题-IStorage.md)，避免第二套 SQL 风格。

**表策略（已定）：**

| 仓 | 用途 | 说明 |
|----|------|------|
| **Preselect 表** | Mode=`Preselect` 必存 | 宜演进现有 `sf_preselect_assignee`；与 Picked **分表** |
| **Picked 表** | Mode=`Pick` 且显式开 persist 时 | 默认实现不写；与 Preselect **分表**；可后置建表 |

数据量大 → 两仓均须在 IStorage/表设计阶段考虑**分表**（常见键：`ProcessInstanceId` 哈希/取模、或按创建时间月表；具体策略实施时定，禁止与业务宽表混存）。

## 4. 跨动词

| 动词 | 适用 |
|------|------|
| 发送 / 下一跳 | ✅ 主场（P0） |
| 转办 / 加签 / 减签 / 改派 / 委托 / 沟通 | ✅ 多为 Pick（P1） |
| 退回 | ✅ **独有**路径（历史/退回规则；不套「未配→任意自选」） |
| 抄送 | ⚠️ 可调共享圈人 API；**分流出口**（R5） |
| 通知 | ❌ Notifier |

**取人形态（已定）：**

| 分层 | 口径 |
|------|------|
| **共享内核** | Mode × Scope 算人一套；**不上**完整 `AssigneeLoader<T>` 类树 |
| **发送 / 下一跳** | **独有**：读节点 `assigneeResolve`，主场管道 |
| **退回** | **独有**：历史办理人 / 退回规则（另见退回专题），不默认任意人 |
| **常规动词**（转办 / 加签 / 减签 / 改派 / 委托 / 沟通…） | **共用**内核 + 薄适配（要不要人、默认 Pick 等）；不各自复制算人逻辑 |
| 若局部仍要 Loader 壳 | 参数体四类：流程配置 · 流程实例 · 业务标识 · Kit；仅薄包，勿再长类树 |

**节点 vs 动词取人配置（已定）：**

| 场景 | 听谁的 |
|------|--------|
| **发送 / 下一跳**（通过后定下一办理人） | **仅**目标节点 `sf:assigneeResolve` |
| **转办 / 加签 / 减签 / 改派 / 委托 / 沟通…** | **仅**该**动词代表**上的 Mode/Scope；**不读**节点 `assigneeResolve` |
| 动词代表**未配置**取人 | 默认 **`selectModel=Pick` + 任意选人（AnyMan）** |
| **退回** | **除外**：不走「未配→任意自选」；目标按退回规则/历史办理人等（另见退回专题），勿默认任意人 |

「通过」按钮本身一般 `needsAssignee=false`（选的是下一节点的人，不是给「通过」动词再配一套）。

| **Mode 字段名** | 配置键 **`selectModel`**（闭集 string：`Fixed`\|`Pick`\|`Preselect`）；**不用** int 魔法数 |
| **节点覆盖** | 全局码表 + 节点 `sf:ButtonsSetting` / `sf:button` 子元素覆盖（见 §5.3） |
| **引擎侧** | 最多只读描述契约；执行仍走 Lane / `FlowOperation` |
| **Approve / 通过** | `needsAssignee=false`；下一跳人只看**目标节点** `assigneeResolve` |
| **图标/主题** | 宿主 UX；可先只进 FE；pure 不依赖图标资源 |
| **办理条** | 字段落地后让 `SailOperationBar` **读配置渲染**，替换硬编码 |
| **sort / priority** | 排序号=**同 priority 内**顺序，优先级=前端分组（`1` 外露实心 / `2` 外露浅底 / `3` 外露文字弱化 / `11` 更多）；**仅前端**，引擎不解释；呈现细则见 [专题-办理工具栏与按钮呈现.md](./专题-办理工具栏与按钮呈现.md) |

### 5.3 XML 形态（已定：每按钮一子元素）

挂在 UserTask（等）的 `bpmn:extensionElements` 下：外层 **`sf:ButtonsSetting`** 作容器，**每个按钮一个 `sf:button` 子元素**，字段一律**属性旁挂**（与 `sf:assigneeResolve` 同风格）。**不**再使用整段 `json="[…]"` 属性；**不**把按钮取人写进 `assigneeResolve`。旧图 `ButtonsSetting@json`：**不做兼容**（本专题无历史 BPMN 兼容；须重存或另做迁移工具）。

```xml
<bpmn:userTask id="Activity_Dept" name="部门审核">
  <bpmn:extensionElements>
    <!-- 发送/下一跳：节点级取人（§2.3） -->
    <sf:assigneeResolve type="AnyMan" selectModel="Pick" params="" />

    <!-- 本节点办理条按钮：一按钮一子元素 -->
    <sf:ButtonsSetting>
      <sf:button id="Approve" enable="true" displayName="通过" />
      <sf:button id="Transfer" enable="true" displayName="转办"
        selectModel="Pick" scopeType="AnyMan"
        minSelect="1" maxSelect="1"
        sort="20" priority="1" icon="transfer" theme="default"
        params="" />
      <sf:button id="SignForward" enable="true" displayName="加签"
        selectModel="Pick" scopeType=""
        sort="30" priority="1"
        params="{}" />
      <sf:button id="SendBack" enable="true" displayName="退回" />
    </sf:ButtonsSetting>
  </bpmn:extensionElements>
</bpmn:userTask>
```

| XML 约定 | 口径 |
|----------|------|
| **容器** | `sf:ButtonsSetting`（无业务属性；可空 = 全用码表默认） |
| **子元素** | **`sf:button`**，一 Id 一条；顺序可作设计器默认顺序，正式排序仍看 `sort` |
| **字段形态** | **属性**（`id` / `enable` / `displayName` / `selectModel` / `scopeType` / …） |
| **Scope 参数** | 属性 **`params`**（JSON 字符串，对齐 `assigneeResolve@params`）；**不用**嵌套子树 |
| **缺省** | 无 `ButtonsSetting` 或无子元素 → Catalog `Merge(null)` |
| **Merge** | 以 `id` 为键；节点上出现的 `sf:button` **覆盖**码表同 Id；未写出的按钮回落码表默认 |
| **Approve** | 通常**不写** `selectModel`/`scopeType`（下一跳看 `assigneeResolve`） |
| **Transfer 等** | 需要选人时写 `selectModel` + `scopeType`（及可选 `params` / min·maxSelect） |
| **SendBack** | 退回独有；可不写取人属性 |
| **与 assigneeResolve** | **并列**扩展，职责不混 |

**`sf:button` 属性（节点可持久化）：**

| 属性 | 必填 | 含义 |
|------|------|------|
| `id` | ✅ | 稳定键（Approve/Transfer/…） |
| `enable` | ✅ | 本节点是否启用（`true`/`false`） |
| `displayName` | ✅ | 展示名 |
| **`selectModel`** | 选人动词建议写 | `Fixed`\|`Pick`\|`Preselect`；未配→§4 默认 Pick+AnyMan（退回除外） |
| `scopeType` | 随 selectModel | Scope 注册键；空/`AnyMan`=任意选人 |
| `params` | 可选 | Scope 参数 JSON 字符串（角色 Id 等） |
| `minSelect` / `maxSelect` | 可选 | 本动词选人数；缺省同 §2.4.2 |
| `type` | 可选 | 空=流程按钮；**`Custom`**=非流程（保存/打印等），见 [办理工具栏专题](./专题-办理工具栏与按钮呈现.md) §2.8 |
| `sort` / `priority` | 可选 | 仅前端；档位与工具栏分层见 [办理工具栏专题](./专题-办理工具栏与按钮呈现.md) §2 |
| `icon` / `theme` | 可选 | 仅前端 UX；空 icon=无图标；theme→宿主按钮色（≠ `type`） |

**不进节点 XML（仍在全局码表）：** `engine`、`contexts`、`defaultEnable`、`note`——Merge 时 Engine 等以 Defaults 为准。

可选预留属性：`needsAssignee`、`persistPick`、`usage`（Assignee\|Copyto，守 R5）；宿主私有可用 `ext`（JSON 字符串）或忽略。

```text
读路径
  解析 ButtonsSetting/button@* → Merge(Catalog)
  → 办理条：enable/displayName/sort/icon…
  → 转办等取人：该 button 的 selectModel × scopeType（不读本节点 assigneeResolve）
  → 通过后下一跳：只读目标节点 sf:assigneeResolve
```

### 5.4 与 §4 衔接

见 §4「节点 vs 动词」表；本节省的是**配置载体与 XML 形态**，§4 定的是**听谁的配置**。

## 9. 易混（实施时对照）

| 勿混 | 说明 |
|------|------|
| Mode ≠ Leave | 定人 vs 办完能否走 |
| **Mode ≠ 配置键名** | 概念叫 Mode；配置写 **`selectModel`** |
| **部门范围 ≠ deptBoss** | 部门范围=**部门所有人**；`deptBoss`=领导；勿混用 |
| Mode ≠ NodePolicy 空人/同人 | R10 后置 |
| **Pick ≠ 发起自选** | Pick=**发送人**选；发起选人用 **Preselect+Start** |
| 旧 Type 模式码 ≠ 自动迁移 | **不做**历史 BPMN 兼容；须显式配 `selectModel` |
| Scope 约束 ≠ 引擎拦截 | Scope 喂给**选人器**；引擎不验 ⊆ |
| `minSelect`/`maxSelect` ≠ Leave 完成人数 | 派几人 vs 几人办完能走 |
| `allowPreselectFrom` ≠ Scope | 谁有权**写**预选 vs 能圈哪些人 |
| **按钮代表 ≠ 节点 assigneeResolve** | 转办等听按钮；发送下一跳听节点 |
| **contexts ≠ Scope** | 办理台语境 ≠ 人员范围 |
| LoadPicked ≠ Fixed Scope.Resolve | 已拆名 |
| Scope ≠ contexts / GroupId | 人员集合 ≠ 办理台语境 ≠ 会签组 |
| 本专题 Store ≠ IStorage 全套表 | 办理人项集 vs 流程套表；后者见 [专题-IStorage.md](./专题-IStorage.md) |
