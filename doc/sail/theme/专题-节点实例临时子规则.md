## 0. 结论先行

| 项 | 口径 |
|----|------|
| **AI Leave 快照** | `ai_leave_type` / `ai_leave_params`；建实例时从设计 `sf:leaveJudge` 拷贝 |
| **读取优先级** | **AI 非空 > BPMN 设计 > Legacy 推断**（`BpmnAssigneeConfigReader.ReadLeave`） |
| **外层（设计）** | BPMN `sf:leaveJudge`（Race / Collaborate …）；写入新 AI 快照，**不因加签改 BPMN** |
| **内层（临时子堆栈）** | `SignForward` 升级主 AI：`ComplexType=SignForward` + **改写**主 AI Leave 为子规则 |
| **子规则落库** | 前/后：`LeaveJudgeType=Collaborate` + `MergeType=Sequence` + `CompleteOrder=席位数`；并：`Collaborate` + `Parallel` + Percentage 全员 |
| **子规则 Passed** | 塌缩主容器（完结主 AI、取消未完成子）并 **ContinueForward**（存续期内不再二次问设计 Leave） |
| **「剩 1 人」≠ 塌缩** | 后加签本人办完只剩加签人时 Waiting，须唤醒加签人；达阈才 Passed |
| **抢办 + 后加签** | 加签后主 AI Leave 改为 Collaborate/Sequence，挡住中途 Race；全员过完才出节点 |
| **抢办 + 并加签** | 主 AI Leave 改为 Collaborate/Parallel 全员；勿用 count=1 |

```text
建 AI：设计 Leave → ai_leave_type（快照）
SignForward：改写主 AI Leave = Collaborate + Merge（子堆栈）
办结子席 → TryCanLeave（优先读 AI）
  Waiting + Sequence → 唤醒下一挂起子
  Passed             → 塌缩主 AI → ContinueForward
```

## 1. 两层帧模型

### 1.1 含义

把一次用户任务上的审批看成**帧栈**：

| 帧 | 何时存在 | 规则 | 规则成功的结果 |
|----|----------|------|----------------|
| **外层（节点帧）** | 令牌落在该活动 | 设计期 Leave | 离开节点 / 旁关 / Waiting |
| **内层（加签子堆栈）** | 办理人执行 `SignForward` 之后、塌缩之前 | 临时子规则（由加签子型决定） | **仅塌缩**内层 |

- **Leave** 仍只回答「多人时怎样才算出**节点**」——不负责建图。  
- **SignForward** 负责建临时图（主+子 AI），并隐含一套**子出栈规则**。  
- 口语「正交」= 外层 Leave 配置不变；内层是额外帧，不是改写 Leave Type。

### 1.2 与结构 B 的关系

落库仍是 [专题-节点实例与任务.md](./专题-节点实例与任务.md) 的结构 B：

```text
原当前 AI ──升级──► 主 AI（Suspended, ComplexType=SignForward）  ← 子堆栈容器
                      ├─ 子 AI（本人）→ Task
                      └─ 子 AI（加签人…）→ Task
```

| 子型 | 入栈节奏 | 主 AI 子 Leave |
|------|----------|----------------|
| **前加签** Before | 加签人先 Ready；本人子常先 Suspended | `Collaborate` + Sequence + Count=席位数 |
| **后加签** Behind | 本人先；加签人子先 Suspended | 同上 |
| **并加签** Parallel | 本人与加签人并行（子 `CompleteOrder` 常 -1） | `Collaborate` + Parallel + Percentage=1（全员） |

前/后差别是**建栈顺序与谁先 Ready**；出栈都走同一 `Collaborate` LeaveJudge，靠 `MergeType` 区分串/并。**不**新增独立 `Sequence` Leave 码。

### 1.3 办结路径（语义）

```text
办结当前子 AI / Task
  → TryCanLeave（主 AI.LeaveJudgeType 优先）
      Waiting + Sequence → Ready 下一挂起子；不出节点
      Waiting + Parallel → 继续等；不出节点
      Passed / NotPassed → 塌缩主 AI → ContinueForward
```

无加签时：AI 快照即设计 Leave，普通 / 会签路径同样走管道。

## 2. 子规则口径

### 2.1 什么算子规则 Passed

| 子型 | Passed 条件（语义） | 非 Passed 时 |
|------|---------------------|--------------|
| 前 / 后（Sequence） | 当前子为串行**末席**且本席办结（同意路径达阈） | `CompleteOrder < maxOrder` → Ready 下一挂起子；**不出节点** |
| 并（Collaborate-like） | 子席完成度达到并签阈值（人数或比例） | WaitingForCompletedMore；**不出节点** |

### 2.2 禁止的误判

| 误判 | 为何错 |
|------|--------|
| 「打开/挂起席位只剩 1 人」→ 塌缩 | 后加签本人办完后常剩加签人 1 席，此时应**继续子帧**，不是塌缩 |
| 把主 AI 上并行通过率 `Count + CompleteOrder=1` 当成串行末席封顶 | 本人 `CompleteOrder=1` 被当成末人 → 取消加签人并出节点（SF2 失败） |
| 子规则 Passed ≡ 外层 Leave Passed | 塌缩 ≠ 出节点；外层可能仍 Waiting（少见）或需再投影席位 |

### 2.3 现行实现对照（已落地）

子规则 = 主 AI 上的 Leave 快照 + `MergeType` / `CompareType` / `CompleteOrder`；判定复用内置 `CollaborateLeaveJudge`：

| 语义 | 锚点 |
|------|------|
| 建 AI 写入设计 Leave | `ActivityInstanceManager.ApplyLeaveSnapshotFromActivity` → `ai_leave_type` / `ai_leave_params` |
| Leave 读取优先级 | `BpmnAssigneeConfigReader.ReadLeave`：AI > BPMN > Legacy |
| 压栈 / 改写子 Leave | `NodeMediatorSignForward.ApplyStackLeaveOnMain` |
| 办结判定 | `NodeMediatorMultiSignForward` → `CheckMIPassRateInfo` / `TryCanLeave` |
| Sequence Waiting | 同 Mediator：Ready 下一挂起子 + `FireActivityReady` |
| 工作台末席 | `IsLastTask`：串行 `CompleteOrder == max(子序)`；中间席不选下一节点 |

## 3. 塌缩与外层席位折叠

### 3.1 塌缩做什么

子规则 Passed 时：

1. 完结加签**主容器**（或等价地结束 SignForward 拓扑）。
2. 取消仍打开的未完成加签子实例/待办（与现行 `CancelUnCompletedMultipleInstance` 同类，仅在**合法末席**触发）。
3. **将子帧审批结果折叠回外层**，再问外层 Leave。
4. 仅当外层 Leave Passed（或 NotPassed 走拒绝路径）时，才 `ContinueForward`。

### 3.2 折叠策略（产品默认）

加签人同意服务的是**子帧**；塌缩后对外层的默认口径：

| 策略 | 说明 | 适用 |
|------|------|------|
| **发起人一票（默认）** | 子帧整体成功 → 外层记**加签发起人席**已同意（加签人不单独膨胀 Collaborate 分母） | 单人节点上前/后/并加签 |
| **多票投影（慎用）** | 子帧每人直接进入外层 Seats | 易与外层 Collaborate 分母冲突；须产品显式选用 |

外层为 **Race** 时：塌缩后若发起人席已同意，Race 通常立刻 Passed（符合「抢办节点上插人把关，把关完再抢出节点」——实际上把关已在子帧做完）。

外层为 **Collaborate** 时：须避免「并加签两人 + 原会签第三人」被算成三票分母，除非产品明确要多票投影。

## 4. 与节点 Leave 的叠用

### 4.1 矩阵（产品）

| 外层 Leave        | 后加签（子=Sequence）                  | 前加签（子=Sequence） | 并加签（子=Collaborate-like）          |
| --------------- | -------------------------------- | --------------- | -------------------------------- |
| **Race**        | ✅ 子串行挡住中途出节点；末席后再 Race           | ✅ 同左            | ⚠️ 子规则须凑齐；子若 Race/count=1 则并加签失效 |
| **Collaborate** | ✅ 子帧先走完再计入外层                     | ✅               | ✅ 两层都是「凑齐」语义，注意 §3 折叠勿双计         |
| **Group**       | 同 Race/Collaborate 精神；席位仍带 Group | 同左              | 同左                               |

### 4.2 抢办上后加签（推荐理解）

```text
外层 Race
  └─ 后加签子堆栈（Sequence）
        本人通过 → 非末席 → 唤醒张三（Race 尚未问）
        张三通过 → 子 Passed → 塌缩
              → 外层 Race（发起人路径已同意）→ 出节点
```

验收对齐改签专题 **SF2**：本人办结后出现加签人待办，**非**直接下一节点。

### 4.3 红线（与改签 / 多人办理一致）

1. 加签**不得**默认可绕过外层 Collaborate / Race。
2. 子规则 Passed ≠ 出节点。
3. 并加签默认子规则是「凑齐」，不是抢办。
4. 沟通参与者、抄送**不进**子帧与外层 Leave 分母。
5. 宿主勿对串行前/后加签下发并行通过率 `Count + CompleteOrder=1` 写到主 AI（会把首席误判为末席）。

## 5. 选型心智图

```text
节点上多人怎样才算出节点？     → 外层 Leave（设计期）
办理时临时插人先/后/并审？     → 压 SignForward 子堆栈 + 子规则
子帧怎样才算结束？             → 子规则 Passed → 塌缩（非出节点）
塌缩后能否往下走？             → 再问外层 Leave
抢办上还想「我批完他再把关」？ → 外层 Race + 后加签（子 Sequence）
抢办上还想「两人一起拍板」？   → 并加签且子规则须凑齐；否则别用并加签
```

**勿混：**

| 说法 | 别当成 |
|------|--------|
| 子堆栈塌缩 | 离开 BPMN 下一节点 |
| 后加签剩一人 | 可以出节点 / 塌缩 |
| 并加签 | 设计期会签节点（Leave=Collaborate 扁平或 SignTogether） |
| 外层 Race | 子帧中途也可一人过就走 |
