# 专题 · 节点实例临时子规则

> 状态：**引擎已改**（2026-11-21：席位级加签子堆栈 1A/2A + 同级子元素；废止「改写节点 Leave / 子帧即出节点」）  
> 用途：把 **加签（`SignForward`）** 收成「**席位 AI 即容器**」的临时审批子堆栈：子规则落在**发起人自己的 AI**；外层（节点或上层容器）Leave **不改写**；子帧 Passed → **折合发起人一票上浮**再问外层；Race 旁人可**淹没**未完成子树；支持**递归**嵌套。  
> 范围：运行时语义与落库契约；不含加批拆命令、不含独立 `Sequence` LeaveJudge 码。  
> 宿主：`SailOperationBar` 前/后/并加签；串行不加 count/1。

## 0. 结论先行

| 项 | 口径 |
|----|------|
| **AI Leave 快照** | `ai_leave_type` / `ai_leave_params`；建实例时从设计 `sf:leaveJudge` 拷贝 |
| **读取优先级** | **AI 非空 > BPMN 设计 > Legacy 推断** |
| **外层 Leave** | 节点（或上层容器）快照 = 设计 Leave；**SignForward 永不改写父 `ai_leave_*`** |
| **容器** | **发起人自己的 AI**（`ComplexType=SignForward`）；本人用**直属 Task**，加签人用**子 AI**；**不建**虚拟空壳容器 |
| **同级子元素** | 任意 AI 的 Leave 分母 = **直属 Task ∪ 直属子 AI（折合席）** |
| **子规则落库** | 写在发起人容器：前/后 `Collaborate`+Sequence+Count=席位数；并 `Collaborate`+Parallel+Percentage 全员 |
| **子规则 Passed** | 完结容器 → 取消未完成子树 → **折合发起人一票** → `TryCanLeave(父)`；仅**节点** Passed 才旁关 + `ContinueForward` |
| **Race 旁人** | 外层 Race 仍生效；旁人抢办 Passed → **递归淹没**未完成 SignForward 子树 |
| **递归嵌套** | 谁加签谁的 AI 升级为容器；上层 seats 对该子 AI 仍只计**一席** |
| **适用范围** | 全部 Leave（Race / Collaborate / Group*）：加签只展开发起人席位 |

```text
建 AI：设计 Leave → 节点 ai_leave_*（快照，加签不改）
SignForward：发起人 AI 升级为容器 + 写子规则 Leave；加签人建子 AI
办结：TryCanLeave(容器) → Waiting 唤醒 / Passed 折合一票上浮
外层 Race 旁人过 → 淹没整棵未完成加签子树
```

**废止（旧口径，勿再实现）：**

| 旧述 | 为何废 |
|------|--------|
| 整节点 AI 升级为空壳主 + 本人/加签人均子 AI | 多余虚拟层；与主 AI 一对多 Task 不一致 |
| 加签改写节点 Leave 为 Collaborate | 挡住中途 Race，违反「外层 Leave 不变」 |
| 子帧 Passed → 直接 ContinueForward | 未折合发起人一票、未再问外层 |

## 1. 帧模型与同级子元素

### 1.1 两层（可递归）帧

| 帧 | 何时存在 | 规则落点 | 规则成功的结果 |
|----|----------|----------|----------------|
| **节点帧** | 令牌落在该活动 | 节点 AI 快照 = 设计 Leave（**不因加签改写**） | Passed → 出节点 |
| **席位加签帧** | 某人 `SignForward` 之后、其容器完结前 | **发起人 AI** 上子规则 Leave | Passed → 折合该发起人一票 → 问父帧 Leave |

- **Leave** 只回答「怎样才算离开当前帧」。  
- **SignForward** 建临时图：升级发起人 AI 为容器 + 挂加签人子 AI；**不改**父 Leave。  
- BPMN `sf:leaveJudge` **不改**；实例上仅容器写入子规则快照。

### 1.2 结构：直属 Task 与子 AI 同级

```text
❌ 废弃 · 虚拟空壳
  虚拟容器
    ├─ 子 AI 张三 → Task
    └─ 子 AI 李四 → Task

✅ 契约 · 发起人 AI 即容器
  节点 AI（Leave=Race/Collaborate/… 不变）
    ├─ 直属 Task 张四
    ├─ 直属 Task 张五
    └─ 张三 AI（容器, ComplexType=SignForward, Leave=Collaborate+Merge）
          ├─ 直属 Task 张三          ← 与子 AI 同级
          └─ 子 AI 李四 → Task
```

| 子型 | 入栈节奏 | 容器子 Leave |
|------|----------|----------------|
| **前加签** Before | 加签人子 AI 先 Ready；本人直属 Task/席常后置 | `Collaborate` + Sequence + Count=席位数 |
| **后加签** Behind | 本人直属 Task 先；加签人子 AI 先 Suspended | 同上 |
| **并加签** Parallel | 本人 Task 与加签人子并行（子 `CompleteOrder` 常 -1） | `Collaborate` + Parallel + Percentage=1 |

前/后差别是建栈顺序与谁先 Ready；出栈都走 `Collaborate` LeaveJudge，靠 `MergeType` 区分串/并。

### 1.3 扁平抬席 / 升级 / 嵌套

| 场景 | 落库动作 |
|------|----------|
| **扁平 1AI·N Task 首次加签** | **不**升级节点；迁/建发起人 **AI 容器**挂到节点下（直属 Task + 加签人子 AI）；旁人直属 Task 不动 |
| **已有子 AI（SignTogether / 叶子）再加签** | **升级本 AI** 为容器，保留直属 Task，挂加签人子 AI；父 Leave 不变 |
| **递归** | 李四在自己子 AI 上再加签 → 李四 AI 升级为容器；张三容器 Leave 不变，seats 里李四仍占一席（子 AI 折合） |

```text
李四再加签后：
  张三 AI（容器）
    ├─ 直属 Task 张三
    └─ 李四 AI（嵌套容器, Leave=Collaborate…）
          ├─ 直属 Task 李四
          └─ 子 AI 王五 → Task
```

## 2. 子规则口径

### 2.1 什么算子规则 Passed

| 子型 | Passed 条件 | 非 Passed |
|------|-------------|-----------|
| 前 / 后（Sequence） | 串行末席办结且同意路径达阈 | Waiting → Ready 下一挂起子 AI；**不上浮** |
| 并 | 同级席完成度达并签阈值 | WaitingForCompletedMore；**不上浮** |

席位数分母 = 容器上**直属 Task（发起人）+ 直属加签子 AI**（同级）。

### 2.2 禁止的误判

| 误判 | 为何错 |
|------|--------|
| 「打开席只剩 1」→ 出节点 / 上浮 | 后加签本人办完常剩加签人 1 席，须 Waiting 唤醒 |
| 串行写 `Count + CompleteOrder=1` | 本人被当成末席 → 取消加签人（宿主禁传；引擎禁写） |
| 加签后改写节点 Leave 挡 Race | **已废止**；外层 Race 仍可旁人抢出 |
| 子帧 Passed → 直接 ContinueForward | **已废止**；须折合一票再问外层 |
| 为发起人再建一层子 AI | **已废止**；本人用直属 Task |

## 3. 办结、塌缩与淹没

### 3.1 容器内办结（A）

```text
办结当前 Task
  ├─ 叶子子 AI 上的 Task → Complete 叶子 AI → TryCanLeave(父容器)
  └─ 容器直属 Task（发起人）→ 不 Complete 容器 → TryCanLeave(本容器)
        Waiting + Sequence → Ready 下一挂起子 AI
        Passed / NotPassed → Complete 容器 → 取消未完成子树
                          → 父帧折合发起人一票 → TryCanLeave(父)
                          → 父仍是容器则递归；父是节点且 Passed → 旁关 + ContinueForward
```

### 3.2 外层旁人办结（B）

```text
张五完结直属 Task → TryCanLeave(节点)
  Race Passed → 旁关节点直属 Task + 递归淹没未完成 SignForward 子树（RaceTaken 等）
  Collaborate Passed/Waiting → 只计外层票；不淹张三子树
```

### 3.3 席位投影（C）

对任意「判定主体 AI」统一投影（`LeaveSeatProjector.BuildSeatsForActivity`）：

| 子元素 | 如何计席 |
|--------|----------|
| 直属非参与者 Task | 一席（Agreed / Refused / 打开） |
| 直属子 AI 且为 SignForward 容器（或未完成容器） | **一席**，SignId=该子 `SignIds`（发起人）；Completed+Agreed 才算同意 |
| 直属普通叶子子 AI | 一席（兼容 SignTogether） |
| 孙代 Task / AI | **不**摊进本层分母 |

节点 Leave 与容器 Leave 共用同一投影，仅主体 AI 不同。

### 3.4 折叠策略

| 策略 | 契约 | 说明 |
|------|------|------|
| **发起人一票再问外层** | ✅ | 子帧达阈 → 折合 → `TryCanLeave(父)` |
| 子帧即离开阈（旧） | ❌ 废止 | 不再子帧 Passed 直接出节点 |

## 4. 与节点 Leave 的叠用

### 4.1 矩阵

| 设计 Leave（节点快照，加签不改） | 后/前/并加签 |
|----------------------------------|--------------|
| **Race** | 外层仍 Race；子堆栈未完时旁人可抢办淹没；子堆栈完 → 折合发起人一票 → 常即 Race Passed |
| **Collaborate** | 外层仍凑齐；子帧完只 +1 发起人票，旁人各自办 |
| **Group\*** | 同精神：只展开发起人席位，不改节点 Leave |

### 4.2 抢办 + 后加签（契约路径）

```text
节点 Leave=Race（不变）
  └─ 张三 SignForwardBehind → 张三 AI 容器 Leave=Collaborate+Sequence
        张三直属 Task 通过 → Waiting → 唤醒李四子 AI
        李四通过 → 容器 Passed → 折合张三一票 → TryCanLeave(节点 Race)
                 → Passed → 旁关张四/张五 + ContinueForward
  若中途张五先过 → Race Passed → 淹没张三容器及李四待办
```

### 4.3 红线

1. 加签**不改** BPMN；**不改**节点/父容器 `ai_leave_*`。  
2. 子帧 Passed **必须**折合一票再问外层；勿直接出节点。  
3. 不建虚拟空壳；发起人用直属 Task。  
4. 并加签默认子规则是凑齐（Collaborate），不是抢办。  
5. 沟通参与者、抄送**不进** Leave 分母。  
6. 宿主串行前/后加签**禁止**下发 `Count + CompleteOrder=1`。

## 5. 选型心智图

```text
节点上多人怎样才算出节点？     → 设计 Leave → 节点 AI 快照（加签不改）
办理时临时插人先/后/并审？     → SignForward：发起人 AI 变容器 + 加签人子 AI
子帧怎样才算结束？             → TryCanLeave(容器) Passed → 折合一票上浮
中间席？                       → Waiting；IsLastTask=false
抢办上后加签未完，旁人先过？   → 外层 Race 淹没子树（允许）
李四再加签？                   → 李四 AI 升级为嵌套容器（递归）
```

**勿混：**

| 说法 | 别当成 |
|------|--------|
| 后加签本人刚通过 | 可以出节点 / 选下一节点人 |
| 并加签 | 设计期会签节点 |
| 加签后外层 Race 失效 | 契约上外层 Leave 不变 |
| 虚拟空壳 + 两人子 AI | 现行废止结构 |
