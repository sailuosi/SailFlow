## 0. 一句话与划界

### 0.1 含义

**沟通** = 当前审批人临时拉人**反馈意见**——对方拿的是**参与者待办**（无审批推进权）；你这边在对方未全部阅办（或你收回）前，**推进类按钮硬锁**。

| 口语 | Sail 码 | 本专题？ |
|------|---------|----------|
| 沟通 / 征询 / 意见征集 | **`Consult`** | ✅ 发起 |
| 阅办 / 已阅反馈 | **`Acknowledge`** | ✅ 参与者关闭自己的沟通待办 |
| 收回沟通 | **`RecallConsult`** | ✅ 发起人取消未反馈参与者并解锁 |
| 前加签 | `SignForward` Before | ❌ 对方有完整审批权 |
| 抄送 | `Copyto` | ❌ 不进 `sf_task`、不锁审批 |
| 委派 | `Delegate` | ❌ 对方代批且办完还回 |

```text
需要别人介入？
 ├─ 只要信息，不让他拍板，且要等他回  → 本专题沟通
 ├─ 仅知情，不锁我、不强制回           → 抄送 Copyto
 ├─ 让他先审我再审 / 一起审            → 加签 SignForward
 └─ 交人代办 / 交出去不还回            → Delegate / Transfer
```

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 发起沟通 | **引擎** | Assignee `ConsultAction` → `TaskManager.Consult` | Gate=`Consult`；Hook=**`OnProcessConsulted`**；参与者 Created | 码表默认开；选人弹窗 | **`AddSailOperationHandlers`** |

## 1. 三动词与等待协议

### 1.1 含义

```text
审批人 Consult（选人）
  → 同活动建参与者 Task（role=1，ConsultSrcTaskId=源 Task）
  → 源 Task 进入 ConsultPending（有打开参与者）
  → 推进类动词硬锁；可继续沟通加人 / 收回

参与者 Acknowledge（意见）
  → 自己的参与者 Task Completed
  → 若该源下无打开参与者 → 解锁

发起人 RecallConsult
  → 取消该源下未关闭参与者 → 解锁
```

| 字段 | 列 | 含义 |
|------|-----|------|
| `AssigneeRole` | `tk_assignee_role` | null/0=常规审批人；**1=沟通参与者** |
| `ConsultSrcTaskId` | `tk_consult_src_task_id` | 参与者挂回发起沟通的审批 TaskId |

### 1.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 办理条点沟通 | 宿主 | UX → ButtonsOperation | — | 选人；禁从参与者任务再发起 | 节点启用 Consult |
| Consult 写库 | 引擎 | `TaskManager.Consult` | Created Lifecycle；**不**刷新 SignIds | 同人已有打开参与者则跳过（幂等）；不可沟自己 | A 骨架 |
| 硬锁 | 引擎 | Guard（Action 入口） | `ConsultPending` | Workbench 藏推进钮、露收回 | — |
| Acknowledge | 引擎 | 仅 Participant 可办 | Completed；意见多走 Conditions.comment | 工具栏仅阅办 | — |
| Recall | 引擎 | 取消打开参与者 | Cancelled Lifecycle | — | — |
| 成功横切 | 引擎 | Assignee AfterSuccess | Consulted / Acknowledged / Recalled | 可订 Hook | — |

**不推进节点**：三动词均 Assignee 族，**不经** Runtime 下一跳。

## 2. 硬锁范围与 UX

### 2.1 含义

源审批 Task 下仍有**打开**参与者时，下列操作 **TryAllow=false**（引擎硬锁，不仅前端藏钮）：

`Run` · `Reject` · `SendBack` · `SignForward` · `Transfer` · `Delegate` · `ChangeAssignee` · `RemoveAssignee` · `Revise` · `Resend` · `Jump` · `Close`

**不锁**（可继续）：`Consult`（再加人）、`RecallConsult`、`Acknowledge`（参与者侧）、抄送等非上表动词。

### 2.2 分层说明

| 角色 | 归属 | Workbench / UX | 引擎 |
|------|------|----------------|------|
| 常规办理人 · 无待反馈 | 宿主 | 正常按钮集 | Guard 放行 |
| 常规办理人 · ConsultPending | 宿主 | 藏推进类；保留沟通/收回/抄送 | Guard 拦截推进类 |
| 参与者 | 宿主 | **仅** Acknowledge | Acknowledge 校验 role=1 |

## 3. 与 Leave / Sign / 推送

### 3.1 含义

| 规则 | 说明 |
|------|------|
| SignIds/Names | 刷新时**排除**参与者 |
| Leave 分母 | Seat 投影**排除**参与者 |
| 节点离开 | 未阅参与者 **级联 Cancel** |
| 待办推送 | 参与者新建走 `Created`；通道按 TaskKinds 订阅即可 |

### 3.2 分层说明

| 项 | 归属 | 层 | 说明 |
|----|------|----|------|
| 排除 Sign | 引擎 | `RefreshActivitySignFromOpenTasks` | 会签名额不被沟通人撑大 |
| 排除 Seat | 引擎 | `LeaveSeatProjector` | 不计入 Collaborate/Race |
| 级联取消 | 引擎 | `CancelOpenParticipantsOnActivity` | 同意推进离开节点时收口 |
| 推送 | 引擎+宿主 | FireTaskLifecycle | 见待办推送专题 |

## 4. 与邻域对照

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 沟通 | 前加签 | 参与者无审批权 + 锁发起人；前加签对方可批 |
| 沟通 | 抄送 | 抄送不进 sf_task、不锁；沟通建 Task 且锁 |
| 阅办 | 通过 Approve | 只关参与者待办，不 ContinueForward |
| 收回沟通 | 撤回 Withdraw | 取消未反馈参与者；≠ 收回已办审批 |
| 设计器「参与者」列表 | 本专题沟通人 | 旧 `sf:Performer` 算人挂载 ≠ runtime AssigneeRole=1 |

多轮：全部阅办/收回解锁后，可再 `Consult` 新一轮。

## 6. 选型与验收

| 意图 | 用 |
|------|-----|
| 问项目负责人能不能批假，对方不批假 | **Consult** → 对方 **Acknowledge** |
| 等不及 / 问错人 | **RecallConsult** |
| 让他先审再轮到我 | **SignForward Before** |
| 只让他知道一声 | **Copyto** |

| # | 期望 |
|---|------|
| C1 | 沟通后发起人 Approve → `ConsultPending` 失败 |
| C2 | 参与者工具栏仅阅办；点 Approve 不可用 |
| C3 | 全员 Acknowledge → 发起人解锁可推进 |
| C4 | Recall → 参与者待办取消；发起人解锁 |
| C5 | 参与者不进 SignIds；不影响会签计数 |
| C6 | 同意离开节点 → 未阅参与者级联取消 |
| C7 | 同轮同人重复沟通 → 幂等不建第二打开待办 |
| C8 | 不可从参与者任务再发起 Consult |

## 7. 红线

1. **沟通 ≠ 加签 ≠ 抄送**：产品勿三钮混文案。  
2. **参与者无推进权**；禁止给参与者露 Approve/Reject。  
3. **硬锁以引擎 Guard 为准**，前端藏钮只是体验。  
4. **参与者不进 Leave / SignIds**。  
5. **禁止**参与者嵌套再 Consult。  
6. 意见轨迹现多走 `Conditions.comment`；专用沟通轨迹展示仍薄。  
7. BPMN Collaboration `participant`（泳池）≠ 本专题 runtime 参与者角色。
