## 0. 一句话与划界

### 0.1 含义

**多人办理模式** = 同一用户任务上有多人待办时，**「通过」怎样才算离开本节点**——编码在 **`sf:leaveJudge`（Leave Type）**，**不是**办理条按钮，也**不是**算人 Resolve。

| 口语 | Sail Leave Type | 一句话 |
|------|-----------------|--------|
| 抢办 / 或签办完即走 | **`Race`** | 任一人同意即可离开；他人待办应失效 |
| 会签 / 协办 | **`Collaborate`** | 按人数或比例凑齐才离开（出厂设计默认） |
| 组间抢办 | **`GroupRace`** | 组内抢办 + 组间 And/Or |
| 组间协办 | **`GroupCollaborate`** | 组内人数/比例 + 组间 And/Or |
| 队长关卡 | **`Captain`** | 关卡身份办完才算该组完成（组员可办但不能 alone 过组） |

```text
多人同节点？
 ├─ 先定 Leave（本专题）——谁办完、办多少算过
 ├─ 再定 Resolve ——找谁来办
 └─ 按钮（Approve/减签/转办…）受 Leave 约束，不能绕过
不要当成 Leave：
 ├─ 并加签 / 前加签     → SignForward（改签专题）
 ├─ 减签 / 改派         → 改集合，不改离开规则
 ├─ 转办 / 委派 / 代批  → 交人语义；代批须与 Leave 对齐
 └─ 沟通参与者         → 不进 SignIds、不计入 Leave
```

**两维正交（管道铁律）：** Resolve（定范围）× Leave（办理模式）。认领/承办 `TakeOn` **仅**叠在 `Race`/`GroupRace` 上（旁关他人或同组、不推进）；Collaborate/Captain 永不露出。

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| Leave 配置 | **宿主设计** | BPMN `sf:leaveJudge` ConfigPair | — | 设计器办理模式面板；发布前 Type **不得空**（R6） | 落盘 XML；无专用 Use |
| 内置判定 | **引擎** assignee | 时刻 B `IActivityLeaveJudge` | `CanLeave` → Passed/Waiting/NotPassed | Type=`Race`/`Collaborate`/… | **`UseBizAssignees`** / `UseAssignees` 注册内置 |

## 1. 五类模式（产品选型）

### 1.1 含义

| Type | 适用 | 完成条件 Params（常用） | 他人未办 |
|------|------|-------------------------|----------|
| `Race` | 多人或签、抢办 | （无人数门槛） | 一人同意后旁关（RaceTaken 等） |
| `Collaborate` | 经典会签 | `completeCount` **或** `completeRate`（建议显式；可回落主 AI `CompareType`/`CompleteOrder`） | 未达阈继续等 |
| `GroupRace` | 多组、组内抢 | `groupJoin=And\|Or`（默认 And） | 组内一人过即该组完成 |
| `GroupCollaborate` | 多组会签 | 组内 count/rate + `groupJoin`；组间可 `groupCompleteCount/Rate`（R7） | 按组凑齐再合 |
| `Captain` | 组长关卡 | `gateRoles` 默认 `["Leader"]`；+ `groupJoin` | 组员可办；**关卡同意**才算组完成 |

**串行 vs 并行：** 主活动 `MergeType` Sequence/Parallel 影响 Collaborate 计票节奏（与加签串/并不同概念——加签是 SignForward 拓扑）。

### 1.2 分层说明

| Type | 归属 | 层 | 判定入口 | 宿主配置 | UseXxx |
|------|------|----|----------|----------|--------|
| Race | 引擎 Builtin | `RaceLeaveJudge` | `MiPassRateHelper.EvaluateRace(Seats)` | Leave Type=Race | `UseBizAssignees` |
| Collaborate | 引擎 Builtin | `CollaborateLeaveJudge` | `Evaluate` + completeCount/Rate | Params 或主 AI CompleteOrder | 同上 |
| GroupRace | 引擎 Builtin | `GroupRaceLeaveJudge` | `GroupLeaveHelper` 按 `GroupId` | 算人须填 Group*（R1） | 同上 |
| GroupCollaborate | 引擎 Builtin | `GroupCollaborateLeaveJudge` | 组内 done + 组间 merge | 同上 | 同上 |
| Captain | 引擎 Builtin | `CaptainLeaveJudge` | 关卡角色同意即组完成 | `gateRoles`；组员也有待办（R8） | 同上 |

**Leave 只读 Group\***，禁止用 Unit 冒充分组（R1）。单位展示走 `UnitId` 等，语义重叠时可双写。

### 1.3 设计默认（R6）

| 项 | 出厂建议 |
|----|----------|
| Mode / Scope | `selectModel=Pick` + Scope 空/`AnyMan`（发送人自选） |
| Leave | **`Collaborate`** |
| Params | 显式完成条件（如 `completeRate: 1` 全员） |
| 发布 | `selectModel` + Leave Type **皆合法非空**（Scope 可空） |

要抢办：设计期改 Leave=`Race`，**不要**改引擎分支、不要靠运行时静默推断。

## 2. 时刻 B：流出判定链路

### 2.1 含义

有人点「通过」办结本任务后，引擎问：**当前节点能否离开？**  
答案三态：`Passed`（走下一跳）/ `Waiting`（继续等人）/ `NotPassed`（否决类收口，视路径）。

```text
Approve/Run → Mediator 办结本人 Task/子 AI
  → ActivityInstanceManager 完成检查
  → Pipeline.TryCanLeave(LeaveInvokeRequest)
      → LeaveConfigReader → sf:leaveJudge（或 Legacy 适配）
      → IActivityLeaveJudge.CanLeave
      → 读 Seats（优先）或 ChildActivityInstances
  → Passed → ContinueForward；Waiting → 停本节点
```

### 2.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 办结本人 | 引擎 | Mediator / TaskManager | 可先 `TryCompleteAsDelegationReturn`（委派回转则**不**问离开） | — | — |
| 灌入请求 | 引擎 | LeaveInvokeRequest | 主/子 AI、可选 Seats、Runner | — | — |
| 读配置 | 引擎 assignee | `LeaveConfigReader` / LegacyInfer | — | `sf:leaveJudge`；旧 `MultiSignDetail` 可适配 Collaborate | `UseAssignees` 挂 Reader |
| 判定 | 引擎 Builtin/覆盖 | `CanLeave` | **无 FlowHook**（纯管道） | 租户可同码覆盖 | `useLeaveJudge` |
| 映射 | 引擎 AIM | `NodePassedTypeEnum` | 失败 Reason=`LeaveConfigMissing` / `LeaveTypeUnregistered` | — | — |
| 旁关他人 | 引擎 | Race 等路径 | TaskLifecycle Cancelled；EndType RaceTaken/ProxyTaken… | — | — |

沟通参与者、抄送：**不进** Leave 分母。

## 3. 结构：扁平多 Task vs 会签子 AI

### 3.1 含义

| 结构 | 形态 | Leave 怎么数 |
|------|------|--------------|
| **A 扁平** | 一 AI 下多 Task | Seats 从 Task 投影 |
| **B SignTogether** | 主 AI 容器 + 每人子 AI(+Task) | Seats 优先 Task；兼容子 AI 人头 |

加权会签 / 委托代批：**同根 EffectiveWeight 去重**——代批人挂原人席，避免「两人两票」。详见权重专题。

### 3.2 分层说明

| 项 | 归属 | 层 | 说明 |
|----|------|----|------|
| 建会签子实例 | 引擎 Mediator | `NodeMediatorMultiSignTogether` 等 | 与 Leave Type 配合；Leave 不负责建图 |
| 席位投影 | 引擎 | `LeaveSeatProjector` | 统一给 Judge |
| 计权 | 引擎 | `EffectiveWeightHelper` | Agreed/Refused/分母 |
| 代批并人 | 宿主 Filter + 引擎 | Surrogate | **须**节点 Leave 对齐「任一可办」→ 常用 Race 或同根 Collaborate |

未改 Leave 只加代批人 → 默认 Collaborate 会变成双人会签（委托专题红线）。

## 4. 与邻域对照

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 会签按钮 | 办理条动词 | Leave=`Collaborate`（配置） |
| 或签 / 抢办 | 转办 | Leave=`Race`；转办是交自己的待办 |
| 并加签 | 会签节点 | 办理时 SignForward Parallel vs 设计 Leave |
| 减签 | 改 Leave | 只减未办人；离开规则不变 |
| 认领 / 承办 | 通过 / 越过会签 | `TakeOn` → `TakeOnProcess`；仅 Race/GroupRace；EndType=`TakeOnTaken` |
| 同人跳过 | Leave | R10 Filter/Hook；跳过仍受节点 Leave 约束 |
| 组 | 单位 Unit | Leave 只读 Group* |

## 6. 选型与验收

| 意图 | Leave |
|------|-------|
| 三人任一批即可 | `Race` |
| 三人全同意 / 至少 2 人 / 60% | `Collaborate` + count 或 rate |
| 每部门一人抢办，各部门都要过 | `GroupRace` + `groupJoin=And` |
| 每组内会签，组间或过 | `GroupCollaborate` + `groupJoin=Or` |
| 组长点头组才过，组员可留意见 | `Captain` |
| 代批「任一可办」 | 节点 `Race`，或 Collaborate+同根计权（权重专题） |

| # | 期望 |
|---|------|
| L1 | 发布前 Leave Type 空 → 拒发 |
| L2 | Collaborate 未达阈 → Waiting；达阈 → 下一跳 |
| L3 | Race 一人同意 → Passed；其余打开待办旁关 |
| L4 | Group* 无 GroupId → 行为可诊断（勿静默当扁平） |
| L5 | Captain：仅组员同意 → 组未完成；Leader 同意 → 组完成 |
| L6 | 代批两人同根 Collaborate → 计一席有效权重，非两票 |
| L7 | 沟通参与者不进分母 |
| L8 | 同码覆盖 Collaborate → 日志/诊断可见 Overridden |

## 7. 红线

1. **Leave ≠ 按钮**：禁止把会签/或签做成码表动词代替 Type。  
2. **Resolve × Leave 正交**：加减人、转办、代批**不得**默认可绕过 Collaborate。  
3. **Leave 不读 Unit**；分组只用 Group*（R1）。  
4. **发布前 Type 非空**；运行时 pure **不**补默认 Leave（R6）。  
5. **同码覆盖须可观测**（R9）。  
6. **队长**：关卡必须办；组员 alone 不能过组（R8）。  
7. 沟通/抄送**不计入** Leave；减签禁减至 0。  
8. 未挂管道的旧会签通过率旁路是**债**，勿当新扩展点。
