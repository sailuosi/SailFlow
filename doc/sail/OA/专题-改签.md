## 0. 一句话与划界

### 0.1 含义

**改签** = 流程**停在当前节点**时，临时改「谁来审」——加人、减人、换全集——**不是**退回、不是委派回转、也不是改图上的未来节点预选。

| 口语 | Sail 码 | 族 | 是否本专题主角 |
|------|---------|----|----------------|
| 前加签 / 后加签 / 并加签 | **`SignForward`**（子型 Before/Behind/Parallel） | Transition | ✅ 加签三子型 |
| 减签 | **`RemoveAssignee`** | Assignee | ✅ |
| 改派 / 变更处理人 | **`ChangeAssignee`** | Assignee | ✅ |
| 催办 | `Urge` | Assignee | 对照：只通知、不改人 |
| 转办 | `Transfer` | Assignee | ❌ 对照：交人且不还回（见委托专题） |
| 委派 | `Delegate` | Assignee | ❌ 对照：办完回转 |
| 沟通 | `Consult` | Assignee | ❌ 对照：参与者无审批权且锁源待办 |
| 加批（生新审批段） | 候选 `SignAddNode` | — | ❌ 现揉在 `SignForward`，**未拆** |
| 未来节点加减人 | 候选 `*FutureAssignee` | — | ❌ 无命令；走预选/设计算人 |

```text
要改「当前谁审」？
 ├─ 临时拉人先审 / 后审 / 一起审     → §1 加签 SignForward（三子型）
 ├─ 多人节点拿掉还没办完的人         → §2 减签 RemoveAssignee
 ├─ 管理态把办理人换成这批（差量）   → §3 改派 ChangeAssignee
 └─ 只催一下、状态不动               → §4 催办（对照）
不要当成改签：
 ├─ 交人且不还回 → Transfer · 办完还回 → Delegate · 出差并入 → Surrogate
 └─ 打回改完再来 → SendBack · 知情不审 → Copyto / Consult
```

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |

## 1. 加签（`SignForward`）

### 1.1 含义

办理人在**当前活动**上临时插入审批人。同一命令、三种子型（`ControlParameterSheet.SignForwardType`）：

| 子型 | 码 | 一句话 | 本人 |
|------|-----|--------|------|
| **前加签** | `SignForwardBefore` | 别人先审，再我审 | 主节点挂起；他人串行办完后回到本人 |
| **后加签** | `SignForwardBehind` | 我先批完，再让他补审 | 本人先审；他人串行后续 |
| **并加签** | `SignForwardParallel` | 拉人进来一起审 | 本人与加签人并行；合并规则见 CompareType/CompleteOrder |

**≠ 加批**：AntFlow 式「生新审批节点/段」产品候选 `SignAddNode`，现仍揉在本命令，**勿**对外再造第二按钮名。

**≠ 并加签 vs 会签节点**：并加签是**办理时**临时加人并改当前 AI 为 SignForward 拓扑；会签是节点 Leave=`Collaborate` 的设计配置。

### 1.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 办理条点加签 | 宿主 | UX → `ButtonsOperation` | — | `SailButtonsCatalog.SignForward`；选 Before/Behind/Parallel + 选人（可带 Weight） | 节点 `sf:ButtonsSetting` 启用 |
| Handler | 宿主 | `SignForwardOperationHandler` | — | → `wf.SignForwardProcessAsync`；或 `POST …/SignForwardProcess` | **`AddSailOperationHandlers`** |
| 控制袋 | 宿主→引擎 | Runner `ControlParameterSheet` | — | `SignForwardType`；并签可选 `SignForwardCompareType`（count/percentage）· `SignForwardCompleteOrder` | — |
| 事务+Action | **引擎** | `RunAction` → `SignForwardAction` | Gate=`FlowOperation.SignForward` | — | Transition 骨架内建 |
| 沟通未清 | **引擎** | Guard | `ConsultPendingGuard` 拦截 | 详情 `consultPending` 时办理条隐藏/禁点 | — |
| Runtime | **引擎** | `WfRuntimeManagerSignForward` | — | Factory `CreateRuntimeInstanceSignForward` | — |
| Mediator | **引擎** | `NodeMediatorSignForward` / MultiSignForward | 主 AI→`ComplexType=SignForward`、挂起；子 AI+Task；Merge=Sequence/Parallel | 列 `ai_sign_fwd_type` | — |
| 成功横切 | **引擎** | Transition AfterSuccess | FlowHook **`OnProcessSignForwarded`** | Debug/BizMirror 等可订 | 默认管道 |

### 1.3 引擎行为要点

- 当前活动升级为加签**主节点**并 **Suspended**；按子型生成本人与加签人子实例（`MainActInstanceId` 挂主）。
- 前/后加签：`MergeType=Sequence`，`CompleteOrder` 串行排队。
- 并加签：`MergeType=Parallel`，子 `CompleteOrder=-1`；通过率可走 count/percentage。
- **会改活动拓扑**（ComplexType / 子 AI），与减签/改派「只动 Task 集合」不同——故落在 **Transition 族**，不是 Assignee 族。

### 1.4 约束

| 项 | 说明 |
|----|------|
| 上下文 | 待办 `handle`；沟通未清不可加签 |
| Leave | 并加签后离开条件仍受节点 Leave / 加签合并规则约束；勿指望加签绕过 Collaborate |
| 权重 | 选人可带 `Performer.Weight`（默认 1）；计权见权重专题 |
| 加批未拆 | 产品文案勿另起「加批」按钮直至引擎拆命令 |

## 2. 减签（`RemoveAssignee`）

### 2.1 含义

从**当前多人节点**拿掉**尚未办完**的办理人；**不推进**下一节点；**禁止**减到 0 人。

典型：会签五人，一人可不参与 → 关掉其 Waiting 待办并刷新 SignIds/Names。

### 2.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 候选人列表 | 宿主 | Workbench API | — | `RemovableAssignees`（当前活动打开待办投影） | Wf2Xml 办理台加载 |
| 办理条弹窗 | 宿主 | `SailOperationBar` | — | 多选待减人 → `ButtonsOperation` | 节点启用 `RemoveAssignee` |
| Handler | 宿主 | `RemoveAssigneeOperationHandler` | — | → `RemoveAssigneeProcessAsync` | **`AddSailOperationHandlers`** |
| Action | **引擎** | `RemoveAssigneeAction`（Assignee 族） | Gate=`RemoveAssignee`；Hook=**`OnAssigneeRemoved`** | `TaskId` 定位活动；`NextActivityPerformers`=待移除人 | A4 骨架 |
| 写库 | **引擎** | `TaskManager.RemoveAssignees` | 路径内 Closed + Cancelled / EndType=`Removed`；**不**在 Action 再抄 Lifecycle | 刷新 SignIds/Names；剩余 &lt;1 → 失败 | 引擎内建 |

### 2.3 约束

| 项 | 说明 |
|----|------|
| 至少 1 人 | 禁减最后一名 Waiting/Reading |
| 只减未办 | 已办结 Task 不在候选人 |
| 不推进 | 仍停本节点；Leave 分母随打开待办变化 |
| ≠ 转办 | 减签是去掉席位；转办是原人交新人 |

## 3. 改派（`ChangeAssignee`）

### 3.1 含义

有权人把**当前节点办理人集合**改成**新全集**（差量：多余关、缺少开）；**不推进**。管理纠偏 / 组织调整常用；办理条默认**关**。

### 3.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 预填全集 | 宿主 | Workbench | — | `CurrentAssignees` | 办理台 |
| 办理条 | 宿主 | 弹窗编辑全集 | — | 码表 `ChangeAssignee` **默认关** | 节点显式启用 |
| Handler | 宿主 | `ChangeAssigneeOperationHandler` | — | → `ChangeAssigneeProcessAsync` | **`AddSailOperationHandlers`** |
| Action | **引擎** | `ChangeAssigneeAction` | Gate=`ChangeAssignee`；Hook=**`OnAssigneeChanged`** | `NextActivityPerformers`=**新全集**（非「仅增量」） | A4 |
| 写库 | **引擎** | `TaskManager.ChangeAssignees` | 不在新集合 → Closed+Cancelled/`Removed`；缺 → Insert+Created；刷新 Sign | — | 引擎内建 |

### 3.3 与加减签选型

| 意图 | 用 |
|------|-----|
| 只拿掉若干未办人 | **减签**（列表减法） |
| 临时插入审批拓扑（先/后/并） | **加签** |
| 整表换成另一批人 | **改派**（提交新全集） |
| 我自己不办了交给他 | **转办**（非改派） |

---

## 4. 催办（对照，非改签）

### 4.1 含义

对当前打开待办发 **`Urged`** 提醒；**不改** TaskState、不改人、不推进。≠ 加急优先级字段。

### 4.2 分层说明（摘要）

| 项 | 值 |
|----|-----|
| 命令 | `Urge` → `UrgeProcess` → `UrgeAction` |
| Hook | `OnProcessUrged`；逐条 `OnTaskUrged` |
| Host | 码表默认关；Notifier `TaskKinds` 须含 `Urged` 才有消息 |
| UseXxx | **`AddSailOperationHandlers`** + 通知通道装配 |

## 5. 与邻域划界

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 加签 | 加批生新节点 | 现 `SignForward`；加批待拆 |
| 并加签 | 设计期会签 | Leave=`Collaborate` vs 办理时 Parallel |
| 减签 | 转办 / 驳回 | 只关未办席位；不交人、不落点 |
| 改派 | 转办 | 改派=集合差量；转办=我的待办交一人 |
| 改签 | 退回 / 撤回 | 人不对用改签；单要打回用 SendBack |
| 沟通 | 前加签 | Consult 无审批权且锁按钮；前加签有完整审批权 |
| 委托代批 | 并加签 | Surrogate 配置并入；加签是办理时点选 |

未来节点加减人：**无** `AddFutureAssignee` 命令；改尚未到达节点预定人走预选表 / 设计算人，不进本专题办理条。

## 7. 选型与验收

| 意图 | 用 |
|------|-----|
| 先让他审我再审 | SignForward + `SignForwardBefore` |
| 我批完再让他把关 | SignForward + `SignForwardBehind` |
| 拉人一起拍板 | SignForward + `SignForwardParallel` |
| 会签去掉某人 | `RemoveAssignee` |
| 管理换当前节点全员 | `ChangeAssignee` |
| 只提醒 | `Urge` |
| 交人不再管 / 代办还回 | `Transfer` / `Delegate`（委托专题） |

| # | 期望 |
|---|------|
| SF1 | 前加签后本人不可先办；他人通过后回到本人 |
| SF2 | 后加签：本人办结后出现加签人待办，非直接下一节点 |
| SF3 | 并加签：双方同时有待办 |
| R1 | 三人会签减一人 → 余 2；禁减最后一人 |
| CA1 | ChangeAssignee 提交全集后 SignIds/打开待办与全集一致 |
| U1 | Urge 后状态不变；有通道则收到 Urged |
| G1 | `ConsultPending` 时加签/减签/改派不可点 |

联调：[联调清单-产品缺口.md](../dev/联调清单-产品缺口.md) 减签 / CA1 / Urge。

## 8. 红线

1. **加签 ≠ 加批**：未拆命令前禁止产品双按钮假装两套引擎语义。  
2. **减签禁空**：至少保留 1 名打开待办。  
3. **改派提交的是全集**，不是「只传增量」；Host 须以 `CurrentAssignees` 为底编辑后整表回传。  
4. **Leave 正交**：加减人不得默认可绕过 Collaborate / 抢办规则。  
5. **沟通未清**时加签/减签/改派与 Run 等一并拦截。  
6. **未来节点改人**不借用本专题三命令伪装。  
7. EndType：减签/改派踢出落 **`Removed`**（与转办交人等区分审计）。
