## 0. 一句话与划界

### 0.1 含义

**业务状态回写** = 流程跑起来之后，把「审批中 / 已通过 / 已驳回 / 已关闭…」写回**业务表**（或中间态字段），让业务列表、报表、下游系统与流程实例一致。  
**流转仍走引擎命令**；回写是宿主**旁路**（FormBiz Handler + Sync Hook），**不进** pure 调度内核。

| 口语 | Sail / 宿主锚点 | 本专题？ |
|------|-----------------|----------|
| 办完把单据改成已通过 | FormBiz `OnFinish` + Lifecycle Hook | ✅ |
| 发起落单 + 挂流程实例 Id | `OnSubmit` / `OnStarted` | ✅ |
| 同意/退回/作废时改业务中间态 | `OnConsent` / `OnBackToModify` / `OnCancel` | ✅ |
| 自写 Sync Hook 回写任意业务表 | `IFlowHook` Mode=Sync | ✅ 对照路径 |
| 待办推门户/邮件 | TaskNotifier | ❌ 待办推送专题 |
| 节点上 sf:bizState | BPMN 扩展码 | ❌ 引擎**不解释**；可由宿主自读 |
| 流程标题 / BizPK 注入 | 创建 Hook / BizData | ❌ 标题专题；本专题消费已有 Biz* |

```text
业务单要跟着流程变状态？
 ├─ 有标准业务表单壳（FormCode）     → §1 FormBiz 一业务一类
 ├─ 仅终态 Status（通过/驳回/关闭） → OnFinish + UseFormBizLifecycleHook
 ├─ 同意/退回也要改业务字段         → OnConsent / OnBackToModify（Dispatcher 回调）
 └─ 非 FormBiz 的老业务             → 自挂 Sync Hook（按 BizChannel/Match）
不要：
 ├─ 在 Notifier 里写复杂回写
 ├─ 只丢 Outbox/Channel 当唯一强一致保障
 └─ 另开连接在 Sync Hook 里改同库表（SQLite 易死锁）
```

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 表单生命周期契约 | **宿主** | `ISailFormBizHandler` | OnInit/Query/Submit/Started/Consent/Back/Cancel/**Finish** | FormCode ↔ `BizChannel` | **`AddSailFormBiz`** |
| 发起落库+启流 | **宿主** | `SailFormBizHost` / `WfBizForm` | — | Submit→Start→OnStarted | API `WfBizForm/*` |
| 办理中回调 | **宿主** | `SailOperationDispatcher` 成功后 | `NotifyAfterOperation` → OnConsent/Back/Cancel | ButtonId 映射 | 办理条统一入口 |
| 终态回写 | **宿主 Hook** | Sync `SailFormBizLifecycleHook` | Events：`OnProcessCompleted` / `Rejected` / `Closed` → **OnFinish** | 按 BizChannel 找 Handler；**Kit 同事务** | **`UseFormBizLifecycleHook`** |
| 请假样例 | **宿主** | `LeaveFormBizHandler` | OnFinish→Status | `sf_demo_leave`；遗留 `UseLeaveStatusHook` 已委托同 Handler | 同上（替代专用 Leave Hook） |
| 通用 Sync 回写 | **宿主/业务** | `IFlowHook` | 自订 Events | 任意业务表 | `AddHook` / `UseFlowAspects` |
| 引擎命令本身 | **引擎** | Transition/… | 只产 FlowHook 事件 | 无业务 Status 语义 | — |

```csharp
services.AddSailFormBiz();                 // Leave + Dynamic + Registry + Host
builder.UseFormBizLifecycleHook();         // Sync：Completed/Rejected/Closed → OnFinish
// 新增业务：实现 ISailFormBizHandler → AddScoped<ISailFormBizHandler, Xxx>()
```

## 1. FormBiz：一业务一类（正统产品路径）

### 1.1 含义

| 方法 | 时机 | 典型回写 |
|------|------|----------|
| `OnInit` | 打开发起默认值 | — |
| `OnQuery` | 按 BizPK 回填 | 读业务表 |
| `OnSubmit` | 首次提交 | 插业务行；写出 **BizPK** / Conditions；Status=审批中 |
| `OnStarted` | Start 成功 | 回写 **ProcessInstanceId** |
| `OnConsent` | 同意办理成功 | 可选：进度、当前环节文案 |
| `OnBackToModify` | 退回成功 | 可选：退回修改态 |
| `OnCancel` | Close/Terminate/Discard/Reject 成功 | 可选：作废/取消态 |
| `OnFinish` | 流程**终态** Hook | **通过 / 驳回结束 / 关闭** → 终态 Status |

`FormCode` 与 Runner **`BizChannel`** 对齐（见业务字段专题）。未注册 FormCode → `FormBizHandlerMissing`，不静默空转。

### 1.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 注册 Handler | 宿主 DI | Registry | — | Leave=`SailLeave`；Dynamic | **`AddSailFormBiz`** + 自研 Scoped |
| 发起 | 宿主 API | SubmitAndStart | OnSubmit→引擎 Start→OnStarted | `POST api/WfBizForm/Submit` | — |
| 办理成功旁路 | 宿主 | Dispatcher | NotifyAfterOperation | Approve→Consent；SendBack→Back；Reject/Close…→Cancel | `AddSailOperationHandlers` |
| 终态 | 宿主 Sync Hook | `SailFormBizLifecycleHook` | FlowHook 上述三事件 | 须有 BizChannel+BizPK | **`UseFormBizLifecycleHook`** |
| 同事务写库 | 宿主 Handler | OnFinish 用 **ctx.Kit** | FailFast：异常回滚流程事务 | 禁止另开 `UseRunSQL` | — |

### 1.3 请假样例映射

| FinishEvent | Status（示意） |
|-------------|----------------|
| `OnProcessCompleted` | 已通过 |
| `OnProcessRejected` | 已驳回 |
| `OnProcessClosed` | 已关闭 |

遗留 `UseLeaveStatusHook`：**已委托** `LeaveFormBizHandler.OnFinish`，默认宿主改挂 FormBiz 生命周期，避免双写分叉。

## 2. 终态 vs 办理中回写

### 2.1 含义

| 档 | 触发 | 适合 |
|----|------|------|
| **终态** | Completed / Rejected / Closed | 单据最终 Status（列表筛选、关闭入口） |
| **办理中** | ButtonsOperation 成功 | 进度%、当前处理人摘要、退回修改标记 |
| **节点码** | 设计器 `sf:bizState` | 引擎不解释；宿主若要按节点改业务态须**自订 Hook**读图 |

退回（SendBack）默认走 `OnBackToModify`，**不是** OnFinish——除非产品把「退回」也映射成业务终态（一般不推荐）。

### 2.2 分层说明

| 意图 | 归属 | 层 | 钩子/回调 | 宿主定义 |
|------|------|----|-----------|----------|
| 终态 Status | 宿主 | Sync Hook → OnFinish | 三终态事件 | FormBiz |
| 同意进度 | 宿主 | Dispatcher → OnConsent | ButtonId=Approve | 可选 override |
| 退回修改 | 宿主 | Dispatcher → OnBackToModify | ButtonId=SendBack | 可选 |
| 驳回/关闭取消 | 宿主 | Dispatcher → OnCancel **且/或** OnFinish(Rejected/Closed) | 注意勿双重矛盾业务态 | Handler 内幂等 |

## 3. 可靠性与装配

### 3.1 含义

| 档 | 用法 |
|----|------|
| **强一致业务 Status** | **Sync Hook + 同事务 Kit**；失败 FailFast 回滚推进 |
| 可晚汇总/外部同步 | AsyncOutbox Hook 或另表对账 |
| 待办推送 | Reliable Notifier（另专题）；**不**替代 Status 回写 |

### 3.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| Sync 终态 | 宿主 | HookMode.Sync | Completed/Rejected/Closed | FormBizLifecycleHook | `UseFormBizLifecycleHook` |
| 自研回写 | 宿主 | AddHook Sync | 自订 Events + Match | 业务服务 | `UseFlowAspects` / `AddHook` |
| 指标/旁路日志 | 宿主 | BestEffort | — | 文件日志等 | 勿当 Status 唯一路径 |

红线（可靠性文档）：须与办结同事务的状态回写，**不要**只丢进 Channel/Outbox。

## 4. 与邻域划界

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 业务状态回写 | 待办推送 | Notifier ≠ 改业务 Status |
| 业务状态回写 | Gate | Gate 拦截推进；回写在成功后 |
| OnFinish | 每次同意 | 同意用 OnConsent；终态用 OnFinish |
| Reject 办理回调 | 仅 OnCancel | 终态 Rejected 仍可能打 OnFinish |
| BizMirror 占位 | 生产回写 | 现为控制台 Stub；正式走 FormBiz/自研 Hook |
| sf:bizState | 引擎自动改业务表 | 引擎不解释；宿主自消费 |
| ProcessName | 业务 Status | 标题/名称见标题专题 |

条件袋 `Conditions`（如 days）供**分支求值**，不是业务 Status 字段。

## 6. 选型与验收

| 意图 | 用 |
|------|-----|
| 标准业务单 + 终态 Status | FormBiz Handler + Lifecycle Hook |
| 同意也要刷业务进度 | override OnConsent |
| 退回改「待修改」 | OnBackToModify |
| 无 FormCode 的遗留表 | Sync Hook 按 ProcessCodes/BizChannel Match |
| 推门户待办 | 待办推送专题，并行不替代 |

| # | 期望 |
|---|------|
| H1 | Submit→Start→业务行有 PI；Status=审批中 |
| H2 | 流程完成后 Status=通过（OnFinish + 同事务 Kit） |
| H3 | 未注册 FormCode → `FormBizHandlerMissing` |
| H4 | 驳回结束 → Status=已驳回 |
| H5 | 关闭 → Status=已关闭 |
| H6 | OnFinish 抛错 → 流程事务回滚（Sync FailFast） |
| H7 | 请假与 FormBiz **不**双挂导致 Status 写两次语义分叉 |

联调：[联调清单-产品缺口.md](../dev/联调清单-产品缺口.md) §H。

## 7. 红线

1. **回写在宿主，不进 pure Mediator。**  
2. **强一致 Status 用 Sync + ctx.Kit**，禁止 Hook 内另开连接死锁。  
3. **Notifier 不做复杂业务回写。**  
4. **FormCode 必须注册**；禁止静默空转。  
5. **OnFinish 与 OnCancel 映射要幂等**，避免 Reject 双写打架。  
6. **勿用 Outbox 作为业务终态唯一来源**（可补调，但列表以 Sync 为准）。  
7. 与转办/退回/分支条件正交：那些改人/改线，不代替 Status 契约。
