> 状态：**已落地**（引擎 R10 契约 + 宿主 Filter/Hook/Job；2026-11-16 主路径改 Hook→`RunProcess`）  
> 用途：把「审批人与发起人相同」「同一人在流程中重复出现」「自动跳过/自动通过」三组产品语义写清——**配置在哪、谁消费、何时生效、与谁正交**。

## 1. 一句话

**「同人 / 重复 / 跳过」都不是新的算人 Resolve Type**——定范围仍走 `sf:assigneeResolve`；策略挂在 **Filter / EmptyAction / 发送成功 Hook → AutoApprove 锚点 → Job `RunProcess`**。先正常建 Waiting 待办留痕迹，再异步代办同意。

| 产品说法 | 配置落点 | 触发层 |
|----------|----------|--------|
| 审批人与**发起人**同一人 | 节点 `assignStartUserHandlerType` | Filter（换人）或 Hook（跳过） |
| 同一人在流程中**重复出现** | 流程 Extra `autoApprovalType` | Dedup Hook |
| 节点**整段自动通过/拒绝** | 节点 `approveType` | Filter（拒绝人）或 Hook（通过） |
| 算人为**空**时自动通过 | 节点 `assignEmptyHandlerType=1` | EmptyAction 写策略人 + Hook |
| 同一节点多人名单**重复 UserId** | （管道内置） | `DedupUsersFilter`（列表去重，不是免批） |
| 跳过表达式 | 节点 `skipExpression` | **设计器已落盘；运行时尚未消费** |

## 2. 勿混：四层问题

| 层 | 问的是 | 正确挂载 | 错误做法 |
|----|--------|----------|----------|
| **定范围** | 这节点该找谁 | `IAssigneeResolver` + ConfigPair | 把同人做成新 Resolve Type |
| **同发起人** | 算出来的人是否全是发起人 | `SameAsStarterFilter` / AutoApproveHook | 在 Leave 里「同人跳过」 |
| **流程重复** | 此人是否在本实例已经办过 / 是否刚从上一节点办完 | `SailProcessExtraDedupHook` | 与 NodePolicy 同人互斥配置抢同一开关 |
| **自动同意执行** | 如何代点同意 | Outbox 锚点 + `AutoApproveAnchorWorker` → `RunProcess` | Filter/Hook 内同步二次 `RunProcess` |

**正交原则：**

- **节点同人**（相对发起人）⊥ **流程去重**（相对本实例已办历史）——可同时开；各自独立入队。  
- **同人=2 跳过** ⊥ **同人=3 换人**——互斥枚举。  
- **列表 Dedup**（同节点多名重复）≠ **流程 autoApprovalType**（跨节点免批）。

## 3. 产品配置

### 3.1 节点 · 审批人与发起人为同一人

**UI：** 设计器节点配置弹窗 →「审批人与发起人为同一人时」  
**落盘：** `sf:NodePolicy.json` → `assignStartUserHandlerType`（默认 `1`）

| 值 | 产品文案 | 运行时 |
|----|----------|--------|
| **1** | 由发起人自己审批 | 不干预 |
| **2** | 自动跳过 | **保留** Waiting 待办；发送成功 Hook 若「该活动全部 Waiting 待办的 SignId = 发起人」→ 入队，意见「同人策略：自动通过」 |
| **3** | 按指定待办人策略重新算人 | Filter 命中「全部 = 发起人」后，按 `assignStartResolveType`（缺省 `deptBoss`）+ `assignStartResolveParams` 再 Resolve；空 → `SameAsStarterResolveEmpty` |

**换人 Type 面板：** 与主定范围同一套 Registry 码（如 `deptBoss` / `RoleGroup`）。  
**宿主默认角色袋：** `Sail:DeptLeaderRoleIds`（兼容旧键 `Sail:SameAsStarter:LeaderRoleIds`）。

### 3.2 流程 · 同一审批人重复出现

**UI：** 四步编辑 →「更多设置」→「自动去重」  
**落盘：** `sf_process_meta.extra_json` → `autoApprovalType`

| 值 | 产品文案 | 命中条件（Waiting 待办） |
|----|----------|--------------------------|
| **0** | 不自动通过 | — |
| **1** | 仅审批一次，后续重复节点自动通过 | 本实例已有 **Completed** 且 `EndedUserId` = 当前 `SignId` |
| **2** | 仅针对连续审批节点自动通过 | 最近一条（不同 ActivityInstance）Completed 的办结人 = 当前 `SignId` |

意见文案：`流程去重：曾办过自动通过` / `流程去重：连续同人自动通过`。  
StrategyCode：`ProcessDedupOnce` / `ProcessDedupConsecutive`。

### 3.3 节点 · 审批类型（整段跳过）

| `approveType` | 产品 | 运行时 |
|---------------|------|--------|
| **1** | 人工审批（默认） | 正常 |
| **2** | 自动通过 | 保留算人结果；Hook 对该活动 Ready+Waiting 全量入队；意见「节点策略：自动通过」 |
| **3** | 自动拒绝 | Filter 覆盖为策略拒绝人；后续 Job/Worker 走拒绝路径（与「同人跳过」不同通道） |

> 设计器提示仍有「不建人工待办」旧文案；**现行实现是建 Waiting 再代办**，与 R10 留痕一致。以本专题与管道 §11 为准。

### 3.4 节点 · 审批人为空时（跳过支路）

| `assignEmptyHandlerType` | 产品 | 与「跳过」关系 |
|--------------------------|------|----------------|
| **2** | 自动拒绝（默认 = R4 拒推进） | 不是跳过 |
| **1** | 自动通过 | EmptyAction 写入 `Sail:PolicySkip` 身份（默认真人可配，否则 `__sail_policy_skip__`）；Hook 认策略人待办入队；意见「空人策略：自动通过」 |
| **3 / 4** | 指定人 / 转管理员 | 换人，不是自动跳过 |

### 3.5 跳过表达式（未消费）

| 项 | 现状 |
|----|------|
| 字段 | `NodePolicy.skipExpression`；面板「签名 / 意见 / 跳过」可编辑 |
| 引擎 / Host | **无**求值与入队逻辑 |
| 口径 | 产品预留；未立项前勿当已交付能力 |

### 3.6 列表去重（非免批）

宿主 `UseSleveenNodePolicyAssignee` 挂载引擎内置 `DedupUsersFilter`（order 60）：同一 Resolve 结果里按 `UserId` 去重，**只少建重复待办**，不会 AutoApprove。

## 4. 运行时链路

```text
时刻 A · 建待办（TryResolveForTaskCreate）
  Resolver 定范围
  → Count==0？ EmptyAction（空人=1 → 策略跳过人）
  → Filters：
       order 0  NodePolicyApproveTypeFilter   （approveType=3 换拒绝人；=2 放行）
       order 10 SameAsStarterFilter           （仅 type=3 换人；type=2 不清人）
       order 50 SurrogateAssigneeFilter
       order 60 DedupUsersFilter              （名单去重）
  → 落库 Waiting 待办（正常痕迹）

发送成功 Hook（仅 Started / Continued / Resent）
  SailNodePolicyAutoApproveHook
    approveType=2 → 全 Waiting 入队
    同人=2 且全部 SignId=发起人 → 入队
    空人=1 且全部为策略跳过人 → 入队
  SailProcessExtraDedupHook
    autoApprovalType 1|2 命中历史 → 入队
  → HookOutboxAutoApproveAnchorStore（与发送同库事务）

不订阅：SendBack / Reject / Withdraw / Reverse / Jump …
  → 退回落点不会「自动回来」

Job · SailNodePolicyJobWorker
  AutoApproveAnchorWorker.ProcessPendingAsync
    → 以 PreferUserId 身份 RunProcess（固定 sail.comment）
    → 失败 AutoApproveFailed，待办保留给人办
  （可选）Sail:PolicySkip:LegacyDrain=true → 扫魔法 skip 待办兜底
```

**退回边界：** Backward 建任务时引擎置 `AllowSameAsStarterPolicy=false` → `SameAsStarterFilter` 直接 return；同人=3 换人亦不在退回落点生效。

## 5. 命中矩阵（速查）

| 场景 | 同人=1 | 同人=2 | 同人=3 | 去重=0 | 去重=1 | 去重=2 | approveType=2 |
|------|--------|--------|--------|--------|--------|--------|---------------|
| 办理人 ≠ 发起人 | 人工 | 人工 | 人工 | 人工 | 若曾办过则过 | 若连续同人则过 | **过**（整节点） |
| 办理人 = 发起人（全员） | 人工 | **过** | **换人** | 人工 | 若曾办过则过 | 若连续则过 | **过** |
| 算人为空且空人=1 | — | — | — | — | — | — | （策略人）过 |
| SendBack 落点 | 人工 | 人工（不开同人） | 不换人 | 不去重入队* | 不去重入队* | 不去重入队* | 不入队* |

\* Dedup / NodePolicy AutoApprove Hook **不订阅** SendBacked；退回后须人办或再次正向发送。

**同时命中：** 同人=2 与 去重=1 可对同一待办各写锚点；Job 幂等按锚点消费，首次成功办结后其余应 `AutoApproveSkipped`（无 Waiting）。

## 11. 红线与余债

**红线**

1. 禁止把同人/重复注册成 Resolve Type。  
2. 禁止在 Filter / EmptyAction / Hook 内同步 `RunProcess`。  
3. 禁止另开第二套 AutoApprove Drain 与 `SailNodePolicyJobWorker` 双开（浪费 reclaim；见 `UseSleveenAssigneeAutoApproveJob` 警告）。  
4. SignTogether **禁止**零 Performer 自动过。  
5. 退回路径默认关闭同人换人/跳过策略。

**余债**

| 项 | 说明 |
|----|------|
| `skipExpression` | 落盘未求值 |
| 设计器 approveType=2 提示文案 | 与「建 Waiting 再代办」现行不完全一致，宜改提示 |
| 同人与去重双锚点 | 行为可接受；若产品要「互斥优先」需另拍板 |
| 会签部分人=发起人 | 同人=2 要求**该活动全部** Waiting 的 SignId=发起人；部分同人不会整节点跳过 |
