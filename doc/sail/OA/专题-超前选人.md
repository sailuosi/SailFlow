## 0. 一句话与划界

### 0.1 含义

**超前选人** = 发起时（或管理改表时）按**流程实例 + 未来活动定义 Id** 持久化办理人；节点到达时时刻 A 用 Resolve Type=`Preselect` **从表取人建待办**——中间领导**同意即可发**，不必再选下一办理人。

| 口语 | Sail 锚点 | 本专题？ |
|------|-----------|----------|
| 超前选人 / 发起预选后续人 | **`Preselect`** + 预选表 | ✅ |
| 当次自选下一跳 | `StarterPick` / `ApproverPick` | ❌ 对照：无实例持久化 |
| 当前节点加/减/改人 | SignForward / Remove / ChangeAssignee | ❌ 改签专题 |
| 未来节点加签动词 | 候选 `*FutureAssignee` | ❌ **无命令**；改预选表即换人 |
| 下一跳走哪条线 | 分支条件 | ❌ 流转分支专题 |

```text
发起时后续人已经清楚？
 ├─ 多节点 / 可改人 / 要审计     → 本专题 Preselect 表
 ├─ 单节点账号列表、极简         → Expression + Conditions（逃生）
 └─ 指望 Start 多 key NextActivityPerformers 带到全程 → ❌ 不会自动延续
```

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| Type + Resolver 骨架 | **引擎** assignee | 时刻 A Resolve | `IAssigneeResolver.Resolve`（读 Store） | Type=`Preselect`；**默认不** RegisterBuiltins | **`UsePreselectAssignees(store)`** |
| Store 契约 | **引擎** assignee | `IPreselectAssigneeStore` | — | Load/Replace/Clear | 宿主注入实现 |
| 表与 API | **宿主** | CRUD | **无 FlowHook**（算人不走 Gate/Hook） | `sf_preselect_assignee`；`api/WfPreselect` | **`UseSleveenPreselectAssignees`** |
| 图配置 | **宿主设计** | `sf:assigneeResolve` | — | 目标节点 Type=Preselect；中间节点勿 ApproverPick | 设计器枚举 |
| 发起 UX | **宿主** | Start 成功后 Replace | — | `SailPreselectPanel`；Start **不**写表 | 面板 persist |
| 办理免选手动 | **宿主** | ProbeNext | — | `SkipManualPick`；`SailPreselectApproveHint` | 办理条 |
| 建待办 | **引擎** | Mediator → Pipeline | 空集 → EmptyAction/R4 | Leave 仍按节点 | `UseBizAssignees` |

```csharp
.UseBizAssignees()
// Build 后：
client.UseSleveenPreselectAssignees(new SleveenPreselectAssigneeStore(client));
// ≡ UsePreselectAssignees(store) → useAssigneeResolver(PreselectAssigneeResolver)
```

## 1. 图怎么配

### 1.1 含义

| 节点角色 | Resolve | 说明 |
|----------|---------|------|
| 需超前选人的**未来节点** | **`Preselect`** | 到达时从表取人 |
| **中间**自动过（部门领导等） | `RoleGroup` / `deptBoss` / `JobRelative`… | **禁止**默认 `ApproverPick`，否则领导必选下一跳 |
| 首跳若仍要人选 | `ApproverPick` / `Specific` 等 | 与预选表正交 |

出厂默认 Resolve=`ApproverPick`（R6）——预选场景下目标节点与中间节点都须**显式改掉**。

Leave（会签/抢办）仍按 [多人办理模式](./专题-多人办理模式.md) 配；预选只定「谁」，不定「几人过」。

### 1.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 设计器选 Type | 宿主 | BPMN ConfigPair | — | Params：`required` / `allowMulti` / `allowMultiGroup` | 落盘 |
| 扫预选目标 | 宿主 API | ListTargets | — | 按定义扫 Type=Preselect | `GET …/ListTargets` |
| 发布校验 | 宿主（待勾） | — | — | required 与 R6 并列 | 待补 |

```xml
<sf:assigneeResolve type="Preselect" params='{"required":true,"allowMulti":true}'/>
<sf:leaveJudge type="Collaborate" params='{"completeRate":1}'/>
```

## 2. 写入与改人

### 2.1 含义

键：**ProcessInstanceId + ActivityId（定义 Id）** → Performer 列表（UserId=Account，可带 Group*/Unit*/Weight）。

```text
StartProcess 成功得 PI
  → 面板 Persist：各预选节点 Store.Replace（整节点覆盖）
  → （可选）管理改表 / Clear
到达节点 → Resolve 读表 → 建待办
```

**无** `AddFutureAssignee` / `ChangeFutureAssignee` 引擎动词；**改预选表 = 换未来人**。

### 2.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| Start | 引擎 | Transition Start | — | **不**写预选表 | — |
| 持久化 | 宿主 | `POST …/Replace` | — | 同库事务建议包住 Start+写表 | `UseSleveenPreselectAssignees` |
| 查询/清除 | 宿主 | Get / Clear | — | — | 同上 |
| 改人生效 | 引擎 | 下次到达时刻 A | — | 已到达节点不靠本表改当前待办 | — |

写入时机：**必须有 PI**；发起前勿插孤儿行。

## 3. 运行时取人（时刻 A）

### 3.1 含义

```text
推进到 Preselect 节点
  → TryResolveForTaskCreate
  → PreselectAssigneeResolver
  → Store.Load(PI, ActivityId)
  → 非空建待办；空 → EmptyAction / R4（禁止暗默认发起人）
```

### 3.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| Resolve | 引擎 | `PreselectAssigneeResolver` | 管道时刻 A | Store 未挂 → 空列表 | `UsePreselectAssignees` |
| 空人 | 引擎+宿主策略 | EmptyAction / NodePolicy | — | 默认拒绝；勿会签零人自动过 | R10 包 |
| Filter 链 | 引擎/宿主 | Dedup / 同人等 | 在 Resolve **之后** | 预选结果仍可被 Filter | `UseSleveenNodePolicyAssignee` 等 |
| Leave | 引擎 | 时刻 B | — | 与预选正交 | `UseBizAssignees` |

未启用 Type 却配了 Preselect → 配置缺失/空人拒绝，**禁止**静默回落。

## 4. 办理体验

### 4.1 含义

| 角色 | 体验 |
|------|------|
| 发起人 | 扫到 Preselect 节点 → 选人（可多选/权重）→ Start → persist |
| 中间审批人 | Probe 下一跳已预选 → **SkipManualPick**，同意即发 |
| 预选节点办理人 | 正常待办；推送/Leave 按常规则 |

### 4.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 发起面板 | 宿主 FE | `SailPreselectPanel` | — | Start 后 `persist(piId)` | — |
| 办理探测 | 宿主 API | ProbeNext | — | `SkipManualPick` | `GET …/ProbeNext` |
| 办理提示 | 宿主 FE | `SailPreselectApproveHint` | — | 合并预览「已预选」展示 | — |

库存下一跳人选树**可能不回填**预选人 → Host 须按表合并展示。

## 5. 与邻域对照

| 说法 | 别当成 | 正确锚点 |
|------|--------|----------|
| 超前选人 | StarterPick | 无持久化；当次 map |
| 超前选人 | ApproverPick | 办理页选下一跳 |
| 超前选人 | 加签 | 当前节点临时拓扑 |
| 改未来人 | ChangeAssignee | 改**当前**节点全集；未来人改预选表 |
| 多 key NextActivityPerformers | 全程预选 | 仅当次 Start/Run |
| Expression+Conditions | 正统多节点产品 | 仅单节点轻量逃生 |
| AI.NextStepPerformers | 预选仓 | 网关等路径序列化，非通用仓 |

退回再提交 / 撤回：产品约定保留预选或 Clear 重选。加签**不要**写入预选表。

## 6. UseXxx / 装配清单

| 项 | 本专题作用 |
|----|------------|
| **`UsePreselectAssignees(store)`** | 引擎侧挂 Preselect Resolver + Store |
| **`UseSleveenPreselectAssignees`** | 宿主具化（表实现 + 注册） |
| `UseBizAssignees` | 管道骨架；Leave/空人等 |
| （无）`UseFutureAssignee*` 动词包 | **不存在**——改表即可 |
| Gate/Hook | **禁止**承载预选算人 |

## 7. 选型与验收

| 意图 | 用 |
|------|-----|
| 发起定好多后续审批人，中间不选人 | Preselect 表 + 图配置 |
| 单字段账号串、不改人 | Expression + Conditions |
| 当前节点临时加人 | SignForward |
| 当前节点换全集 | ChangeAssignee |

| # | 期望 |
|---|------|
| P1 | 发起选齐 → 中间同意无选人框 → 目标待办=预选人 |
| P2 | required 漏选 → 前端拦或到达空人 ReasonCode |
| P3 | Replace 改人后再到达 → 待办为新人 |
| P4 | 未 `UsePreselect*` 却配 Preselect → 可诊断失败，非静默成功 |
| P5 | 会签预选行带齐 Group*（若 Leave 组模式） |
| P6 | Start 失败不留下孤儿预选行 |

联调清单见指南 §10.C。

## 8. 红线

1. **勿用 StarterPick/多 key Performers 冒充超前选人。**  
2. **中间节点禁止默认 ApproverPick**（否则领导被迫选人）。  
3. **空人禁止暗默认发起人**（R4）。  
4. **新建 Type=`Preselect`**，禁止覆盖 StarterPick 语义（R9）。  
5. **算人只走 Assignee 管道**，禁止塞进 Gate/Hook/Leave。  
6. **UserId = Account**（R3），勿绑死组织表 GUID。  
7. **无 FutureAssignee 动词伪装**；当前节点改人用改签专题命令。  
8. 只注册 Resolver 不做 UX → 办理页仍可能强制选人（不完整）。
