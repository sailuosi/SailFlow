## 0. 一句话与划界

### 0.1 含义

**待办推送** = 引擎在待办**生命周期旁路**上，把「开待办 / 关待办 / 交人 / 催办」投递给邮件、IM、统一日程等通道——**不阻断**流转，默认走 **Outbox 可靠补调**。

| 口语 | Sail 锚点 | 是否本专题主角 |
|------|-----------|----------------|
| 待办推送 / 待办中心 / 日程同步 | **`ITaskNotifier`** + `TaskNotifyKind` | ✅ |
| 流程成功后回写业务表 | `IFlowHook` / FormBiz | ❌ 对照：订 Events，不是 TaskKinds；见 [专题-业务状态回写.md](./专题-业务状态回写.md) |
| 推进前卡控 | `IFlowGate` | ❌ 对照：可 Reject |
| 抄送知会 | `ICopytoNotifier` / `CopytoNotifyKind` | ❌ **独立通道** |
| 同人/超时自动过 | AutoApprove Outbox / Job | ❌ 对照：执行 `RunProcess`，不是推消息 |

```text
要不要推外部？
 ├─ 待办开/关/交人/催 → 本专题 ITaskNotifier（TaskKinds）
 ├─ 知会无审批权     → Copyto + AddCopytoNotifier（禁止冒充 TaskNotifier）
 ├─ 回写业务 / 汇总  → IFlowHook（Events）
 └─ 卡控推进         → IFlowGate
```

### 0.2 分层说明（总览）

| 能力 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 生命周期点火 | **引擎** | `TaskManager` / Mediator 写库后 | **`FireTaskLifecycle(kind)`** → Sync Hook + Enqueue Notifier | — | 引擎内建（有注册才投递） |
| 契约与分发 | **引擎** pure | `FlowCapabilityDispatcher` / Registry | Outbox Kind=`TaskNotify`；强制 AsyncOutbox | `HookRegistrationOptions.TaskKinds` | `AddNotifier` / `addNotifier` / `UseFlowAspects` |
| 可靠骨架 | **ext/msg** | `ReliableTaskNotifierBase` ← `TaskNotifyChannelBase` | `SendCoreAsync` 失败须抛出 | — | 实现类挂在 `AddNotifier` |
| Outbox 消费 | **引擎** Drain | `HookOutboxDrainLoop` | 认领 → 调 Handler → 重试/死信 | 表 `sf_hook_outbox` | **`UseHookOutboxDrain`**（或宿主包内连带） |
| 削峰 | **引擎** + 注册项 | `NotifierThrottleHub` / `InProcessThrottle` | Drain **之后**限流 | `NotifyThrottleOptions` | 注册 Notifier 时配置 |
| 门户日程 | **宿主** | `PortalScheduleTaskNotifier` | Created/Entrusted→add；Completed/Cancelled/Urged→update | `UnifiedReport:*`；流水 `sf_todo_portal_record` | **`UsePortalScheduleTaskNotifier(sp)`** |
| 默认邮件 | **ext/msg** | `DefaultMailTaskNotifier` | Created / Completed | SMTP 配置 | **`UseDefaultTaskMail`** / `UseBizTaskMail` |
| Debug 控制台 | **宿主** | `SailDebugConsoleNotifier` | 可含 Urged/Entrusted | — | `UseDebugConsoleHook`（内挂 Notifier+Drain） |

```csharp
.UseFlowAspects(b => { /* AddNotifier… */ })
.UseHookOutboxDrain(autoStart: true)   // Reliable 必开
// 宿主能力包（示意）：
.UsePortalScheduleTaskNotifier(sp)     // Enabled 时连带 Drain + PostBuild addNotifier
.UseDefaultTaskMail()                  // 可选邮件轨
```

## 1. 生命周期种类（`TaskNotifyKind`）

### 1.1 含义

| Kind | 意图（渠道辅助） | 典型触发 | 待办状态 |
|------|------------------|----------|----------|
| **`Created`** | Open | `TaskManager.Insert` 建待办 | 新 Waiting |
| **`Completed`** | Close | 本人办结 / 正常完成 | Completed |
| **`Cancelled`** | Close | 减签踢出、撤回/退回关单、取消委托残片等 | Closed/Canceled 等 |
| **`Entrusted`** | Open（映射） | 转办/委派**关原人**路径上的 Lifecycle Kind | 原人已 Closed；Kind 名历史复用 |
| **`Urged`** | 提醒（状态不变） | `UrgeProcess` / 超时提醒策略 | **不改** TaskState |

`TaskNotifyMessageIntent`：Created/Entrusted→Open；Completed/Cancelled→Close；其余（含 Urged）默认按 Open 辅助。

### 1.2 分层说明

| Kind | 归属点火点 | 层 | 伴随 FlowHook 事件（Dispatcher） | 宿主须订 TaskKinds？ |
|------|------------|----|----------------------------------|----------------------|
| Created | 引擎 Manager Insert | `FireTaskLifecycle` | `OnTaskCreated` | ✅ 要推「开」必须订 |
| Completed | Complete / 办结 | 同上 | 历史映射 **`OnTaskCompleted`** | ✅ 关待办 |
| Cancelled | Remove/Withdraw 等 | 同上 | 同上映射 `OnTaskCompleted` | ✅ 消除残留 |
| Entrusted | Transfer/Delegate 关原 | 同上 | 同上映射 `OnTaskCompleted` | 视通道：门户当「推新」见 §4.3 |
| Urged | `UrgeOpenTasks` | 同上 | **`OnTaskUrged`**；Operation=`Urge` | ✅ 催办/超时提醒 |

**未配 `TaskKinds` = 永不推送**（与 Hook 未配 `Events` 同理）。

### 1.3 谁在何时点火（产品对照）

| 办理动作 | 常见 Lifecycle | 产品期望（外部待办中心） |
|----------|----------------|--------------------------|
| 启动/同意产生新待办 | Created | 对方出现待办 |
| 通过办结本人 | Completed | 本人待办关闭 |
| 减签 / 部分取消 | Cancelled | 被减人待办消失 |
| 转办 | 原 **Entrusted** + 新 **Created** | 原人关、新人开（见 §4.3） |
| 委派发起 | 原 Entrusted + 新 Created（受托挂链） | 受托人开；原人关展示 |
| 催办 | Urged | 提醒，状态不动 |
| 抄送 | **不走**本表 | `FireCopytoLifecycle` |

命令级成功 Hook（如 `OnProcessTransferred`）与路径内 Lifecycle **分工**：骨架 AfterSuccess 只打流程 Hook；**待办推送只认** `FireTaskLifecycle`，防双响见手册 §5.15。

## 2. 投递与可靠档

### 2.1 含义

```text
写库（同事务）
  → FireTaskLifecycle
      → Sync Hook（可回滚）
      → EnqueueAsyncHooks / EnqueueTaskNotifiers → sf_hook_outbox Pending
  → 提交
Drain（后台）
  → 认领 → ITaskNotifier.NotifyAsync
      → 成功 Succeeded / 失败重试 / 死信
可选：Drain 后 InProcessThrottle（Channel 背压 + 并发 + 最小间隔）
```

| 档 | 含义 | 骨架 | 适用 |
|----|------|------|------|
| **Reliable** | 不能静默丢 | `ReliableTaskNotifierBase` + Outbox + Drain；失败**抛出** | 待办中心 / 门户日程 |
| **BestEffort** | 可丢日志类 | `BestEffortFlowHookBase` 等 | 文件审计，**不是**待办推送主档 |
| **Reconcile** | 另表对账补漏 | 宿主历史模型 | 有推送记录表时可并存 |

### 2.2 分层说明

| 步骤 | 归属 | 层 | 钩子/回调 | 宿主定义 | UseXxx |
|------|------|----|-----------|----------|--------|
| 入队 | 引擎 | Dispatcher `EnqueueTaskNotifiers` | 与流转**同库同事务** | Outbox 行含 TaskId+Kind | 有 Notifier 注册即可 |
| 消费 | 引擎 | `UseHookOutboxDrain` | HostedService / Loop | 死信台 `/sail/outbox`（宿主） | **必开**才 Reliable |
| 业务发送 | 宿主/msg | `SendCoreAsync` | HTTP/SMTP/IM | 凭证、URL、流水表 | 自研 `AddNotifier` 或能力包 |
| 削峰 | 引擎注册项 | `InProcessThrottle` | Drain **认领后**限流 | Capacity/MaxDegree/MinInterval | 门户包已示例 |
| 批量运维 | 产品约束 | — | — | 禁止管理 API 同步风暴式推送 | 见副作用可靠性 D5 |

红线：`SendCoreAsync` **禁止**「丢进 Channel 立刻 return 成功」——Outbox 会提前 Succeeded。

## 4. 与邻域划界

### 4.1 抄送

| 项 | 待办推送 | 抄送 |
|----|----------|------|
| 接口 | `ITaskNotifier` | `ICopytoNotifier` |
| Kind | `TaskNotifyKind` | `CopytoNotifyKind` |
| 点火 | `FireTaskLifecycle` | `FireCopytoLifecycle` |
| Outbox | TaskNotify | **`CopytoNotify`** |
| 注册 | `AddNotifier` | **`AddCopytoNotifier`** + `CopytoKinds` |

禁止用待办 Notifier 冒充抄送知会。

### 4.2 FlowHook / Gate / 自动过

| 能力 | 别当成待办推送 |
|------|----------------|
| `OnProcessContinued` 等 | 流程事件回写，不是按 Task 开/关 |
| Gate Reject | 阻断推进，无 Outbox 推送语义 |
| AutoApprove Anchor Outbox | Job 代点 `RunProcess`，Kind 不同 |

### 4.3 转办 × Entrusted（实现注意）

| 项 | 说明 |
|----|------|
| 引擎 Transfer | 关原：`Fire(Entrusted)`；开新：`Fire(Created)` |
| 意图映射 | Entrusted → Open |
| 门户现行 | Entrusted 与 Created 一样 **addSchedules** |
| 风险 | 原人已 Closed 却走「推新」；门户文档曾写期望 Cancelled→update |
| 专题立场 | 产品期望「原关新开」；通道实现应对 Entrusted **按关原人**（update/close）或引擎改关原为 **Cancelled**——与 [专题-转办.md](./专题-转办.md) §2.3 一并跟踪 |

委派：Entrusted 在「关原」上同样复用 Kind；受托新建另有 Created。通道勿把 Kind 名「Entrusted」直接当产品文案「委派」。

## 5. UseXxx / 装配清单

| 项 | 本专题作用 |
|----|------------|
| **`AddNotifier` / `addNotifier`** | 挂 `ITaskNotifier`；**必填** `TaskKinds`；建议 `Match=All` 或白名单 |
| **`UseHookOutboxDrain`** | Reliable 消费；门户包启用时连带 |
| **`UsePortalScheduleTaskNotifier`** | 宿主统一日程 Reliable 包 |
| **`UseDefaultTaskMail`** | 默认邮件轨 |
| `UseFlowAspects` | 收拢 AddGate/Hook/Notifier |
| `UseDebugConsoleHook` | 开发旁路 |
| （无）`UseTodoPush*` 引擎总开关 | **不存在**——无注册则主路径不推 |

Probe：宿主开了门户推送时 `ProbeInstalledFeatures` 含 `HookOutboxDrain`。

## 6. 选型与验收

| 意图 | 用 |
|------|-----|
| 待办进统一日程/待办中心 | Reliable Notifier + Outbox + Drain（门户包或自研） |
| 仅邮件提醒开/办结 | `UseDefaultTaskMail` |
| 知会无审批权 | **Copyto** 通道，非本专题 |
| 催办有声 | TaskKinds 含 **`Urged`** + 通道实现提醒 |
| 开发看日志 | Debug Notifier |

| # | 期望 |
|---|------|
| N1 | 未 `AddNotifier` / 未订 TaskKinds → 无推送、流转正常 |
| N2 | Created → 外部出现待办；Completed/Cancelled → 关闭/更新 |
| N3 | Outbox 与流转同事务：流程回滚则无 Pending 推送 |
| N4 | 发送失败 → 重试/死信；修配置后可复活 |
| N5 | 批量关单不在管理请求栈同步狂推（Throttle / 分片） |
| N6 | 抄送走 CopytoNotifier，Probe/Outbox Kind 可区分 |
| N7 | Urge 后状态不变，通道收到 Urged |
| P1 | 门户 Enabled=true：流水 `sf_todo_portal_record` 成功行 |

## 7. 红线

1. **Notifier ≠ Hook ≠ Gate**：勿用一个「回调」吞三种职责。  
2. **Notifier ≠ 抄送**：禁止 `AddNotifier` + `TaskNotifyKind` 冒充知会。  
3. **Reliable 必须 Drain**：只 `AddNotifier` 不开 Drain = 队列堆积不消费。  
4. **`SendCoreAsync` 须等真实调用完成**再返回；失败要抛（Reliable）。  
5. **防双响**：待办推送只挂在 `FireTaskLifecycle`；不要在命令 AfterSuccess 再抄一遍同内容推送。  
6. **Entrusted 文案**：审计/产品用 EndType（如 `TransferredOut`/`DelegatedOut`）区分转办与委派，勿只凭 Kind。  
7. 超时/策略提醒走 TaskNotifier + `Urged`（或策略计数），**不要**在 Mediator 内嵌套同步 HTTP。
