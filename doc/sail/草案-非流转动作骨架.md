# 草案 · 动作骨架（族群基类 + 共同父类）

> 状态：**草案 / 未立项**（2026-11-14；2026-11-15 修订；已拍板事务/锁与 Forward 约束见 §4.5）  
> 用途：把「办理动词」从 `WorkflowService` 逐方法样板，收敛为**可继承的动作骨架**——共同父类提供横切**工具箱**；**族群基类按「调用哪些钩子 / 何种时序」分组并固化该时序**；动词子类**只写核心执行**。  
> 动机：同业态动词的 Gate/Hook/Notifier 调用模式相同，不该每动词复制；不同业态的钩子集合与环境不同，不该由共同父类强行一条全家桶流水线。  
> 关联：[特性说明-中国式OA审批要素.md](./特性说明-中国式OA审批要素.md) · [开发手册-OA命令执行链路.md](./dev/开发手册-OA命令执行链路.md) · [特性设计-回调与事件.md](./特性设计-回调与事件.md) · [草案-命令执行管道.md](./草案-命令执行管道.md)（**已吸收，不再单独立项**） · [特性说明-引擎能力基线.md](./特性说明-引擎能力基线.md) · [todo-产品缺口.md](./todo-产品缺口.md)

**简称「动作骨架」**（文件名仍含「非流转」：历史动机）。正文以**多族群**为准，初始清晰的三族见 §4。

---

## 1. 一句话

**新增一个办理特性 ≈ 新增一个操作枚举值 + 一个落在既有族群上的动作子类（只实现 Core）。**  

| 层级 | 职责 |
|------|------|
| `FlowActionBase` | 工具箱：`TryGate` / `OnFireFlowHook` / 诊断等 **protected**；**不**排统一时序 |
| 族群 `*ActionBase` | **固化本族钩子调用清单与顺序**（分组依据 = 钩子模式不同）；薄 `Execute` 跑该时序 |
| 动词子类 | **只写 `ExecuteCore`**（及本动词的 `Operation` / 成功事件码等身份） |

命令入口 DRY 与诊断槽**并入本骨架**，不再并行推进 [草案-命令执行管道.md](./草案-命令执行管道.md)。

---

## 2. 问题

今日事实（见 OA 命令手册）：

| 路径 | 代表动词 | 横切怎么挂 |
|------|----------|------------|
| Mediator / Runtime | Run、SendBack、Withdraw、SignForward… | 各 `Execute*Core` 内手写 `BuildGateContext` + `TryGate` + `AfterSuccess` |
| Manager 短路径 | Transfer、Terminate、Suspend… | 有的挂 Gate，有的直接 `bool`，样板不一致 |

痛点：

1. **同钩子模式的动词扩不动**：减签 / 改派与 Transfer 应共用同一套 Gate→Core→成功 Hook→TaskLifecycle，却继续复制或漏挂。  
2. **不同钩子模式未分族**：改人、改图、改实例状态的前置环境与成功事件集合不同，却挤在同一 Service 里靠自觉。  
3. **共同父类不宜专制流水线**：全家桶会逼无 Task 的 Suspend 造假；时序应沉到**族群**，不是顶层父类。  
4. **与 Command Pipeline 草案抢同一块 DRY**：已拍板**吸收管道、废并列立项**（见 §5）。

Assignee 管道（Resolve / Leave / EmptyAction）解决的是**通过时谁能离开**，**不是**办理动词骨架——二者正交，勿混。

## 3. 边界（红线）

| 做 | 不做 |
|----|------|
| 共同父类 = **工具箱**；族群基类 = **固化钩子时序**；动词子类 = **只写 Core** | **不**在共同父类排一条适用所有动词的 Gate→Hook 全家桶 |
| 开族群的首要判据：**钩子调用模式（清单+顺序+环境）不同**；业态陈述与之对齐 | **不**因「实现方便」或「类名好看」开族 |
| 动词子类禁止再手写一套 Gate/AfterSuccess 样板（应走族群 `Execute`） | **不**让动词子类 Override 掉族群钩子时序（除非文档记载的豁免） |
| **事务 + 实例锁：仅 `WorkflowService` 外壳**（`CommitOnSuccess` / `RunVerbAsync`）；Action 只消费已开 `kit` | **不**在 `FlowActionBase` / 族群 `Execute` 内 `beginTransaction` 或 `InstanceExecutionLock.Acquire` |
| **图推进能力仅挂 `TransitionActionBase`**（protected / 本族 Context）；Assignee·Lifecycle 的 Core 上下文类型上不存在 Forward | **不**靠审查清单「禁止调用 ContinueForward」；**不**给三族同一个含 Forward 的胖 Environment |
| 吸收原 Command Pipeline 的诊断/结果规范化进父类复用点 | **不**用骨架替代 `AddGate` / `AddHook` / Notifier 产品语义 |
| 先文档 + Transfer（A1）试点 | **不**再单独立项洋葱中间件与骨架「叠加」；**不**空壳上码表 |
| | **不**把 UserTask Leave / Assignee Resolve 塞进动作骨架 |

## 4. 类型分层（目标形状，非 API 定稿）

命名待立项敲定；下文用概念名固定职责。

```text
                         FlowActionBase（共同父类 · 工具箱）
                         │  TryGate / OnFireFlowHook / FireTaskLifecycle / 诊断…
                         │  不排时序、不假设 Task 必有
                         │
     ┌───────────────────┼───────────────────┐
     │                   │                   │
AssigneeActionBase  TransitionActionBase  LifecycleActionBase
 固化：Task 向钩子时序  固化：流转向钩子时序  固化：实例状态向钩子时序
 无 Forward 能力         可注入 Forward/Runtime  常无 Task 的 Context
     │                   │                   │
 动词子类只写 Core       动词子类只写 Core       动词子类只写 Core
 Transfer / 减签 / …     Run / SendBack / …      Suspend / Terminate / …
```

\*催办：默认先挂 Assignee 族（针对当前待办人 + TaskLifecycle）；禁止无论证开 Notify 第四族。  
\*Close：管理终态 → Lifecycle；图内走到 End → Transition。

### 4.1 共同父类 · `FlowActionBase`（工具箱）

**只提供能力，不排时序。** Gate/Hook/Notifier 的**调用顺序由族群基类固化**。

| 复用点（概念名，protected） | 说明 |
|-----------------------------|------|
| `BuildHookContext(...)` | 组装 `FlowHookContext`；缺哪些实体由**调用方（族群）**传入 |
| `TryGate(...)` | 适配现有 `FlowCapabilityPipeline.TryGate` |
| `OnFireFlowHook(...)` | 按给定 `EventFireType` 跑成功 Hook（对齐今日 `AfterSuccess`） |
| `FireTaskLifecycle(...)` | Notifier/Outbox |
| `NormalizeResult` / 诊断记时 | 吸收原 Command Pipeline |
| `Sail` / `Kit` | 只读访问插槽 |

**反例：** 共同父类 `Execute` 固定 `LoadAll → Gate → Core → Hook` 且强要 Task。  
**正例：** 见 §4.3 各族 `Execute` 伪码。

### 4.2 族群基类：按钩子模式分组，并固化时序

**分组判据（拍板）：** 族群之间的本质差别 = **调用哪些钩子、以什么顺序、Context 需要什么实体**；业态（改人 / 改图 / 改实例状态）与此对齐，不是另起一套分类学。

| 族群职责 | 动词子类职责 |
|----------|--------------|
| 实现 `Execute`：装载本族环境 → 调 Gate → 调 `ExecuteCore` → 按本族清单点火 Hook/Notifier | 实现 `ExecuteCore`（写库 / 调 Runtime·Mediator） |
| 规定本族**必调 / 选调**的钩子槽位 | 提供 `Operation`、本动词成功 `EventFireType`（及 Notifier kind 等身份） |
| 注入或禁止危险能力（如 Forward 仅 Transition） | **不**再手写 Gate/AfterSuccess 样板 |
| 各族 `ExecuteCore` 使用**本族 Context 类型**（见 §4.5） | **不**共用一个含 Forward 的胖环境袋 |

动词子类若需「跳过某钩子」，须走族群提供的显式扩展点（如 `bool SkipTaskLifecycle`，**白名单宜极短**），**禁止**复制一套旁路 `Execute`。

#### 开族群门槛

开新 `*ActionBase` 必须同时满足：

1. **钩子模式陈述**：写出与现族不同的调用清单/顺序/Context 实体（一张小表）。  
2. **业态对齐**：说明改的是谁的状态，且无法在不破坏现族时序的前提下塞进去。  
3. **文档入库**：改本文 §4 树图 + 该族钩子时序表；禁止只在代码里出现新基类。

**禁止**：「实现方便」「少写 if」「对齐外来类名」。

### 4.3 初始三族（钩子时序 + 业态）

下列时序为**概念固化**；具体 `EventFireType` 名以动词身份为准（Transfer→`OnProcessTransferred`，SendBack→`OnProcessSendBacked`…）。立项落地时与现网 `WorkflowService` 对齐，缺的枚举再补。

#### 4.3.1 `AssigneeActionBase` — 待办人/办理人变化

| 项 | 约定 |
|----|------|
| **业态** | 实例仍运行、当前 BPMN 活动通常不变；改 Task / `AssignedUser*` |
| **Context** | 需要 Task + ActivityInstance + ProcessInstance |
| **禁止** | **不注入** `ContinueForward` / Runtime 推进能力 |
| **参考** | 今日 `TransferProcess` |
| **候选动词** | Transfer、RemoveAssignee、ChangeAssignee、Delegate、Urge（轻量） |

**固化时序（概念）：**

```text
AssigneeActionBase.Execute
  1. LoadAssigneeEnv（Task 必有）
  2. TryGate(Operation)            // 必调
  3. ExecuteCore()                 // 动词子类：只改人/待办
  4. OnFireFlowHook(SuccessEvent)  // 必调；事件码由动词提供
  5. FireTaskLifecycle(...)        // 本族默认必调（待办变更旁路）；Urge 等可用族内开关收窄
```

```text
// TransferAction : AssigneeActionBase  — 子类几乎只剩：
Operation => Transfer
SuccessEvent => OnProcessTransferred
ExecuteCore(AssigneeActionContext) => TaskManager.Transfer(...)
```

#### 4.3.2 `TransitionActionBase` — 流程发生流转

| 项 | 约定 |
|----|------|
| **业态** | 活动实例集合或「当前办理位置」变化（含加签拓扑） |
| **Context** | Task/AI/PI + 通常需要 ProcessModel / Runtime 袋 |
| **可注入** | Runtime/Mediator 外壳；Forward/SendBack 等**仅本族**可见的辅助 |
| **代表动词** | Run、SendBack、Withdraw、Resend、Reject、Jump、SignForward… |
| **SignForward** | 归本族（Mediator + 拓扑变化），**不**进 Assignee |

**固化时序（概念）：**

```text
TransitionActionBase.Execute
  1. LoadTransitionEnv（含 Runtime 创建所需）
  2. TryGate(Operation)            // 必调
  3. ExecuteCore(TransitionActionContext)  // 动词子类；ctx 可含本族 Forward/Runtime 辅助
  4. OnFireFlowHook(SuccessEvent)  // 必调；如 OnProcessContinued / SendBacked / SignForwarded…
  5. （TaskLifecycle）             // 由 Mediator/TaskManager 路径内既有通知承担时，族内注明「不在此重复」；
                                   // 若某动词仅 Service 层建待办，则在此时序补 FireTaskLifecycle
```

> 说明：今日部分待办通知在 Mediator/`TaskManager` 内触发——Transition 族落地时须**对账**，避免 Hook 双响；原则是「族群时序拥有 Service 级 AfterSuccess；路径内 Notifier 不删，只禁止在 Action 再抄一份 AfterSuccess」。

#### 4.3.3 `LifecycleActionBase` — 流程实例状态变化

| 项 | 约定 |
|----|------|
| **业态** | 改 `ProcessState`（挂起/恢复/终止/作废/取消/管理关闭…） |
| **Context** | **以 ProcessInstance 为主**；不要求当前用户 Task |
| **代表动词** | Suspend、Resume、Terminate、Discard、Cancel；管理向 Close |
| **勿混** | 人点 Suspend ≠ [WaitToken Resume](./草案-挂起与统一Resume.md) |

**固化时序（概念）：**

```text
LifecycleActionBase.Execute
  1. LoadLifecycleEnv（PI 必有；Task 可选）
  2. TryGate(Operation)            // 必调（今日部分短路径缺失，迁入时补齐）
  3. ExecuteCore(LifecycleActionContext)  // 动词子类：ProcessInstanceManager.*；无 Forward
  4. OnFireFlowHook(SuccessEvent)  // 必调；缺枚举则立项时补 OnProcessSuspended 等
  5. FireTaskLifecycle             // 本族默认不调；若终止需批量取消待办通知，由 Core 或族内显式步骤处理并写进时序表
```

### 4.4 枚举与可选元数据

现行 `FlowOperation` 已含 `Run`…`Transfer`，缺 Suspend/减签等。

| 方案 | 做法 |
|------|------|
| **A. 扩 `FlowOperation`**（倾向） | 新动词直接加枚举；与现 Gate 一致 |
| **B. 另立 `FlowActionKind`** | 仅当需要与 Hook 操作码长期分叉时 |

**必须：** 有子类必有稳定枚举。  
**建议（非必须）：** 枚举旁挂只读标签，如 `ActionFamily = Assignee|Transition|Lifecycle`、`RequiresTask`，供审计/Metrics；**标签不能替代开族门槛**，只作观测。

### 4.5 已拍板：事务/锁归属 · Forward 硬约束

#### 4.5.1 事务与实例锁 → 仅 Service（H 壳）

| 项 | 约定 |
|----|------|
| **归属** | `CommitOnSuccess` / `RunVerbAsync`（或收成 `RunAction`）留在 **`WorkflowService`** |
| **Action** | 构造或 `Execute(kit, runner)` **只消费已打开的 `SQLBuilder kit`**；内部禁止再开事务、禁止再 `Acquire` 实例锁 |
| **寿命** | Service = H；Action = 每请求 B 袋（用毕即弃，禁止扣 Runner） |
| **嵌套** | 外传 `kit` 的现有路径继续有效；避免 Action 自管事务导致双事务 |
| **单测** | 测试可自开事务再调 `action.Execute(kit, …)`；**生产入口永远经 Service** |

```text
XxxProcess / XxxProcessAsync
  → CommitOnSuccess / RunVerbAsync          // 事务 + 实例锁 + ct（Service）
       → new XxxAction(sail, kit, runner).Execute()
            → 族群：Gate → ExecuteCore(本族 Context) → Hook…
```

#### 4.5.2 图推进 → 仅 Transition 族（类型面硬约束）

| 档 | 做法 | 阶段 |
|----|------|------|
| **A** | `ContinueForward` / Runtime 推进辅助仅 `TransitionActionBase` 的 `protected`；Assignee/Lifecycle **无此类方法** | **A1 必做** |
| **B** | 各族 `ExecuteCore` 使用不同 Context：`AssigneeActionContext`（Task/AI/PI + 待办变更能力，**无** `IGraphAdvance`）、`TransitionActionContext`（可含 Forward/Runtime）、`LifecycleActionContext`（PI 为主） | **A1 推荐与 A 同做** |
| **C** | `ContinueForwardCurrentNode` 保持 `internal`；仅 Transition 可达（同程序集/友元） | A3 有余力再做 |

**禁止：** 三族共用含 Forward 的胖 Environment；靠文档/PR「禁止调用」；Assignee 里 `if (forward != null)`。

## 5. 与 Command Pipeline：吸收后废弃并列

原 [草案-命令执行管道.md](./草案-命令执行管道.md) 的痛点（入口样板、诊断槽、Gate 适配器）与本骨架**同一块 DRY**。  
已拍板：

| 原管道槽位 | 落点 |
|------------|------|
| Exception / Result 规范化 | Service 外壳 + 父类 `NormalizeResult`（按需） |
| Diagnostics / Metrics | 父类 protected 记时/埋点；可由族群 `Execute` 调用 |
| GateAdapter | 父类 `TryGate`；**由族群 `Execute` 按时序调用**（非动词子类手写） |
| Core | 动词子类 `ExecuteCore` |
| 事务 / 锁 | **仅 Service**（§4.5.1）；**不**进管道/骨架自管 |
| （曾设想的洋葱叠加） | **不做**；禁止 `Pipeline(action.Execute)` 双层 |

管道文地位改为：**历史引子 / 已并入动作骨架，不再单独立项**。其「学外壳不换心、不替代 AddGate」红线仍然有效，改由本文 §3 继承。

```text
WorkflowService.XxxProcess
  → CommitOnSuccess / RunVerbAsync   // 事务 + 锁（Service）
       → Action.Execute()            // 族群固化钩子时序
            → TryGate → ExecuteCore(族 Context) → OnFireFlowHook → （族定）TaskLifecycle
```

| 机制 | 层 | 与骨架关系 |
|------|-----|------------|
| **动作骨架（本文）** | 命令扩展主轴 | 枚举 + 族群时序 + 动词 Core |
| **Command Pipeline** | — | **吸收废弃并列** |
| **Gate / Hook / Notifier** | 产品横切 | 父类提供调用能力；**族群固化何时调用** |
| **事务 / 实例锁** | Service（H） | Action 无事务语义（§4.5.1） |
| **Assignee Resolve/Leave** | 算人 / 离开 | 仅 Transition 族 Core 内（如 Approve）调用 |
| **Host Handler** | 按钮 → API | 仍调 `XxxProcess`；内部改派 Action |

## 6. 扩展配方

**Assignee 族：减签**

1. `FlowOperation` + 成功 `EventFireType`（如 `OnAssigneeRemoved`）补齐。  
2. `class RemoveAssigneeAction : AssigneeActionBase`：**只写** `ExecuteCore`（校验 → 取消待办 → 刷新 AssignedUser*）；Gate/Hook/Lifecycle 走族群时序。  
3. `RemoveAssigneeProcess` 薄壳。  
4. Host Handler + 码表（有命令后再进办理条）。

**Lifecycle 族：挂起** — `SuspendAction` 只写 `ProcessInstanceManager.Suspend`；Gate/成功 Hook 由 `LifecycleActionBase.Execute` 固化调用。

**Transition 族：SendBack** — Core 委托现有 `NodeSendBack*`；删 Service 内重复的 BuildGate/AfterSuccess 三段。

**验收直觉：** 新动词 PR **几乎只有 Core + 枚举身份**；审查项含「枚举 + 正确族群 + 未私自改族群时序 + Core 上下文无越界 Forward + 未在 Action 内开事务/加锁」。

| 阶段 | 内容 | 验收直觉 |
|------|------|----------|
| **A0 本稿** | 文档：工具箱 + 族群钩子时序 + 开族门槛 + 管道吸收 + §4.5 拍板 | 评审认同 |

## 8. 开放问题（留给立项）

### 8.1 已拍板（勿再议）

| 题 | 结论 | 见 |
|----|------|-----|
| 事务 / 实例锁 | **仅 Service**；Action 只吃 `kit` | §4.5.1 |
| Forward 硬约束 | **仅 Transition 族**；各族不同 Core Context；A1 做 A+B 档 | §4.5.2 |

### 8.2 仍开放

1. **注册表 vs switch**：是否 `UseAction<T>`。  
2. **Urge / Copyto**：默认不新开 Notify 族；Urge 的族内开关白名单。  
3. **Close** 归族判定表；现行动词→族群对照表（Withdraw/Reject/…）。  
4. **Transition 与路径内 Notifier 对账表**（避免双响）——A3 前置。  
5. Lifecycle 成功事件枚举补齐（Suspended/Resumed/…）。  
6. WaitToken Resume 与人点 Suspend 文档互链。
