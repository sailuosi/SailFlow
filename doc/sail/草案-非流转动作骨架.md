# 草案 · 动作骨架（族群基类 + 共同父类）

> 状态：**草案 / 未立项**（2026-11-14；2026-11-15 修订父类与族群口径）  
> 用途：把「办理动词」从 `WorkflowService` 逐方法样板，收敛为**可继承的动作骨架**——共同父类提供**可复用、由子类显式调用**的横切能力（Gate/Hook/事件/Notifier/诊断等），各族群基类按**业态**收口；新动词 = 枚举 + 落在正确族群的子类。  
> 动机：中国式 OA 大量动词只改办理人/待办，另一些改图位置，还有一些改流程实例状态；横切调用不该每动词复制，但也不该由父类臆造统一时序硬跑一遍。  
> 关联：[特性说明-中国式OA审批要素.md](./特性说明-中国式OA审批要素.md) · [开发手册-OA命令执行链路.md](./dev/开发手册-OA命令执行链路.md) · [特性设计-回调与事件.md](./特性设计-回调与事件.md) · [草案-命令执行管道.md](./草案-命令执行管道.md)（**已吸收，不再单独立项**） · [特性说明-引擎能力基线.md](./特性说明-引擎能力基线.md) · [todo-产品缺口.md](./todo-产品缺口.md)

**简称「动作骨架」**（文件名仍含「非流转」：历史动机）。正文以**多族群**为准，初始清晰的三族见 §4。

---

## 1. 一句话

**新增一个办理特性 ≈ 新增一个操作枚举值 + 一个落在既有族群上的动作子类。**  
父类不假设「一定有 Task / 一定要 Gate / 一定要 Hook」；只提供 `protected` 复用点（如 `TryGate`、`OnFireFlowHook`）。**是否调用、何时调用由子类（或族群基类）写明。**  
命令入口 DRY 与诊断槽**并入本骨架**，不再并行推进 [草案-命令执行管道.md](./草案-命令执行管道.md)。

---

## 2. 问题

今日事实（见 OA 命令手册）：

| 路径 | 代表动词 | 横切怎么挂 |
|------|----------|------------|
| Mediator / Runtime | Run、SendBack、Withdraw、SignForward… | 各 `Execute*Core` 内手写 `BuildGateContext` + `TryGate` + `AfterSuccess` |
| Manager 短路径 | Transfer、Terminate、Suspend… | 有的挂 Gate，有的直接 `bool`，样板不一致 |

痛点：

1. **同业态动词扩不动**：减签 / 改派等本应仿 Transfer，却继续复制 Gate/Hook 样板或漏挂。  
2. **业态未类型化**：只改待办人、改图位置、改流程状态三套前置与写库面不同，却挤在同一 Service 文件里靠自觉。  
3. **横切复制 ≠ 需要统一强制流水线**：需要的是「少复制调用」，不是父类替所有动词排好 Gate→Core→Hook 且假定环境齐全。  
4. **与 Command Pipeline 草案抢同一块 DRY**：两案并存易双重 Gate；已拍板**吸收管道、废并列立项**（见 §5）。

Assignee 管道（Resolve / Leave / EmptyAction）解决的是**通过时谁能离开**，**不是**办理动词骨架——二者正交，勿混。

---

## 3. 边界（红线）

| 做 | 不做 |
|----|------|
| 共同父类提供 **protected 复用方法**；子类/族群**显式**决定调用点 | **不**在父类 `Execute` 里假定环境字段齐全并强行跑完整横切链 |
| 用枚举 + 族群内子类表达「新特性」 | **不**为每个按钮再造一套 Host 合同以外的引擎 API 风格 |
| 开新族群必须书面阐明**业态不同、行为确实不同** | **不**因「这个按钮感觉特殊」就新开 `*ActionBase` |
| 族群内可提供更具体的辅助（如流转族才注入 Forward 能力） | **不**用骨架替代 `AddGate` / `AddHook` / Notifier 产品语义 |
| 吸收原 Command Pipeline 的诊断/结果规范化进父类复用点 | **不**再单独立项洋葱中间件与骨架「叠加」 |
| 先文档 + 1～2 动词试点（建议 Transfer） | **不**空壳上码表；无引擎命令不得进办理条 |
| | **不**把 UserTask Leave / Assignee Resolve 塞进动作骨架 |

## 4. 类型分层（目标形状，非 API 定稿）

命名待立项敲定；下文用概念名固定职责。

```text
                         FlowActionBase（共同父类）
                         │  只提供可复用 protected 行为
                         │  不假设 Task/AI/PI 必有
                         │  自己不擅自 OnFire* / TryGate
                         │
     ┌───────────────────┼───────────────────┐
     │                   │                   │
AssigneeActionBase  TransitionActionBase  LifecycleActionBase
（待办人/办理人变化族） （流程发生流转族）   （流程实例状态变化族）
 同节点改人/加减待办     图位置/拓扑变化      结束、冻结、恢复…
 不注入 ContinueForward  可提供 Forward 辅助  常无当前 Task
     │                   │                   │
 Transfer / 减签 /       Run / SendBack /    Suspend / Resume /
 改派 / 委派 / 催办* …   Withdraw / Reject / Terminate / Discard /
                         Jump / SignForward… Cancel / Close* …
```

\*催办偏旁路通知：若几乎不改库、只打 Notifier，立项时可挂本族「轻量子类」或另议；**默认先挂 Assignee 族**（针对当前待办人），禁止无论证开第四族。  
\*Close 若产品语义是「管理结束实例」而非图内走到 End，归 **Lifecycle**；若走完结节点 Mediator，归 **Transition**——以业态为准，不抠类名。

### 4.1 共同父类 · `FlowActionBase`

**定位：工具箱，不是专制流水线。**

父类**可以**提供一个很薄的 `Execute` 入口（事务/锁/异常→`WfExecutedResult` 规范化），但 **Gate / Hook / Notifier / 装载 Task** 均不在父类里无条件触发。

| 复用点（概念名，protected） | 说明 |
|-----------------------------|------|
| `Operation` / 枚举身份 | 供 Gate 白名单、审计、Metrics；子类必给 |
| `BuildHookContext(...)` | 组装 `FlowHookContext`；调用方传入已有的 PI/AI/Task 等，**缺什么由调用方决定** |
| `TryGate(...)` | 适配现有 `FlowCapabilityPipeline.TryGate`；Reject 写法统一 |
| `OnFireFlowHook(...)` | 成功/指定 `EventFireType` 时唤起 Hook；**父类不调用，子类在自己的时序里调用** |
| `FireTaskLifecycle(...)` | Notifier/Outbox 入口复用 |
| `NormalizeResult` / 诊断记时 | 吸收原 Command Pipeline 的 Exception/Result、Correlation、Metrics |
| `Sail` / `Kit` 只读 | 经构造或环境袋访问插槽；禁止在动作里 `new` 基础设施 |

**反例（禁止）：** 父类 `Execute` 固定 `LoadAll → TryGate → ExecuteCore → OnFireFlowHook`，并要求 Environment 必含 Task——这会逼 Suspend/Terminate 造假数据或到处 Override。

**正例：**

```text
// TransferAction（Assignee 族）伪码
result = TryGate(ctxWithTask, Operation.Transfer);
if reject → return;
TaskManager.Transfer(...);
OnFireFlowHook(OnProcessTransferred, ...);
FireTaskLifecycle(Entrusted, ...);

// SuspendAction（Lifecycle 族）伪码
result = TryGate(ctxWithPiOnly, Operation.Suspend);  // 无 Task 的 HookContext
if reject → return;
ProcessInstanceManager.Suspend(...);
OnFireFlowHook(OnProcessSuspended, ...);  // 若产品需要；不需要则不调
```

同一套 `TryGate` / `OnFireFlowHook`，**零强制、少复制**。

### 4.2 开族群门槛（硬纪律）

允许的族群数量**不是**封闭为 2 或 3；但 **开新 `*ActionBase` 必须同时满足**：

1. **业态陈述**：用一两句话说明与现有各族的业务对象不同（改谁的状态？）。  
2. **行为差异**：前置装载、可调用的危险能力（如 `ContinueForward`）、成功后典型事件，与现族冲突或强行塞入会导致大量空 Override。  
3. **文档入库**：改本文 §4 树图 + 代表动词表；禁止只在代码里出现新基类。

**禁止**的开族理由：「实现方便」「想少写几个 if」「和 AntFlow 类名对齐」。

### 4.3 初始三族（业态锚点）

#### 4.3.1 `AssigneeActionBase` — 仅（或主要）待办人 / 办理人变化

| 约定 | 含义 |
|------|------|
| **业态** | 流程实例仍在跑、BPMN 当前活动通常不变；变的是 Task 行与 `AssignedUser*` |
| **禁止** | 族群**不注入** `ContinueForward`；子类拿不到图推进能力（硬约束优于审查清单） |
| **参考** | `TransferProcess` → `TaskManager.Transfer`（原待办 `Closed` ≠ `Completed`） |
| **候选动词** | Transfer、RemoveAssignee（减签）、ChangeAssignee、Delegate、Urge（轻量） |

#### 4.3.2 `TransitionActionBase` — 流程发生流转（图位置 / 活动拓扑变化）

| 约定 | 含义 |
|------|------|
| **业态** | 推进、退回、撤回、跳转、驳回落点、加签复杂类型等——活动实例集合或「当前办理位置」变化 |
| **可提供** | Runtime/Mediator 外壳辅助；**可选**的 Forward/SendBack 路径辅助（由子类显式调用） |
| **代表动词** | Run、SendBack、Withdraw、Resend、Reject、Jump、SignForward… |
| **SignForward** | 归本族：走 Mediator、改活动/子活动拓扑；即使不立刻交到「下一 BPMN 用户节点」，业态仍是流转侧，**不**塞进 Assignee 族 |

#### 4.3.3 `LifecycleActionBase` — 流程实例自身状态变化

| 约定 | 含义 |
|------|------|
| **业态** | 改 `ProcessState`（挂起/恢复/终止/作废/取消/管理关闭等），不是「换一批办理人」，也不是「沿图画笔走一格」 |
| **典型** | 常无当前用户 Task；环境以 ProcessInstance 为主 |
| **代表动词** | Suspend、Resume、Terminate、Discard、Cancel；（管理向）Close 若属实例终态也归此 |
| **勿混** | 与 [草案-挂起与统一Resume.md](./草案-挂起与统一Resume.md) 的 WaitToken（自动节点等待）**不是**同一 Action；人点 Suspend ≠ Bookmark Resume |

### 4.4 枚举与可选元数据

现行 `FlowOperation` 已含 `Run`…`Transfer`，缺 Suspend/减签等。

| 方案 | 做法 |
|------|------|
| **A. 扩 `FlowOperation`**（倾向） | 新动词直接加枚举；与现 Gate 一致 |
| **B. 另立 `FlowActionKind`** | 仅当需要与 Hook 操作码长期分叉时 |

**必须：** 有子类必有稳定枚举。  
**建议（非必须）：** 枚举旁挂只读标签，如 `ActionFamily = Assignee|Transition|Lifecycle`、`RequiresTask`，供审计/Metrics；**标签不能替代开族门槛**，只作观测。

## 5. 与 Command Pipeline：吸收后废弃并列

原 [草案-命令执行管道.md](./草案-命令执行管道.md) 的痛点（入口样板、诊断槽、Gate 适配器）与本骨架**同一块 DRY**。  
已拍板：

| 原管道槽位 | 落点 |
|------------|------|
| Exception / Result 规范化 | `FlowActionBase` 薄入口或 `NormalizeResult` |
| Diagnostics / Metrics | 父类 protected 记时/埋点；子类不必复制 |
| GateAdapter | `TryGate(...)` protected；**由子类显式调用** |
| Core | 各族群 / 动词子类本体 |
| （曾设想的洋葱叠加） | **不做**；禁止 `Pipeline(action.Execute)` 双层 |

管道文地位改为：**历史引子 / 已并入动作骨架，不再单独立项**。其「学外壳不换心、不替代 AddGate」红线仍然有效，改由本文 §3 继承。

```text
WorkflowService.XxxProcess
  → new XxxAction(...).Execute()     // 薄入口：事务/锁/异常规范化（可选）
       → 子类自行：TryGate? → 写库/Mediator → OnFireFlowHook? → FireTaskLifecycle?
```

| 机制 | 层 | 与骨架关系 |
|------|-----|------------|
| **动作骨架（本文）** | 命令扩展主轴 | 枚举 + 族群子类 |
| **Command Pipeline** | — | **吸收废弃并列** |
| **Gate / Hook / Notifier** | 产品横切 | 经父类 protected **按需**唤起 |
| **Assignee Resolve/Leave** | 算人 / 离开 | 仅 Transition 族 Approve 等路径内部调用 |
| **Host Handler** | 按钮 → API | 仍调 `XxxProcess`；内部改派 Action |

## 6. 扩展配方

**Assignee 族：减签**

1. `FlowOperation` 增加 `RemoveAssignee`。  
2. `class RemoveAssigneeAction : AssigneeActionBase`：校验 → 取消待办 → 刷新 AssignedUser*；需要处 `TryGate` / `OnFireFlowHook`。  
3. `RemoveAssigneeProcess` 薄壳。  
4. Host Handler + 码表（有命令后再进办理条）。

**Lifecycle 族：挂起** — `SuspendAction : LifecycleActionBase`，无 Task 的 Context 调 `TryGate`，再 `ProcessInstanceManager.Suspend`。

**Transition 族：SendBack** — Core 委托现有 `NodeSendBack*`；横切调用点集中，删 Service 内重复三段。

**验收直觉：** 新动词 PR 不复制 Gate/Hook 样板代码；审查项含「枚举 + 正确族群 + 未违规开族 + 危险能力未越界（Assignee 无 Forward）」。

## 8. 开放问题（留给立项）

1. **薄 `Execute` 是否强制事务/锁**：全放 Service，还是基类可选 `using` 范围？  
2. **Action 寿命**：每请求 `new`（对齐 B 袋） vs 无状态；禁止扣 Runner。  
3. **注册表 vs switch**：是否 `UseAction<T>`；与 Host Handler 是否重复。  
4. **Urge / Copyto**：引擎命令 vs Host 旁路；默认不新开 Notify 族。  
5. **Close**：Lifecycle vs Transition 的产品判定表。  
6. WaitToken Resume 与人点 Suspend 的文档互链是否在 Lifecycle 试点时一并写清。
