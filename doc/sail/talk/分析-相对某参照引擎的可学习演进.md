## 0. 结论先行

| 维度 | 结论 |
|------|------|
| **总原则** | 学某参照引擎的「**引擎如何被宿主稳定消费**」（业务同事务回写、故障可恢复、能力版本、一致性套件、设计器/办理条门禁）；**不学**其薄办理面、非 BPMN、产品故意不开放退回/催办等收窄 |
| **Sail 已强、不必改弦** | 中国式动词面、Leave×Resolve 正交、BPMN+`sf:`、Gate/Hook/Outbox、`UseXxx` 分层、冷热归档 |
| **某参照引擎明显强、Sail 应补** | 审批业务一等 SPI、结论回调失败→可 Retry、Conformance 挂任意存储、Capability 版本、多实例租约领导权、发布校验路径级诊断、通知 receipt 去重 |
| **关系** | 二者不在同一抽象层：某参照引擎 = 平台内嵌引擎+审批产品闭环；Sail = 可嵌入引擎+仓外 Host。对照目的是**增强可嵌入性**，不是合并代码或换引擎 |
| **首推路径** | **A 契约（业务 SPI + Outcome 故障语义 + CapabilityCatalog）→ B 验证（conformance + 码表漂移门禁）→ C 运行时（Lease + Ambient 事务样板）→ D 体验契约（校验路径 / 可选 Trail·Receipt）** |
| **禁止** | 用 `Any/All/Sequential` 取代 Leave 五型；为对齐某参照引擎砍 Script/BPMN/沟通/退回两维；把参照应用实体表塞进 pure |

## 1. 对照对象与边界

### 1.1 某参照引擎两层（勿混称）

```text
参照产品面（可选工作流模块）
  定义/实例操作 · 组织受理人 · 审批中心 · 业务 Handler · 通知 · 设计器
        │ requires 参照侧 execution 能力
        ▼
参照引擎内核
  契约+引擎 · 数据库 Provider（分区表+poller）· 内存 Provider · 一致性套件
```

| 层 | 落点（泛称） | 职责摘要 |
|----|----------|----------|
| **参照引擎内核** | 工作流契约/引擎包 + 存储 Provider | 自有定义 JSON、书签、引擎/任务接口、租户分区存储 |
| **参照产品面** | 应用工作流包 + 跨包契约 + 前端模块 | 产品操作与页面；**不实现引擎内核** |

宿主恒装参照侧数据库工作流；模块开关只关产品面。

### 1.2 sailflow 一层引擎 + 仓外 Host

```text
仓外宿主
  → biz（UseBiz*）→ ext → pure（engine / assignee / …）→ mooSQL
```

产品按钮、审批中心壳、组织主数据在 **Host**；引擎承诺见能力基线，产品缺口见 `todo-产品缺口.md`。

### 1.3 本文不讨论

- 是否用 sailflow 替换某参照引擎（或反之）的迁移方案  
- 逐 API 字段映射表（若需要另开「对齐矩阵」稿）  
- Host 具体菜单/CSS

## 3. 总原则与决策过滤器

落地任一条「学」之前，过三问：

1. **是否强化可嵌入性？**（另一宿主少写胶水、少猜语义）——是则优先。  
2. **是否削弱 Leave×Resolve / 动词定型？**——是则标 **不跟** 或改成「仅 Host UX」。  
3. **是否必须进 pure？**——组织表、审批意见 UI、租户权限码默认 **Host**；pure 只留契约与可选 Provider。

**过滤器结果预设：**

| 提案类型 | 默认落点 |
|----------|----------|
| 业务 SPI、Outcome ReasonCode、CapabilityCatalog、Conformance | pure 契约 + biz/Host 默认实现 |
| Lease、Receipt、Trail、Ambient Transaction 适配 | ext 或可选包；`UseXxx` 显式启用 |
| 审批中心四页签、权限码文法、Vue 设计器 | **Host only** |
| 砍退回/沟通、改用 CompletionPolicy 取代 Leave | **不跟** |

## 4. 学习项详解

下列每项含：某参照引擎证据 → Sail 现状 → 建议形态 → 验收口径 → 非目标 → 优先级。

优先级：**P0** 契约正确性；**P1** 可嵌入门槛；**P2** 体验/运维；**P3** 可延后产品化。

### 4.1 审批业务一等 SPI（学 · P0）

> 场景化说明见：[专题-审批业务门面.md](../OA/专题-审批业务门面.md)（现行）；讨论归档：[仿真-采购申请与审批业务门面-分析归档.md](../done/仿真-采购申请与审批业务门面-分析归档.md)。  
> **讨论收敛（2026-11-22）：** 糖落点 **`sailflow.biz`**；失败只保留 **一种唤起**，副作用由业务自理；终态按 **是否到达结束节点** 分为 `OnFinish`（正常结束，Outcome 区分通过/驳回）与 `OnAborted`（撤销结束）；不把某参照引擎故障态+重试 做成门面默认承诺。

#### 某参照引擎侧证据

- 契约：参照侧审批业务 Handler（`OnTaskCompletingAsync` / `OnChangingAsync` / `结论回调Async` / `OnAbortedAsync` / `GetFormDataAsync`）+ `WorkflowBusinessDescriptor`（业务码、单据组件、允许结论、缺省 参照侧定义 JSON）。  
- 登记：`AddWorkflowBusiness<T>()`；同业务码重复 → **启动失败**。  
- 服务：参照侧业务运行时 Start / Withdraw / Progress（进度一次 ≤1000 单据）。  
- 结论：顶层实例走到带 `Outcome` 的 End → 参照侧结论处理器 **同事务**回调；失败 → 结束节点故障、实例 Faulted，修好后 Retry 再回写（要求幂等）。  
- 改动前校验：转办、加签、撤回、管理员取消/终止/重试/挂起/恢复；只读失败即拒绝该项。

#### Sail 现状

- 横切已有 **Gate / Hook / Notifier** 与 FormBiz 等宿主 Handler；语义强但 **分散**，新宿主需自行拼「业务码、缺省定义、结论回写、中止回写」。  
- 无「业务描述符 + 启动核对重复」的一等产品契约。  
- FormBiz OnFinish 同事务 Kit 已有联调路径（产品缺口 H），属个案而非可引用 SPI。

#### 建议形态（讨论名，非最终 API）

在 **不替代 Gate/Leave** 的前提下，于 **`sailflow.biz`** 增加可选「审批业务」糖（与 FormBiz 合并展开；名称待定，下文称 `ISailApprovalBusiness`）：

| 成员 | 职责 |
|------|------|
| `Descriptor` | `BusinessCode`（常=流程 Code/Name）、允许结论集、缺省 BPMN/模板键、单据组件键 |
| `OnTaskCompleting` | 办理前只读校验 |
| `OnChanging` | 转办/加签/撤回/管理生命周期前校验 |
| `结论回调` / Finish | 流程到达业务结论时回写；需要同事务则用 Kit |
| **失败唤起（单一）** | 成功路径失败时只唤起一次；业务在回调内自管副作用（不在糖层并行 故障态+重试 产品语义） |
| `OnAborted` | 取消/终止/作废/发起人撤回后回写（业务自撤是否回调要写死） |
| `GetFormData` | 审批详情单据 JSON |

配套：

- `AddApprovalBusiness<T>()` / `UseApprovalBusinesses()`（biz 包）；重复 Code → 构建或启动失败。  
- `ISailApprovalRuntime.Start / Withdraw / QueryProgress`（Progress 支持业务单号批量）。  
- 与现有 Gate：**展开为 Gate 注册**，禁止第三套 if-else 堆在 Mediator。

#### 验收口径

- 新宿主仅实现一个 `ISailApprovalBusiness`（引用 `sailflow.biz`）即可跑通「发起→办理→结论回写→中止回写」样板。  
- 失败路径：业务失败唤起 **恰好一次**；无「流程已结束但单据未更新」的静默成功；无第二套必选 Retry 产品轨。  
- 重复登记 Code → 启动失败（测试覆盖）。

#### 非目标

- 不把某参照引擎「业务码必须等于定义名」写成唯一合法模型（允许 Descriptor 显式映射）。  
- 不把 SPI 塞进 NodeMediator / pure。  
- 不把 故障态+重试 做成 biz 糖的默认承诺（引擎若将来要，另专题）。

### 4.2 结论 / 副作用失败语义硬化（学 · P0）

#### 某参照引擎侧证据

- Outcome 失败停在 Faulted；Retry 再调。  
- 通知失败只打日志、不阻断流程（与业务回写分级）。  
- 对外故障文案偏消息键；细节进日志。

#### Sail 现状

- Gate 拒绝 vs 系统异常已有通道（`WfExecutedResult` / ReasonCode）。  
- Hook：`Sync` vs `AsyncOutbox`；业务回写若误挂 Outbox，会出现「流程已过、单据未写」。  
- 文档有可靠性专题，缺「审批结论回写必须 Sync 且失败可恢复」的硬条款。

#### 建议

| 副作用类型 | 建议模式 | 失败时 |
|------------|----------|--------|
| 单据结论 / 中止回写 | **Sync**（可并入调用方事务） | 推进失败或实例进入可 Retry 故障；ReasonCode 稳定 |
| 站内信 / 邮件 / Webhook | AsyncOutbox 或 Notifier | 不阻断；可重试 Drain |
| 审计轨迹 | 同事务或 Outbox（产品定） | 写清一致性等级 |

基线增补一小节：**ApprovalOutcome 不得默认 AsyncOutbox**。

#### 验收

- 单测：Outcome Handler 失败 → 无「已完成+未回写」终态。  
- 文档：与[特性说明-副作用可靠性.md](../特性说明-副作用可靠性.md)交叉引用。

### 4.3 CapabilityCatalog：活动与办理动词门禁（补 · P0）

#### 某参照引擎侧证据

- `参照侧 activity-types 目录`：设计器只放后端列出的活动（参照产品面再裁到 16 种，排除 EventGateway/Compensate/ExternalTask/Script）。  
- 方案明确：框架多出的认领/退回/催办等 **产品不开放（W4）**。

#### Sail 现状

- 办理条码表 `defaultEnable` + Host Handler；引擎命令更全。  
- 「引擎有 / 码表关 / 联调未勾」已在审计与 todo 出现，但 **缺少引擎侧可查询的统一目录 API**，设计器与办理条易漂移。

#### 建议

暴露只读目录（纯数据，无副作用），例如：

| 目录 | 内容 |
|------|------|
| 节点/扩展 | 已注册 Mediator / `sf:` 能力；依赖哪些 `UseXxx` |
| 办理操作 | `FlowOperation` → 码表 Id、默认开/关、是否需 Host Handler、成熟度 |
| Leave / Resolve | 内置 Type 列表与参数 schema 摘要 |

设计器与办理条 **只渲染目录 ∩ 宿主启用集**。CI：码表 Id 与 `FlowOperation` / `*Action` 双向扫描，防止「有按钮无命令」或「有命令文档过时」（承接审计复核纪要里的口径债）。

#### 验收

- 关闭某 `UseXxx` 后，目录不再宣称对应节点可用（或标 Unavailable+原因）。  
- 漂移扫描进入 CI（允许名单须显式、禁止默默扩大）。

#### 非目标

- 不把某参照引擎「产品永久不开放退回」学过来；Sail 默认方向是 **引擎齐 → Host 按场景打开**。

### 4.4 Conformance 套件（学 · P0）

#### 某参照引擎侧证据

- `参照引擎·一致性套件`：引擎套件 + 任务套件；参照应用在 DatabaseWorkflow + SQLite/PostgreSQL 上跑。  
- 方案把「可被框架验证」写成架构承诺。

#### Sail 现状

- `sailflow.engine.tests` 覆盖广，但偏实现细节；UAT 脚本在 Host 仓。  
- 新存储 / 新 Host 无法「挂同一套剧本」证明语义未漂。

#### 建议

新增（或从现有测试提炼）**`sailflow.conformance`**（名待定）：

| 剧本族 | 最低覆盖 |
|--------|----------|
| 流转 | Start → Run(Approve) → 结束；Reject 各 RejectMode 抽样 |
| 退回 | SendBack 目标×再发送 + Resend |
| 加签 | SignForward 前/后/并 + Leave 交互抽样 |
| Leave | Race / Collaborate / Group* / Captain 各至少一条黄金路径 |
| 空人 | R4/R10：拒绝推进 vs 锚点 Job（可标记 Host 依赖） |
| 生命周期 | Terminate / Discard；Cancel/Suspend 可标「可选」 |

约束：

- 入口只依赖 `IWorkflowService` / `SailClient` 公开面 + 可替换持久化。  
- **禁止** conformance 依赖 仓外宿主。  
- Host 可选再跑「产品码表」扩展套件。

#### 验收

- 默认 Provider + 至少一种外部库（或 SQLite）CI 全绿。  
- 破坏 Leave/退回语义的 PR 必须改 conformance 或显式版本说明。

### 4.5 能力版本与构建期 Requires（学 · P1）

#### 某参照引擎侧证据

- Feature Manifest：`Provides` / `Requires`（如 `参照侧 execution 能力版本`）。  
- 包 `Stability.Preview`。

#### Sail 现状

- `UseXxx` 显式启用优秀；缺 **能力 id + version** 机器可读声明。  
- README「暂勿生产」无「通过何套件可升 Stable」的门闸。

#### 建议

- 每个 `UseXxx` / 核心引擎声明 `Capability(id, version)`。  
- `SailClient.Build` 可校验 Host 声明的 Requires。  
- 破坏性语义（如 Leave 默认值、RejectMode）→ **升 version**，文档写迁移。  
- Stable 门闸草案：conformance 指定集 + UAT 烟雾 P1–P3 + 无「假 Async」违规。

### 4.6 Ambient 事务与发件箱对齐（补 · P1）

#### 某参照引擎侧证据

- 引擎写入并入调用方工作单元；`workflow.*` 经发件箱随提交发出。  
- 「写单据 + Start」「授予 + 结束」同事务。

#### Sail 现状

- 支持传入 `SQLBuilder kit` 的事务内调用；FormBiz 同事务有实践。  
- Outbox Drain 成熟。  
- 缺：**跨 ORM**（EF / 宿主 UoW）的标准适配与「禁止文档外新开连接写引擎表」的红线测试。

#### 建议

| 产出 | 说明 |
|------|------|
| `UseAmbientTransaction(...)` 或文档化 Kit 规则 | 三种样板：mooSQL Kit / 宿主共享连接 / 「引擎自管事务」显式模式 |
| 红线测试 | 业务失败回滚时引擎实例不得残留「已启动」 |
| 事件 | 领域事件若引出站，优先 Outbox；与 Approval Outcome Sync 分级（见 4.2） |

与[草案-引擎异步化.md](./草案-引擎异步化.md)一致：宿主 offload ≠ 引擎假 Async。

### 4.7 多实例 Lease / 领导权（学 · P1）

#### 某参照引擎侧证据

- `参照侧租约/锁表`：实例锁 + poller 领导权；租约续约；滚动发布释放领导权。  
- SQLite 须独立 LockConnection，否则自锁至超时。

#### Sail 现状

- 超时 / 自动过 / 催办依赖 **Host Job**；归档分表强。  
- 多实例下同一 `overdue` / Outbox / Timer 的互斥多靠库锁或作业框架，**引擎未提供统一 Lease SPI**。

#### 建议

可选 `ISailLeaseProvider`（ext）：

| 用途 | 键示例 |
|------|--------|
| 实例推进互斥 | `proc:{piId}` |
| Job 领导权 | `job:r10-autoapprove` / `job:outbox-drain` / `job:timer` |

默认内存/DB 实现；未 `UseLease` 时行为与今相同（单实例友好）。文档写清：多实例生产 **建议**启用。

#### 非目标

- 不强制照搬某参照引擎九表分区模型。

---

### 4.8 发布 / 校验路径级诊断（学 · P1）

#### 某参照引擎侧证据

- 发布结构校验：`errors` 键为定义 JSON 路径（如 `nodes[2].properties.Cron`）；设计器按下标标节点/边。  
- 文案按调用方语言。

#### Sail 现状

- `ValidateProcess` → `ProcessValidateResult` 可用。  
- 设计器高亮依赖 Host 解析；路径稳定性与 `sf:` 节点 id 对齐程度不一。

#### 建议

- 校验问题输出稳定定位：`activityId` / `transitionId` / BPMN xpath 或 `sf:` 扩展路径三选一写死。  
- 本地化：ReasonCode → 消息键（接 `UseLocalize`）。  
- Host 设计器只消费目录，不重新发明错误码。

---

### 4.9 批量进度与「我发起的」查询契约（补 · P1）

#### 某参照引擎侧证据

- `ProgressAsync`：业务单号批量，返回最近顶层实例 + 运行中待办节点与人。  
- 审批中心「我发起的」：顶层实例、状态过滤、运行中带等办人。

#### Sail 现状

- `WorkflowQueryService` 分页待办/实例；下一跳树 API 强。  
- 缺「按业务主键列表」的薄契约，宿主易 N+1。

#### 建议

- `QueryProgressByBizKeys(IReadOnlyList<string> keys, int max = 1000)` 一类 API（名待定）。  
- 返回：实例状态、当前活动摘要、待办人摘要、结论（若结束）。  
- 明确：**不做**权限过滤（Host 负责），引擎只按分区/数据可见性返回。

---

### 4.10 通知 Receipt 去重（学 · P2）

#### 某参照引擎侧证据

- `参照侧消息回执表`：按消息 ID 去重；90 天清理作业。  
- 竞争消费 + 至少一次投递。

#### Sail 现状

- Task Notifier 可挂；重复投递治理多在 Host/MQ。

#### 建议

- 可选 `UseNotifierReceipts`：`(messageId | piId+taskId+eventType)` 唯一；TTL 可配。  
- 与 Outbox 去重键对齐，避免双套。

---

### 4.11 可选审批轨迹投影（学 · P2）

#### 某参照引擎侧证据

- 引擎书签 ≠ 审批历史；应用表只追加：办理 / 转办 / 加签 / 抄送。  
- 「我已审批」「抄送我的」、时间线都读该表。

#### Sail 现状

- 任务/活动实例可追溯，但 Host 拼装成本高；意见字段在 `sf_task` 等。

#### 建议

- **可选**包：订阅 Hook，写入 `sf_approval_trail`（或视图约定），动作枚举与 FlowOperation 子集对齐。  
- pure **不**强制依赖该表；未 `UseApprovalTrail` 时零开销。

#### 非目标

- 不把 参照应用的 参照侧审批轨迹表 实体原样搬进引擎。

---

### 4.12 结束实例保留期与归档衔接（补 · P2）

#### 某参照引擎侧证据

- `RetentionDays` + housekeeping 周期清理已结束实例。

#### Sail 现状

- 冷热归档 / 按年冷表策略已有专题（[分析-流程运转表存储与分表策略.md](./分析-流程运转表存储与分表策略.md)）。  
- 与「热表保留窗」产品参数可再对齐某参照引擎的「配置键 + 默认作业」开箱体验。

#### 建议

- 配置键与归档作业入口写进基线「运维」节；默认仍由 Host 定时器唤起（与分表分析一致）。  
- 避免第三套清理语义与冷迁冲突。

---

### 4.13 租户 / 分区可见性写死（补 · P2）

#### 某参照引擎侧证据

- 平台四表 + 租户四表 + 租约；平台定义租户不可见；业务缺省定义按分区各发一份。  
- 无租户上下文则查不到租户数据。

#### Sail 现状

- 组织 schema 不进引擎（正确）。  
- 「定义是否跨租户共享」多由 Host 表设计决定，**引擎基线未强制陈述**，易在多租户宿主上踩坑。

#### 建议

基线增「分区语义」一节（即使首版实现是 Host 过滤）：

| 问题 | 必须回答 |
|------|----------|
| 流程定义是否按租户隔离？ | 是/否/可选 Provider |
| 平台模板如何下发到租户？ | 复制发布 / 引用 / 禁止 |
| 待办查询是否跨租户？ | 禁止（默认） |

实现可仍在 Host；**语义不得各宿主各猜**。

---

### 4.14 算人产品开关对照（补 · P2，不改 Leave）

#### 某参照引擎可吸收的「开关名」

| 开关 | 含义 | 与 Sail |
|------|------|---------|
| `ExcludeStarter` | 受理人排除发起人 | Resolve 后置 Filter 或内置 Filter；建议一等配置项 |
| `EmptyAssigneeStrategy` | Fallback / AutoApprove / AutoReject | 对齐 R10 EmptyAction；todo 已列「整单 Reject」选项 |
| `ApprovalThreshold` | 会签人数或百分比 | 与 Collaborate `completeRate` **文档对照表**，避免两套说法 |
| `CcRules` | 抄送规则 | Sail 抄送已独立通道；规则解析可产品化 |

#### 不跟

- 用 CompletionPolicy 三档取代 Race/Collaborate/Group/Captain。  
- SignTogether 零人自动过（Sail 硬拒；保持）。

### 4.15 Cancel / Suspend 等管理向产品化（补 · P3）

#### 某参照引擎

- 实例 `suspend` / `resume` / `cancel` / `terminate` / `retry` / `signal` 已进 参照产品面操作与权限码（执行类 vs 更新类权限分权 分权）。

#### Sail

- 引擎 Lifecycle 齐；码表暂缓（todo）。  
- 学的是 **「管理向与办理条分权」**，不是立刻全开按钮。

#### 建议

- 产品拍板后：管理 API / 权限与办理条码表分离（对标某参照引擎execute/update）。  
- 与[草案-挂起与统一Resume.md](./草案-挂起与统一Resume.md)一并收口，避免 WaitToken Resume 与 Suspend 语义混淆。

## 5. 刻意不跟（反模式清单）

| 某参照引擎选择 | 为何 Sail 不跟 | 若业务要类似能力 |
|------------|----------------|------------------|
| 产品不开放退回/催办/认领/跳转 | 差异化主战场；审计亦显示 OA 侧常弱在接线而非模型 | Host 打开码表 + conformance |
| 无 Script；设计器无 EventGateway/Compensate/ExternalTask | BPMN 扩展与自动节点是卖点 | 用 CapabilityCatalog 标依赖，而非删除 |
| 参照侧定义 JSON 非 BPMN | 迁移成本高、生态差 | 保持 BPMN；仅学校验诊断 UX |
| CompletionPolicy 取代正交 Leave | 组抢办/队长无法一等表达 | 文档对照表即可 |
| 审批轨迹强制应用实体 | 污染 pure | 可选 Trail 包 |
| 模块关仍装引擎表 | Sail 可用 UseXxx 真正不装 | 保持显式启用 |
| 对外只暴露异常类型名 | 可学「不泄细节」，但应用 ReasonCode 本地化而非类型名 | 见 4.2 / 4.8 |

另见[存疑参考功能点.md](./存疑参考功能点.md)：外来「承办」等 **不默认纳入**。

## 8. 候选接口草图（仅讨论，非承诺）

> 命名空间/程序集归属未定；用于对齐评审，**禁止**直接当已实现 API。

```csharp
// 讨论稿伪代码
public interface ISailApprovalBusiness
{
    SailApprovalDescriptor Descriptor { get; }
    Task<GateDecision> OnTaskCompletingAsync(SailApprovalTask ctx, CancellationToken ct);
    Task<GateDecision> OnChangingAsync(SailApprovalChange ctx, CancellationToken ct);
    Task 结论回调Async(SailApprovalOutcome ctx, CancellationToken ct); // 失败抛或返回错 → 可 Retry
    Task OnAbortedAsync(SailApprovalAborted ctx, CancellationToken ct);
    Task<string> GetFormDataAsync(string bizKey, CancellationToken ct);
}

public sealed record SailApprovalDescriptor(
    string BusinessCode,
    IReadOnlyList<string> AllowedOutcomes,
    string? DefaultProcessCode,
    string? FormComponentKey);

public interface ISailCapabilityCatalog
{
```
