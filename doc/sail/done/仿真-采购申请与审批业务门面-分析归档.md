## 0. 结论先行

| 问题 | 答 |
|------|----|
| 业务场景本质是什么？ | **一张会变状态的业务单据**，一生必须与流程实例强一致（提交、审批中、退回改、转办约束、通过/驳回/作废、列表进度） |
| 不是什么？ | 不是「再发明会签/退回」；图语义仍归引擎 |
| 门面解决什么痛？ | **场景拼装成本**（FormBiz+Gate+Hook+Progress+缺省定义），不是补引擎能力缺口 |
| 推荐落地 | 糖在 **`sailflow.biz`**：一个 `PurchaseApprovalHandler`（或扩 FormBiz）+ `UseApprovalBusiness` 展开注册；与请假 FormBiz **同构放大** |
| 失败 | **一种失败唤起**交给业务；不在糖层做第二套引擎故障态产品 |
| 终态 | **结束节点 → OnFinish**；**否则 → OnAborted（撤销结束）**；Finish 内再用 Outcome 区分通过/驳回 |
| 与某参照引擎 | 学「一个业务一个类」的 DX；终态二分接近其结论回调 vs Aborted；不照搬故障态+重试 |

## 1. 产品故事：物资采购申请

公司要上线「物资采购申请」：

1. 员工填申请单（品名、金额、供应商意向）。  
2. 金额 ≤ 5000：直属主管审批即可。  
3. 金额 > 5000：主管通过后再到财务会签。  
4. 任一环**驳回结束** → 单据「已驳回」，可改后再提（新实例或重提，产品另定）。  
5. 主管可**退回**给申请人改金额（**不是**终态驳回）。  
6. 审批中财务可**转办**给另一财务（须仍是财务角色）。  
7. 全部通过 → 业务表 `Status=已通过`，下游采购系统才能下单。  
8. 申请人可在「审批中」**撤回**；管理员可**作废**。  
9. 列表要显示：审批中 / 退回修改 / 已通过 / 已驳回 / 已撤回 / 已作废，并带当前待办人。

约定仿真键：

| 字段 | 值 |
|------|-----|
| `BizChannel` / FormCode | `purchase` |
| `BizPK` | `PO-2026-001` |
| 业务表 | `biz_purchase`（示意） |
| 流程 | BPMN：开始 → 主管 →（金额网关）→ 财务会签? → 结束 |

## 2. 业务要 vs 引擎做 vs 门面做

```text
【业务开发者只想维护这一类】
PurchaseApprovalHandler
  OnSubmit / OnStarted     → 落单、挂实例 Id
  OnCompleting             → 同意前校验
  OnChanging(Transfer…)    → 转办合法性
  OnSendBack               → 退回修改态
  OnConsent                → 可选进度文案
  OnFinish                 → 已通过 / 已驳回终态
  OnAborted                → 作废 / 撤回
  GetFormData              → 审批页单据
  Progress                 → 列表批量进度

【门面在启动时展开成】
  FormBiz 注册(purchase)
  + Gate(Match BizChannel=purchase)
  + Sync Lifecycle Hook → OnFinish
  + Dispatcher 成功后 → Consent/Back/Cancel
  （引擎命令、Leave、BPMN 条件分支仍是流程图的事）
```

| 关注点 | 业务要 | 引擎做 | 门面做 |
|--------|--------|--------|--------|
| 条件分支（金额） | 规则说清 | Decision/网关 + 变量 | 不实现分支，只保证发起写入金额变量 |
| 会签 | 「财务多人」 | Leave Collaborate / 图 | 不实现 Leave |
| 单据 Status | 列表/下游唯一真相 | 不解释业务 Status | Submit/Back/Finish/Aborted 回写 |
| 强一致 | 通过才能下单 | 提供 Sync Hook + Kit | OnFinish 必须 Sync FailFast |
| 转办约束 | 仅财务可接 | TransferProcess | OnChanging 校验角色 |
| 列表进度 | 50 单摘要 | 实例/待办查询 | Progress 批量薄封装 |

## 3. 时间线（逐步对照）

### 3.1 员工点「提交」

**业务要：** 先落业务单再挂流程；任一步失败整单回滚（禁止有流程无单据 / 有单据无流程）。

| 步骤 | 归属 | 动作 |
|------|------|------|
| 1 | 门面 `OnSubmit` | `INSERT biz_purchase`：`Status=审批中`，写出 `BizPK`、金额等 |
| 2 | 引擎 `StartProcess` | 建实例；Runner 带 `BizChannel=purchase`、`BizPK`、金额变量 |
| 3 | 门面 `OnStarted` | 回写 `ProcessInstanceId` |

**宿主锚点：** FormBiz Submit → Start → OnStarted（与请假同构）。

**失败：** Start 失败 → 事务回滚，业务行不应残留「审批中且无实例」。

---

### 3.2 主管打开待办，点「同意」

**业务要：**

- 单据仍应是可审状态；金额未被篡改超权。  
- 可选：列表显示「当前在财务」。

| 步骤 | 归属 | 动作 |
|------|------|------|
| 1 | Gate / `OnCompleting(Approve)` | 只读校验；拒绝则待办保留、流程不推进 |
| 2 | 引擎 `RunProcess` | 按 Leave/网关推进 |
| 3 | `OnConsent`（可选） | 更新「当前环节」文案；**不**改终态 Status |

**门面价值：** 业务只写校验；展开注册时自动挂 Gate（Match=`purchase` + Operation∈Approve 等）。

---

### 3.3 主管点「退回修改」（SendBack）

**业务要：** `Status=退回修改`；**不是**已驳回；申请人改完再送，流程仍在。

| 步骤 | 归属 | 动作 |
|------|------|------|
| 1 | 引擎 `SendBackProcess` | 目标×再发送两维按设计 |
| 2 | `OnSendBack` / FormBiz `OnBackToModify` | 写退回修改态 |

**相对某参照引擎：** Sail FormBiz 已有退回一等回调；某参照引擎产品五方法几乎无「退回改单」一等钩子——门面应**保留** Sail 细回调，勿削成只有 Outcome。

---

### 3.4 财务「转办」给同事

**业务要：** 目标人必须在财务角色内。

| 步骤 | 归属 | 动作 |
|------|------|------|
| 1 | `OnChanging(Transfer)` | 校验目标角色；失败则不交引擎 |
| 2 | 引擎 `TransferProcess` | 同节点换人 |
| 3 | Status | 通常仍为审批中 |

**无门面时：** 开发者须自知在 Transfer 前挂 Gate。  
**有门面时：** 业务类一个 Changing，展开时挂到对应 `FlowOperation`。

---

### 3.5 财务会签通过 → 流程结束

**业务要（最硬）：** `Status=已通过`；下游靠此下单；失败不得假装成功。

| 步骤 | 归属 | 动作 |
|------|------|------|
| 1 | 引擎办结 | 触发 `OnProcessCompleted`（等） |
| 2 | Sync Hook → `OnFinish` | **同一事务**用 `FlowHookContext.Kit` 更新 `Status=已通过` |
| 3 | OnFinish 失败 | 走门面约定的 **单一失败唤起**；业务在该唤起内自行决定副作用（补写 Status、告警、补偿单…）。糖层不另开「实例 Faulted + 管理 Retry」产品轨 |

**宿主锚点：** `UseFormBizLifecycleHook` → 按 BizChannel 调 Handler.OnFinish（请假已委托消双写）。

**失败语义（讨论收敛）：**

- 门面保证：成功路径清晰；失败时 **只唤起一次** 业务可感知的失败入口（名称待定，如 `OnFinish` 抛错/返回失败，或显式 `OnFailed(ctx)`——实现时二选一写死，勿两套并行）。  
- 业务保证：在该唤起里按自己的一致性模型做事；需要与流程同事务则继续用 **Kit**；需要事后补偿则自己发消息——**不由糖层代选**。  
- 相对某参照引擎：不把「故障态+重试 再调结论回调」做成 sailflow.biz 门面的默认承诺；若将来引擎层要该模型，另开专题，与本糖解耦。

---

### 3.6 终态二分：正常结束 vs 撤销结束

**约定（讨论收敛）：**

| 判据 | 门面回调 | 业务含义 |
|------|----------|----------|
| 实例因 **到达结束节点（End）** 而终局 | **`OnFinish`** | **正常结束**；`Outcome`/`结论` 区分已通过、已驳回等（图上可有多个 End） |
| 实例 **未到达结束节点** 即终局 | **`OnAborted`（撤销结束）** | 撤回、作废、强制终止、管理关闭等「非走完图」的收场 |

要点：

- **「正常结束」≠「业务通过」。** 驳回到带 `rejected` 的 End，仍是 OnFinish，只是结论为驳回。  
- **「撤销结束」≠「办理条点了驳回」。** 若 Reject 设计为 RejectMode=Terminate、不经 End，则归 OnAborted；若 Reject 连到 End，则归 OnFinish——**以是否抵达结束节点为准**，不以按钮文案为准。  
- SendBack（退回修改）**不是**终态，继续走 `OnSendBack`，两侧都不进。  
- 与现行 FormBiz：今日 `OnProcessCompleted` / `OnProcessRejected` / `OnProcessClosed` **都进 OnFinish 再靠 FinishEvent 分支**。糖层可收成两回调，展开时再映射到现有三事件（见下表）。

| 引擎 / 宿主事件（现状） | 建议归入门面 | 说明 |
|-------------------------|--------------|------|
| `OnProcessCompleted`（典型：走到通过 End） | `OnFinish(outcome≈approved)` | 正常结束 |
| `OnProcessRejected`（若语义=驳回到 End / 驳回办结） | `OnFinish(outcome≈rejected)` | 仍是正常结束+驳回结论；**不要**默认叫撤销 |
| `OnProcessClosed` / Terminate / Discard / Cancel / Withdraw | `OnAborted` | 撤销结束；Closed 若实际不经 End，归此侧 |
| SendBack 成功 | `OnSendBack` | 非终态 |

#### 3.6.1 「业务自撤」是什么（及为何 Sail 糖默认不采用）

某参照引擎有一句特例：业务经 `参照侧业务运行时 Withdraw` **自己撤**时 **不**再调 `OnAborted`；只有审批中心发起人撤回才回调。

其背景是 **防双写**，不是第二种引擎语义：

```text
业务页面「撤销申请」
  → 业务代码先改 Status=已撤回
  → 再调引擎 Withdraw
  → 若再 OnAborted，可能把 Status 写第二次
```

「业务自撤」= **撤回意图已在业务层处理完**，引擎只是附带停流程，所以跳过回调。

**Sail 糖默认不做这套特例**（与你的理解一致）：

- 凡 **走流程引擎** 导致「未到 End 即终局」（含撤回）→ **正常触发 `OnAborted`**。  
- 业务 **不要**在调引擎前先改终态；终态以 `OnFinish` / `OnAborted` 为准。  
- 业务页「撤销」= 调引擎 Withdraw → 等 `OnAborted` 回写。一条真相，无需「自撤跳过」。

| 动作 | 业务要 | 门面（按上表） |
|------|--------|----------------|
| 同意走到「已通过」End | `Status=已通过` | `OnFinish(approved)` |
| 驳回走到「已驳回」End | `Status=已驳回` | `OnFinish(rejected)` |
| 管理员 Discard/Terminate、关闭不经 End | `Status=已作废` 等 | `OnAborted` |
| 申请人撤回（经引擎） | `Status=已撤回` | `OnAborted`（正常触发） |

## 4. 没有门面时要手搓什么（痛点清单）

同一采购场景，碎片化接入通常要：

1. 实现 FormBiz Handler（Submit/Finish/Back…）  
2. `AddSailFormBiz` + `UseFormBizLifecycleHook`  
3. 另写 Gate：Approve 前防篡改  
4. 另写 Gate：Transfer 前校角色  
5. 死记 OnFinish = Sync + Kit（否则死锁或单据漂移）  
6. 列表自拼实例查询  
7. 缺省流程图是否首次自举——再写一段 Host  

**能力都在；贵的是每次业务重复拼装与踩坑。** 门面 = 把 1–7 收成「一个类 + 一次 Use」。

## 5. 与真实代码的同构（降低仿真感）

宿主请假已是缩小版同一故事：

| 请假（已落地） | 采购（仿真放大） |
|----------------|------------------|
| `LeaveFormBizHandler` | `PurchaseApprovalHandler` |
| FormCode ↔ BizChannel | `purchase` |
| `OnFinish` → 请假 Status | `OnFinish` → 采购 Status |
| `UseFormBizLifecycleHook` | 同 |
| 旧 Leave Hook 委托 FormBiz 防双写 | 门面展开时禁止第二套 Finish Hook |
| （弱）办理前校验 / Changing | 金额篡改 Gate、转办 Changing |
| （弱）退回改态 | `OnBackToModify` 一等 |
| （弱）列表 Progress | `QueryProgressByBizKeys` |

结论：采购仿真**不**要求新引擎原语；要求把请假已验证的回写路径，升级成「可复用的业务接入配方」。

## 6. 推荐实施形态（讨论默认）

### 6.1 路线与落点（已收敛）

| 项 | 结论 |
|----|------|
| 程序集 | **`sailflow.biz`**（对接前哨；糖与默认组合根放这里，不进 pure） |
| 形态 | **B1**：Facade 与 FormBiz 合并（一接口或组合）；`UseApprovalBusiness` 展开为已有 Gate/Hook/FormBiz |
| 不取 | B2 双轨；C pure 一等 SPI |
| Host | 仓外宿主只实现具体 Handler + `UseXxx`，不再私有一套平行门面 API |

### 6.2 门面方法建议（跟 Sail，不照搬某参照引擎五件套）

| 方法 | 背后挂到 |
|------|----------|
| `OnSubmit` / `OnStarted` | FormBiz 已有 |
| `OnCompleting(op, ctx)` | Gate（按 `FlowOperation`） |
| `OnConsent` / `OnSendBack` / … | Dispatcher `NotifyAfterOperation` |
| `OnFinish(outcome)` | **仅**到达结束节点的办结 → Sync Lifecycle；outcome 区分通过/驳回 |
| `OnAborted(kind)` | **未**到结束节点的终局（撤回/作废/终止/关闭…） |
| `GetFormData` | Query |
| Descriptor（可选） | 缺省流程、允许结论、组件键 |
| Progress（可选 Runtime） | 批量查询封装 |

### 6.3 硬约束

1. 禁止 Facade 改 NodeMediator；糖只在 **`sailflow.biz`**。  
2. 同一 `BizChannel` / BusinessCode 只登记一次 → 启动失败。  
3. 成功终态路径：OnFinish 走 Sync + Kit（需要同事务时）；Notifier/邮件不得进 OnFinish。  
4. **失败：仅一种唤起**；业务在唤起内自管副作用；糖层不并行承诺故障态+重试。  
5. 与 FormBiz：**合并（B1）**；展开时不得再挂第二套终态 Hook。  
6. Leave/Resolve/抄送推送：**不**进门面。

### 6.4 分阶段

| 阶段 | 产出 |
|------|------|
| 0 评审 | 已收敛：落点 / 失败 / 终态二分 / Q5–Q7 倾向（见 §7） |
| 1 薄门面 | `sailflow.biz` 接口 + `UseApprovalBusiness` 展开；**引擎终态→Finish/Aborted 映射测试（Q8）**；请假样例改走门面登记 |
| 2 补齐 | Changing 操作集、Progress |
| 3 延后 | DefaultProcess 自举（Q5）；可选采购演示种子（Q6） |
| 4 验证 | conformance：同意→Finish；回调失败只一条路径；SendBack 不走 Finish；撤销→OnAborted |

## 7. 问题结论（已收敛）

| # | 问题 | 结论 |
|---|------|------|
| ~~Q1~~ | 放哪 | **`sailflow.biz`** |

> **糖在 `sailflow.biz`：FormBiz 合并展开；到 End→OnFinish、否则→OnAborted；回调失败即失败、无 OnFailed；一期请假验证、自举与采购种子延后。**
